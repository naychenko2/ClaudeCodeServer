# Модалка «Выгрузить историю решений в репозиторий» — спецификация

Этап 3 «Истории решений»: экспорт паспортов изменений в локальную ветку
`ccs/dossiers/v1`. Этот файл — макет-спецификация кнопки тулбара и диалога
подтверждения со всеми состояниями. Реализация — за Кирой; здесь только
композиция из существующих контролов и токенов, ничего нового в дизайн-систему
не добавляется.

## Сценарий и проблема

Человек накопил историю решений по проекту и хочет поделиться ею с тем, кто
работает с репозиторием без AI Home, — выгрузить паспорта в git-ветку. Действие
пишет в репозиторий (пусть и в отдельную ветку), поэтому обязано подтверждаться
диалогом, который честно отвечает на три вопроса: **куда** уедет (ветка
`ccs/dossiers/v1`), **что НЕ случится** (рабочее дерево не тронут, пуша не будет),
и **кому это станет видно** (если папку подключил ещё один пользователь — он тоже
увидит историю после отправки ветки).

По ходу действия у диалога шесть состояний: обычное подтверждение, то же с
предупреждением об общей папке, загрузка, успех, «нечего выгружать», ошибка.

## Точка входа: кнопка тулбара

Панель «История решений» (`DossierHistoryPanel`) — `PanelShell`, шапка принимает
контролы через `PanelHeaderSlot`. Кнопка:

- **Десктоп:** `PanelHeaderSlot side="right"` → `IconButton size="sm"`, иконка
  `Upload` (lucide, `strokeWidth={ICON_STROKE}`), `title="Выгрузить в репозиторий"`.
  Без `pinned`: выгрузка — не главное действие панели, в покое шапка остаётся
  чистой, кнопка появляется по наведению на карточку вместе с соседями.
- **Мобила** (панель — шторка, `PanelShell`-шапки нет): `useHasPanelHeader()`
  возвращает false → запасной вариант в теле панели: чип в subheader-ряду рядом
  с «sha или текст», тот же `chipStyle`, что у соседних чипов (см. код панели) —
  `C.bgCard` / `C.border` / `R.max`, иконка `Upload` + подпись «Выгрузить».

Открывает модалку в состоянии 1 (или 2, если папка общая — флаг приходит с
бэкенда вместе со списком/настройками проекта).

## Модалка

База — `Modal` из `components/ui` (`width={MODAL_W.confirm}` = 380, футер —
зона действий). Заголовок через проп `title` (PT Serif 22 автоматически):

> **Выгрузить историю решений в репозиторий**

Имя ветки в текстах набирается инлайн-кодом: `FONT.mono`, `FS.sm`, фон
`C.bgInset`, радиус `R.sm`, паддинг `SP.xxs`/`SP.xs` — как mono-фрагменты в
карточках панели (`FONT.mono` у sha коммита).

### Состояние 1. Обычное

```
+--------------------------------------------------+
|  Выгрузить историю решений в репозиторий         |
|                                                  |
|  Паспорта изменений уедут в ветку                |
|  `ccs/dossiers/v1`. Ваше рабочее дерево не       |
|  изменится, а ветка останется локальной, пока    |
|  вы не отправите её сами.                        |
|--------------------------------------------------|
|  [Отмена]      [Выгрузить]  [Выгрузить и отправить] |
+--------------------------------------------------+
```

- Тело — текст дословно: «Паспорта изменений уедут в ветку `ccs/dossiers/v1`.
  Ваше рабочее дерево не изменится, а ветка останется локальной, пока вы не
  отправите её сами.» Шрифт `FS.md`, `C.textPrimary`, line-height 1.5.
- Футер — три кнопки `Button size="md"`:
  - «Отмена» — `variant="ghost"`;
  - «Выгрузить» — `variant="ghostAccent"` (действие-ветвление без акцентной
    заливки: безопасный путь, ветка остаётся локальной);
  - «Выгрузить и отправить» — `variant="primary"` (главное действие — единственная
    акцентная заливка в диалоге, accent-дисциплина).
- Порядок слева направо: отмена → безопасное → главное. `ModalActions` на пару
  действий не ложится — футер собирается вручную тем же паттерном: `flex`,
  `gap: 10` (как в `ModalActions`), кнопки равной доли (`flex: 1`), главная —
  `flex: 1.5`.

### Состояние 2. С предупреждением об общей папке

То же, что состояние 1, плюс выноска над футером:

```
|  !  Эту папку как проект подключил ещё один      |
|     пользователь. После отправки ветки историю   |
|     решений увидит и он.                         |
```

- Выноска: фон `C.warningBg`, текст `C.warningText`, радиус `R.lg`, паддинг
  `SP.sm`/`SP.md`, иконка `AlertTriangle` (16, `ICON_STROKE`) слева, текст
  `FS.base`, line-height 1.45. Отступ от тела — `SP.md`.
- Текст дословно: «Эту папку как проект подключил ещё один пользователь. После
  отправки ветки историю решений увидит и он.»
- Кнопки и их смысл не меняются — предупреждение не повышено до danger: ветка
  остаётся локальной, ничего необратимого на этом шаге нет.

### Состояние 3. Загрузка

После клика по «Выгрузить» или «Выгрузить и отправить»:

- нажатая кнопка — `loading` (спиннер внутри `Button`, у primary фон сам уходит
  в `C.accentSoft`), обе другие — `disabled`;
- диалог не закрывается: `closeOnBackdrop={false}`, Escape глушится (передать
  no-op в `onClose` на время запроса) — закрытие посреди git-операции оставило
  бы человека без ответа;
- тело и предупреждение остаются на месте — диалог не перерисовывается, ничего
  не прыгает.

### Состояние 4. Успех

Диалог переключается в финальную карточку (тот же `Modal`, заголовок «Выгрузить
историю решений в репозиторий» сменяется телом результата):

```
+--------------------------------------------------+
|  ✓  История решений выгружена в ветку            |
|     ccs/dossiers/v1 — паспортов: 12.             |
|--------------------------------------------------|
|                              [Закрыть]           |
+--------------------------------------------------+
```

- Иконка `CircleCheck` (20) цветом `C.success`, слева от текста.
- Текст дословно: «История решений выгружена в ветку ccs/dossiers/v1 —
  паспортов: N.» (`N` подставляет бэкенд; имя ветки — тем же mono-инлайном).
  `FS.md`, `C.textPrimary`.
- Единственная кнопка «Закрыть» — `variant="secondary"`, `size="md"`, закрывает
  диалог. *(Микротекст сверх заданного списка — согласовать; альтернатива —
  оставить только закрытие по Escape/оверлею, но у финального состояния должна
  быть видимая точка выхода.)*

### Состояние 5. «Нечего выгружать»

Бэкенд вернул ноль новых паспортов (как при открытии с предзагрузкой, так и в
ответ на действие):

```
+--------------------------------------------------+
|  i  Всё уже выгружено — новых паспортов с        |
|     прошлого раза нет.                           |
|--------------------------------------------------|
|                              [Закрыть]           |
+--------------------------------------------------+
```

- Иконка `Info` (20) цветом `C.textSecondary`; текст `FS.md`, `C.textPrimary`,
  дословно: «Всё уже выгружено — новых паспортов с прошлого раза нет.»
- Тон нейтральный, НЕ warning и НЕ success: ничего не сломалось и ничего не
  произошло. Кнопка — «Закрыть» (`secondary`).

### Состояние 6. Ошибка

```
+--------------------------------------------------+
|  !  Не удалось выгрузить историю решений.        |
|     Рабочее дерево не тронуто — попробуйте       |
|     ещё раз.                                     |
|--------------------------------------------------|
|  [Отмена]                        [Выгрузить]     |
+--------------------------------------------------+
```

- Выноска: фон `C.dangerBg`, текст `C.dangerText`, иконка `AlertTriangle` (20)
  цветом `C.danger`; геометрия та же, что у warning-выноски состояния 2.
- Текст дословно: «Не удалось выгрузить историю решений. Рабочее дерево не
  тронуто — попробуйте ещё раз.»
- Футер возвращается к действию: «Отмена» (`ghost`) + «Выгрузить» (`primary`,
  повтор запускает состояние 3). Если ошибка пришла от «Выгрузить и отправить» —
  правая кнопка повторяет исходное действие («Выгрузить и отправить»).

## Темы и мобила

- **Тёмная тема:** все поверхности — только семантические пары токенов
  (`warningBg/warningText`, `dangerBg/dangerText`, `bgInset`, `overlay`,
  `SHADOW.modal`), поэтому переключение бесплатно; отдельных значений для dark
  не требуется. Контраст warning-выноски в тёмной теме обеспечен парой
  `C.warningText` на `C.warningBg` — сырых hex нет.
- **Мобила:** `Modal` сам уезжает в bottom-sheet (drag-handle, `R.sheet`,
  `SHADOW.sheet`, safe-area) — специальной раскладки не нужно. Футер шторки у
  `Modal` уже столбик (`flex-direction: column`, `gap: 10`): кнопки выстраиваются
  сверху вниз «Выгрузить и отправить» → «Выгрузить» → «Отмена» (главная сверху,
  до неё ближний большой палец). Высоты `size="md"` (40) достаточно для tap.
- **Длинные тексты:** имя ветки фиксированное и короткое, переполнения не даёт;
  `N` в успехе не ограничено — строка переносится, mono-фрагмент ветки не
  разрывается (`whiteSpace: 'nowrap'` на инлайн-коде).
- **Фокус с клавиатуры:** кнопки получают `SHADOW.focus` из общих стилей
  контролов; начальный фокус — на «Выгрузить и отправить» (главное действие).

## Спецификация для реализации

Контролы (всё из `frontend/src/components/ui/`, новых нет):

| Кусок | Контрол / паттерн |
|---|---|
| Диалог | `Modal` (`width: MODAL_W.confirm`, `footer`) |
| Кнопки | `Button` (`primary` / `ghostAccent` / `ghost` / `secondary`, `size="md"`, `loading`) |
| Футер | ручной flex по паттерну `ModalActions` (3 действия — `ModalActions` не подходит) |
| Кнопка тулбара | `PanelHeaderSlot side="right"` + `IconButton size="sm"`; мобильный запасной — чип по `chipStyle` из `DossierHistoryPanel` |
| Иконки (lucide) | `Upload`, `AlertTriangle`, `CircleCheck`, `Info`, `strokeWidth={ICON_STROKE}` |

Токены: `C.textHeading/textPrimary/textSecondary`, `C.warningBg/warningText`,
`C.danger/dangerBg/dangerText`, `C.success`, `C.bgInset`, `FS.base/md/sm`,
`R.lg/sm`, `SP.xxs/xs/sm/md`, `FONT.mono`, `SHADOW.modal/sheet/focus`,
`MODAL_W.confirm`. Ни одного литерала цвета или размера.

Поведение: во время запроса — `closeOnBackdrop={false}` + no-op `onClose`;
переходы состояний 1→3→4/5/6 внутри одного открытого `Modal`, без закрытия и
переоткрытия (карточка не моргает).

## Итерации

- **v1** — первый проход: шесть состояний, тексты дословно из постановки,
  композиция целиком на существующих контролах. Открытые микротексты (сверх
  постановки, требуют согласования): кнопка «Закрыть» в финальных состояниях
  (успех / «нечего выгружать») и заголовок модалки «Выгрузить историю решений в
  репозиторий» (взят из названия фичи в постановке).
