# Графики панели «Локальные модели» v2: читаемость

Спецификация для Киры. Макет — [local-model-stats-charts-v2.html](local-model-stats-charts-v2.html) (обе темы, 340 px и мобильный лист).
Код, который меняется: `frontend/src/features/localModel/ThroughputChart.tsx` и `ChartCard` в `TextTab.tsx`.
Прежняя версия — [local-model-stats-panel.html](local-model-stats-panel.html), раздел «График».

## Проблема

Андрей открыл карточку «Нагрузка» и не понял, что на ней. По коду видно почему:

1. **Две оси на одном поле.** Слева ток/с, справа очередь, у обеих числа без единиц. Подписи «ток/с, левая ось» стоят под графиком, глаз их не связывает с цифрами.
2. **«1» дважды.** При простое масштаб зажат в `max(…, 1)`. Слева метки 0 / `round(0.5)` / 1 дают «0, 1, 1», справа «0, 1». Отсюда две единицы, и непонятно, чего.
3. **Узкая полоса у правого края.** Точка приходит раз в 5 с: за 1 ч это 720 столбиков шириной 4 px на ~300 px поля, они слипаются в сплошную полосу. Ось X при этом всегда покрывает всё окно, а история живёт в памяти и после рестарта сервера есть только за последние минуты. Данные жмутся вправо, а слева пусто и никак не подписано.
4. **`preserveAspectRatio="none"`** растягивает SVG вместе с текстом: на узкой панели подписи сплющены.
5. **Нет считывания.** Навести или коснуться нельзя, точное значение не узнать.

Вкладка «Медиа» графиков сейчас не содержит: там списки «Сейчас считается», «Очередь», «Последний час». Менять там нечего. Если график появится, правила ниже обязательны и для него.

## Решение одной строкой

Не одно поле с двумя осями, а **несколько маленьких графиков друг под другом с общей осью времени**. У каждого одна величина (или одна единица), единица прямо в заголовке, своя шкала. Точки сводятся в интервалы по ширине. Сверху строка-итог (среднее и пик), при наведении или касании она становится строкой считывания.

**v2.1 (решение Андрея):** график очереди убран — на нём почти всегда ноль, и он ничего не объяснял. На его место встают **показатели кэша**: они и объясняют, почему выработка проседает. Карточка теперь называется «Нагрузка и кэш». Текущее число «ждут в очереди» в блоке «Сейчас» остаётся как было.

## Карточка «Нагрузка и кэш»: состав сверху вниз

```
НАГРУЗКА И КЭШ                           [15 мин | 1 ч]
в среднем 412 ток/с · пик 980 · кэш 87 %      ← строка-итог / считывания
Выработка, ток/с                         1000 ┐
  ▁▂▅▇▆▅▃ ─ ─ ─ ─ ─ ─ ─ ─ ─ ср.            500 │  график 1, 96 px
                                            0 ┘
Кэш, %                                    100 ┐
  ‾‾‾\__/‾‾‾  (попадания)                    50 │  график 2, 64 px
  ▒▒▒▓▓▓▒▒▒   (занято блоками)               0 ┘
● попадания  ● из RAM  ▮ занято                   ← легенда / значения
Вытеснения                          за окно 7   2 ┐  график 3, 32 px
      ▌ ▌▌                                    0 ┘
−15 мин      −10      −5         сейчас           ← общая ось времени
```

Отступы: между строкой-итогом и графиком 1 — `SP.sm`; между графиками — `SP.sm`; между графиком 2 и легендой — `SP.xxs`; между графиком 3 и осью времени — `SP.xxs`.

**Почему в одной карточке, а не отдельной.** Ценность кэша на графике — увидеть связь: выработка просела ровно там, где упали попадания и выросли вытеснения. Для этого нужна одна ось времени и одна вертикаль считывания через все три поля. Отдельная карточка разорвала бы ось и потребовала бы второй переключатель окна.

**Почему два графика кэша, а не один.** Доли (занято, попадания) живут на шкале 0–100 % и читаются вместе. Вытеснения — штуки, редкие всплески; на процентной шкале их не нарисовать. Четыре серии на одном поле — снова каша, поэтому: один процентный график с **тремя** сериями разного вида (две линии и фоновая область) плюс маленький столбиковый для вытеснений.

### Строка-итог (над графиками)

- Шрифт `FS.sm`, цвет `C.textSecondary`; числа `FONT.mono`, weight 700, `C.textHeading`.
- Текст: `в среднем {formatTps(avg)} · пик {round(max)} · кэш {formatPerc(hitAvg)}`, например `в среднем 412 ток/с · пик 980 · кэш 87 %`. `formatTps` из `format.ts` сам добавляет « ток/с», второй раз единицу не писать. `hitAvg` — см. «Данные». Нет `hitAvg` (движок не отдаёт кэш или запросов не было) — хвост ` · кэш …` не пишется.
- Нет точек с генерацией в окне — `за период генерации не было`, цвет `C.textMuted`.
- При наведении или касании графика строка **заменяется** считыванием (см. ниже). Ушёл курсор или пропало касание — вернулся итог.
- Высота строки фиксированная: `FS.sm × 1.45`. Смена текста не двигает график. Не помещается — многоточие (`white-space: nowrap; overflow: hidden; text-overflow: ellipsis`).

| Подпись | слева над полем: `Выработка, ток/с`, `FS.xs`, weight 600, `C.textSecondary` |

| Сетка | три горизонтали на метках, 1 px `C.borderLight`; нижняя (ноль) — 1 px `C.border` |

| Пустое окно | см. «Состояния» |

### График 2 — «Кэш, %»

Три серии на одной шкале 0–100 %. Различаются **видом**, а не только цветом: фоновая область без обводки и две линии разной толщины.

| Серия | Величина | Вид |
|---|---|---|
| **Занято** блоками KV-кэша | `kvUsage`, **максимум** в интервале (пик давления не теряется) | **область без линии**, заливка `C.textMuted`, opacity 0.18. Лежит фоном под линиями |
| **Попадания** в prefix-кэш | `Σ prefixHits / Σ prefixQueries` за интервал | линия `C.success` 1.75 px, `stroke-linejoin: round` |
| **Из RAM** — попадания в RAM-тир | `Σ ramHits / Σ ramQueries` за интервал | линия `C.info` 1.25 px. Если движок RAM-тир не отдаёт (все `ramQueries` в окне `null`), серии нет, и в легенде её пункта нет |

| Что | Как |
|---|---|
| Подпись | `Кэш, %`, стиль как у графика 1 |
| Высота поля | 64 px |
| Ось Y | справа, **фиксированная**: `0`, `50`, `100`. Не «круглая» и не по максимуму: доля всегда 0–100, а плавающая шкала сделала бы 60 % похожим на 100 % |
| Сетка | горизонтали на 50 и 100 — 1 px `C.borderLight`; ноль — 1 px `C.border` |
| Интервал без запросов (`Σ queries = 0`) | у линий попаданий **обрыв**, без фона «нет данных»: стенд жив, просто не спрашивали. Область «занято» рисуется как есть. Это не разрыв движка (тот — по `genThroughput == null`, правила ниже) |
| Легенда | строкой **под** полем, `FS.xs`, `C.textSecondary`: `● попадания  ● из RAM  ▮ занято`. Маркер линии — кружок 6 px цвета серии; маркер области — квадрат 8×8 `C.textMuted` opacity 0.18 с обводкой 1 px `C.border` (иначе в светлой теме его не видно). Пункты через `SP.md`. Высота строки фиксированная `FS.xs × 1.45` |
| Легенда при считывании | у пунктов появляются значения интервала: `● попадания 87 %  ● из RAM 52 %  ▮ занято 61 %`. Числа `FONT.mono`, weight 700, `C.textHeading`. Нет значения — `—`. Ширина < 300 px — подписи короче: `● попад. 87 %  ● RAM 52 %  ▮ занято 61 %` |

**Почему так.** Попадания — главная линия: это то, что Андрей ищет («кэш работает или нет»), поэтому зелёная и толще. RAM-тир — вторичная, тоньше и синяя: она важна, когда агентов несколько и их выбивает из видеопамяти, а у одиночного агента почти всё время у нуля. «Занято» — контекст, а не сигнал: нейтральная серая подложка показывает, где кэш забит, и не спорит с линиями. Когда подложка у верха, а зелёная линия падает — это и есть «кэш не помещается».

### График 3 — «Вытеснения»

| Что | Как |
|---|---|
| Величина | `preemptions`: сколько запросов движок выбил из кэша, **сумма** за интервал. Штуки, целые |
| Подпись | слева `Вытеснения`, стиль как у графика 1. Справа в той же строке — значение: без считывания `за окно {N}` (сумма по окну), при считывании — число интервала, `0` тоже пишется. Числа `FONT.mono` weight 700 `C.textHeading` |
| Тип | **столбики** по интервалам |
| Цвет | `C.danger`, opacity 0.85. Вытеснение — прямой вред (запрос читает промпт заново), и в «Памяти» оно уже красное: цвет совпадает с прежним смыслом |
| Ширина столбика | ширина интервала минус 1 px зазора, скругление 1 px сверху |
| Высота поля | 32 px |
| Ось Y | справа, **две** метки: 0 и верх. Верх — целое: `max(2, ceil(max))` |
| Сетка | только нулевая линия, 1 px `C.border` |
| Вытеснений в окне 0 | **поле не рисуется вовсе**: остаётся одна строка подписи `Вытеснения` и справа `не было`, `C.textMuted`. Это обычное состояние, 32 px пустоты на него тратить жалко. Первое вытеснение раскрывает поле — карточка вырастает вниз, графики выше не двигаются |
| Движок не отдаёт счётчик (все `preemptions` `null`) | строки нет совсем |

**Подписи осей Y справа у всех графиков**: сравнивать глазом приходится по последнему значению, а оно у правого края («сейчас»).

### Общая ось времени (под последним графиком)

- 15 мин: `−15 мин`, `−10`, `−5`, `сейчас`. 1 ч: `−1 ч`, `−45`, `−30`, `−15`, `сейчас`. Единица — только на первой метке.
- `FONT.mono` `FS.xs` `C.textMuted`; крайние метки прижаты к краям (`start` / `end`), средние по центру.
- Ширина < 300 px — средние метки убрать, оставить только крайние.

### Легенда

У графиков 1 и 3 отдельной легенды нет: одна величина и своя подпись над полем. Легенда есть только у графика 2 (три серии), она же строка значений. Прежнюю строку «ток/с, левая ось · очередь, правая ось» удалить.

## Данные: интервалы, шкала, среднее

Чистые функции в `ThroughputChart.tsx`, тесты рядом в `ThroughputChart.test.ts`.

**Интервалы.** Точки идут раз в 5 с, рисуются по интервалам:
- 15 мин — 60 интервалов по 15 с;
- 1 ч — 60 интервалов по 60 с.

В интервале:

| Серия | Сведение | Пустой интервал |
|---|---|---|
| выработка | **среднее** значений `!= null` | `null` (разрыв) |
| занято (`kvUsage`) | **максимум** значений `!= null` | `null` |
| попадания | `Σ prefixHits / Σ prefixQueries` по точкам, где оба `!= null` | `Σ queries = 0` → `null` (обрыв линии, не разрыв) |
| из RAM | `Σ ramHits / Σ ramQueries`, так же | так же |
| вытеснения | **сумма** значений `!= null` | все `null` → `null`, столбика нет |

**Доля за интервал считается из сумм, а не средним долей точек.** Точка в 5 с с одним коротким запросом дала бы 0 % или 100 % и перевесила бы минуту реальной работы. Поэтому бэкенд отдаёт приращения счётчиков, а не готовые проценты.

60 интервалов на ~300 px — 5 px на столбик, читается на любой ширине.

**«Круглая» шкала (только график 1).** Верх оси = ближайшее сверху число из ряда `1, 2, 5 × 10ⁿ` от максимума интервалов, **не меньше 10**. Середина = верх / 2. Примеры: макс 37 → 50 (метки 0 / 25 / 50); 412 → 500; 980 → 1000; 0 → 10. Подписи целые, без единицы (она в заголовке графика), а 1000 и больше — `1k`, `1.5k`. Для этого новая функция `formatAxisTps(v)` в `format.ts`, а не `formatTps`: тот добавляет « ток/с». У графика 2 шкала фиксированная 0–100, у графика 3 — целая `max(2, ceil(max))`.

**Среднее за окно** (`avg`) — среднее `genThroughput` по **исходным** точкам окна, где `genThroughput != null` **и** `running > 0`. Простой в среднее не входит: «412 ток/с» значит «так быстро стенд пишет, когда работает». Иначе ночной простой даст «12 ток/с», и число соврёт. Пик — максимум по тем же точкам. Если в точке нет `running` (поле `running?` в `history` из `lib/api.ts`), она в среднее не входит. В `ThroughputSample` нужно добавить поле `running`.

**Кэш за окно** (`hitAvg` в строке-итоге) — `Σ prefixHits / Σ prefixQueries` по всем точкам окна. Простой сюда сам не попадает: без запросов приращения нулевые.

## Что нужно от бэкенда (Денису)

Сейчас точка истории (`LocalModelStatsPoint`) несёт только `GenThroughput`, `Running`, `Waiting`. Доли попаданий и вытеснения поллер считает лишь для «сейчас» (`UpdateCurrent`, окна 60 с и 15 мин), в историю они не попадают. Нужно добавить в **ту же** точку кольца — с тем же шагом `PointStep` = 5 с и той же глубиной `HistoryWindow` = 1 ч — шесть полей:

| Поле JSON (`history[]`) | Тип | Единица | Откуда | Как считать |
|---|---|---|---|---|
| `kvUsage` | `number \| null` | доля 0..1 | `vllm:kv_cache_usage_perc` (`KvUsagePerc`) | **максимум** по опросам с прошлой точки (при нагрузке опрос раз в 1 с, пик между точками не теряется). Нет метрики — `null` |
| `prefixHits` | `number \| null` | токены | `vllm:prefix_cache_hits_total` | приращение счётчика с прошлой точки |
| `prefixQueries` | `number \| null` | токены | `vllm:prefix_cache_queries_total` | приращение с прошлой точки |
| `ramHits` | `number \| null` | чанки | `vllm:kv_offload_tiering_chunk_hits_total` | приращение с прошлой точки |
| `ramQueries` | `number \| null` | чанки | `vllm:kv_offload_tiering_chunk_queries_total` | приращение с прошлой точки |
| `preemptions` | `number \| null` | штуки | `vllm:num_preemptions_total` | приращение с прошлой точки |

Правила для приращений (одинаковые для всех пяти счётчиков):

- **Отдаём приращения, а не проценты.** Фронт сводит точки в интервалы по 15 и 60 с и считает долю из сумм. Процент из точки в 5 с сложить честно нельзя.
- `null`, если нет прошлой точки, счётчик на прошлой или текущей точке не отдан движком, или счётчик **уменьшился** (рестарт движка). Ровно та же проверка сброса, что уже есть в поллере для буфера счётчиков (`cur < prev`). Отрицательных значений в JSON быть не должно.
- Приращение считать между **точками кольца** (как сейчас `GenThroughput` через `_lastPointSnap`), а не между опросами: иначе при опросе раз в 1 с между точками потеряются 4 опроса из 5.
- Целые; доли единиц не нужны.

`waiting` в истории оставить: график его больше не читает, но поле дешёвое, а убирать его — отдельное изменение контракта без пользы. В `lib/api.ts` тип элемента `history` расширить шестью необязательными полями того же имени.

Объём: 720 точек × 6 полей — пренебрежимо.

## Почему средняя — в карточке «Нагрузка и кэш», а не в «Скорости»

«Скорость» показывает **сейчас и на поток**: генерация на поток и чтение промпта. Средняя за окно — **за 15 мин или 1 ч и по стенду целиком**: другое окно и другая единица учёта. Третье число в «Скорости» с тем же «ток/с» будут сравнивать с «на поток», а это разные величины. В «Нагрузке» число стоит рядом со своим переключателем окна и меняется вместе с ним. Пунктир на графике показывает, выше или ниже среднего стенд идёт сейчас.

В «Скорости» ничего не меняется.

## Считывание: наведение и касание

- Область считывания — все графики вместе, по всей ширине поля.
- **Мышь**: `pointermove` выбирает ближайший интервал. **Касание**: `pointerdown` + `pointermove` при прижатом пальце, `touch-action: pan-y` на области (вертикальный скролл листа не ломается). Отпустил палец — считывание держится 2 с, потом гаснет. Новое касание вне графика гасит сразу.
- Вертикаль через все поля на центре интервала: 1 px `C.textMuted`, разрывается на строках подписей и легенды (в SVG — по отрезку на каждое поле). На линиях выработки, попаданий и «из RAM» — точка 6 px, заливка цветом своей линии, обводка 2 px `C.bgCard`. Столбик вытеснений под курсором — opacity 1, остальные остаются 0.85.
- Строка-итог превращается в считывание: `14:32 · 412 ток/с`. Время — `HH:MM` начала интервала (для 15 мин — `HH:MM:SS`). Выработка `null` → `нет данных`. Значения кэша в эту строку **не** пишутся: они встают в легенду графика 2 и в правый край подписи «Вытеснения», рядом со своими сериями (иначе строка не влезает в 320 px). Попадания `null` из-за отсутствия запросов → в легенде `—`.
- **Плавающего тултипа нет**: в панели 320 px он перекрывает график и вылезает за край, а под пальцем его не видно. Считывание в строке над графиком решает и десктоп, и touch одним способом.
- Клавиатура: область графика `tabIndex=0`, `←` / `→` двигают интервал, `Esc` — сброс; фокус-кольцо `C.borderFocus` 2 px, `R.md`. `aria-label` области: `Выработка и кэш за 15 минут, в среднем 412 ток/с, попадания в кэш 87 %`. Строка-итог — `aria-live="polite"`; легенда графика 2 и значение вытеснений — тоже `aria-live="polite"`.

## Размеры и узкая ширина

- **Отказаться от `preserveAspectRatio="none"`.** Ширину поля мерить `ResizeObserver` на обёртке и рисовать SVG в реальных px: `viewBox="0 0 {w} {h}"`, `width={w}`. Текст тогда не растягивается. Подписи осей лучше вынести в HTML поверх или рядом с SVG. Тогда работают `FS.xs` и токены шрифтов, а не `fontSize={9}`. Литерала 9 px в шкале нет, его быть не должно.
- Поле справа под подписи оси Y — 28 px (влезает `1.5k`), слева 0: подписи «ср.» и «данных нет» рисуются внутри поля.
- Панель 320–360 px: всё как описано, это основная ширина.
- < 300 px: ось времени — только крайние метки; строка считывания укорачивается до `14:32 · 412` (единица уже в подписи графика); строка-итог теряет хвост `· кэш …` по многоточию; легенда графика 2 — короткие подписи (см. выше).
- **Мобильный лист** (`isMobile`): высоты полей те же (96 / 64 / 32). Переключатель `InlineSegmented` уже растёт до touch-размера сам. Область считывания по высоте не меньше 44 px — выполняется (от 168 px).

## Что проверить при реализации

1. Простой (все нули) → шкала 0 / 5 / 10, единиц-дублей нет.
2. 1 ч при трёх минутах истории → слева зона «данных нет», данные у правого края 3 интервалами по ~5 px, не полосой.
3. Рестарт движка посередине → обрыв линии, пунктирная вертикаль, считывание `движок не отвечал`.
4. Тёмная тема: столбики вытеснений, подложка «занято» и линия «из RAM» видны, пунктир средней виден.
5. 320 px и мобильный лист: подписи не сплющены, касание показывает считывание, вертикальный скролл листа работает.
6. Тесты на чистые функции: интервалы (среднее/максимум/сумма/`null`), доля из сумм (точка `1/1` и точка `0/99` в одном интервале дают 1 %, а не 50 %), `Σ queries = 0` → `null`, «круглая» шкала (0, 37, 412, 980, 1000), среднее без простоя.
7. Простой с открытым графиком кэша: линия попаданий обрывается, фона «нет данных» под ней нет.
8. Вытеснений в окне нет → только строка `Вытеснения · не было`; появилось одно → поле 32 px раскрывается, графики выше не сдвигаются.
9. Ответ без новых полей `history` (старый бэкенд) → график 2 заменён `NotReported`, ошибок в консоли нет.
