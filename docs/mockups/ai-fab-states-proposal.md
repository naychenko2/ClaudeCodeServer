# Состояния плавающей кнопки AI-хаба

Макет: [ai-fab-states-v1.html](ai-fab-states-v1.html) — все состояния × обе темы × оба размера,
переключатели темы, размера, наведения и `prefers-reduced-motion` внутри витрины.
Реализация: `frontend/src/components/ai/AiLauncher.tsx` + `frontend/src/index.css`.

## Проблема

1. **«Идея» и «работа» говорят одним приёмом.** Оба состояния рисуют кольца «Эхо» и
   отличаются только цветом колец — оранжевый против серого. Расходящееся кольцо в
   периферийном зрении читается как «что-то происходит», а цвет на 2-пиксельной линии
   36-пиксельного круга человек не различает, пока не посмотрит в упор. При этом принятый
   язык живых состояний (решение команды от 2026-08-07) закрепляет «Эхо» за **работой AI** —
   в ленте чата кольца значат именно её. То есть «идея» заняла чужой приём.
2. **«Идея» гаснет раньше повода.** `cc-fab-hop` отыгрывает ровно 3 подскока и замирает.
   После этого кнопка визуально неотличима от покоя, хотя сильная рекомендация никуда не
   делась — она живёт до смены раздела. Сигнал исчезает, а повод остаётся.
3. **Носителя статуса нет.** Аватар — голый круг без оправы, весь статус держится на
   движении. Значит при `prefers-reduced-motion: reduce` статуса нет вовсе: кольца сейчас
   не рендерятся, подскок и дыхание выключены, остаётся одинаковое лицо во всех состояниях.
4. **Ожидание человека маскируется под работу.** Когда Claude упёрся в permission-запрос
   или вопрос, ход стоит и ждут человека — но глобально это ничем не показано. Пользователь,
   ушедший в другой раздел, узнаёт об этом, только вернувшись в чат.

## Решение

**Постоянная оправа вокруг лица** — она есть всегда и меняет цвет, характер линии и ритм.
Оправа растёт **наружу** (отдельный слой с `inset: -3px`), поэтому лицо не ужимается ни на
54, ни на 36 px. Толщина фиксирована 2 px и не масштабируется вместе с кнопкой: на 36 px
пропорциональная оправа выродилась бы в нитку.

**У каждого состояния своя механика движения**, а не свой цвет одной и той же анимации:

| Состояние | Механика | Почему различимо периферийным зрением |
|---|---|---|
| Есть идея | вертикальный транспорт (подскок) | смещается вся кнопка |
| AI работает | круговое непрерывное (бегущая дуга + «Эхо») | движение по окружности, ровный ритм |
| Нужен ответ | радиальный маячок: два удара + пауза | прерывистый ритм = «требуется действие» |

**Цвет оправы отвечает на один вопрос — надо ли тебе реагировать.** Серый (покой, работа) —
нет; акцент (идея) — можно; янтарь (нужен ответ) — да, прямо сейчас. Поэтому покой и работа
делят один цвет и разводятся движением, а не оттенком.

## Карта состояний: четыре, а не три

Четвёртое состояние — **«нужен ответ человека»** — заслужено, и вот чем. Это единственное
состояние, где **бездействие пользователя блокирует работу**: ход стоит намертво, пока не
нажата кнопка. Цена пропуска максимальна, а FAB — единственный элемент, видимый из любого
раздела. Без него ожидание неотличимо от работы, то есть кнопка врёт: показывает «занята»,
когда на самом деле «ждёт тебя».

**«Оффлайн» отклоняю.** Это свойство всего приложения, а не персоны AI-хаба; оно уже
показывается своими средствами, и пятая градация на 36-пиксельном круге превратила бы
светофор в мигающую ёлку. Признак `online` в компоненте остаётся тем, чем и был — гейтом
доступности действий, а не настроением лица.

Приоритет при совпадении: **нужен ответ → работает → идея → покой.**
Логика та же, что и сегодня у пары «работа/идея»: звать занятую персону не время, а когда
она ждёт ответа — тем более.

## Спецификация

### Разметка (слои кнопки, порядок z)

```
button.fab                     ← подскок и маячок живут здесь (transform / box-shadow)
├─ span.echo  ×2   z:1         ← кольца «Эхо», только «работа»
├─ span.face       z:2         ← PersonaAvatar fill / логотип, inset: 0
├─ span.ring       z:3         ← ОПРАВА: inset: -3px, border: 2px solid var(--ring-c)
└─ span.arc        z:4         ← бегущая дуга, только «работа»: тот же inset,
                                  border: 2px solid transparent + border-top-color
```

Переменные (в `index.css`, рядом с существующими `--cc-fab-*`):

```css
--cc-fab-ring-w: 2px;    /* толщина оправы, от размера кнопки НЕ зависит */
--cc-fab-ring-gap: 3px;  /* зазор лицо ↔ оправа */
```

### Таблица состояний

| Состояние | Признак | Оправа | Движение | reduced-motion |
|---|---|---|---|---|
| **Покой** | `!strong && !aiBusy && !aiAwaiting` | 2 px сплошная, `C.smoke`; лицо `opacity .85` | нет | без изменений |
| **Есть идея** | `fabLevel === 'strong'` | 2 px сплошная, `C.accent` + `SHADOW.button` | `cc-fab-hop` ×3, затем **оправа и ореол остаются** | оправа + ореол статично |
| **AI работает** | `aiBusy` | 2 px сплошная, `C.smoke`; поверх — дуга `C.textSecondary` | `cc-fab-arc` 1.1s linear infinite + `cc-echo-ring` ×2 (`--cc-echo-color: C.smoke`) + `cc-fab-breathe` на лице | дуга и «Эхо» скрыты; оправа → `border-style: dashed`, цвет `C.textMuted` |
| **Нужен ответ** | `aiAwaiting` | 2 px сплошная, `C.warning` | `cc-fab-alert` 2.6s infinite (два удара + пауза) | оправа 3 px + постоянный `SHADOW.alert` |

Ключевое отличие от текущего кода: **у «идеи» больше нет колец** — они целиком уходят
работе, а идея держится на оправе и подскоке. И оправа «идеи» **не гаснет** после трёх
подскоков: класс `cc-fab-hop` отыгрывает и снимается, состояние живёт на цвете.

### Анимации (index.css)

```css
/* Бегущая дуга — «AI работает» */
@keyframes cc-fab-arc { to { transform: rotate(360deg); } }

/* Маячок «нужен ответ»: два удара и пауза */
@keyframes cc-fab-alert {
  0%        { box-shadow: 0 0 0 0   rgba(201,146,62,.42), var(--shadow-fab-neutral); }
  12%       { box-shadow: 0 0 0 7px rgba(201,146,62,0),   var(--shadow-fab-neutral); }
  24%       { box-shadow: 0 0 0 0   rgba(201,146,62,.42), var(--shadow-fab-neutral); }
  36%       { box-shadow: 0 0 0 7px rgba(201,146,62,0),   var(--shadow-fab-neutral); }
  40%, 100% { box-shadow: 0 0 0 0   rgba(201,146,62,0),   var(--shadow-fab-neutral); }
}
```

Тёмной теме нужен парный `cc-fab-alert-dark` с `rgba(224,172,90, …)` — цвет внутри
`box-shadow` берётся из rgba-литерала, а не из токена, поэтому вариант на тему один в один
как у существующих `--shadow-*` (см. макет, там оба keyframes выписаны).

`cc-fab-hop`, `cc-fab-breathe`, `cc-echo-ring` — существующие, менять не нужно.

### prefers-reduced-motion

Требование: статично, но **различимо**. Сейчас блок гасит всё и оставляет четыре одинаковых
круга. Новое поведение — статус несёт оправа, и состояния разводятся характером линии и
толщиной, то есть читаются даже в оттенках серого:

```
покой        тонкая сплошная нейтральная
идея         сплошная акцентная + ореол
работа       ПУНКТИР
нужен ответ  утолщённая (3 px) + постоянный ореол
```

Кольца «Эхо» при reduced по-прежнему не рендерятся — их работу забирает пунктир.

### Наведение (десктоп)

Без изменений: 36 → 54 px, подъём на `--cc-fab-lift`. Статус-цвет оправы при наведении
**не меняется** — наведение говорит про доступность, а не про состояние. Приглушение лица
в покое (`opacity .85`) на наведении снимается, как и сейчас.

### Мобилка

Hover недоступен, кнопка всегда 36 px — поэтому статус целиком лежит на оправе и движении,
и ни одно состояние не требует наведения, чтобы быть узнанным. Толщина оправы на 36 px
та же, что на 54 (2 px), внешний диаметр — 36 + 2×(3+2) = 46 px; лицо не теряет ни пикселя.

## Токены

Всё берётся из существующей шкалы, кроме одного добавления:

| Токен | Роль | Светлая | Тёмная |
|---|---|---|---|
| `C.smoke` | оправа покоя и работы | есть | есть |
| `C.textSecondary` | бегущая дуга | есть | есть |
| `C.textMuted` | пунктирная оправа при reduced | есть | есть |
| `C.accent` | оправа «есть идея» | есть | есть |
| `C.warning` | оправа «нужен ответ» | есть | есть |
| `SHADOW.button` | ореол «есть идея» | есть | есть |
| **`SHADOW.alert`** | **статичный янтарный ореол при reduced — НОВЫЙ** | `0 0 0 4px rgba(201,146,62,.26), 0 6px 18px rgba(60,50,35,.22)` | `0 0 0 4px rgba(224,172,90,.30), 0 6px 20px rgba(0,0,0,.50)` |

`SHADOW.alert` заводится в `theme.css` как `--shadow-alert` в **обе** темы и добавляется в
объект `SHADOW` в `design.ts`. Это единственное расширение шкалы; новых цветов не нужно.

## Что требуется от бэкенда/фронта под четвёртое состояние

Сигнала «AI ждёт ответа человека» глобально сейчас **нет** — признак живёт внутри ленты
(`ChatPanel.tsx`: `it.kind === 'permission_request' || it.kind === 'ask_question'` без
`resolved`). Нужен глобальный сторедж по образцу `lib/ai/busy.ts`:

- `lib/ai/awaiting.ts` — счётчик/флаг + `useAiAwaiting()` на `useSyncExternalStore`;
- `ChatPanel` выставляет его там же, где считает `waitsForUser`, и снимает при ответе,
  завершении хода и размонтировании;
- `AiLauncher` читает `useAiAwaiting()` и ставит состояние выше `aiBusy`.

Пока сигнала нет, три остальных состояния самодостаточны и внедряются отдельно — четвёртое
можно докатить вторым шагом, ветка `data-state="awaiting"` просто не активируется.

## Итерации

**v1 (текущая).** Первичный вариант держал оправу покоя на `C.border`. На скриншотах она
пропадала в обеих темах: `#E0D7C8` теряется на бежевом холсте, `#3D3830` — на тёмном.
Оправа-константа должна быть видна всегда, иначе смена состояния читается как «появилась
рамка», а не «рамка сменила цвет». Заменено на `C.smoke`, а бегущая дуга подтянута до
`C.textSecondary` — иначе на дымчатой оправе она сливалась.
