# Индикатор prompt cache и перенос в новый чат

Фича за фич-флагом `prompt-cache` (dark launch). Польза: человек видит, насколько жив кэш промпта и почему он не помог, и одним действием переносит разговор в новый чат с короткой запиской — вместо тяжёлого ветвления, которое тащит всю историю.

## Что делает интерфейс

- **Циферблат кэша** в шапке чата (поверх кольца контекста): живой остаток TTL, статус (тёплый / скоро остынет / остыл). Озвучка пилюли нейтральная («Кэш промпта») — имя не меняется со временем (WCAG 4.1.2); живые детали — в подсказке и поповере.
- **Причина промаха в подвале хода**: если последний результат имел `promptCache.missReason != "none"`, в мета-строке последнего хода — «кэш не помог: <причина>» с человеческими подписями (смена системного промпта, изменение истории, истечение срока, смена инструментов, смена модели, другая причина). Показ только у последнего результата.
- **Личный порог предупреждения**: диалог «когда предупреждать об остывании» — минуты, `warn1hMin` (1..59) и `warn5mMin` (1..4); пустое тело `{}` — сброс к дефолтам (5 мин / 1 мин). Пороги per-owner, сбрасываются на logout.
- **Кнопка «Перенести в новый чат»** в поповере; вторая точка входа — предложение в подсказке, когда контекст почти полон (level danger) и есть данные кэша. Перенос — не авто-действие.

## Контракт handoff

`POST /api/chats/{id}/handoff` → `{chatId, projectId, draft, warm}`.

- **Тёплый путь**: записку пишет сам чат своим видимым ходом (поток 5 мин, `preempt: false`). Любой блокёр (чат занят, идущий ход, группа/штаб, архив, офлайн-устройство) — тихый переход на холодный, причина логируется.
- **Холодный путь**: дешёвый раннер по транскрипту (бюджет 60 000 символов), явный потолок 4 мин (`ColdPathTimeout`); превышение — 502 с текстом «перенос не успел завершиться», преемник не создаётся.
- Преемник создаётся **без `--resume`** — в этом смысл: новый чат стартует с короткой запиской, а не с пересказом всей истории. Черновик записки кладётся в `cc_pending_chat_prompt` (без авто-сабмита), переход только после успешного `openChatById`.
- Отказы: 404 «Чат не найден или удалён» (с телом), 409 «чат занят…», 409 с честным текстом про очередь (просьба уже в старом чате, новый не создан), 502 «модель не дала записку». `[Authorize]` на классе контроллера, per-owner: чужой id — 404.
- Очередь «1 поток на владельца» — только для холодного пути; тёплый ход — собственный ход чата, сериализуется штатной очередью ходов (намерение зафиксировано комментарием в сервисе).

## Инварианты

- Семантика «последнего результата с данными кэша» одинакова на бэке (`IsCacheWarm`) и фронте (`promptCacheState`): результат без якоря или с невалидным TTL пропускается, а не гасит более ранний живой якорь.
- Якорь считается при любом касании кэша (read или creation), TTL — из обеих строк usage; интервал half-open `[anchor, anchor+TTL)`.
- Единственный контракт порога — минуты (`warn1hMin`/`warn5mMin`); секундные имена origin/master не переносятся, при чтении users.json легаси-секунды мигрируют в минуты (отрицательные — отсекаются, край 30 с → 1 мин).
- `_ownerGates` не вычиждается (паттерн `ChatDigestService`/`PlanMapService`): вычистка по ключу после неатомарной проверки создавала второй семафор для того же владельца.

## Телеметрия

Метрика `ccs.prompt_cache.turns` с тегом `reason`; алерт `09-prompt-cache-system-changed.json` — на `reason = 'systemChanged'`.

## Открытые хвосты (следующая волна)

- Перенос в чатах без сигнала кэша (локальные модели) — вне текущей области флага.
- Озвучивание состояния кэша скринридеру без открытия деталей — отдельный узел `aria-live` вне кнопки.
- Guard копий ленты в шапке сужен до компонента `RingPillBadge`; при добавлении ленты в другой компонент шапки guard молчит.
