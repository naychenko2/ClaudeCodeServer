# Режим диалога: как устроен у нас и как у ChatGPT / Claude (август 2026)

> Срез во времени: анализ кода CCS на 19.08.2026 плюс публичные данные о голосовых
> режимах ChatGPT, Claude и о практике cascaded voice-агентов. Раздел `research/`
> **не поддерживается** после написания — читать как «так было тогда». Актуальное
> описание фичи живёт в [features.md, раздел «Голосовой режим чата»](../architecture/features.md).

Задача документа — зафиксировать, где именно наш разговор отстаёт от эталонов, чтобы
не изобретать приоритеты заново в каждой сессии.

## 1. Как устроено у нас

Петля целиком на фронте, бэкенд про неё не знает: он видит обычный ход чата с флагом
`Session.VoiceMode`.

```
 [микрофон] Web Speech API (облако Google, ru-RU)
      |  continuous=false, цикл перезапускается вручную
      v
 useHandsFree.ts — чистый редьюсер, 6 фаз
   off -> listening -> pending(2c) -> sending
        -> waiting -> speaking -> listening
      |
      v
 ход: claude CLI  ИЛИ  Ollama (место chat-voice)
      |
      v
 tts.ts: санитайзер -> нарезка на предложения
        -> очередь синтеза (Yandex SpeechKit, mp3)
        -> HTMLAudioElement (играет при погашенном экране)
```

Ключевые файлы: [useHandsFree.ts](../../frontend/src/hooks/useHandsFree.ts) (автомат),
[useVoiceInput.ts](../../frontend/src/hooks/useVoiceInput.ts) (Web Speech + watchdog),
[tts.ts](../../frontend/src/lib/tts.ts) (санитайзер, нарезка, очередь, стрим),
[ChatPanel.tsx](../../frontend/src/components/ChatPanel.tsx) (владелец фазы озвучки),
[VoicePrompts.cs](../../backend/ClaudeHomeServer/Services/Prompts/VoicePrompts.cs) (формат ответа),
[OllamaClient.cs](../../backend/ClaudeHomeServer/Services/Llm/OllamaClient.cs) (`ChatTurnAsync`).

### Что сделано хорошо

- **Автомат — чистый редьюсер**, эффекты вынесены в обёртку; покрыт юнитами
  (`hooks/__tests__/handsFree.test.ts`).
- **Эхо-защита в две линии**: микрофон открыт ровно в `listening`/`pending`, плюс гвард
  `isSpeaking()` перед открытием. `speak()` резолвится по реальному концу звука на обоих
  путях (сервер и браузерный фолбэк) — самый частый канал эха закрыт.
- **Поточная озвучка уже есть**: `takeSpeakableChunk` режет нарастающий текст хода по
  предложениям, `startStreamSpeak` синтезирует следующий кусок, пока играет текущий.
- **Формат ответа держат ДВЕ точки промпта** (секция `voice-mode` + оговорка последним
  блоком слоя персоны) — иначе слот «Формат ответов» персоны перебивает голосовое правило.
- **Санитайзер речи** с расшифровкой идентификаторов («SessionManager.cs» → «Session Manager
  це шарп») — редкая для голосовых режимов вещь, а для чата про код обязательная.

### Бюджет задержки «замолчал → услышал ответ»

Расчёт по константам кода на момент анализа, **не измерение** (замеров тогда не было —
см. разрыв №6). Колонка «после P0» — состояние после правок 19.08.2026.

| Этап | На момент анализа | После P0 |

| Web Speech решает, что человек замолчал (`onend`) | 0.5–1.5 с | без изменений |

## 2. Как у эталонов

**ChatGPT.** Три поколения: цепочка STT→LLM→TTS → Advanced Voice Mode (нативный
speech-to-speech внутри одной модели, но дискретные ходы) → GPT-Live на **full-duplex**
архитектуре: слушает и говорит одновременно. Turn detection в Realtime API — два режима:
`server_vad` (по громкости) и **`semantic_vad`**: классификатор оценивает по словам
вероятность, что мысль закончена, и динамически растягивает таймаут — «эээ…» ждёт дольше
законченного утверждения. Ручка `eagerness` (low/medium/high/auto) регулирует, насколько
агрессивно перебивать. Обратная сторона видна по жалобам: агрессивный барж-ин принимает
кашель, музыку и паузу посреди мысли за конец реплики.

**Claude.** Ближе к нашей схеме: hands-free «слушает непрерывно и отвечает на естественные
паузы», **перебить можно, просто начав говорить** (Claude замолкает и слушает), плюс явный
**push-to-talk** для шумных мест. На экране — живая подсказка с ключевыми пунктами,
транскрипт падает в обычную историю чата. В Claude Code голосового режима нет.

**Индустрия (cascaded-пайплайны, 2026).** Дефолт остаётся STT→LLM→TTS ради отлаживаемости,
но с бюджетом: 60–100 мс streaming STT, 100–180 мс до первого токена LLM, 40–80 мс до
первого чанка TTS; порог «как у человека» — 200–300 мс. Эхо решают браузерным AEC
(`getUserMedia({echoCancellation: true})`) плюс эхо-гейтом, приглушающим микрофон под
озвучку — но микрофон **не закрывают**, иначе барж-ин невозможен физически.

## 3. Разрывы

1. **Барж-ина нет вообще.** Следствие Web Speech: он берёт микрофон своим потоком,
   `echoCancellation` ему не задать. Отсюда решение «микрофон закрыт под озвучку» и отсюда
   же то, что голосовое «стоп» не работает во время ответа. У обоих эталонов перебивание —
   ключевая механика разговора.
2. **Endpointing фиксированный.** `PENDING_MS = 2000` одинаков и для оборванной мысли
   («ну, короче…»), и для законченного вопроса. Semantic VAD решает ровно это.
   *Закрыто P0 19.08.2026: `pendingDelayFor` — 1.0 / 2.0 / 2.8 с по хвосту фразы.*
3. **Web Speech — самое хрупкое звено.** Облако Google, не работает без GMS (отсюда весь
   наш клавиатурный фолбэк, watchdog и синтетический `mic-dead`), режется DPI/прокси,
   `continuous` на Android сломан. При этом TTS уже оплачен Яндексу, а у SpeechKit есть
   потоковый STT v3 тем же сервисным аккаунтом.
4. **Локальный ход не стримит**: `ChatTurnAsync` зовёт Ollama с `stream = false`, ответ
   уходит одним `TextDeltaMessage`. Готовая стрим-механика фронта на локальном маршруте
   простаивает. *Закрыто P0 19.08.2026: поток NDJSON, куски по границе предложения.*
5. **Вопрос модели рвёт разговор.** `awaitingResponse` → реплика «нужно твоё решение» →
   выход из петли. Для `permission_request` это правильно, для `ask_question` («вариант А
   или Б?») — грубо: у эталонов на такое отвечают голосом.
6. **Нет цифр.** `talkDiag` пишет события движка, но никто не меряет «конец речи → первый
   звук». Улучшать латентность без замера — гадание. *Закрыто P0 19.08.2026: `talkMark`
   размечает круг, дамп печатает сводку и средние.*

## 4. План работ

### P0 — дёшево, эффект сразу (сделано 19.08.2026)

- [x] **Стриминг локального хода**: `stream = true` в `OllamaClient.ChatTurnAsync`, слать
      `TextDeltaMessage` по мере генерации (`RunLocalVoiceTurnAsync`). Фронт готов —
      правки только на бэке. Выигрыш: −1…2 с до первого звука, на длинном ответе больше.
      Риск: `RecordSpend`/`UsageInfo` собираются из финального JSON — при стриме считать
      по последнему чанку (`done: true`).
- [x] **Адаптивное окно отправки** вместо фиксированных 2 с: чистая функция в редьюсере —
      фраза кончается на `?`/`.` и длиннее 3 слов → 700–900 мс; обрыв на союзе/междометии
      («и», «а», «ну», «э») или короче 2 слов → 2.5 с. Бедный аналог semantic VAD, 80%
      эффекта, покрывается юнитами существующего набора.
- [x] **Замер фаз в `talkDiag`**: таймстемпы `speech-end → send → turn-start → first-audio`
      плюс сводка в конце дампа (`talkDiagDump`). Без этого P1 нечем валидировать.

### P1 — среднее по цене, максимум по эффекту

- [x] **Свой аудиостек и барж-ин**: `getUserMedia({echoCancellation: true,
      noiseSuppression: true})` + Silero VAD в браузере (`@ricky0123/vad-web`, ONNX в
      воркере). Микрофон держим открытым и под озвучку: уверенная речь дольше ~300 мс →
      `stopSpeaking()` + переход в `listening`. Чинит и голосовое «стоп» во время ответа.
      Полумера для первого шага: VAD слушает **только** ради барж-ина, распознаёт
      по-прежнему Web Speech — уже после глушения озвучки.
      *Сделано 19.08.2026 (`lib/bargeVad.ts`, событие автомата
      `bargeIn`); отличие от плана выше: VAD-трек живёт только в фазе озвучки (на WebKit
      второй захват микрофона убивает SpeechRecognition — там канал выключен вовсе), а
      перебивание недоигранного хода прерывает его целиком, как кнопка «Стоп». Детали —
      [features/voice-barge-in.md](../features/voice-barge-in.md).*
- [ ] **STT через Yandex SpeechKit v3 streaming**: бэкенд проксирует WebSocket → gRPC (как
      уже сделано для TTS). Даёт работу без Google-сервисов, частичный транскрипт на экране
      в реальном времени и контроль над endpointing. Web Speech остаётся фолбэком — ветка
      фолбэков уже написана.

### P2 — после P0/P1

- [ ] Голосовой ответ на `ask_question` без выхода из петли (`permission_request` —
      по-прежнему только глазами и руками, это предохранитель).
- [ ] Филлер под инструменты: на первом `tool_use` озвучить короткое «секунду, смотрю…» —
      стандартный приём voice-агентов против тишины в трубке.
- [ ] Push-to-talk как явная альтернатива для шумных мест (второй режим у Claude).

### Предостережение

Не копировать агрессивность OpenAI: главная жалоба их пользователей — «режет посреди
мысли». Наш перекос обратный (перебить нельзя вовсе) и лечится барж-ином, а не
сокращением пауз до предела.
