# Шаблон QA-отчёта о прогоне

Копируй этот каркас в новый файл `docs/qa/<фича>-<дата>.md` и заполняй. Имена — латиницей
в kebab-case, как у существующих отчётов; снимки экрана — в `.cc-attachments/` (скрыта из
git и из базы знаний), ссылки на них — относительные.

## Железное правило находок

**Каждая находка прогона обязана становиться карточкой дефекта** (задача с
`kind: "defect"` в трекере того стенда, где шёл прогон), а отчёт — содержать её id строкой
`Карточка: <id>` прямо у описания находки. Находка без id карточки считается
неоформленной: отчёт не принимается. Это же правило действует при заведении находок
через MCP — `tasks_create({ kind: "defect", ... })`.

Скриншоты — доказательства, а не украшение: у каждого дефекта должен быть снимок момента
отказа/поломки, у каждого пройденного краевого сценария — по возможности тоже.

---

## Каркас отчёта

```markdown
# QA: <что проверялось> (<дата>)

**Дата:** YYYY-MM-DD
**Сборка:** ветка/коммит, стенд (порт), откуда фронт
**Тесты автоматические:** dotnet test / npm run test / lint:design — итог и exit-код
**Инструмент:** Playwright (chromium, headless), REST через curl — чем реально работал
**Учётки:** какие пользователи и с какими флагами
**Скриншоты:** .cc-attachments/<имя-прогона>/…

## Сводный вердикт

<ПРОЙДЕНО | ВЕРНУТЬ В ДОРАБОТКУ | ЧАСТИЧНО> — один абзац: что главное, что блокирует.

## Сценарии

### N. <Название сценария>

- ✅/❌/⚠️ **Сценарий:** что делал (шаги, входные данные) → что получил → что ожидал.
- Скриншот: [имя.png](../../.cc-attachments/<имя-прогона>/имя.png)

## Дефекты

### Д-1. <Суть одним предложением> (severity: блокер/средний/мелкий)

**Шаги воспроизведения:**
1. …
2. …

**Фактический результат:** …
**Ожидаемый:** …

Карточка: <id задачи-дефекта>

## Перепрогон после правок

<если разработчики чинили по ходу: что перепроверено, итог, новые скриншоты>
```

## Замечания по заполнению

- Сценарий «пройден» только с доказательством: снимок, ответ API, строчка лога — не «на
  глаз кажется нормальным». Чего не проверял — честно перечисли отдельным списком.
- Дефекты нумеруй Д-1, Д-2… в порядке нахождения; severity — блокер/средний/мелкий.
- Карточку дефекта заводи ДО закрытия отчёта и вписывай её id сразу — потом теряется
  соответствие «находка ↔ карточка».
- Восемь отчётов до 2026-08-28 написаны без строк «Карточка:» — задним числом не
  перерабатываются (решение владельца); правило действует с этого шаблона.
