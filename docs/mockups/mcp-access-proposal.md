# v2. Allow-list: экран показывает, где сервер включён

Макет: [mcp-access-v2.html](mcp-access-v2.html) — самодостаточный, открывается двойным кликом.
Переключатели в верхней полосе: тема, мобильная раскладка 390px, плашка миграции и все
состояния (только что добавлен, включён в 1 проекте, проект + 2 персоны, чаты вне проектов,
выключен целиком, стресс, загрузка, ошибка, пусто, диалог удаления).

## Что изменилось в модели

Было: сервер доступен везде, экран показывал **исключения-выключения**.
Стало: сервер доступен только там, где включён, экран показывает **выданный доступ**.

Две оси включения:

1. **Проект целиком** — включённый в проекте сервер доступен всему, что идёт в этом проекте:
   всем его чатам и всем его персонам. Плюс отдельная строка **«Чаты вне проектов»** — ось
   для чатов, у которых проекта нет.
2. **Персона целиком** — включил сервер персоне, он у неё во всех её чатах.
   Пар «персона × проект» нет: проектная персона и так живёт в одном проекте.

Сервер едет в ход, если включён **(а)** в проекте этого чата **ИЛИ (б)** у персоны этого чата.
Чат вне проекта — по строке «Чаты вне проектов».

## Главный экран новой модели: сервер подключён, но никому не выдан

Норма для только что добавленного сервера — **«нигде не включён»**, и это осознанный дефолт,
а не ошибка. Поэтому карточка в этом состоянии не выглядит ни пустой, ни сломанной:

```
+----------------------------------------------------+
| Miro   свой                 http  [Доступ не выдан] |
|                                                     |
| +-------------------------------------------------+ |
| | (i) Сервер подключён, но в ходы не едет.        | |
| |     Он не включён ни в одном из 38 проектов и   | |
| |     ни у одной из 149 персон. Выберите, где он  | |
| |     нужен: проект отдаёт сервер всем своим      | |
| |     чатам и персонам, персона забирает его во   | |
| |     все свои чаты.                              | |
| +-------------------------------------------------+ |
|                                                     |
| [           +  Выдать доступ                      ] |  <- accent, во всю ширину
+----------------------------------------------------+
```

Три вещи, которые человек считывает не читая:

- **плашка «Доступ не выдан»** — нейтральная (`C.bgSelected`/`C.textSecondary`), не danger
  и не warning: сервер исправен, просто ещё не роздан;
- **блок-объяснение** говорит и про причину («в ходы не едет»), и про механику двух осей —
  это единственное место, где новую модель объясняют словами; числа 38/149 заодно
  подтверждают, что данные загрузились;
- **одна кнопка во всю ширину** — следующий шаг ровно один, промахнуться не по чему.

Как только доступ выдан, шапка меняется на зелёную **«Работает: 1 проект · 2 персоны»**
(`C.successBg`/`C.successText`) — сервер реально едет в ходы, и это стоит сказать цветом.

## Главное действие и accent

В v1 главного действия не было и accent не использовался. В allow-list оно появилось:
**выдача доступа**. Но оранжевый стоит только там, где он зовёт:

| Состояние карточки | Кнопка |
|---|---|
| Доступ не выдан | `Button variant="primary"`, **во всю ширину**, «+ Выдать доступ» |
| Доступ уже выдан | `Button variant="ghost"`, обычная, «+ Выдать доступ ещё ⌄» |

Если серверов несколько и все настроены, оранжевого на экране нет вовсе. Если добавили
новый — он один и светится. Это и есть accent-дисциплина: призыв там, где есть куда звать.

## Один пикер на две оси

Кнопка открывает **один** пикер с сегментами «Проекты | Персоны» — не две кнопки в футере,
иначе главное действие раздваивается и accent некуда ставить.

```
+-------------------------------------+
| Кому выдать доступ к «Miro»?        |
| [  Проекты  ][   Персоны   ]        |
| [ (o) Поиск по 38 проектам        ] |
|-------------------------------------|
| Чаты вне проектов          [выдан]  |  <- закреплена сверху
|=====================================|
| AI Home                             |
| НСИ Каталог                [выдан]  |
| Вагонный парк                       |
|-------------------------------------|
| Выданное помечено — повторный клик  |
| уберёт доступ. Проект отдаёт сервер |
| всем своим чатам и персонам.        |
+-------------------------------------+
```

- 38 проектов и 149 персон — это по-прежнему **поиск**, а не колонки и не простыня.
- **«Чаты вне проектов»** закреплена первой строкой в сегменте «Проекты», а не отдельной
  третьей вкладкой: это та же ось «где идёт чат», просто её частный случай — проекта нет.
  При непустом поиске строка скрывается, чтобы не мешать выдаче.
- Сегмент «Персоны» показывает под именем роль и проект персоны («QA-тестер · НСИ Каталог»)
  или «глобальная» — по 149 однофамильцам иначе не выбрать.

## Как уживаются проекты и персоны в одном списке

Строки в карточке идут в порядке **проекты → чаты вне проектов → персоны**, различаются
иконкой и подписью, действие у всех одно — «Убрать».

Главная ловушка allow-list — выдать доступ дважды: сначала проекту, потом его же персоне.
Закрывается в трёх местах:

1. **Подпись строки проекта считает покрытых:** «Проект · все его чаты и 7 персон». Человек
   видит, что персоны этого проекта уже получили сервер.
2. **В пикере персон** такие помечены серым чипом **«есть через проект»** — рядом с зелёным
   «выдан» это читается как «уже не нужно».
3. **Выдать всё равно можно**, и это не ошибка: тост объясняет смысл — «Доступ у персоны
   «Вера» уже был через проект «НСИ Каталог» — теперь он не пропадёт, даже если убрать
   проект». В карточке у такой строки стоит тот же чип «есть через проект».

Родовых форм в подписях нет: персона может быть и «Вера», и «Глеб», поэтому «выдан»,
«есть через проект», а не «включена»/«покрыта».

## Персона: включаем отсюда — и это честнее, чем ссылка в студию

**Предложение: строка «Включить персоне» пишет ту же самую привязку, что и студия.**
Ссылка «Студия →» на строке остаётся, но как переход к остальным настройкам персоны,
а не как единственный способ выдать доступ.

Почему так, а не «отсюда только смотрим»:

1. **Это буквально одна запись.** И там, и здесь — Tool-привязка персоны `mcp:<ключ>`
   (`PersonaBindingsService`). Второго источника истины не появляется: два экрана правят
   одно поле, как «права пользователя» и «состав роли» правят одну таблицу.
2. **Инвариант v1 держался на deny-list.** Пока дефолт был «включено», вкладка «Доступ»
   была витриной исключений — включать там было нечего, и запрет ничего не стоил.
   В allow-list без выдачи фича мертва, и «правится только в студии» превращается в
   «раздайте доступ, обойдя 149 карточек персон по одной».
3. **У экранов разная единица работы.** Студия отвечает на вопрос «что может эта персона»
   (одна персона × много инструментов). Вкладка «Доступ» — на «кому доступен этот сервер»
   (один сервер × много персон). Это две законные проекции одной таблицы; запрет на одну
   из них не защищает данные, а просто прячет половину задачи.
4. **Связь не теряется.** Строка персоны ведёт в студию, и там та же привязка видна и
   переключается — человек, включивший отсюда, найдёт её там, где она живёт.

Единственное, что нужно соблюсти на реализации: писать **тем же эндпоинтом привязок**
(`PUT /api/personas/{id}/bindings`, target `mcp:<ключ>`), не заводя параллельного поля.

## Миграция глазами пользователя

После переключения модели сервер, который работал везде, **перестаёт работать** до первой
выдачи. Молча этого делать нельзя: инструменты просто исчезнут из хода, и человек пойдёт
искать баг в MCP, а не в настройках. Поэтому — плашка над списком:

```
+----------------------------------------------------+
| /!\ Доступ теперь выдаётся явно                    |
|     Раньше ваши серверы ехали во все проекты и ко   |
|     всем персонам, пока их не выключали точечно.    |
|     Теперь наоборот: сервер работает только там,    |
|     где включён. 1 сервер сейчас не выдан никому    |
|     и в ходы не едет.                               |
|     [ + Выдать доступ ]   Понятно, скрыть           |
+----------------------------------------------------+
```

- Тон — `C.warningBg` / рамка `C.warning` / заголовок `C.warningText`: это предупреждение
  о последствии, а не ошибка.
- Счётчик «N серверов не выданы» считается живьём и пропадает сам, когда доступ роздан.
- Кнопка внутри плашки — нейтральная `btn-sm`: оранжевый уже занят карточкой, два accent'а
  на экране спорят.
- Живёт до первой выдачи доступа или до «Понятно, скрыть» — признак «плашку закрыли»
  хранится per-user и с фич-флагом `mcp-allowlist` не путается.

**Автопереноса «было включено везде → включить везде» не делаем.** Он воспроизвёл бы старую
модель в новых полях: 38 строк в карточке, смысл allow-list обнулён. Реально сервер нужен
в одном-двух проектах — пусть человек это и скажет. Цена решения честная и названа прямо
в плашке: до выдачи сервер не работает.

  если он включён в проекте этого чата или у персоны этого чата…».

### Карточка сервера

| Слой | Токены |
|---|---|
| Карточка | `background: C.bgWhite`, `border: 1px solid C.border`, `borderRadius: R.xl`, `overflow:'hidden'`, **`flexShrink: 0`** |
| Шапка | `padding: '11px 13px'`, `gap: SP.sm`; имя `13.5/600 C.textHeading` + `ellipsis` + `title` |
| Бейдж «свой»/«наследство» | `Badge tone="own" / "legacy"` (как в `McpServerList`) |
| Транспорт | `FONT.mono`, `10.5`, рамка `C.border`, `R.sm` |
| Плашка «Доступ не выдан» | `C.bgSelected` / `C.textSecondary` — норма, не ошибка |
| Плашка «Работает: …» | `C.successBg` / `C.successText` |
| Плашка «Выключен целиком» (`server.enabled === false`) | `C.warningBg` / `C.warningText`, вся карточка `opacity: .62` |
| Блок-объяснение (доступ не выдан) | `background: C.bgPanel`, `R.lg`, иконка `Info` `C.textSecondary` |
| Строка доступа | `padding: '9px 13px'`, `borderTop: 1px solid C.borderLight`; иконка в квадрате 26 `R.md` на **`C.successBg`/`C.successText`** — строка означает «работает» |
| Чип «есть через проект» | `C.bgSelected` / `C.textMuted` + `title` с пояснением |
| Футер | `borderTop: 1px solid C.borderLight`; кнопка по таблице из раздела «Главное действие» |

**`flexShrink: 0` на карточках обязателен** — контейнер вкладки flex-колонка со скроллом,
без него нижние строки уезжают под собственную границу (ловушка воспроизводилась в v1).

**Иконки внутри кнопок:** `lucide` рендерит `svg` как `display:block`, поэтому у любой
кнопки с иконкой нужен `display:flex; alignItems:center; gap` — иначе подпись переносится
на вторую строку (в макете это ловилось трижды: `btn-sm`, кнопка плашки, «Показать ещё»).

### Строки доступа

- **Проект:** иконка `Folder`, заголовок — имя проекта (`ellipsis` + `title`), подпись
  «Проект · все его чаты и N персон» (N = персоны с этим `projectId`), действие — `Button
  variant="ghost" size="sm"` «Убрать».
- **Чаты вне проектов:** иконка `MessageSquare`, подпись «Чаты, у которых нет проекта —
  включая чаты с персонами», действие «Убрать».
- **Персона:** иконка `User`, подпись «Персона · роль», чип «есть через проект» если её
  проект включён, действия — ссылка «Студия →» (`C.accent`, подчёркнутая,
  `navPush({screen:'personas', persona:id})` + `onClose()`) и «Убрать».
- Порядок: проекты → чаты вне проектов → персоны.
- Больше 5 строк — показываем 5 и «Показать ещё N строк» (`C.accent`, `FS.xs`/600,
  на всю ширину, `borderTop`), в раскрытом виде «Свернуть». Проверено на 11 строках.

### Пикер

- Десктоп: `Menu` с `anchor={rect кнопки}` (портал `position:fixed` — то, что нужно внутри
  скролл-контейнера модалки), ширина ~330, `maxHeight` списка 264.
- Мобила: `Modal` (сам становится bottom-sheet ниже `MOBILE_MAX`), список до ~46vh.
  Отдельной вёрстки шторки не нужно.
- Заголовок «Кому выдать доступ к «<сервер>»?», сегменты «Проекты | Персоны»
  (`C.bgPanel` подложка, активный — `C.bgWhite` + `SHADOW.thumb`), `TextField` с автофокусом,
  placeholder «Поиск по 38 проектам» / «Поиск по 149 персонам».
- Фильтр — подстрока без учёта регистра: по `project.name`; по `persona.name + role`.
  Клавиши: ↑/↓, Enter — выбор, Esc — закрыть.
- Пометки: `C.successBg`/`C.successText` «выдан»; `C.bgSelected`/`C.textMuted`
  «есть через проект». Повторный клик по выданному — снимает.
- Пустой результат: «Ничего не нашлось / Проверьте написание названия проекта (имени персоны)».

### Состояния

| Состояние | Что показываем |

| Своих серверов нет | `EmptyState compact` (`Plug`): «Своих серверов пока нет» + «Выдавать доступ пока не к чему: встроенные серверы продукта доступны всегда» + «Добавить сервер» |
| Только что добавлен | главный экран новой модели (см. выше) |
| Выключен целиком | плашка warning + текст «выданный ниже доступ сейчас ни на что не влияет», `opacity .62` |
| Проектов нет | сегмент «Проекты» показывает только строку «Чаты вне проектов» |
| Длинные имена | `ellipsis` + `title` на имени сервера, проекта, персоны; подписи однострочные |

### Мобильная раскладка (390px)

- Шапка карточки переносится: имя на всю строку, бейджи под ним.
- Кнопка футера — на всю ширину.
- Действия переносятся под строку **только у персоны** (их два: «Студия →» + «Убрать»);
  у проекта одно короткое «Убрать» остаётся в строке — иначе высота растёт зря.
- Пикер — bottom-sheet, сегменты и поиск в шапке шторки.

### Тёмная тема

Все цвета — токены, новых значений не нужно. Проверено в макете: `C.successBg`/`C.successText`
на плашке «Работает» и метке «выдан» читаются; `C.warningBg` плашки миграции не сливается
с `C.bgCard`; `C.bgSelected` чипа «есть через проект» отличим от `C.bgWhite` карточки.

### Диалог удаления (`McpServersModal`)

Перечисляет то, что реально отвалится:

- «пропадёт из N проектов: A, B, C и ещё N» (`onProjects`);
- «пропадёт из чатов вне проектов» (если ось включена);
- «пропадёт у N персон: Вера, Глеб» (`onPersonas`);
- если доступ не выдан никому — так и сказать: «в ходах сервер сейчас не участвует»;
- фраза про стирание секретов + «а доступ выдать заново».

### Чего делать НЕ надо

- Не заводить новых токенов: всё из существующих `C`/`FS`/`SP`/`R`/`SHADOW`.
- Не показывать встроенные серверы продукта — они доступны всегда.
- Не делать пар «персона × проект»: две оси независимы, и это намеренно.
- Не ставить accent на карточку, где доступ уже выдан.

## Стыковка с планом бэкенда

Хранение, каскад доставки, фич-флаг и миграцию описывает план тимлида —
[docs/research/mcp-allowlist-plan.md](../research/mcp-allowlist-plan.md); он источник правды,
здесь — только то, чем на него опирается UI. Имена в макете и спецификации выше даны по плану:

| Что на экране | Куда пишется |
|---|---|
| Строка проекта | `Project.McpServersOn` (allow-list, заменяет `McpServersOff`) |
| Строка «Чаты вне проектов» | `McpServerRecord.AllowOutsideProjects` (bool, дефолт `false`) |
| Строка персоны | привязка `mcp:<ключ>` с `Mode != Off`, читается **новым** методом `McpServerGranted`; `ServerToolEnabled` не трогаем — у него своя deny-семантика для встроенных серверов |

Три следствия для UI:

1. **Вкладка ветвится по фич-флагу `mcp-allowlist`** (per-user, `Default: false`): выключен —
   матрица v1, включён — экран v2. Обе поверхности подписываем честно, потому что настройки
   одной модели не действуют в другой.
2. **Чат вне проекта, но с персоной** покрывается строкой «Чаты вне проектов»: правило
   доставки OR-овое, а ось означает «у чата нет проекта». Так строка и подписана —
   «Чаты, у которых нет проекта — включая чаты с персонами».
3. **Пар «персона × проект» не изобретать даже «умно»** — авто-выдача персоне, чей проект
   получил сервер, и есть запрещённый разрез. На экране покрытие показано подписью строки
   проекта и чипом «есть через проект», но записью не становится.

В студии персоны у `mcp:`-ключей меняются дефолт и текст подсказки (`GetToolDefaultState` /
`ToolCatalogFor` по плану). На них завязано обещание внизу вкладки «одна и та же настройка»:
разъедутся тексты — экран начнёт врать.

Плашка миграции согласуется с решением плана «чистый старт, без автопереноса» и не
подменяет собой уведомления: момент разворота человек выбирает сам, включая флаг, а плашка
объясняет тишину прямо там, где её увидят, — на вкладке доступа.

## Итерации правок макета

1. **v2, первая сборка.** Карточка с состоянием «доступ не выдан», единый пикер с сегментами,
   плашка миграции.
2. **Кнопки с иконками ломались на две строки** — `svg` внутри `display:block`. Вылечено
   `display:inline-flex` у `btn-sm` и `ex-more`; вынесено в спецификацию, потому что в
   React-коде с `lucide` ловушка та же.
3. **Родовые формы подписей.** «Включена», «покрыта проектом» верны для «Веры» и неверны
   для «Глеба» → «выдан», «есть через проект».
4. **Тосты про персону** получили родовое слово: «доступ у персоны «Вера»…» вместо
   «доступ у «Вера»…».
5. **Мобильные строки.** Безусловный перенос действий под строку растил высоту у проектов
   ради одной кнопки «Убрать» → переносим только у персон, где действий два.

# v1 (архив). Deny-list: список исключений вместо двух матриц

> Раздел оставлен для сравнения: он объясняет, почему две матрицы вообще ушли с экрана.
> Действующая модель — v2 выше.

Макет: [mcp-access-v1.html](mcp-access-v1.html).

## Проблема

Вкладка была двумя таблицами ([McpAccessMatrix.tsx](../../frontend/src/features/mcp/McpAccessMatrix.tsx)):
«сервер × проект» с тумблером в каждой ячейке и read-only «персона × сервер».
На боевых данных владельца это не работало:

| Ось | Данных на проде | Что получалось |
|---|---|---|
| Проекты | **38** | 38 колонок в горизонтальном скролле, нужный проект глазами не найти |
| Персоны | **149** | простыня из 149 строк с галочками, править всё равно нельзя — только студия |
| Свои серверы | **1** | матрица «много на много» строится ради одной строки |
| Исключения | **0 проектов, 0 персон** | 99% решётки показывает «включено» — иголки в стоге нет вовсе |

Корень: экран рисовал **полное декартово произведение**. Этот диагноз в v2 остаётся в силе —
меняется только то, что вместо исключений экран показывает выданный доступ.

## Решение v1

Ось экрана — **сервер**, содержимое — **только исключения**.

```
+--------------------------------------------------+
| ГДЕ СЕРВЕР ВЫКЛЮЧЕН                              |
| +---------------------------------------------+  |
| | Miro   свой        http   [2 исключения]    |  |
| | (o) НСИ Каталог           [Вернуть доступ]  |  |
| | (o) Вера                        Студия ->   |  |
| | [ (o) Выключить в проекте  v ]              |  |
| +---------------------------------------------+  |
+--------------------------------------------------+
```

Что из v1 перешло в v2 без изменений: карточка сервера как ось экрана, поиск вместо колонок,
`flexShrink: 0`, мобильная шапка с именем на всю строку, плашка состояния в шапке карточки,
диалог удаления со списком «кого заденет».

Что отменено переходом на allow-list: формулировка «Доступен везде», плашка «N исключений»
(`C.infoBg`/`C.info`), отсутствие главного действия и accent'а, инвариант «доступ персоны
правится только в студии» (обоснование замены — в разделе v2 выше).
