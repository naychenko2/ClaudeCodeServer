# QA-прогон на стенде из worktree

Рецепт для проверки фичи на живом стенде одним spec-файлом: без `curl`, без разведки через Bash
и без перезапусков стенда между проверками. Каркас — [frontend/e2e/qa/](../../frontend/e2e/qa/):
хелперы `helpers.ts`, шаблон `_template.qa.spec.ts`, свой конфиг `playwright.config.ts`.

## Пять шагов

1. **Стенд.** `start_stand` (service — `.csproj` бэкенда или id из панели «Сервисы»): поднимает
   стенд из рабочего дерева чата на порту из 5500–5699 и возвращает URL. Стенд раздаёт
   `frontend/dist`; в свежем worktree его нет, и страница отдаёт 404. Для UI-сценариев сначала
   `build kind=npm target=frontend`, и только потом `start_stand`: каталог `dist` стенд видит
   лишь на старте (появился позже — перезапусти стенд). Сценарии только через API фронта не требуют.
   `start_stand` поднимает стенд **только из рабочего дерева чата**: путь вне проекта отклоняется,
   стенд чужого worktree так не поднять — проверяемую фичу ведут из её же дерева.
2. **Токен — хелпером.** Спек сам зовёт `login(request)` из `helpers.ts`; учётка из `E2E_USER` /
   `E2E_PASS`. Токен руками не добывают. На свежем стенде админ создаётся со **случайным паролем**
   (`UserStore.cs:83-97`, в лог пишется один раз), поэтому дефолт `admin/12345` не подходит. Либо
   возьми пароль из лога стенда, либо подложи `users.json` из основного чекаута в `data/` стенда и
   перезапусти его. Учётку передают через `env` у `run_tests`: `{E2E_USER: …, E2E_PASS: …}`.
3. **Адрес.** URL стенда из шага 1 передают как `env.PLAYWRIGHT_BASE_URL`.
4. **Прогон.** `run_tests kind=playwright target=frontend/e2e/qa files=["frontend/e2e/qa/<фича>.qa.spec.ts"] env={PLAYWRIGHT_BASE_URL: <URL>}`.
5. **Отчёт.** Число прошедших/упавших, имена упавших, ошибки консоли из `collectConsoleErrors`;
   стенд — `stop_stand`.

## Как писать spec

Скопируй `_template.qa.spec.ts` в `frontend/e2e/qa/<фича>.qa.spec.ts` (суффикс `.qa.spec.ts`
обязателен — по нему конфиг находит файл). Файл вне `frontend/e2e/qa/` попадёт в основной прогон:
игнор основного конфига работает только по сегменту-каталогу `qa`. Шаблон из прогона всего
каталога исключён, но запускается, если назван явно: `files=[frontend/e2e/qa/_template.qa.spec.ts]`. Логин → `seed` (проект, чат, задача с префиксом имени вашей фичи) → сценарий
→ проверки → `cleanup()` в `afterAll`. Шаблон засевает `qa-tpl-*` и убирает за собой.

## Сценарии с ходом агента

CLI-логин на деве может быть недоступен, и реальный ход агента не получить. Тогда ленту чата
подменяют моком из [frontend/e2e/contextRowMock.ts](../../frontend/e2e/contextRowMock.ts): он
перехватывает запросы страницы и отдаёт заранее заданный мир (чат, сообщения, префы), поэтому
спек проверяет интерфейс без живого хода.

## Правила

- Код читать `Read` / `Grep`, а не `grep` / `sed` через Bash.
- `curl` не нужен: всё, что делал бы `curl`, есть в `api(request, token)`.
- Стенд перезапускать только после правки `data/` (стенд читает её на старте); правка кода
  фронта/бэка — пересборка тем же `start_stand`, не ручной рестарт.
- Один spec на группу сценариев: не плодить файл на каждую проверку, каждый `run_tests` — это
  отдельная очередь и сборка.
- Засев — всегда с префиксом и уборкой в `afterAll`, чтобы на стенде не копился мусор.

## Почему `target` — `frontend/e2e/qa`, а не `frontend`

Основной `frontend/playwright.config.ts` содержит `testIgnore: ['**/qa/**']`, чтобы QA-спеки не
попадали в обычный прогон. Но `testIgnore` отсекает и явно названный файл: `--list` с игнором и
`files=[…]` даёт `0 tests`. `run_tests` запускает Playwright в каталоге `target`, а конфиг берётся
оттуда — поэтому `target=frontend/e2e/qa` подхватывает `e2e/qa/playwright.config.ts`
(`testMatch: '**/*.qa.spec.ts'`) без игнора. Расширить белый список env у `run_tests` флагом
вместо этого нельзя: он пропускает только `PLAYWRIGHT_BASE_URL`, `E2E_USER`, `E2E_PASS`.
