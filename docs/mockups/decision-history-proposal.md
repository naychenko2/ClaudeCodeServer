# Панель «История решений» (change-dossiers, этап 1)

Макет: [decision-history-v1.html](decision-history-v1.html) (обе темы переключаются кнопкой в шапке).
Фич-флаг: `change-dossiers`, по умолчанию выключен. Реализация ещё не начата — этот файл идёт
перед кодом; тексты и суть фичи — заметки «Тексты — Паспорта изменений (UI, empty-state, «Что
нового»)» и «Концепт — Паспорта изменений (память кода)»; техчасть — `docs/adr/ADR-004-change-dossiers.md`.

## Проблема

Код коммитится, а «зачем» — обсуждение в чате, отвергнутые варианты, грабли — живёт только в
шапке коммита и теряется. `git blame` отвечает «кто и что», не «зачем». Открыв файл через полгода,
человек не понимает контекст решения без раскопок в истории чатов.

## Решение

Панель у файла — того же класса, что «Документация» и «Чтение»: рельса, drag-and-drop, сплиттер,
шторка на мобиле — бесплатно от `PanelZone`. Открывается из файлового менеджера и от просмотра
изменений. Список карточек, отфильтрованных по файлу/символу/коммиту (чипы под шапкой панели),
каждая — «зачем» крупно + метаданные + раскрываемые «Что решили» / «Что отвергли и почему» /
«Грабли» + ссылки на источники.

## Как отвечаю на три продуктовых вопроса

**1. Как показать 20+ записей у файла-хаба, не превратив панель в свалку?**
Двухуровневая плотность: последние 30 дней — полные карточки (в реальности их обычно 3–6, редко
файл получает больше активных изменений за месяц). Всё, что старше, сворачивается в группы по
месяцам со счётчиком («Июнь 2026 · 8 записей»); внутри открытой группы — однострочные компактные
записи (аватар + «зачем» + sha), клик разворачивает конкретную в полную карточку на месте. Порог
30 дней — не хардкод в UI, а естественная граница ранжирования `active` из ADR §5 (там же живёт
«код с тех пор менялся»); панели она подошла и для группировки списка. Раздел 3 макета.

**2. Что видно без раскрытия — достаточно ли «зачем»?**
Нет: одного «зачем» мало, чтобы решить, стоит ли раскрывать карточку — оно объясняет цель, но не
даёт понять, какое решение приняли. Добавил вторую строку-превью: первый пункт «Что решили»,
усечённый в одну строку (карточки B/D/E в разделе 2). Так видно и «зачем», и «что сделали»,
не раскрывая карточку — раскрытие нужно только за деталями отказов и граблей.

**3. Отличима ли запись персоны от записи по коммиту человека?**
Да, на уровне аватара и подписи, без слов «AI» — персона получает акцентное кольцо вокруг аватара,
иконку-«бота» вместо инициалов и имя accent-цветом с подписью «· персона»; у человека — нейтральный
круг с инициалами, без подписи. Отличие читается боковым зрением в списке, не требует наведения.

## Обязательные состояния — где смотреть в макете

| Состояние | Раздел макета |
|---|---|
| Список 3–5 карточек, одна развёрнута | §2, карточка A развёрнута |
| Пометка `degraded` — нюанс, не ошибка | §2, карточка B: серый текст рядом с датой, без danger-заливки |
| Запись без выжимки (`summaryFailed`) | §2, карточка C: курсивный плейсхолдер вместо «зачем» |
| Протухшие ссылки (чат/задача удалены) | §2, карточка D: кнопки погашены и заменены текстом, «Показать изменения» жива всегда — она держится на коммите, а не на чате/задаче |
| Файл-хаб 20+ записей | §3 |
| Три empty-state (пусто / у файла нет / флаг выключен) | §5, тексты дословно из заметки |
| Загрузка | §4, скелетон повторяет форму карточки |
| Мобильная раскладка + обе темы | §6 (шторка), кнопка в шапке макета переключает тему на всех разделах |

## Отклонения от системы

Нет: все размеры, цвета и радиусы — токены `design.ts`/`theme.css`, новых значений не вводилось.
Единственное новое решение — компактная однострочная запись (`.compact-row`) для свёрнутых
месячных групп: у существующих панелей аналога не было, потому что ни у «Документации», ни у
«Чтения» нет сценария «десятки однотипных элементов одного экрана». Высота строки и отступы взяты
из готовой шкалы (`SP.xs`/`SP.sm`), нового токена не заводит.

## Границы задачи

Бэкенд (стор паспортов, `DossierCaptureService`, `SecretRedactor`, recall) не реализован — весь
этот макет статичен и показывает целевой вид данных из ADR §4 (`why/decisions/rejected/pitfalls`,
`status: active|degraded|archived`). REST-эндпоинт (`GET /api/projects/{id}/dossiers?file=|symbol=|commit=`)
и сама реализация панели — отдельная задача для Киры по этому макету. Тумблер «Не сохранять решения
из этого чата» (настройки чата) в макет не включён — он не входит в состав панели у файла и не был
частью этой постановки.
