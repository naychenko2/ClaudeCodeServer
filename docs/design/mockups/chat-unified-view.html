Список чатов v2 — однострочный тулбар

Переработка по обратной связи: поиск скрыт (вернулся в поповер фильтров, как в проде), «Новый чат» внутри тулбара рядом с рычагами, все рычаги собраны в одну строку: создание, группировка (PillSwitch Дни/Теги/Без компакт), фильтры с бейджем, сортировка, иерархия. Сайдбар — жёстко 220…520px (дефолт 288, sidebarWidth.ts).

Почему поиску не место в строке. Сценарий «найти чат по названию» случается в разы реже сценария «открыть свежий/рабочий чат» — а платил за него каждый пиксель панели постоянно. Редкое действие живёт за одним кликом (кнопка фильтров → фокус уже в поле), частое — в строке. Это же поведение в проде сегодня, значит и привычку пользователя не ломаем.

Логика компоновки. Слева направо по частоте жеста: «+» (главное действие, solid accent — единственный залитый элемент, глаз находит мгновенно) → группировка (перестройка всего списка, 1 клик, значение видно текстом) → фильтры с бейджем → сортировка → иерархия. Правый край — «как смотреть», левый — «что сделать».
Арифметика 288 (контент 264): [+] 32 + Pill-compact ~126 (активный «Дни» 46 + 2 иконки по ~34 + трек) + 3×IconButton sm 84 + gaps ~16 = ~258 — впритык, но без переполнения. 220 (контент 204): даже без Pill «[+] + Ф + С + И» = 32+84+12 = 128 ✓, но с Pill (130) сумма 258 > 204 — PillSwitch честно схлопывается в кнопку группировки, чья иконка = текущий режим (CalendarDays/Tags/List), клик → меню из варианта В. Рычаг не исчезает — уходит за один клик, а его значение читается по иконке.

Чем Б отличается от А и чем проигрывает. Смысловое деление чище: слева «как смотреть» (оси), справа «что делать» (фильтры + создать). Но главное действие уезжает в конец скан-линии, а на 288 «+» стоит вплотную к трём однотипным IconButton — визуально читается как четвёртая иконка-тумблер, хотя по весу это действие. Акцентная заливка спасает, но в А порядок «действие → оси» честнее по F-паттерну: пользователь сначала видит, что можно создать, потом — как настроено. По ширинам ведёт себя один-в-один как А (те же ступени и та же деградация на 220).

логика v2
1. Поиск — первая секция (обведена), точно как в проде сейчас: IconField h=36 с крестиком очистки, фокус в поле сразу при открытии поповера. В тулбаре поиска нет — строка отдана частым рычагам.
2. Активный поиск не теряется вне поповера: он входит в счётчик скрытых на кнопке фильтров (бейдж «2») и в текст EmptyState («Ничего не найдено по запросу…» + кнопка сброса) — обратная связь есть, даже когда поповер закрыт.
3. Секция «Теги» сохранена из v1: чипы реестра проекта с цветными точками, OR-пересечение (matchChatFilter уже умеет).
4. Секции «Статус», «Тип», «Персона», «Показать только» и футер («Скрыто N · Сбросить всё · Готово») — без изменений.
5. На мобиле — та же шторка ui/Modal, что в проде: поиск наверху, далее крупные чипы (large).

Правила комбинаций. Корни дерева попадают в секции по дню максимальной активности поддерева (логика maxActivity из chatTree.ts) — корень с живым ребёнком не тонет в старых днях. При Группировка=Теги чат с несколькими тегами дублируется в каждой своей секции (groupByTags), дочерние висят под ним в обеих; свёрнутость — по id чата, поэтому дубль свёрнут синхронно (состояние 5). Секция «Закреплённые» существует только при Группировка=Дни (как сейчас в groupChats); при «старые сверху» обращается и порядок секций, и порядок внутри них, а закреплённые остаются сверху. При Группировка=Теги порядок секций — реестровый (ручной, ▲▼), обращается только порядок внутри секций.
