## Проблема → решение

Проект перестаёт быть «моим»: в нём несколько людей, а деньги и настройки по-прежнему одного человека. Человек должен понимать
три вещи, не читая документацию: **кто ещё здесь**, **кто увидит то, что я пишу** и **чьи это деньги и настройки**. Отсюда три сквозных
приёма, которые повторяются на всех экранах:

1. **Автор везде, где есть человек**: аватар-инициал плюс имя (сообщения, версии файла, задачи, расход).
2. **Видимость названа словами**: бейдж «общий», замок приватного чата, плашка «видите только вы», заглушка «приватный чат Марии».
3. **Чьи настройки — названо словами**: «ходы идут по настройкам Андрея и за его счёт» — в плашке, в меню модели, в расходе и в передаче владения.

Всё, что запрещено роли, показано выключенным **с причиной и путём дальше**, а не спрятано. Исключение — то, чего роль не может даже
захотеть: поле добавления участников и блок подключений у не-владельца не рисуем вовсе.

## Общая спецификация (для всех экранов)

**Контролы — только `components/ui`:** `Button` (primary / secondary / ghost / ghostAccent / danger), `IconButton`, `Badge`, `Notice`,
`Field`, `Select`, `Toggle`, `Segmented`, `Tabs`, `Chip`, `Menu`, `Modal` / `ConfirmDialog` / `ModalActions`, `EmptyState`, `Checkbox`.
Новых компонентов не нужно, кроме одного: **`UserAvatar`** (кружок с инициалом) — см. ниже.

**Новых токенов нет.** Всё собрано из существующих `C.*`:

| Роль | Токены |
|---|---|
| Бейдж «общий» | `Badge tone="info"` (`C.infoBg` / `C.info`) + иконка `Users` 10–12 px. Своё общее — текст «общий», чужое — имя владельца |
| Бейдж роли | владелец — `Badge tone="accent"` с иконкой `Crown`; редактор и читатель — `tone="neutral"` |
| «Без исполнителя» | `Badge tone="warning"` |
| Приватность | иконка `Lock` цветом `C.textSecondary`; заглушка ссылки — `C.bgInset` / `C.textMuted`, `R.sm` |
| Плашки | `Notice tone="info"` — пояснения (приватный чат, настройки владельца, роль); `warning` — необратимость и последствия; `danger` — ошибки и отказы |
| Идущие ходы | капсула `C.successBg` / `C.successText`, точка `C.success`, высота 28 (мобила 40), `R.max` |
| Дифф | `C.diffAddBg/Text`, `C.diffRemBg/Text`, моноширинный `FONT.mono`, `FS.sm` |
| Blame | кромка 2 px цветом тона аватара автора; наведение — фон `C.accentLight` |
| Ошибка поля | рамка `C.danger`, кольцо `SHADOW.focusDanger`, текст `C.dangerText`, `FS.sm` |

**`UserAvatar`** — круг `R.full`, размеры 20 / 28 / 36, инициал `FS.xxs`/`FS.sm`/`FS.md` 700. Цвет — пара фона и текста из тонов Badge,
выбирается **стабильно по userId** (хеш → индекс): `accentLight/accent`, `infoBg/info`, `successBg/successText`, `planLight/planText`.
Бывший участник и внешний автор git — `bgInset/textMuted`. В стопке — кольцо 2 px цветом фона подложки, нахлёст −6 px, до 3 штук + «+N».

**Мобила (`useIsMobile`):** все модалки → шторка снизу (`R.sheet`, `SHADOW.sheet`), кнопки столбиком на всю ширину, высота 40;
строки списков ≥ 48; Select в строке списка заменяется меню «…». Настройки проекта — полноэкранная шторка со стрелкой «назад».

**Тёмная тема:** отдельных значений не требуется — всё через переменные. Проверено снимками обеих тем; контраст бейджа info и
подложек diff в тёмной теме держится.

**Тексты:** на «вы», без терминов (не «ACL», «арендатор», «409», «коммит» — кроме экрана истории, где git уже назван).
Кнопка подтверждения повторяет действие («Убрать Марию», «Покинуть и удалить 2 чата»), а не «ОК». Числа в подтверждениях — живые с сервера,
строки с нулём не показываем. Каждая ошибка говорит, что **ничего не потеряно** и что делать дальше.

## Спецификация по экранам

### 1. Участники (S1)

- Вкладка «Участники · N» в настройках проекта, между «Основное» и «Git». Счётчик — с 2 человек.
- **Пусто** (только владелец): `EmptyState` с четырьмя пунктами «что даёт общий доступ» + форма добавления.
- **Форма:** `Field` «Имя учётки» (без автодополнения и поиска — намеренно), `Select` роли (по умолчанию «Редактор»), `Button primary` «Добавить».
  Загрузка — поле `disabled`, кнопка `loading` «Добавляем…».
- **Первое добавление** открывает `ConfirmDialog` (MODAL_W.form) «Открыть проект для участников?» с тремя последствиями; пункт про git —
  только если репозитория нет. Кнопка — «Открыть доступ и добавить».
- **Ошибки** — под полем, введённое не стирать: не найден; уже участник (с ролью); это вы; у получателя выключен флаг (куда нажать);
  сеть. **Локальный проект** — вместо формы `Notice danger` с причиной (`ProjectCapabilities.Shareable`), формы нет вовсе.
- **Список:** аватар, имя, username, `Select` роли, `IconButton` «…» → «Убрать из проекта». Владелец — бейдж, без меню.
  Ошибка смены роли — подпись строки `C.dangerText`, Select откатывается.
- **Убрать:** `ConfirmDialog` danger: задачи станут «без исполнителя» (N), приватные чаты скроются и вернутся при повторном приглашении (N),
  сделанное остаётся, идущий ход доработает.
- **Подключения для участников:** список MCP владельца с `Toggle`, все выключены по умолчанию, подпись «с вашими ключами и от вашего имени».
  Пусто — «Своих подключений у вас нет». Подпись «Ваши плагины в ходах участников не работают».
- **Вид участника:** `Notice info` «вы редактор/читатель: что можно», список с бейджами ролей без контролов, `Button ghost` danger-цвета
  «Покинуть проект». Вкладки — только «Основное» (просмотр) и «Участники»; **пункта «Сфера» нет**.
- Загрузка — 2 скелетон-строки; ошибка — `Notice danger` + «Повторить».

### 2. Бейдж и шапка (S1, S2a)

- Бейдж в списке проектов (`xs`), на карточке «Домой» и в шапке (`sm`). Мобила в шапке — только иконка.
- Шапка: стопка аватаров (клик → вкладка «Участники»), капсула ходов (клик → `Menu`: «Чат X · автор · время» со стрелкой перехода;
  чужой приватный — `disabled` строка «Игорь работает в приватном чате» без перехода). Ходов нет — капсулы нет.
- Плашка «Проект Андрея — ходы идут по его настройкам»: участнику, один раз над лентой, закрывается; дальше — в «Основное».
- В меню модели композера у участника: модель `disabled` «выбирает владелец»; группа «Ваши персоны» `disabled` «в общем проекте доступны
  только персоны проекта».
- **Читатель:** композер заменён плашкой `C.bgInset` + `Eye` + «попросите Андрея сделать вас редактором»; кнопки «Новый чат» нет.
- Загрузка аватаров — 2 круга-скелетона; ошибка — `IconButton` «Повторить» с подсказкой; бейдж не пропадает никогда.
- Доступ отозван при открытом проекте — `Notice warning` + «На „Домой“».

### 4. Приватный чат (S2d)

- `Toggle` «Приватный» в «Новый чат» — только в общем проекте, только владелец и редактор, выключен по умолчанию. Включён — кнопка
  «Создать приватный чат».
- Дерево: иконка `Lock` вместо `MessageSquare`. Владельцу — одна `disabled` строка «Ещё N приватных чатов участников» без перехода.
- **Плашка** `Notice info` закреплена вверху ленты, рисуется из признака чата **до загрузки сообщений**. Полный текст (три пункта):
  1. Всё, что агент сделает в проекте — файлы, задачи, коммиты, заметки, — увидят все участники.
  2. Агент этого чата не записывает факты в общую память команды и проекта.
  3. Скрытность обеспечивает AI Home, а не компьютер: агент из другого чата этого проекта, работающий с командной строкой,
     технически может прочитать файлы и вложения этого чата.
  «Свернуть» → одна строка «Видите только вы. Сделанное агентом в проекте — видят все. Подробнее». Совсем не закрывается.
- «Сделать общим…» в меню «…» → `ConfirmDialog` с `Notice warning` «обратно нельзя». Обратного пункта нет.
- Режимы «Привязать к фиче», «Командная реализация», «Совещание персон» — `disabled` с причиной в `Menu`; внизу «Нужен режим — сделайте чат общим».

- Понижен до читателя — чат остаётся у автора, композер заблокирован с текстом «он остаётся приватным».

### 5. Конфликт 409 (S2c)

- Текст/заметка: `Modal` MODAL_W.wide, две колонки «Ваша версия» / «Сейчас в проекте» с диффом; строка автора «Андрей изменил … 4 минуты
  назад — через агента в чате X». Кнопки: `ghost` «Взять текущую», `secondary` «Оставить мою», `primary` «Сохранить мою копией»
  (имя копии — `<имя> (<Имя участника>).<расширение>`). Подпись «обе версии останутся в истории».
- Office/двоичные: `Modal` 520, радио-карточки версий (размер, автор, время), действие повторяет выбор + `ghost` «Сохранить мою копией».
- Мобила: шторка, `Segmented` «Ваша / В проекте / Разница», кнопки столбиком (копией — первой).
- Повторный конфликт — `Notice warning` над колонками, выбор сбрасывается. Третий раз за минуту — добавка «в файл сейчас пишет агент».
- Загрузка — скелетоны колонок, кнопки выключены; ошибка сохранения — «текст остался в редакторе»; файл удалён — «сохранить как новый».
- Читатель конфликтов не получает: редактор только на просмотр, свежая версия подменяется тихо с тостом.

### 6. История и blame (S3)

- Панель файла, `Segmented` «Версии / Кто менял строки».
- Строка версии: аватар человека, «с агентом · модель» или «с персоной X» / «правка в редакторе», источник — ссылка на чат, заглушка
  приватного или «автор из git · коммит не из AI Home». «Показать ещё 50» внизу.
- Справа — дифф выбранной версии с текущей, `secondary` «Открыть версию», `primary` «Восстановить» (пишется новым изменением от вашего имени).
  Читатель — «Восстановить» `disabled` с подсказкой.
- Blame: колонка 150 px «автор · давность» с цветной кромкой по коммиту; мобила — инициал 28 px, тап → шторка.

### 9. Уход и передача (S5)

- «Покинуть проект» (не у владельца): `ConfirmDialog` danger; приватные чаты перечислены по названию (это свои), кнопка «Покинуть и удалить N чата».
  Без приватных — «Покинуть проект». Идёт свой ход — кнопка `disabled` с причиной.
- «Передать проект» (только владелец): радио-карточки участников; живая проверка условий (галочка `C.success` / крест `C.danger` с
  причиной и действием / спиннер); `Notice warning` «что изменится для вас»; кнопка «Предложить Марии» активна только при всех галочках.
  Пусто — «Передавать некому» + «К участникам».
- Ожидание — `Notice info` во вкладке «Участники» с «Отозвать предложение»; отказ — `Notice warning`.
- Получатель — карточка уведомления «Принять проект / Отклонить» с «ходы пойдут за ваш счёт и по вашим настройкам».
- Перенос идёт — `Notice info` «чаты пока только для чтения»; сбой — `Notice danger` «всё вернули как было»; итог — окно «Проект теперь у Марии»
  с четырьмя последствиями.
- Удаление учётки владельца: `Notice danger` + список общих проектов с «Передать»; «Удалить учётку» `disabled`.

## Открытые вопросы к Андрею (только развилки)

1. **Флаг у получателя.** Добавить человека, у которого фича выключена, — отказ с подсказкой «попросите включить» (так в макете) или
   добавить сразу, а проект появится у него, когда он включит? Первое честнее, второе меньше трения.
2. **Строка «Ещё N приватных чатов участников» в дереве владельца** — показывать (владелец не удивится расходу и предупреждению при удалении
   проекта) или держать число только в «Расходе»? В макете — показываем.
3. **Главное действие в конфликте 409** — в макете «Сохранить мою копией» (ничего не теряется, но плодит файлы). Альтернатива — «Оставить мою»
   основной: git всё равно хранит чужую версию.
4. **Плашка приватного чата: пункт про предел приватности** — держать его в свёрнутом виде за «Подробнее» (в макете) или всегда раскрытым?
   Раскрытый честнее, свёрнутый не утомляет в каждом чате.
5. **Читатель как исполнитель задач** — в макете можно назначить (он делает руками). Если читатель — «только смотрит» и в задачах тоже, уберу его из списка.
