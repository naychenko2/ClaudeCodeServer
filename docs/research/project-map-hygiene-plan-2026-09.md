# Уборка карты проекта: гигиена CLAUDE.md как продуктовое действие

Статус: **план, реализация не начата** (задача трекера `12d5757d`).
Круг: постановка — Андрей + архитектурный разрез Александра; UI согласован с Майей и Кирой;
разведка кода и замеры — в этом документе, каждый проверен на живом репозитории 21.09.2026.

## Зачем

Корневой `CLAUDE.md` грузится в контекст КАЖДОЙ сессии — это не документация, а постоянная
плата токенами. Файл растёт сам собой (каждая фича дописывает абзац), а усыхает только
руками. Нужна кнопка: проверить гигиену карты и показать человеку, что именно раздулось,
что протухло и что можно свернуть в ссылку.

Замер на нашем репозитории (21.09.2026, ветка master):

| Показатель | Значение |
|---|---|
| Корневой `CLAUDE.md` | 974 строки / 100 248 байт (~33 000 токенов) |
| Ориентир Anthropic | ≤200 строк |
| Секций `##` | 28, из них длиннее 40 строк — 7 |
| Три крупнейшие секции | «Внутренние подсистемы» 257, «LLM-провайдеры» 110, «Реализовано» 106 — половина файла |
| Ссылок на пути | 54, из них **мёртвых 2** |
| Вложенных `CLAUDE.md` | 3 (Video, Desktop, Telemetry) |

Мёртвые ссылки на сегодня: `backend/ClaudeHomeServer/Services/Deploy/CLAUDE.md` (файла нет) и
`backend/ClaudeHomeServer/Models/FeatureFlag.cs` (переехал в `ClaudeHomeServer.Core/Models/`).
Обе воспроизведены прототипом сканера — фича ловит реальные дефекты в первый же прогон.

## Принципы

1. **Модель не читает карту целиком.** Сначала детерминированный сканер, модели уходит его
   отчёт. Факт «существует ли путь» модель обязана получать, а не угадывать.
2. **Автоправок нет.** Запись в `CLAUDE.md` — только по явному утверждению человека, по
   одному предложению. Файл под git, его параллельно правят исполнители задач в общем дереве.
3. **Сканер самоценен.** Фаза 1 проверяема без модели и без UI; модель и экран строятся поверх
   готового отчёта.
4. **Факт важнее формулировки.** Модель не ответила или отдала битый JSON — показываем факты
   сканера без формулировок, а не пустой экран и не выдуманные предложения. Где факт и
   суждение модели стоят рядом, первым идёт факт.
5. **Пороги — настройка, а не константа.** Разные проекты живут с разной картой.

## Р1. Двухфазность и её доказательство

**Фаза 1 — сканер** (детерминированный, без модели): размер, мёртвые ссылки, длинные секции,
секции со ссылками на `docs/*`, вложенные карты.
**Фаза 2 — one-shot модели** по отчёту: формулировки предложений.

Допущение «отчёт влезет в окно» проверено прототипом на живом файле: **100 248 байт входа →
2 364 символа отчёта (~790 токенов)**, сжатие в 40 раз. Профиль `CheapProfile.Large` — это
`NumCtx: 16384` (`LocalActionCatalog.cs:141-143`), то есть запас двадцатикратный даже для карты
вчетверо крупнее нашей. Сам файл (~33 000 токенов) в это окно не влезает — двухфазность не
украшение, а единственный способ уложиться.

## Р2. Вертикаль и файл сканера

**Вертикаль `Docs`**, новый файл `backend/ClaudeHomeServer.Docs/ProjectMapScanner.cs`,
namespace `ClaudeHomeServer.Services.Docs`.

Почему `Docs`, а не `ProjectServices`:

- в `DocsIndexService` уже живут `LinkRegex()`, `HeadingRegex()`, `FenceRegex()`
  (`DocsIndexService.cs:2065` и соседние) — `internal static partial`, то есть доступны **только
  внутри сборки `ClaudeHomeServer.Docs`**. Сканер переиспользует их, а не заводит свой третий
  набор регулярок разбора markdown;
- `Docs` уже зовёт модель через Core-шов: `DocumentAiService.cs:36,55,69,80` —
  `cheap.RunAsync(Llm.LocalActionCatalog.DocFormat, …)`. Прецедент «вертикаль Docs → `ICheapTextRunner`»
  существует, новых швов не требуется;
- `ProjectServices` — про дев-серверы и прокси `/preview/**`, разбор markdown там чужероден.

**Сторож границ не трогаем.** Запись `Docs` в `Boundaries` уже есть
(`SubsystemBoundaryTests.cs:891-906`), новой не заводим — дубль записи сторожа не ловят ни один
(известная грабля, CLAUDE.md «Внутренние подсистемы»). Ссылка на Core легальна: допуск идёт по
**имени сборки** (`IsCoreAssembly`, комментарий на `SubsystemBoundaryTests.cs:144-147`), а не по
namespace, — «сборка `ClaudeHomeServer.Core` — спинка целиком».

Регистрация сервиса — `Program.cs` рядом с остальными сервисами `Docs` (`:477-483`): у вертикали
`Docs` нет `IAppSubsystem`, её сервисы регистрируются вручную. Заводить `DocsSubsystem` в рамках
этой задачи не надо — это отдельная уборка со своей ценой.

## Р3. Предварительная уборка: `ClaudeMdExpander` → Core

**Это единственное место, где задача задевает чужой код, и без него разрез роняет сторожа.**

Карта едет в контекст не как файл, а с раскрытыми `@`-импортами (`@rules/git.md`). В продукте это
уже реализовано: `ClaudeMdExpander.Read(path)` — глубина 5, циклы, потолок 256 КБ. Сканер обязан
мерить РАСКРЫТЫЙ размер: проект с `CLAUDE.md` в 20 строк и пятью `@`-импортами платит за всё
дерево, и без раскрытия отчёт соврёт в пользу «всё хорошо».

Сейчас файл лежит в `backend/ClaudeHomeServer.Llm/Claude/ClaudeMdExpander.cs` — вызов из `Docs`
был бы «вертикаль → вертикаль», сторож поймает.

Решение — **перенос в спину по буквальному прецеденту `SafePath`** (CLAUDE.md: «Спина лечится
переносом в Core с сохранением namespace, call-site'ы не меняются»):

`backend/ClaudeHomeServer.Llm/Claude/ClaudeMdExpander.cs` → `backend/ClaudeHomeServer.Core/Services/Llm/Claude/ClaudeMdExpander.cs`

Перенос дешёвый и проверенный:

- namespace `ClaudeHomeServer.Services.Llm.Claude` **не меняется** — в Core уже есть каталог
  `Services/Llm/Claude/` с `TranscriptProbe.cs` того же namespace;
- у класса ноль зависимостей от `Llm`: только `System.Text`, `File`, `Path`;
- call-site'ов два: `ClaudeSession.cs:4378` и `ClaudeMdExpanderTests.cs` — **ни один не правится**.

## Р4. Что считается картой проекта

Не один файл. Источник правды — то, что реально собирает продукт (`ClaudeSession.cs:4363-4366`):

| Файл | Входит в отчёт |
|---|---|
| `<корень>/CLAUDE.md` | да, основной предмет |
| `<корень>/.claude/CLAUDE.md` | да, вторая проектная карта |
| `<профиль CLI>/CLAUDE.md` | **нет** — это личный файл пользователя, не проекта |
| Вложенные `CLAUDE.md` в подпапках | да, но **справочным списком**, а не находкой |

**Вложенная карта — не дефект, а правильный приём** (возражение Майи, принято). Наши три
вложенных файла (Video, Desktop, Telemetry) подхватываются по месту работы и есть ровно то
прогрессивное раскрытие, к которому уборка и ведёт. Плашка серьёзности рядом с ними отправит
человека чинить здоровое. В отчёте они идут отдельным блоком без плашек и без действий, с
оговоркой, что в общий счёт контекста не входят.

Карты нет вовсе — это не ошибка, а штатный ответ «карты нет» (у большинства проектов
пользователя её и не будет).

`docs/CLAUDE-local.md` (у нас — 14,7 КБ) в счёт **не входит**: он едет только при `BareMode`
как `SystemPromptFile` и обычные ходы за него не платят. Упомянуть его в отчёте стоит одной
справочной строкой — он показывает, что компактная карта того же проекта уже написана и
цель достижима.

**Обход дерева обязан исключать** `.git`, `node_modules`, `bin`, `obj` и `.claude/worktrees`.
Проверено на живом репозитории: наивный `find` нашёл 8 файлов `CLAUDE.md` вместо 4 — половина
это копии в рабочих деревьях, и в отчёте они были бы чистым мусором.

## Р5. Правило резолва ссылок

Проверяются **только markdown-ссылки** вида `[текст](путь)`. Правило резолва — по фактическому
устройству наших карт:

1. Внешние (`http://`, `https://`, `mailto:`) — пропускаем, в сеть не ходим.
2. Абсолютные (`/…`, `C:\…`) — помечаем «не проверяли», **в `SafePath.Join` не отдаём**:
   у примитива задокументировано, что на Linux `/a/b` станет относительным и приклеится к
   корню, то есть проверка «ссылка наружу» молча исчезнет (`SafePath.cs:4-9`).
3. Относительные — резолвим **от каталога файла, а если не нашлось, то от корня проекта**;
   мёртвая только если не нашлось нигде. Причина: во всех трёх наших вложенных картах
   (Video, Desktop, Telemetry) ссылки написаны **относительно корня репозитория**, а не файла —
   наивный резолв «от каталога» объявил бы мёртвыми все до единой.
4. Выход за корень (`../..`) — ловим `UnauthorizedAccessException` от `SafePath.Join` и
   помечаем «ссылка за пределы проекта». Сканер от этого не падает.
5. **Содержимое кодовых блоков (``` и ~~~) не разбирается вовсе** — ни ссылки, ни заголовки.
   Найдено самопроверкой: прогон прототипа по ЭТОМУ плану дал две «мёртвые ссылки», и обе
   оказались иллюстрациями внутри примеров — шаблон `[текст](путь)` и намеренно устаревший
   путь в примере JSON. В документации про документацию такие примеры — норма, и сканер,
   который на них ругается, обесценивает себя на первом же прогоне. Состояние «внутри забора»
   у разбора заголовков уже есть — то же состояние обязано гасить и разбор ссылок.

**Голые пути в бэктиках (`` `lib/featureFlags.ts` ``) на существование НЕ проверяем.** Замер:
из 16 таких путей в нашей карте буквально существуют 2. Остальные верны, но сокращены
(`lib/featureFlags.ts` = `frontend/src/lib/featureFlags.ts`), либо рантайм-файлы (`data/*.json`),
либо машинно-локальные (`appsettings.Local.json` в `.gitignore`). Проверка дала бы 14 ложных
тревог из 16 — это шум, который обесценит настоящие находки.

## Р8. Контракт: факты сканера и предложения модели

Два ответа, а не один: факты приходят мгновенно, модель — десятки секунд. Разделение позволяет
показать половину отчёта сразу (требование Киры и Майи независимо друг от друга).

**Ответ сканера** (форма проверена прототипом на живом файле):

```jsonc
{
  "path": "CLAUDE.md", "exists": true,
  "baseSha": "…",              // хеш содержимого; едет обратно в review и apply
  "lines": 974, "bytes": 100248, "approxTokens": 33416,
  "expandedLines": 974, "importCount": 0,   // с раскрытыми @-импортами (Р3)
  "budget": { "recommendedLines": 200, "overBudget": true },
  "sections": [                // только кандидаты (> порога), не весь файл
    { "title": "Внутренние подсистемы (Services/Composition)", "startLine": 268,
      "lines": 257, "docsRefs": 6, "firstLine": "Внутренние границы продукта — …" }
  ],
  "deadLinks": [
    { "section": "Фич-флаги (feature toggles)", "line": 845,
      "target": "backend/ClaudeHomeServer/Models/FeatureFlag.cs", "reason": "notFound",
      "candidates": ["backend/ClaudeHomeServer.Core/Models/FeatureFlag.cs"] }
  ],
  "nestedMaps": [ { "path": "backend/ClaudeHomeServer.Video/CLAUDE.md", "lines": 41 } ],
  "skipped": [ { "target": "C:\\Users\\…", "reason": "absolute" } ]
}
```

**Кто какие предложения порождает** — важное следствие двухфазности: механические предложения
(мёртвая ссылка, у которой сканер нашёл ровно одного кандидата) формирует **сканер** и отдаёт
прямо в ответе `scan` — модель для них не нужна вовсе. Модель добавляет только содержательные
(`long-section`, `duplicate`), у которых `apply` всегда `null`. Отсюда и раскладка экрана:
группа «Правки в один клик» рисуется сразу, а группа «Работа для чата» догружается.
Практическое следствие: **при неработающей модели фича остаётся полезной** — ровно те две
мёртвые ссылки, что есть у нас сегодня, чинятся без единого обращения к LLM.

**Ответ модели** — предложения поверх тех же фактов; форма записи общая со сканерной:

```jsonc
{
  "baseSha": "…",
  "modelNote": null,           // причина неполноты человеческим текстом, не молчание
  "suggestions": [{
    "id": "…",                              // стабилен в пределах baseSha
    "severity": "high | medium | low",      // ровно три градации
    "kind": "dead-link | long-section | duplicate | other",
    "fact": "257 строк, внутри ссылка на docs/adr/ADR-014-internal-subsystems.md",
    "modelSays": "Похоже на пересказ ADR-014 — свернуть в ссылку",
    "anchor": { "line": 268, "heading": "Внутренние подсистемы (Services/Composition)" },
    "savingLines": 257,
    "apply": {                              // null ⇒ кнопки нет вовсе
      "before": "[FeatureFlag.cs](backend/ClaudeHomeServer/Models/FeatureFlag.cs)",
      "after":  "[FeatureFlag.cs](backend/ClaudeHomeServer.Core/Models/FeatureFlag.cs)",
      "anchorText": "…"                     // якорь замены — текст, не номер строки
    }
  }]
}
```

Решения формы и почему именно так:

- **`firstLine`, а не тело секции.** Модели уходят заголовки и первые строки — этого хватает,
  чтобы узнать «секция пересказывает ADR-014», и только это удерживает отчёт в 790 токенах.
- **`docsRefs`** — число живых ссылок на `docs/*` внутри секции: сильный признак пересказа
  существующего документа (у трёх наших крупнейших секций он 6–8).
- **`fact` и `modelSays` — РАЗНЫЕ поля, и это главное решение контракта.** Модель не читала
  карту целиком, значит её суждение — догадка по метаданным. Факт сканера показывается
  основным текстом, фраза модели — вторичной. Поменять местами — человек снесёт живой раздел,
  поверив красивой фразе (возражение Майи, принято).
- **`apply: null` вместо отсутствия ключа.** Применимость определяется **наличием готового
  патча, а не типом находки**: мёртвая ссылка чинится кнопкой только если сканер нашёл ровно
  один файл с тем же именем; ноль или два кандидата — решение человека. Без этого поля фронт
  начнёт угадывать по `kind`, и половина кнопок «Применить» окажется ложью (возражение Майи,
  подтверждено требованием Киры «`apply: null`, чтобы не гадать по наличию ключа»).
- **`severity` — ровно три значения:** у `ui/Badge` три подходящих тона
  (`danger`/`warning`/`neutral`), четвёртая градация потребовала бы нового цвета в обе темы.
- **`before`/`after`, а не unified diff.** Проверено: на бэкенде генератора unified diff нет и
  пакета (`DiffPlex` и т.п.) в `.csproj` нет — весь дифф в продукте приходит от git
  (`/git/diff`, `/files/diff`), а правку нужно показать ДО записи, когда git её ещё не видит.
  Писать LCS-алгоритм ради показа замены одной ссылки несоразмерно; механическая правка по
  конструкции точечная. Полный дифф после применения доступен штатно — в панели «Изменения».
- **`anchorText`.** Применение идёт по якорю-тексту, а не по номеру строки: между проверкой и
  применением файл могли подвинуть.
- **`modelNote`** — отказ модели показывается настоящей причиной, а не глухим «не удалось»:
  по глухому человек не починит «модель для разбора не настроена».

Промпт строится по отчёту и просит JSON. Разбор — с тем же тихим фолбэком, что у `project-icon`
(`ProjectIconGlyphService.ParsePick`, `ExtractJsonObject`): битый JSON = факты сканера без
формулировок, а не ошибка экрана.

## Р9. Эндпоинты

Новый контроллер `ProjectMapController` в Main (`api/projects/{projectId}/map-hygiene`).
В `DocsController` не лезем: гигиена карты — не часть корпуса документации.

| Метод | Назначение |
|---|---|
| `GET  …/map-hygiene/scan` | только сканер: мгновенно, без модели и без трат |
| `POST …/map-hygiene/review` | формулировки модели поверх фактов; тело `{ baseSha }` |
| `POST …/map-hygiene/apply` | применить отмеченные; тело `{ baseSha, ids[] }` |

Владение — дословно как у соседей (`ProjectsController.cs:461`):
`var p = projects.GetById(id); if (p is null || p.OwnerId != UserId) return NotFound();`
— 404 на чужой проект, существование не подтверждаем.

`apply` отвечает честным отчётом `{ applied[], failed: [{ id, reason }], newSha, scan }` по
образцу `POST /api/projects/{id}/preset` (`onboarding-intro.md:199`), а не мнимой атомарностью:
часть правок могла не найти свой якорь. Свежий `scan` в ответе избавляет фронт от второго
запроса ради перерисовки шапки.

**Грабля фронта, обязательная к учёту:** дефолтный таймаут `request()` — 30 с
(`lib/offline.ts:318`), а ход модели до минуты; без явного `timeoutMs: 180_000` (образец —
`api.ts:1339`, `analyzePrompt`) обрыв покажется пользователю как «действие недоступно офлайн».

## Р10. Инварианты записи

1. **Ни одна правка не применяется без явной отметки человеком.** Чекбоксы сняты по умолчанию,
   у неприменимых предложений чекбокса нет вовсе, автоприменения нет ни на одном пути.
   Применить несколько отмеченных за раз можно — «Отметить все» это тоже действие человека,
   и каждая отметка видна ему на экране вместе со счётчиком в кнопке. Запрещено другое:
   предотмеченные галочки и любая запись, которой человек не видел.
2. **Применяются только механические правки** (починка мёртвой ссылки). Вынос секции в
   `docs/*` кнопкой не делается никогда: это содержательная работа, и её цена — потеря знания,
   оплаченного инцидентами.
3. **Проверка перед записью:** файл не изменился с момента скана (сверка хеша) — иначе 409.
   Карту параллельно правят исполнители задач в общем дереве.
4. **Ни одной перезаписи вслепую** — прямая перекличка с требованием приёмки знакомства v2:
   «затёртый `CLAUDE.md` считается дефектом» (`project-onboarding-v2.md:17-19`).
5. **Кэшируется только дорогая половина.** Факты сканера пересчитываются всегда (миллисекунды,
   устаревший факт опаснее пересчёта), а ответ модели сохраняется: минута ожидания и трата
   модели на каждое открытие — это фича, которую откроют один раз (возражение Майи, принято).
   **Нового хранилища при этом не заводим** — три поля в `Project` по буквальному прецеденту
   `Session.ArchiveSummary`/`ArchiveSummaryAt` (`Session.cs:476-478`): `MapReview`,
   `MapReviewAt`, `MapReviewSha`. Стор `data/projects.json` уже в бэкапе, правило «новое
   хранилище → сверка с бэкапом» соблюдено без правок `BackupPaths`. Инвалидация — по
   расхождению `MapReviewSha` с текущим хешем файла.

## Р11. Фич-флаг

`project-map-hygiene`, `Default: false`, `Stage: "dev"` — dark launch по конвенции. Три шага:
строка в `FeatureFlagCatalog.All` (`backend/ClaudeHomeServer.Core/Models/FeatureFlag.cs`), ключ в

разобрана ниже по фактам, а не по авторитету.

### Где живёт запуск

**Основной вход — настройки проекта**, `features/projects/dialogs/EditDialog.tsx`: одна строка
`<ProjectMapSection project={project} />` между `GitHistorySection` (:571) и `BackgroundSection`
(:572). Аккордеон со сводкой в заголовке («CLAUDE.md · 974 строки · 6 замечаний»), отчёт —
вложенной модалкой поверх (вложенные модалки в проекте работают, живой пример —
`BackgroundSection.tsx:253`).

**Второй вход, обязательный — `features/chat/PromptSnapshotDialog.tsx`** (~6 строк): в строке
корневого `CLAUDE.md` группы «Файлы CLAUDE.md» (`cliRows`, ~:531), когда размер выше порога, —
`Button variant="ghost" size="xs"` **«Прибраться»**. Это горячий путь: человек смотрит «кто съел
контекст», видит карту на 98 КБ — и ровно в этот момент у него возникает наш вопрос. Обе
консультации назвали эту точку сильной; без неё фичу найдут только те, кто уже знает о ней.

**Панель «Документы» отклонена**, хотя Майя предлагала её основным входом (довод: решать
«правда ли раздел пересказывает ADR-014» удобнее рядом с деревом `docs`). Отклонено по двум
проверенным фактам:

- корневой `CLAUDE.md` в эту панель по умолчанию **не попадает**: `DocsIndexService.DefaultScope`
  — это `rootFiles: ["README.md"]` (`DocsIndexService.cs:29`). Человек обсуждал бы файл, которого
  в панели не видит, а точка входа плавала бы от проекта к проекту;
- цена: правка панели на 2 640 строк против одной строки в диалоге настроек.

Встречный довод Майи против настроек («форма значений, минутное ожидание там — чужой жанр»)
проверен и не подтвердился: в этом же диалоге уже живут `BackgroundSection` (генерация фона
моделью, `generateBackground`, :143) и `GitHistorySection` — прецедент долгого хода модели в
настройках проекта существует.

### Раскладка отчёта

`Modal width={MODAL_W.wide}` (720, уже в шкале), высота фиксированная — содержимое от проекта к
проекту разное, прыгающая карточка мешает сравнивать. Мобильную шторку `Modal` делает сам
(`useIsMobileModal`), отдельной раскладки не пишем.

Шапка — метки `Badge size="sm"`: «3 секции длиннее 80 строк» (`warning`), «2 мёртвые ссылки»
(`danger`), «Ориентир: до 200 строк» (`neutral`). **Прогресс-бара «487 % от нормы» не рисуем:**
у большого проекта карта объективно больше, и приговор в процентах обесценивает весь отчёт.

Тело — **один список, две озаглавленные группы, не табы**: «Правки в один клик · 4» и «Работа
для чата · 11». Табы прячут половину картины и дают ложное «я прибрался», когда закрыт только
механический таб, — а весь вес файла (473 строки из 974) сидит как раз во второй группе.
Подвал — «Ещё в проекте»: вложенные карты справочно, без плашек и действий (Р4).

Честность «применить можно не всё» держится на трёх вещах, а не на дисклеймере: заголовки групп
прямо называют способ, **у неприменимых предложений чекбокса нет вовсе** (галочка, которая
ничего не делает, врёт сильнее любой подписи), счётчик в кнопке считает только применимое.
Чекбоксы в группе 1 **по умолчанию сняты** — предотмеченная галочка это не «явное утверждение
человека», а дефолт, который прокликивают; цена — одна кнопка «Отметить все».

**Двухфазная загрузка:** факты и группа 1 показываются сразу, на месте группы 2 —
`WaitingIndicator` с подписью «Читаю карту и прикидываю, что свернуть…». Один спиннер на весь
экран здесь неуместен: детерминированная половина отчёта уже готова и уже полезна.

Состояния, которые обязаны быть: скан идёт · модель думает · модель отказала (настоящая причина
+ «Повторить») · предложений ноль («Карта в порядке») · карты нет («Создать через /init») ·
применено частично · файл изменился после проверки (плашка + «Проверить заново») · 360 CSS.

### Что придётся завести во фронте

- `components/ui/Checkbox.tsx` — **примитива-чекбокса в `ui/` нет** (проверено: в каталоге его
  нет). Квадрат с галкой сейчас нарисован руками в `DocsScopeDialog.ScopeRow`, а в футере

- Три новых файла: `ProjectMapSection.tsx` (~120 строк), `MapHygieneDialog.tsx` (~300),

  `types/index.ts`, одна строка в `EditDialog.tsx`.
- `DiffView` **не используем** (Р8: показываем «было → стало» на токенах

## Волны реализации

**Волна 1 — сканер (самоценна, проверяема без модели и UI).**
Перенос `ClaudeMdExpander` в Core → `ProjectMapScanner` + контракт отчёта, включая механические
предложения → `GET …/map-hygiene/scan`. Критерий: на нашем репозитории отчёт находит ровно
2 мёртвые ссылки и 7 длинных секций, без ложных срабатываний.

**Волна 2 — формулировки модели.** Строка каталога, промпт, разбор JSON с тихим фолбэком,
кэш ответа в `Project` (Р10.5), `POST …/map-hygiene/review`.

**Волна 3 — UI, часть 1.** `Checkbox` в `ui/`, типы и клиент API, `ProjectMapSection`, модалка с
фактами скана и пустыми состояниями, фич-флаг. Критерий: кнопка есть, факты видны, модель не
дёргается.

**Волна 4 — UI, часть 2 и применение.** `POST …/map-hygiene/apply` (по якорю-тексту, сверка
`baseSha`, 409), карточки предложений, выборочное применение, второй вход в
`PromptSnapshotDialog`. Критерий: предложение применяется, «было → стало» видно до записи.

Волны 3 и 4 — **две отдельные задачи исполнителю, а не одна**: ~600–700 строк нового фронтового
кода в одно окно не лезут (оценка Киры, принята).

## Тесты

Пишутся в `ClaudeHomeServer.Tests` (у `Docs` есть `InternalsVisibleTo ClaudeHomeServer.Tests`).
Обязательные кейсы — каждый закрывает грабли, найденные замером, а не гипотезу:

1. ссылка относительно корня репо из вложенной карты — **живая**, не мёртвая (Р5.3);
2. абсолютный путь в `SafePath.Join` не уходит, помечается `skipped` (Р5.2);
3. `../..` — `skipped`, сканер не падает (Р5.4);
4. `##` внутри ```-забора не считается заголовком секции;
5. **ссылка внутри ```-забора не проверяется и в `deadLinks` не попадает** (Р5.5) — кейс
   найден самопроверкой на живом тексте, а не придуман;
6. `@`-импорт увеличивает `expandedLines` (Р3);
7. карты нет — штатный ответ, не исключение;
8. `.claude/worktrees` и `node_modules` в `nestedMaps` не попадают (Р4);
9. чужой проект — 404;
10. мёртвая ссылка с двумя одноимёнными кандидатами отдаёт `apply: null` (Р8);
11. `apply` с устаревшим `baseSha` — 409, файл не тронут (Р10.3);
12. якорь-текст не найден — предложение уходит в `failed`, остальные применяются (Р9).

Платформонезависимость обязательна (CI на Linux): пути через `Path.GetTempPath()` +
`Path.Combine`.

## Что НЕ делаем

- **Фоновый процесс, правящий карту по расписанию.** Нет измеримого критерия «знание не
  потеряно», а файл хранит инварианты, оплаченные инцидентами.
- **`@`-импорты как способ экономии контекста** — они не ленивые, грузятся сразу.
- **Проверку голых путей в бэктиках** — 14 ложных из 16 (Р5).
- **Вынос секций кнопкой** — только руками человека (Р10.2).
- **Новое хранилище под отчёт** — кэшируется только ответ модели, и то в существующем сторе
  проектов (Р10.5); факты сканера не кэшируются вовсе.
- **Генератор unified diff на бэкенде** — механическая правка показывается как «было → стало»,
  полный дифф после записи даёт штатная панель «Изменения» (Р8).
