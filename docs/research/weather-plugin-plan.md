## 1. Источник данных: Open-Meteo подходит (проверено curl 22.10.2026, 15:07 MSK)

Без ключа (секретов нет), CORS `*` (это нужно только эмулятору), ответы маленькие (прогноз ≈ 1,2 КБ при потолке прокси 1 МиБ), редиректов нет.

**Прогноз** — `GET https://api.open-meteo.com/v1/forecast`
```
?latitude=57.62987&longitude=39.87368
&current=temperature_2m,apparent_temperature,relative_humidity_2m,weather_code,wind_speed_10m,wind_direction_10m,is_day
&daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max
&wind_speed_unit=ms&timezone=auto&forecast_days=7
```
Ответ (сокращён):
```json
{"timezone":"Europe/Moscow","utc_offset_seconds":10800,
 "current":{"time":"2026-10-22T15:00","interval":900,"temperature_2m":10.7,"apparent_temperature":7.3,
   "relative_humidity_2m":43,"weather_code":1,"wind_speed_10m":2.1,"wind_direction_10m":115,"is_day":1},
 "daily":{"time":["2026-10-22",…,"2026-10-28"],"weather_code":[3,61,3,3,2,3,3],
   "temperature_2m_max":[10.8,7.3,11.4,11.9,10.3,8.9,8.7],"temperature_2m_min":[-1.8,2.6,3.2,1.5,0.2,-0.3,-1.3],
   "precipitation_probability_max":[0,88,2,0,8,33,5]}}
```
Соответствие макету: «Сейчас · ЧЧ:ММ» ← `current.time`; температура ← `temperature_2m`; «Ощущается» ← `apparent_temperature`; «Ветер N м/с, румб» ← `wind_speed_10m` + `wind_direction_10m` (откуда дует, 8 румбов С/СВ/В/ЮВ/Ю/ЮЗ/З/СЗ, `round(deg/45)%8`); «Влажность» ← `relative_humidity_2m`; состояние и сцена ← `weather_code` (WMO) + `is_day`; «Днём/ночью» ← `daily.max[0]/min[0]`; неделя ← `daily.*`, процент осадков ← `precipitation_probability_max`. Плитки «осадки (мм)» в макете нет — `precipitation`/`precipitation_sum` не запрашиваем (макет — источник правды).

WMO → шесть сцен: 0–1 ясно · 2–3 облачно · 45, 48 туман · 51–67, 80–82 дождь · 71–77, 85–86 снег · 95–99 гроза; ночной вариант — `is_day = 0`. Подписи по кодам («Небольшой дождь» и т. п.) — таблица в панели.

**Пакетный прогноз для списка городов** (температура справа в строке): координаты через запятую — один вызов на весь список, ответ — массив:
`?latitude=57.62987,58.58259&longitude=39.87368,50.53756&current=temperature_2m,weather_code&timezone=auto` → `[{"timezone":"Europe/Moscow","current":{…}}, {"timezone":"Europe/Kirov",…}]`.

**Геокодинг** — `GET https://geocoding-api.open-meteo.com/v1/search?name=<encodeURIComponent>&count=10&language=ru&format=json`
```json
{"results":[{"id":468902,"name":"Ярославль","latitude":57.62987,"longitude":39.87368,
  "timezone":"Europe/Moscow","population":608722,"country":"Россия","admin1":"Ярославская Область"},
 {"id":468891,"name":"Ярославль","latitude":58.58259,"longitude":50.53756,"timezone":"Europe/Kirov",
  "country":"Россия","admin1":"Кировская Область"}]}
```
Координаты = `latitude`/`longitude` выбранной строки, больше ничего не нужно.

**Грабли, которые обязан учесть исполнитель (все проверены):**
- Пусто → ключа `results` нет вовсе (`{"generationtime_ms":0.15}`), а не пустой массив.
- 1 символ → пусто; 2 символа → точное совпадение («Яр» даёт сёла «Яр»); с 3 символов — нечёткий поиск, мусорный: «Ярс» Ярославль не находит, «Ярц» ставит Ярцево Смоленское третьим. Решение: поиск с 2 символов, дебаунс 400 мс, `count=10`, сортировка по `population` (без населения — в конец), показываем до 6. Латиница работает («Yaroslavl» → тот же Ярославль).
- Кириллица в URL только закодированная (`URLSearchParams`/`encodeURIComponent`): сырой UTF-8 nginx Open-Meteo отбивает 403.
- `admin1` приходит как «Ярославская Область» — в подписи «Область» → «обл.», как в макете.
- Ошибка API — HTTP 400 с телом `{"error":true,"reason":"…"}`. **Прокси отдаёт её как успех** `net.fetch` (`{status:400, headers, body}`): панель обязана смотреть `status`, а не только `catch`.

**Часовой пояс и язык (запрос идёт с сервера).** Сервер и его часы в ответе не участвуют: Open-Meteo без состояния, всё задают параметры. `timezone=auto` → Open-Meteo сам берёт пояс по координатам города; проверено: в 12:07 UTC Ярославль отдаёт `current.time = 15:00`, Сидней — `23:00`, `daily.time` — даты города. `Accept-Language` прокси не пропускает (нет в белом списке) — язык задаёт только `language=ru` у геокодинга; в прогнозе текста нет, подписи наши. Правило для панели: **строки времени из ответа никогда не превращать в `Date` в поясе браузера.** «2026-10-22» разбирать руками, день недели — `new Date(Date.UTC(y, m-1, d)).getUTCDay()`; «Сегодня» = `daily.time[0]` (сегодня города, не браузера); «Сейчас · 15:00» = `current.time.slice(11,16)`; «обновлено в» — время запроса в поясе города: `Date.now() + utc_offset_seconds*1000`, читать `getUTCHours/Minutes`. Часы на экране одни — города.

**Лимиты, в которые укладываемся:** прокси — 30 вызовов в минуту на плагин, таймаут 10 с, 1 МиБ. Главный экран = 1 вызов, поиск = 2 (геокодинг + пакетный прогноз), «Обновить» = 1. Open-Meteo бесплатно — до 10 000 в сутки, **только некоммерческое использование**, атрибуция CC BY 4.0 (подвал «Данные: Open-Meteo» её закрывает). Для тестового плагина годится; если плагин пойдёт заказчику в коммерцию — нужен платный тариф, это риск, не задача v1.

**Замена не нужна.** Nominatim (OSM) требует свой `User-Agent`, а прокси такой заголовок не пропускает; остальные бесплатные сервисы требуют ключ.

**Что будет без права** (по коду `PluginBridge` + `PluginNetProxy`):
- выдано одно из двух `net:` — вызов на второй хост → `denied` «Нет права: net:geocoding-api.open-meteo.com», хост рисует плашку с точным ключом;
- не выдано ни одного `net:` — на `master` мост называет хост из url вызова («Нет права: net:{host}»), если url нечитаем — «Нет права: net:» [сверено: `PluginBridge.DeniedError` на `master`]. Эмулятор воспроизводит это: хост из url, а при нечитаемом url — текст «Нет права на сетевые запросы» (формулировка эмулятора, не сервера) [сверено: `dev-host/index.html`]. Панели это безразлично: **бейдж с ключом права панель строит из своего URL, а не из `message`** [сверено: `renderProblem('denied')`, `FORECAST_HOST`].

### 2а. Право `storage` и запоминание города **[Андрей]**

- Манифест просит `storage` [сверено]. Операции хоста (по `docs/features/plugin-kit.md` на ветке `feat/plugin-storage`): `storage.get {key}` → `{exists, value}`, `storage.set {key, value}`, `storage.remove`, `storage.keys`; данные лежат в `localStorage` браузера человека, на сервер не уходят, на другом устройстве их нет [сверено по доке той ветки]. Панель использует только `get` и `set`, ключ `city` [сверено: `index.html`].
- В город кладётся **объект** `{name, lat, lon}`, сериализует хост; при чтении панель принимает и старую запись-строку (JSON внутри строки) [сверено: `readStoredCity`/`rememberCity`, коммит f3cb2fbb5].
- **Без права `storage` панель работает полностью, но город не запоминает**: `denied`/`unavailable` глотаются молча, без плашек и ошибок [сверено: `.catch(function () {})` в обоих вызовах]. Каждый запуск панели — Ярославль по умолчанию.
- **Подсказка в режиме выбора** — «Город запоминается в этом браузере.» — показывается только если право выдано (через `hasStorageRight()`), иначе подсказки нет **в рабочем дереве, не закоммичено** (правка по дизайн-приёмке, задача 6c56d3f8 inProgress). ⚠ В этом рабочем дереве функция `hasStorageRight` **нигде не определена** (в файле есть только вызов на строке ~350) — пока её не допишут, открытие поиска упадёт; это работа Киры/Полины, здесь не правится **[сверено grep'ом; проверить после их коммита]**.
- **Эмулятор операций `storage` не знает**: на `storage.*` он отвечает `unavailable` «Обработчик не зарегистрирован: storage», а `grant=` принимает только хосты `net:` [сверено: `dev-host/index.html`]. Значит запоминание в эмуляторе не проверить — только вживую на стенде с веткой `feat/plugin-storage` (D0-д / D1).
- Ветка `feat/plugin-storage` (задача aed2131b): в хосте и мосте операции `storage.*` есть, но **в `master` и в эту ветку ещё не влиты** [сверено: `git log master..feat/plugin-storage`, в `feat/weather-plugin` в `docs/features/plugin-kit.md` раздел `storage` ещё «в коде хоста пока нет»]. Порядок: **сначала мерж `feat/plugin-storage`, потом приёмка «Погоды»**, иначе валидатор манифеста на стенде отобьёт пакет с `unknown-permission` (запись командной памяти от Веры).

Всё, что нужно панели, уже есть: `net.fetch` с правом на точный хост, GET с query, ответ `{status, headers, body}`, лимиты с запасом, кит, токены тем, правило высоты. Хранилище нужно и делается отдельной фичей (`feat/plugin-storage`, §2а) **[Андрей]**; геолокацию не делаем. Что нашёл попутно — **не в объёме этой фичи**, на решение Софье:
