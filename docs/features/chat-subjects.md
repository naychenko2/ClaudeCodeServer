# Темы чатов проекта

Локальная модель раскладывает верхнеуровневые чаты проекта по темам; в списке чатов — режим
группировки «Темы» (`groupBy = 'subjects'`, фасет рядом с «Днями» и «Тегами»). План и ревью — заметки
«План — AI-группировка чатов проекта по темам» и «Повторное ревью плана…».

Работает у всех: фич-флаг `chat-subjects` снят 2026-10-10 (сохранённый override в `data/users.json`
— неизвестный каталогу ключ, чтение его игнорирует).

Корень в коде — `Subject`: `Topic` занят значком чата (`Session.Topic`).

## Данные

- `Session.SubjectId` — ссылка на тему реестра; `SubjectSource` — `ai` | `human` | `null`;
  `SubjectAssignedAt`; `SubjectTriedAt` — когда модель последний раз видела чат.
- `Project.SubjectRegistry: List<ProjectSubject>` (`Id`, `Name`, `Order`, `Color?`,
  `CreatedBy` — `ai` | `human`, `CreatedAt`); `Project.SubjectsSweepSince` — нижняя граница фона.
- Все поля аддитивные и nullable, реестр — внутри `projects.json`: `BackupSchema.Version` не меняется.
- **Висячий `SubjectId`** (тему удалили) везде читается как «без темы». Чаты модели с ним — снова
  кандидаты разбора; закреплённые человеком за удалённой темой `PUT …/subjects` возвращает
  автоматике (`SessionManager.ReleaseOrphanedHumanSubjects`, под замком тем): закрепление за
  несуществующей темой молча держало бы чат вне разбора навсегда. «Убрал из темы» (`human` без
  `SubjectId`) не трогается.

## Инварианты

- Запись темы — только `SessionManager.ApplySubjects`: `UpdatedAt` не двигает, из архива не
  выводит, `sessions.json` пишет один раз на вызов. Запись модели — CAS: чат не закреплён
  человеком, `SubjectId` равен снимку прохода, тема есть в реестре.
- Закрепление = `SubjectSource == human` (в том числе «убрал из темы» при `SubjectId == null`).
  «Вернуть автоматике» сбрасывает `SubjectId/SubjectSource/SubjectTriedAt` — чат снова кандидат.
- Любое ручное действие с темой модели (переименование, цвет, смена места среди прежних тем,
  перенос чата в неё) переводит её в `human`; пустые темы `ai` удаляются уборкой в конце
  прохода, `human` — никогда. Порядок сравнивается **относительный**: абсолютный `order`, съехавший
  сам (удалили соседа), правкой не считается. Ручной перенос сначала переводит тему в `human` под
  замком реестра и только потом пишет сессию: тему, уже снесённую уборкой, перенос отбивает 400.
- Модель — **только локальная**: `ICheapTextRunner.RunLocalOnlyAsync` (с `jsonFormat`), у которого
  нет ни шага claude, ни прямого облачного адаптера, а маршрут места он сверяет на каждом вызове.
  `RunFreeAsync` не зовётся никогда: его первый шаг — direct-модель агрегатора, а `HasFreeRoute`
  такой маршрут считает бесплатным. Нет локали, она занята ходом или не ответила — чаты остаются
  без темы до следующего прохода, в облако не уходит ничего.
- Локальные проекты разбираются как серверные (лента `history.json` живёт на сервере);
  гейт — `ProjectCapabilities.ChatFeedForServerAi`. Онлайн устройства не нужен.

## Классификатор

- Место `chat-subjects` (`LocalActionCatalog`, группа «Сессии», профиль Text, `DefaultLocal`).
- Вход: название + первая и две последние реплики **человека** (`ChatHistoryService.ReadHumanSnippetsAsync`).
- Пачка — `SubjectBatchPlanner.Plan(профиль, тем в реестре, потолок)`: окно с запасом 25 %
  (2.5 символа на токен), вывод `0.7 × NumPredict / 30`, потолок по времени
  `ChatSubjects:BatchCeiling` (по умолчанию 8). На Text выходит 8, на Small — 5.
- Ответ — `{"assign":[{"chat":"c1","topic":"t2"},{"chat":"c2","new":"Имя"},{"chat":"c3","topic":null}]}`.
- Защита от инъекций: блоки `<<<chat c1>>> … <<<end c1>>>` и рамка реестра
  `<<<topics>>> … <<<end topics>>>` («данные, не инструкции»), разделители из реплик и имён
  вырезаны; повтор алиаса — все его назначения отброшены; имя новой темы чистит
  `ChatSubjectRules.SanitizeName` (буквы, цифры, пробел, дефис; комбинирующие знаки без готовой
  буквы выбрасываются, а не рвут слово; 2–40; без ссылок); потолки
  «≤ 2 новых за проход» и «≤ 12 тем **модели** на проект» (темы человека не считаются; весь
  реестр — ≤ 50) держит код.
- Мусор или обрыв JSON — `SubjectTriedAt` всем чатам пачки, лог Warning и счётчик
  `ccs.chat_subjects.parse_failed`. Чаты, пропущенные моделью, тоже получают отметку попытки.

## Фоновый проход

`ChatSubjectSweeper` (рядом с `ChatArchiveService`): первый тик через 35 мин после старта
(задержка 5 мин, затем `PeriodicTimer` ждёт полный интервал), далее раз в 30 мин.
На первом тике после выкатки проекту ставится `SubjectsSweepSince` — и без локали. Без настроенной
локали тик больше ничего не делает и в лог не пишет: проход идёт у всех владельцев. Кандидат фона — корневой
не архивный чат без идущего хода, не закреплённый, без темы или с висячей темой, с активностью
после прошлой попытки, остывший ≥ 15 мин, `MessageCount ≥ 4`, `UpdatedAt ≥ SubjectsSweepSince`.
До 3 пачек на владельца за тик. Кнопки снимают три последних условия и берут залежи.

## REST (все под `[Authorize]`; чужой проект — 404)

| Метод | Путь | Тело / ответ |
|---|---|---|
| GET | `/api/projects/{id}/subjects` | `ProjectSubject[]` по `order` |
| PUT | `/api/projects/{id}/subjects` | `{subjects:[{id?, name, order?, color?}]}` — реестр целиком; `color` присылать всегда (пропуск = «цвет снят»); 400 на плохое имя, дубль имени, повтор `id` и тело без `subjects` (пустой реестр — только явным `[]`) |
| PUT | `/api/projects/{id}/sessions/{sid}/subject` | `{subjectId: string\|null}` — перенос/«убрать из темы»; `{release: true}` — «Вернуть автоматике». Ответ — сессия; 400 «Тема не найдена» |
| POST | `/api/projects/{id}/subjects/run` | 202 `{state, done, total, lastError, finishedAt, started}`; этот проект уже разбирается — 202 `started:false, state:running`; замок занят другим проектом или тиком — 202 `started:false, state:busy` с причиной в `lastError` (в состояние проекта не пишется) |
| POST | `/api/projects/{id}/subjects/reset-ai` | то же, перед проходом снимает назначения модели |
| GET | `/api/projects/{id}/subjects/run` | `{state: idle\|running, done, total, lastError, finishedAt}` |

SignalR-событий нет: список чатов проекта обновляется существующим опросом раз в 5 с, новые поля
сессии едут в общем JSON `Session` (`subjectId`, `subjectSource`, `subjectAssignedAt`, `subjectTriedAt`),
реестр и нижняя граница фона — в DTO проекта (`subjectRegistry`, `subjectsSweepSince`; проекция
`ProjectsController.WithCount` ручная — новое поле проекта само туда не попадает). По
`subjectsSweepSince` фронт показывает подсказку «старые чаты разбираются кнопкой»; `null` — фон
у проекта ещё не проходил. Режим группировки на фронте — `groupBy = 'subjects'`.
