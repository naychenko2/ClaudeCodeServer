# Шаблон задачи исполнителя

> Источник истины структуры — `TeamImplementPrompts.SubtaskDescription`
> ([backend/ClaudeHomeServer/Services/Team/TeamImplementPrompts.cs](../../backend/ClaudeHomeServer/Services/Team/TeamImplementPrompts.cs));
> этот документ — её человекочитаемый контракт. Любое изменение разделов задачи
> правится в обоих местах.

Шаблон применяется ко всем задачам исполнителей, которые координатор создаёт в режиме
«Командная реализация» (`docs/architecture/team-implement-mode.md`, раздел «Э3. Раздача и волны»).

## Структура описания

Описание задачи собирается в порядке:

1. **Что сделать** — формулировка цели под-задачи (поле `Goal` плана; фолбэк — `Title`).
2. **Рабочее дерево** — присутствует только когда штаб работает в worktree; содержит
   путь и ветку, и предостережение «не правь основной репозиторий».
3. **Файлы во владении** — список из плана; если пуст, исполнитель определяет сам
   и не выходит за границу своей части.
4. **Критерий готовности** — формулировка из плана; фолбэк — «сделано и проверено
   фактическим прогоном (сборка/тесты), результат приложен к задаче».
5. **Тестирование** — правила прогона тестов и агентских сборок (этот блок — шаг 5.3
   фичи «Модульные тесты: отвязать от монолита и разнести по вертикалям»).
6. **Сверка числа тестов** — как и через что сверять, чтобы не потерять тест за дублем.
7. **Контекст** — краткое описание плана и номер волны.

## Тестирование

> Блок обязателен для задач, которые правят код с тестами. Координатор не редактирует
> его от случая к случаю: текст общий, изменения — только в `SubtaskDescription`.

На итерации запускай **только** затронутые тест-проекты.
Определить их: `bash scripts/tests-affected.sh` (по `git diff` + графу `ProjectReference`,
включая транзитивное замыкание).
Полный прогон `dotnet test backend/ClaudeHomeServer.slnx` — только перед мержем в master.
Агентские сборки: `dotnet build -v q -clp:ErrorsOnly` (минимум шума, максимум сигнала).

## Сверка числа тестов

Сверять число тестов через **trx-сводку** прогона
(`--logger "trx;LogFileName=…"`, читать `TotalCount`/`Executed`/`Passed`/`Failed`/`Inconclusive`),
не через stdout `--list-tests` (stdout теряет строки при параллельном выводе testhost).
Эталон baseline-файла: `docs/research/tests-by-module-baseline-tests.txt` (15203 FQN,
см. [tests-by-module-baseline-2026-10.md](../research/tests-by-module-baseline-2026-10.md)).
Совпадать должны **сумма И набор** имён (diff по сортированному списку) — иначе потеря
одного теста маскируется дублем другого. После шага фичи эталон не переписывается.
