# UX-ревью описаний инструментов в ToolCatalog

## Контекст
Четыре инструмента (git, kb, personas-manage, personas-automation) получили новые Key-привязки после разреза MCP-инструментов по ролям. Их описания в ToolCatalog ([PersonaBindingsService.cs](../backend/ClaudeHomeServer/Services/PersonaBindingsService.cs)) находятся в файле и отображаются в редакторе персоны при добавлении Tool-привязок.

**Задача**: убедиться, что описания понятны пользователям, которые не разработчики.

## Текущие формулировки и проблемы

### 1. `git` — Git проектов
**Текущее:**  
> Секция git workspace (mcp__wsp__git_*): статус, diff, история, blame, stage/commit. Надстройка над секцией files

**Проблемы:**
- `mcp__wsp__git_*` — технический шум для пользователя
- `diff`, `blame` — git-жаргон, неопытный пользователь не поймёт
- `stage/commit` — предполагает знание git
- Слово «надстройка» создаёт ненужный вопрос «что это значит?»

**Рекомендуемо:**  
> **История и управление проектами**: просмотр изменений в файлах (кто, когда, что менялось), сохранение ключевых точек в коде через коммиты

**Почему лучше:**
- Говорит о пользе, а не о деталях реализации
- Использует простые слова: «кто, когда, что менялось» вместо `blame`
- Не пугает незнакомым концептом git
- Подчёркивает два главных действия: просмотр и сохранение версий

---

### 2. `kb` — Базы знаний владельца
**Текущее:**  
> Секция knowledge_bases workspace (mcp__wsp__kb_*): датасеты Dify владельца — список, поиск, добавление документа. Надстройка над секцией knowledge

**Проблемы:**
- `mcp__wsp__kb_*` — технический шум
- `датасеты Dify` — Dify может быть неизвестен 90% пользователей
- Что такое «надстройка»? Непонятно
- Слишком фокусируется на технической реализации

**Рекомендуемо:**  
> **Личные базы знаний**: управление документами, которые ваша персона может искать при ответах (загрузка, поиск, удаление документов)

**Почему лучше:**
- Начинается с цели: «личные базы знаний»
- Говорит о конкретных действиях: загрузка, поиск, удаление
- Не упоминает внутренние названия сервисов (Dify)
- Связывает инструмент с его практическим применением

---

### 3. `personas-manage` — Управление персонами
**Текущее:**  
> Модуль manage сервера персон: personas_create/update/delete/bindings_set/generate_avatar/ai_team

**Проблемы:**
- Список функций выглядит как устрашающее меню
- `bindings_set`, `ai_team` — новые для пользователя слова
- Техническое название «сервер персон»
- Нет понимания, **зачем** это нужно персоне

**Рекомендуемо:**  
> **CRUD персон**: создание, редактирование, удаление персон команды, привязка им источников знаний, генерация аватаров, и режим «команда для задачи»

**Альтернатива (покороче):**  
> **Создание и редактирование персон**: полный контроль над командой — их описаниями, знаниями, внешностью и правилами

**Почему лучше:**
- Использует понятный язык вместо `personas_create/update/delete`
- Объясняет, что именно можно делать (не просто список функций)
- Вторая версия более доступна для новичков

---

### 4. `personas-automation` — Правила проактивности
**Текущее:**  
> Модуль automation сервера персон: personas_automation_* — триггеры, по которым персона пишет сама

**Проблемы:**
- Фраза «Правила проактивности» звучит странно и неинтуитивно
- Пользователь не сразу поймёт, что это означает
- `personas_automation_*` — технический шум

**Рекомендуемо:**  
> **Автоматизация персон**: настройка триггеров (по времени, событиям, упоминаниям), при которых персона автоматически пишет в нужный чат

**Почему лучше:**
- Ясная цель: автоматизация
- Приводит примеры триггеров, которые поймёт пользователь
- Объясняет результат: персона пишет сама
- Использует слово «триггеры», но объясняет, что это значит

## Резюме

| Инструмент | Текущее состояние | Улучшение |
|---|---|---|
| `git` | Технически правильно, но непонятно | Переориентировать на пользу: просмотр истории и сохранение версий кода |
| `kb` | Упоминает неизвестный сервис | Убрать `Dify`, сосредоточиться на действиях (загрузка, поиск документов) |
| `personas-manage` | Список функций выглядит устрашающе | Переформулировать с акцентом на результат (контроль над командой) |
| `personas-automation` | Странная формулировка | Переименовать и переформулировать с примерами триггеров |
