# Оптимизация промпта постановки задач: замер до/после

**Дата:** 2026-08-09
**План:** `.omc/plans/task-execution-token-optimization.md`
**Метод:** фикстурный бенч (`PromptBenchTests`), 6 замороженных кейсов
**Единица:** символы (точная величина; `TotalTokensEst` = chars/4 занижает на кириллице
и годится только для порядка величины)

## Итог

| | Символов | Доля |
|---|---:|---:|
| Baseline (до) | 20 853 | 100% |
| После оптимизации | 10 663 | 51,1% |
| **Экономия** | **10 190** | **48,9%** |

**Цель плана была 50% — не достигнута на 1,1 пункта.** Остаток упирается в секцию
ПРАВИЛА: верификационная дисциплина держится на дословных формулировках, и резать её
ради процента означает менять поведение исполнителя. Порог теста поставлен на 48% —
он сторожит регрессию (промпт не должен разрастись обратно), а не рисует достижение цели.

## Что сделано

| Правка | Экономия | Обоснование |
|---|---:|---|
| Убрана таблица категорий OmO из промпта | ~1 562 на промпт с персоной | Дублировала шапку файла-справочника `.claude/delegation-categories.md`, ссылка на который стоит рядом. 45% размера промпта кейса 02 |
| ОЖИДАЕМЫЙ РЕЗУЛЬТАТ + ИНСТРУМЕНТЫ + ОБЯЗАТЕЛЬНО + НЕЛЬЗЯ → ПРАВИЛА | ~400 на промпт | Четыре секции говорили об одном (`tasks_complete` с итогом и файлами) тремя формулировками. Содержание правил сохранено дословно |
| Таблица уровней → строка | ~250 | Пояснения «когда какой уровень» есть в справочнике; в промпте остались только алиасы владельца, которые больше неоткуда взять |
| id подзадач только у невыполненных | ~40 на фикстурах | `tasks_toggle_subtask` по отмеченной подзадаче звать незачем. На задачах с длинными списками выполненных даст больше |
| Короткий формат: 4 правила → 3 | ~40 | Убран повтор про `tasks_complete` |
| Доклад Model Z: потолок 400 символов | зависит от итога | Полный `resultMarkdown` лежит в задаче и читается `tasks_get`; копия в ленте оплачивается на каждом последующем ходу чата постановщика |
| `topK` заметок 5 → 2 | **бенчем не измеряется** | Фикстура заморожена в состоянии «3 заметки». Эффект виден только на живых данных |

## Что НЕ тронуто (сознательно)

- **Верификационная дисциплина** — «НЕТ СВИДЕТЕЛЬСТВ = НЕ ГОТОВО», проверка делегированной
  работы, правило остановки после первой верификации, границы задачи. Под тестом-сторожем
  `BuildPrompt_СПерсоной_ВерификационнаяДисциплинаСохранена`
- **Структура короткого формата** — постановка без персоны осталась плоским блоком
  «Правила:» и не превратилась в секционный контракт
- **Ходы исполнения** — основная масса токенов цикла, но это работа Claude, а не постановка

## Оговорки к цифрам

1. **Живая экономия выше замеренной.** `topK` 5→2 режет блок заметок, который на реальных
   задачах бывает крупнее фикстурного. Бенч этого не показывает.
2. **Проценты — по символам, не по токенам.** Абсолютные токены надо смотреть в `SpendStore`
   (реальный `usage` провайдера), а не по оценке `chars/4`.
3. **Знаменатель — постановка + доклад.** Ходы исполнения в него не входят: их мы не
   оптимизировали, и включение сделало бы цифру нечестной.
4. **Постановка перечитывается каждый ход** как input/cache-read, поэтому экономия
   умножается на число ходов задачи.

## Воспроизведение

```powershell
cd backend
dotnet test ClaudeHomeServer.Tests/ClaudeHomeServer.Tests.csproj --filter "FullyQualifiedName~PromptBenchTests"
```

- `prompt-baseline.json` — состояние «до», снят до правок, перезаписывать нельзя
- `Показать_Разбивку` — снять `Skip`, чтобы увидеть таблицу по секциям
- `Заморозить_Baseline` — снимает baseline заново; запускать только при осознанной смене
  набора фикстур (тогда прежнее сравнение теряет силу)
