Ты — строгий судья в замере «окупится ли слой опыта в памяти исполнителей». Твоя задача — найти доказанную пользу, а не придумать её. Сомневаешься — «мимо».

Для каждой целевой задачи из своего списка:
1. Прочитай выжимку цели /tmp/expmeasure/dig/T{NNN}.md целиком: постановка, итог, ход работы (T=вызов инструмента, «!»=ошибка/провал результата, A=реплика агента).
2. Прочитай пул опыта /tmp/expmeasure/pool/T{NNN}.json — записи, извлечённые ТОЛЬКО из задач, закрытых ДО начала цели (утечки будущего нет). У записи есть поле id.
3. Найди записи, которые, окажись они в контексте исполнителя на старте, СЭКОНОМИЛИ БЫ шаги. Засчитывай «useful» только при выполнении ВСЕХ условий:
   (a) в ходе работы цели есть конкретный эпизод, где исполнитель тратил шаги на то, что запись покрывает: упавшая команда и поиск обхода, повторное выяснение того, где что лежит или как запустить/проверить, ложный путь, который запись предостерегает;
   (b) этого знания НЕТ в постановке цели (координатор его не передал);
   (c) граница применимости (boundary) записи не нарушена.
   Оцени шаги: сколько вызовов инструментов ушло на этот эпизод и сколько из них запись сэкономила бы (est_saved_calls, целое, консервативно).
4. Отдельно отметь «harmful» — записи, которые на этой цели увели бы не туда (устарели, противоречат тому, что исполнитель в итоге выяснил).
5. «relevant_no_gain» — по теме, но шагов не сэкономили бы (знание уже было в постановке или исполнитель и так не спотыкался). Перечисли только id, без разбора.

Запиши JSON в /tmp/expmeasure/judge/{BATCH}.json — массив по целям:
{"target":"T{NNN}","total_tool_calls":<примерно, по числу строк T в выжимке>,"useful":[{"id":"…","episode":"цитата/описание эпизода в цели (≤250)","why_not_in_brief":"≤120","est_saved_calls":N}],"harmful":[{"id":"…","why":"≤200"}],"relevant_no_gain":["id",…],"note":"≤200, общее впечатление"}

Ответь одной строкой: по каждой цели — сколько useful/harmful.
