# Уборка карты проекта: инвентаризация `CLAUDE.md` по трём корзинам

Разведка, 22.09.2026. Шаг 1 из двух: **файл не правится**, результат — таблица решений,
которую можно проверить глазами до того, как что-то потеряно. Правка идёт отдельной задачей,
по одной секции на коммит.

Исходное состояние: **1001 строка / 103 КБ** — около 34 000 токенов в КАЖДОЙ сессии при
ориентире Anthropic в 200 строк.

**200 строк честно не получается, и гнаться за цифрой не надо.** Из 282 остающихся строк
около 120 — поимённые инварианты и грабли (раздел «Инварианты»), которые по коду не
восстанавливаются; ещё около 60 — секции, УЖЕ стоящие в целевом формате «фраза + ссылка»
(Видео, Десктопный агент, Выкатка, Observability) и шесть блоков ссылок «перед правками
прочитай». Резать их — терять знание ради круглого числа.

Из −719 строк:
- **~350 снимаются сразу**, без единой правки документов (доказанный пересказ + дубли внутри карты);
- **~370 — только после дописываний** в целевые документы (раздел «Блокеры»): сегодня это
  знание живёт ТОЛЬКО в карте, вынести его сейчас = потерять.

## Метод

Карта пройдена сверху вниз, по каждому смысловому абзацу отвечали на один вопрос: **«если это
убрать, сломается ли чья-то работа так, что по коду не восстановишь?»** Три корзины:

1. **ИНВАРИАНТ / ГРАБЛЯ** — остаётся в карте, сжатое до 1–2 фраз.
2. **ПЕРЕСКАЗ ДОКУМЕНТА** — выносится, остаётся ссылка. Вердикт ставился **только с
   доказательством**: файл + номер строки + цитата из целевого документа. Наличия ссылки рядом
   с абзацем недостаточно.
3. **ИСТОРИЯ И ОБОСНОВАНИЕ** — замеры, метрики, номера коммитов, «почему решили так»,
   опорные точки динамики. Переезжает в `docs/`, в карте не нужно вовсе.

Участков шесть, каждый сверялся со своим набором целевых документов; выводы по критичным
местам перепроверены отдельно (мёртвые ссылки, состав фич-флагов, актуальность формулировок).

## Инварианты, обязанные пережить уборку

**Это главный артефакт задачи.** По этому списку проверяется результат шага 2: каждый пункт
обязан присутствовать в убранной карте — в одной-двух фразах, но присутствовать. Пункт,
исчезнувший из карты и не появившийся в документе, — дефект уборки.

### Запуск и среда

- **И-1.** Хостовый дев-стенд — только `dotnet run` / явный `ASPNETCORE_ENVIRONMENT=Development`:
  иначе `Kestrel:Endpoints` уводит на занятый боевым :80, и `ASPNETCORE_URLS` это не чинит.
- **И-2.** Сборка и прогон по умолчанию — в dev-контейнере, не на хосте.
- **И-3.** Стенд :5000 раздаёт `frontend/dist` ПОСЛЕДНЕЙ сборки; `wwwroot` в репозитории не живёт.
- **И-4.** Смена `ExecutionEnvironment` при существующих чатах запрещена.
- **И-5.** Токен подписки доставляется в песочницу per-exec, а не запекается при создании контейнера.
- **И-6.** Бэкенд работает ТОЛЬКО с хостовыми путями; в контейнерные их переводит `IPathMapper`
  в момент запуска.
- **И-7.** Главная защита от OOM — потолок cgroup на `ccs-agents.slice` (наследуется всему
  поддереву scope, включая сборки из Bash агента); `BuildConcurrencyGate` — дополнение, а не замена.
- **И-8.** **`MemoryHigh` не ставим ни на slice, ни per-scope**: под systemd-oomd дроссель сам
  становится источником PSI-сигнала для убийцы.
- **И-9.** Счётчик `BuildConcurrencyGate` — единственный на процесс; второй семафор где-то ещё
  делает потолок неправдой.

### Дизайн

- **И-10.** Сырой hex/rgb в `.tsx` — дефект; цвета только токенами `C.*`, новый цвет — в ОБЕ темы.
- **И-11.** `npm run lint:design` обязан быть зелёным ПЕРЕД коммитом (не после каждой правки).
- **И-12.** Контролы — только из `components/ui/`; самодельная кнопка/модалка из div — дефект.

### LLM и ходы

- **И-13.** Профили CLI `data/claude-profiles/{key}` изолируют OAuth-логин `~/.claude` — иначе
  CLI пошлёт чужому эндпоинту токен подписки (401); креденшалы в профили не копируются никогда.
- **И-14.** На КАЖДОМ запуске CLI чистятся унаследованные `ANTHROPIC_*` / `CLAUDE_CONFIG_DIR`;
  `CLAUDE_CODE_OAUTH_TOKEN` не трогается.
- **И-15.** BareMode гасит автозагрузку CLAUDE.md недокументированной env
  `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` (не флагом CLI): обновление CLI может убрать её молча —
  сторож первого хода в `ClaudeSession`.
- **И-16.** У container-владельцев пара «bind-mount `SystemPrompts` ↔ правило `DockerPathMapper`»
  обязана быть синхронной: расхождение рантайм не ловит, оно даёт exit=1 и ложный `Unreachable`
  у каждого container-владельца при зелёных тестах.
- **И-17.** Нестабильные секции промпта (recall, досье, привязки персоны, граф кода) едут
  хвостом хода, а не системным блоком (`RecallInTurnText`) — иначе рвётся prefix cache.
- **И-18.** Слот → модель разворачивает только `UserModelTierResolver.ModelFor(tier, ownerId)`;
  дублировать её логику нельзя.
- **И-19.** Фолбэк — только по цепочке, автоподбора нет; неопознанная ошибка (`None`) фолбэк не
  запускает, но ход обязан завершиться `error`, а не штатным finished.
- **И-20.** Классификатор ошибок смотрит в СЫРОЙ текст: по русской формулировке 429/529 не
  распознаются.

### MCP

- **И-21.** **Состав `tools/list` не зависит от ХОДА** (от свойств сессии — может): он входит в
  сигнатуру запуска CLI, любая зависимость от свойства хода перезапускает процесс со ВСЕМИ
  MCP-серверами («Stream closed», «No such tool available»). Сторож — `McpToolsetStabilityTests`.
- **И-22.** Транспорт только `http` на адресе из `ResolveTasksApiUrl`: по https CLI молча теряет
  инструмент. `NO_PROXY` ставится на каждый ход; заголовки контекста шлёт КЛИЕНТ.
- **И-23.** Не плодить однокоренные имена инструментов с пересекающейся семантикой
  (`execute` vs `complete` — LLM путает).
- **И-24.** Личный реестр — allow-list, единственная модель: сервер едет, только если включён в
  проекте чата ИЛИ выдан персоне (вне проекта — `AllowOutsideProjects`).
- **И-25.** Ссылка на каталог хранится как `McpCatalogRef`, а НЕ как новое значение enum `Source`:
  откат кода унёс бы `mcp-servers.json` всех владельцев в `.corrupt`.
- **И-26.** Allow-list рантайм-флагов uvx ПУСТ: `--from`/`--with`/`--index*` подменяют источник пакета.

### Данные и владение

- **И-27.** Ключ Dify общий на инстанс, поэтому единственная граница между владельцами —
  проверка релевантности датасета на КАЖДОМ `{id}`-эндпоинте (иначе 403).
- **И-28.** Контуры Dev/Prod на одном Dify разводит `Dify:Namespace` — без него дев-стенд лезет
  в боевые датасеты.
- **И-29.** У задач `PersonaId != null ⇒ Assignee = Claude`.
- **И-30.** Доступы персоны: `Persona.Access` → `PersonaAccessPolicy` (disallowed-инструменты),
  `Persona.Tools` гейтит tasks/notes/web.
- **И-31.** **Удаление чата уносит транскрипт CLI: только файл с точным именем `{csid}.jsonl`,
  никогда по маске и никогда сама папка** — один `~/.claude` делят все инстансы плюс
  интерактивные сессии пользователя.
- **И-32.** `resumeSessionId` валидируется белым списком `^[A-Za-z0-9_-]{1,128}$` — иначе `".."`
  снёс бы всю папку `data`.
- **И-33.** `UpdatedAt` не двигают ни настройки чата, ни архивация/возврат; признак архива
  производный (`IsArchived = ArchivedAt != null && UpdatedAt <= ArchivedAt`).
- **И-34.** Новое хранилище → сверься с бэкапом: секреты в `BackupPaths.SecretFileNames`, сторы
  вне `data/` — в `BackupCore.CopyDataTo`, ломающее изменение формата = инкремент `BackupSchema.Version`.
- **И-35.** Одна папка — один проект на владельца (датасет Dify ключуется по `RootPath`).
- **И-36.** Path traversal — через `SafePath.Join`; из вертикали звать Core-примитив напрямую
  (обращение через `FileService` — ссылка на чужую вертикаль, сторож границ её ловит).
- **И-37.** Разбор ```-заборов — единственный примитив `MarkdownFence`; новый построчный разбор
  markdown обязан звать его.
- **И-38.** HTTP-клиент к опциональной зависимости — через `AddQuietHttpClient`.

### Границы подсистем

- **И-39.** Вертикаль зависит от спины и явных швов, но НИКОГДА от другой вертикали напрямую;
  связь — событие `TurnEventBus` либо интерфейс-шов.
- **И-40.** Реестр, который наполняют разные слои, а читает REST-гейт, кладётся в спину, а не
  внутрь питающей вертикали.
- **И-41.** **Дубль записи в `Boundaries` не ловит ни один сторож** (`ToHashSet()` по
  `NamespaceRoot` схлопывает вторую запись): видно только по расхождению числа тестов.
- **И-42.** Статические конструкторы сторожей форсят загрузку всех вертикальных сборок — иначе
  порядок тестов ложно рушит сторож при изолированном прогоне; в `IlBoundaryRegressionTests`
  конструктора нет намеренно, там защита — fail-closed ассерт «тип не найден».
- **И-43.** Единственная точка сбора типов — `BoundaryIlScanner.CollectAllReferencedTypes`; её
  подмена роняет только `IlBoundaryRegressionTests`.
- **И-44.** Чего сторож не видит: IL-ассемблер/`Reflection.Emit`, `Type.GetType(string)` и
  рефлексия, рантайм-резолвы по атрибутам.
- **И-45.** Объём выноса мерить заглушками до сходимости, а не одной пробной сборкой (Roslyn
  встаёт на фазе объявлений); скрытое чаще оказывается спиной, а она лечится переносом в Core с
  сохранением namespace, а не швом.
- **И-46.** Обязательный параметр конструктора от отключаемой вертикали вне её самой — дефект;
  легальных форм три (`?.`/`?? []`, ранний выход по `is null`, честный отказ 502/503).
- **И-47.** Гейт отключаемости ставится НА РЕГИСТРАЦИЮ: пост-хок удаление дескрипторов не видит
  регистрацию через `ImplementationFactory`.
- **И-48.** `ApplicationPart` вертикали под `Microsoft.NET.Sdk.Web` подключается MSBuild сам —
  изоляция маршрутов делается только УДАЛЕНИЕМ части в `Program.cs`.
- **И-49.** У штаба (`Services/Team`) швов ровно четыре, новые не заводим.

### Продукт и поведение

- **И-50.** Голосовой формат держат ДВЕ точки промпта — секция `voice-mode` и оговорка
  последним блоком слоя персоны; одной мало.
- **И-51.** Маркер `<voice>` режется только ВНЕ блоков кода и остаётся в транскрипте (иначе
  `--resume` теряет пример формата, а ответ с маркером в примере обрывался бы на экране).
- **И-52.** В петле разговора распознавание и озвучка не пересекаются никогда (эхо).
- **И-53.** Коды `/api/tts` 503 `not_configured` / 502 `upstream` — контракт фолбэка на голос
  браузера, менять осознанно.
- **И-54.** Долгое ожидание — только `watch_start`: Monitor и `run_in_background` умирают вместе
  с процессом CLI.
- **И-55.** Вынос секции карты кнопкой не делается никогда (цена ошибки — потеря знания,
  оплаченного инцидентами); регулярной автоматики тоже нет.
- **И-56.** Значок проекта — имя иконки lucide из белого списка, не картинка; разметки от модели
  не приходит никогда.
- **И-57.** Явно выбранного провайдера картинок не подменяем; переход на другого — только в
  режиме «Автоматически».
- **И-58.** Полноценный чат через мессенджер не делаем (не отрендерит diff/артефакты/виджеты);
  Max для ботов закрыт.
- **И-59.** Питание машины: три независимых замка (роль admin, `PowerControl:Enabled`, платформа);
  **скрывать пункт в UI без серверной проверки нельзя** — веб-морда торчит наружу.
- **И-60.** Отсчёт до выключения ведёт сервер, а не `shutdown /t`.
- **И-61.** Все эндпоинты и хаб — под `[Authorize]`; новая ручка без него — дыра наружу.
- **И-62.** Машинно-специфичное не правим в отслеживаемых `appsettings*.json` — только в
  `appsettings.Local.json` (в `.gitignore`).
- **И-63.** Реестр фич-флагов — `FeatureFlagCatalog.All` в коде; ключ дублируется в C# и TS,
  при переименовании править оба.
- **И-64.** `.claude/agents/` в `.gitignore` (туда синкаются персоны владельца); версионируются
  только точечные `!`-исключения.
- **И-65.** Conventional Commits, сообщения по-русски, трейлер `Co-Authored-By` по вендору модели.
- **И-66.** `commit`/`push` — только по явной просьбе; исключение — цепочка задач в общем
  worktree (untracked-файлы не защищены ни reflog, ни `fsck`).
- **И-67.** Комментарии в коде по-русски.
