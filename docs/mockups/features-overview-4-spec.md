# Спецификация для Киры · волна 4 · 2А2 и 6А (Майя, 23.10)

Макет: [features-overview-4.html](features-overview-4.html) — точка 2 (`id="pt2"`, вариант «А2») и точка 6
(`id="pt6"`, вариант «6А»). Читать только эти две секции. Записка с решениями — [features-overview-4.md](features-overview-4.md).

Привязка: `featureId` ba38ba28-d8a6-489d-a23a-1d6f153456a2 (эпик волны 4). Шаги, которые пользуются
спецификацией: **W4-2F1, W4-2F2** (точка 2) и **W4-4F1, W4-4F2** (точка 6 на ступенях Ганта точки 4).
Задача спецификации — f08a8e20.

Общие правила, без исключений:

- Цвета — только `C.*`, размеры — шкалы `FS`, `SP`, `R`, `SHADOW`, `Z`. Сырых hex и `rgba` в `.tsx` нет.
- Контролы — из `components/ui/`: `Menu`/`MenuItem`, `Tooltip`, `Button`, `IconButton`. Своих кнопок из `div` нет;
  если элемент кликабельный — `button` или `role="button"` + `tabIndex={0}` + Enter/Space.
- Мобильная ширина — `useIsMobile()`. Цель касания на мобиле — не меньше 40×40 px (видимый элемент может быть
  меньше, тогда добирать невидимым полем).
- Фокус с клавиатуры — `SHADOW.focus` через `:focus-visible` (как у `ChatCard`/`Chip`).
- Тёмная тема получается сама: все токены — CSS-переменные. Проверять её глазами всё равно обязательно.

## Точка 2 · вариант А2 — меню на коде шага, узлы цепочки ведут в чаты витков

### Сценарий

«Открыл „Производство“ — вижу задачи в порядке старта; у каждой цепочка „работа → вернул → доработка → принят“.
Нужен чат конкретного витка — жму на узел. Нужны время старта или карточка задачи — жму на код „Ш3“».

Карточка — как в варианте А (W4-2F2), но **без нижней строки «старт · чат · задача»**: высота ~52 px вместо ~74.

### Код шага: меню «старт · чат · задача»

Код шага — триггер `Menu` (`components/ui/Menu.tsx`), `align="left"`, `minWidth` 230, тень и фон меню —
штатные (`SHADOW.dropdown`, `C.bgWhite`, рамка `C.border`, `R.lg`).

Пункты меню:

1. **старт** — не кнопка, строка-информация: подпись «старт» `C.textMuted` `FS.xs` (колонка 46 px) и время
   `FONT.mono` `FS.xs` `C.textPrimary` в формате `formatDateTime` из `FeatureStatsBits.ts`. Источник —
   задача `chain.taskIds[0]`: `claudeStartedAt ?? createdAt`. Нет обоих — строки нет.
2. **чат** — `MenuItem`, значок чата, текст «Чат {Имя} · {работа | доработка}». Источник — `chain.chatId`
   (чат исполнителя шага). `chatId === null` → пункта нет. Чат в архиве (`chatArchived` у исполнителя) →
   подпись `hint` «в архиве», переход всё равно работает.
3. **задача** — `MenuItem`, значок файла, «Карточка задачи {Ш3}» → карточка `chain.taskIds[0]`.

Если остаются только «старт» без переходов — меню всё равно открывается (информация полезна).

Состояния кода шага:

| Состояние | Вид |
|---|---|
| Покой | как в таблице выше |
| Наведение | рамка `C.accentMuted`, текст `C.textHeading` |
| Фокус с клавиатуры | `SHADOW.focus` |
| Нажатие / меню открыто | фон `C.bgSelected`, рамка `C.accentMuted`; `aria-expanded="true"` |
| Нет данных шага (Ш5 «не начат», чата и старта нет) | код — обычный текст без рамки, не кнопка |

Клавиатура: Enter/Space открывают, Esc и клик мимо закрывают (`handleMenuEscape`), фокус возвращается на код.
`aria-label` кода: «Шаг {Ш3}: старт, чат и задача». Подсказка `title` не нужна — её заменяет aria-label.

### Узлы цепочки — переходы в чат витка

Модель узлов строит W4-2F1 (`featureProdCards.ts`): у каждого узла добавить поле `chatId: string | null`.

| Узел | Куда ведёт |
|---|---|
| «работа» | `chatId` исполнителя задачи `chain.taskIds[0]` (= `chain.chatId`) |
| «доработка» N-я | `chatId` исполнителя задачи `chain.taskIds[N]` — берётся из `run.stages[prod].executors` по `taskId` |
| «{Имя}: вернул / принят» | `round.reviewChatId` соответствующего витка `chain.rounds` |
| Пунктирный «ревью» / «работа» впереди | никуда — не кнопка |

Узел с `chatId === null` — тоже не кнопка (выглядит как сейчас, без курсора-руки).

Токены узлов (размеры как у существующих узлов цепочки): `FS.xs`, высота строки 20, `R.max`, padding `SP.xxs SP.sm`.

| Вид узла | Фон | Текст | Рамка |
|---|---|---|---|
| Готово (`ok`) | `C.successBg` | `C.successText` | нет |
| Возврат (`ret`) | `C.warningBg` | `C.warningText` | нет |
| Текущий (`cur`) | `C.bgWhite` | `C.textHeading`, 600 | `1px C.accent` + `SHADOW.focus` |
| Впереди (`pend`) | прозрачный | `C.textMuted` | `1px dashed C.dashed` |
| Длительность в узле | — | `FONT.mono` `FS.xxs` `C.textMuted` | — |

Состояния узла-кнопки:

| Состояние | Вид |
|---|---|
| Покой | как выше + курсор-рука |
| Наведение | дополнительная обводка `0 0 0 1px C.accentMuted` (через `boxShadow`, размер не меняется) |
| Фокус | `SHADOW.focus` (у текущего узла он уже есть — тогда рамка `C.accent` 2 px вместо 1) |

`aria-label` узла: «Открыть чат витка: {подпись узла}». На десктопе — `Tooltip` «Открыть чат витка».

### Мобильная ширина (360)

- Название шага уходит на вторую строку шапки целиком (`flexBasis: 100%`), код шага остаётся первым.
- Код шага: `minWidth` и `minHeight` 40 (видимая рамка остаётся `R.sm`, содержимое по центру).
- Меню на мобиле — тот же `Menu`, пункты `MenuItem` с `isMobile` (40+ px), ширина не больше острова; если
  меню не влезает справа — `clampPopupLeft` уже сдвигает.
- Узлы цепочки переносятся (`flexWrap: wrap`, зазор `SP.xs`). Высоту узла на 360 НЕ раздувать до 40 —
  цепочка развалится; вместо этого невидимое поле касания: `::before`/обёртка с `minHeight` 40 по вертикали,
  отрицательными отступами, без смещения раскладки. Соседние узлы не перекрывают поле касания друг друга:
  по горизонтали поле = ширина узла.
- Tooltip на мобиле не показываем: смысл несёт aria-label и сам переход.
- Горизонтальной прокрутки у карточки нет никогда.

### Пустые и краевые состояния

| Случай | Поведение |
|---|---|
| `run.stepChains` пуст / нет | блок «Производство» показывает существующее пустое состояние, без карточек |
| Шаг «не начат» | одна пунктирная «работа», код — не кнопка, счётчика циклов нет |
| Старые данные без `rounds` | узлы возвратов не рисуются, только «работа» по статусу |
| Загрузка | существующий скелет вкладки, отдельного не нужно |
| Ошибка загрузки run | существующий `Notice` вкладки |

### Проверка (W4-2F2)

Тест: «клик по узлу возврата открывает `reviewChatId` этого витка»; «у шага без старта и чата код не кнопка».
Глазами: обе темы, 880 и 360, фокус с Tab проходит код → узлы по порядку.

## Точка 6 · вариант 6А — метки на ступенях Ганта

### Сценарий

«Зашёл на фичу и за 3 секунды понял: где она, не зависла ли, сколько было возвратов и где ушло время».
Ответы живут на ступенях Ганта точки 4 (W4-4F1 — модель, W4-4F2 — рендер). Отдельного блока анализа нет.

| Вопрос | Ответ на Ганте |
|---|---|
| Где сейчас | точка у имени этапа + пилюля «сейчас» над отметкой |
| Зависла ли | заштрихованный хвост ступени + пилюля краснеет + строка с действием под Гантом |
| Сколько возвратов | флажки ↺ на полосе в момент возврата + «↺ N» под минутами |
| Где ушло время | минуты справа, самый долгий этап — тоном предупреждения |

### Строка этапа

Сетка: `110px 1fr 84px`, зазор `SP.sm`, `minHeight` 28. На 360 — `86px 1fr 60px`, зазор 6 (`SP.xs` + `SP.xxs`),
`minHeight` 40.

| Элемент | Токены |
|---|---|
| Имя этапа | `FS.sm`, 600, `C.textHeading`, многоточие |
| Точка «сейчас» перед именем (только у этапа `run.now.stage`) | круг 7 px `C.accent` + `SHADOW.focus`; `title` «Фича сейчас здесь» |
| Дорожка | высота 16, сетка четвертей 1 px `C.borderLight`, `R.sm` / 4 |
| Полоса этапа | высота 12, отступ сверху 2, радиус 3; сегменты как сейчас: работа `C.accent`, ожидание `C.info`, простой `C.progressTrack`, ревью `C.plan`, ошибка `C.danger` (`kindBackground`) |
| Минуты справа | `FONT.mono` `FS.xs` `C.textSecondary`, выравнивание вправо |
| Самый долгий этап | минуты `C.warningText`, 700; `title` «Самый долгий этап» |
| Счётчик возвратов под минутами | «↺ N», `FS.xxs`, 700, `C.warningText`; только если N > 0 |
| Этап впереди (`state: pending`) | без полосы, имя и минуты с `opacity` 0.55, справа «впереди» |

«Самый долгий» — максимум `approxMinutes` среди этапов, у которых он больше 0; при равенстве — первый по порядку;
если этап один — не подсвечиваем.

| Часть | Токены |
|---|---|
| Круг | 18 px, `R.full`, фон `C.warningBg`, рамка `1.5px C.warning`, значок ↺ (lucide `rotate-ccw`) 10 px `C.warningText` |
| Положение | центр по `completedAt`, сверху −3 px от дорожки, `zIndex` 2 (над полосой, под пилюлей) |
| Поле касания | невидимое 40×40 вокруг круга на 360, 24×24 на десктопе |

Состояния флажка:

| Состояние | Вид |
|---|---|
| Покой | как выше |
| Наведение / фокус / касание | ореол `0 0 0 3px C.warningBg` + `Tooltip` |
| Tooltip | **«{Имя} вернул {Ш3}»** жирным `C.textHeading`, через « · » время `formatDateTime`; строкой ниже — причина `round.reason` в кавычках `C.textPrimary` `FS.sm`; ссылка «Чат ревью →» `C.accent` 600 → `round.reviewChatId` (нет чата — ссылки нет). Ширина 220, `R.lg`, `SHADOW.dropdown` |

### «Зависла» — штриховка «без движения»

Это не переключатель в продукте. Переключатель «движется / зависла» есть только в макете, чтобы показать оба
состояния. В продукте состояние выводится из данных.

Источник (нужен бэк, шаг W4-AN): порог «зависла» и момент последнего события текущего этапа. До поля бэка:
состояние «зависла» = `run.attention?.kind === 'stopped'`, начало хвоста — `attention.since`. `wait` (ждёт
человека) — НЕ «зависла»: это обычное ожидание, без штриховки. Когда бэк отдаст своё поле, меняется только
источник `since`, рендер тот же.

| Часть | Токены |
|---|---|
| Хвост | от `since` до «сейчас» на строке текущего этапа, высота 12, радиус `0 3px 3px 0`, косая штриховка 135° полосами 3 px `C.danger` / `C.dangerBg` (`repeating-linear-gradient` на токенах — сырых цветов нет) |
| `title` хвоста | «Без движения с {ЧЧ:ММ}» |
| Отметка и пилюля | `C.danger` вместо `C.accent`, текст пилюли `C.onAccent`; текст «стоит {длительность} · {причина коротко}», на 360 — «стоит {длительность}» |
| Строка под Гантом | `Badge tone="danger"` «стоит {длительность}» (это `C.dangerBg` / `C.dangerText`, `icon` — часы) + причина `FS.sm` `C.textPrimary` + `Button variant="primary" size="sm"` с действием (например, «Запустить ревью Ш4» или «Открыть чат») |
| Легенда | добавляется пункт «без движения» с образцом штриховки |

Действие строки — то же, что у существующей тревоги `attention` (не изобретать новое): переход в
`attention.linkedSessionId`. Нет чата — кнопки нет, только текст.
