# Ревью пачки A плагина «Погода» (каркас пакета + хост-эмулятор)

Дата: 2026-10-22. Ревьюер: Глеб (код-ревьюер). Предмет: коммиты `66f59af09` (A1, каркас
пакета) и `e4e294866` + `113b02a8a` (A2, хост-эмулятор + фикстуры).

## Вердикт одной строкой

**Возвращено исполнителю: два major.**

1. Пакет «Погода» **не проходит валидатор пакета** — каталог `fixtures/` внутри пакета
   вне allow-list (`not-allowed`), а валидатор — единственный арбитр установки.
2. Хост-эмулятор **уезжает в прод-сборку** (`frontend/public/**` → vite → `dist` →
   `wwwroot`) и доступен без авторизации; при этом он даёт панели credentialed-запрос
   с origin приложения — то есть обходит модель «выход наружу только через прокси хоста
   с правом и без секретов хоста».

Отклонение от плана по `name` подтверждено: правило `name == slug` каталога в валидаторе
реальное, `name: "Погода"` пакет бы отбил (`deny-name-not-equal-slug`). Исполнитель прав.

## Находки

### MAJOR-1. Пакет не валиден: `fixtures/` вне allow-list

`tools/plugins/weather/fixtures/*.json` (6 файлов, коммит `e4e294866`) лежат ВНУТРИ
каталога пакета. Allow-list пакета (`PluginPackageValidator.IsAllowed`) — только манифесты,
`skills/**`, `commands/*.md`, `panel/**`. Всё прочее → `not-allowed`.

Проверка (временный тест на `ValidateFull(root, "owner-test", "weather")` по
`tools/plugins/weather`, тест после проверки удалён):

```
Expected r.Problems ... to be empty ... but found at least one item
{"not-allowed: Файл не в allow-list пакета: fixtures/error-400.json"}
```

Тот же пакет без каталога `fixtures/` — 0 проблем; пакет с `name: "Погода"` —
`deny-name-not-equal-slug` (ожидаемо).

Сценарий поломки: человек ставит пакет «Погода» из папки → `PluginInstaller` отбивает
установку (`not-allowed`), пакет не появляется в списке плагинов; весь B1/B2/C1 упирается
в этот гейт.

Рекомендация: вынести фикстуры из пакета — например, в `tools/plugins/weather-fixtures/`
(или внутрь эмулятора: `frontend/public/plugin-dev/fixtures/`), и поправить пути в
`frontend/public/plugin-dev/README.md` и в `SELFTEST_JS`. Стоит завести постоянный
сторож: «каталог пакета проходит `ValidateFull` без проблем» — иначе это повторится
на каждой новой пачке.

### MAJOR-2. Эмулятор попадает в прод и даёт панели канал к origin хоста

`frontend/public/**` копируется vite'ом в `dist` (publicDir по умолчанию), `dist`
копируется в образ (`backend/ClaudeHomeServer/Dockerfile:39` → `publish/wwwroot`), а
статика раздаётся `UseStaticFiles` без `[Authorize]` (`Program.cs:2125`). Значит
`/plugin-dev/index.html` в проде доступен любому, кто открыл ссылку.

Эмулятор выполняет `window.fetch(args.url)` от имени страницы приложения: куки/токены
origin уходят вместе с запросом (по умолчанию `credentials: 'same-origin'`), а ответ
уходит в панель. Боевой хост так не умеет: там выход наружу только через серверный
`PluginNetProxy` (SSRF-guard, белый список методов/заголовков, право `net:{host}`,
секреты вычищаются из ответа).

Сценарий поломки: зловредная панель (или подделанная ссылка на эмулятор с
`grant=<origin приложения>`) заставляет страницу приложения сходить на собственный API
с полными правами сессии и отдать ответ панели. Плюс сам эмулятор становится публичным
«прокси из браузера посетителя» на любой хост, названный в `grant=`.

Рекомендация (в фиче `a67380ae` «Эмулятор панели как штатная функция»):
- не держать эмулятор в `frontend/public/` (это прод-статика). Либо перенести в
  `tools/plugins/plugin-dev/` и раздавать только дев-стендом, либо исключить из продовой
  сборки явным шагом билда;
- в прокси-ветке эмулятора — `credentials: 'omit'`, проверка схемы (только https),
  жёсткий список хостов из `grant=` (как сейчас) и запрет origin самого приложения;
- если эмулятор остаётся в проде — закрыть страницу тем же `[Authorize]`, что и продукт.

### Минор 1. Копия панели без механизма синхронизации

`frontend/public/plugin-dev/weather/panel/index.html` — побайтовая копия
`tools/plugins/weather/panel/index.html` (сейчас идентичны, проверено `diff`). Синхронизации
нет: в B1 панель разъедется, и разработчик будет проверять устаревшую копию — «зелёное
в эмуляторе» ≠ «зелёное в бою». Рекомендация: не дублировать, а ссылаться на исходник
(`/tools/plugins/weather/panel/index.html` — `python3 -m http.server` отдаёт корень
репозитория), либо синхронизировать скриптом с проверкой в CI.

### Минор 2. Эмулятор воспроизводит не все ограничения хоста

Что НЕ воспроизведено (сверка с `frontend/src/features/plugins/bridge.ts` и
`PluginFrame.tsx`): проверка `e.origin === 'null'` (хост требует, эмулятор смотрит только
`e.source`); потолок 8 вызовов в полёте и 64 КиБ на `args`; таймаут `ready` 3 с и
состояние `bridge_timeout`; разбор структурированных отказов и коды статусов
(`callErrorCodeOfStatus`). Для dev-инструмента это допустимо, но в фиче `a67380ae` надо
зафиксировать явным списком «чего эмулятор НЕ воспроизводит», иначе «зелёное в эмуляторе»
читается как «зелёное в бою».

### Минор 3. Тексты отказа продублированы вручную

«Нет права: net:», «Вышестоящий сервис не ответил», «Превышено число запросов…» в
эмуляторе написаны руками, в сервере — в `PluginBridge`/`PluginNetProxy`. Правка текста
на сервере разойдётся с эмулятором молча. Рекомендация: держать перечень в одном месте
(README + комментарий) либо генерировать тексты из общего источника.

### Минор 4. Пути эмулятора зашиты от корня репозитория

`/frontend/src/lib/theme.css` и `/frontend/public/plugin-dev/...` работают только при
раздаче корня репозитория. README при этом даёт два разных адреса: в примере —
`/frontend/public/plugin-dev/index.html`, в тексте — «на дев-стенде доступен как
`/plugin-dev/`». На стенде пути `/frontend/...` не отдаются → эмулятор не заработает.
Рекомендация: пути сделать относительными/настраиваемыми и привести README к одному
варианту.

### Замечание (не дефект): имя плагина в интерфейсе

`name: "weather"` — требование валидатора (сверка `name == slug` каталога, Ordinal),
отклонение от плана подтверждаю: `name: "Погода"` дал бы `deny-name-not-equal-slug`
(проверено тестом). Название «Погода» в интерфейсе не потеряно: панель называется
`contributes.panels[].title` = «Погода» (`panelDisplayName` берёт title). Но карточка
плагина в разделе «Плагины» выводит `humanizeId(id)` → «Weather»: поля «отображаемое
имя» в манифесте нет, бэк его не отдаёт. Это к фиче `a67380ae` (документация/связи),
не к пачке A.
