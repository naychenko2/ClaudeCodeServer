# Аналитика токенов: ценовые классы моделей — пункт для «Что нового»

**Фич-флаг:** нет — класс только раскрашивает и раскладывает уже посчитанный расход.

**Польза одной фразой:**

> В аналитике токенов видно, во что обходится модель: бесплатные, дешёвые и дорогие
> отделены друг от друга.

## Пункт для «Что нового»

> **В аналитике токенов видно, во что обходится модель.** Расход теперь раскладывается по
> трём ценовым классам: бесплатные, дешёвые (MiniMax, GLM, Kimi, DeepSeek) и дорогие
> (Claude). График по дням показывает все три объёма сразу, полосы по моделям и разбивка
> расхода фичи подкрашены по классу, а на карточке провайдера появилась пилюля «дёшево»
> или «дорого».

Текст не обещает внутреннего: стека по источникам, «:free» в каталоге и правила для
неизвестных провайдеров в интерфейсе нет.

## Провайдер записи = маршрут запуска (SP1–SP4, разрез c47fe6da)

**Правило.** Провайдер (и модель) записи расхода — фактический маршрут прогона хода,
а не настройки чата и не имя модели из отчёта CLI.

- Прямой прогон: ключ считается при старте прогона — `ClaudeSession.ComputeUpstreamProviderKey()`:
  `LlmProviderRegistry.ResolveByModel(EffectiveModel)?.Key`; при родной модели (резолв null)
  доверяется ключ подписки, только если он НЕ ключ стороннего провайдера (`"claude"` или аккаунт
  пула), иначе `"claude"`. Ключ пишется как есть, суффикс `-direct` не срезается.
- Прогон через шлюз: при result приоритетен текущий маршрут токена хода — ключ
  `ProviderKey ?? SubscriptionKey`, модель `Route.Model` (ротацию аккаунта посреди хода знает
  только шлюз, сессия её не видит); токен отозван — резерв: ключ, сохранённый при старте прогона.
- Ключ и модель доезжают до записи через `ResultMessage.UpstreamProvider`/`UpstreamModel`
  («учётка хода»); `SpendMapping.RecordTurnSpend` пишет их в запись, фолбэк на старые result
  без этих полей — настройки сессии.

**Отчёт CLI (`modelUsage`) — не источник правды.** CLI называет модель, которую запросил;
шлюз может переписать её на модель провайдера. Порядок модели в записи: апстрим шлюза →
`modelUsage` → модель сессии. `isLocal` считается по тому же ключу, что пишется в запись:
ценовой класс и источник расхода не разъезжаются.

### Известный остаток (не пересчитан)

Разовый проход `SpendStore.RekeyNonClaudeModelsOnClaudeKeys` (маркер `provider-rekey-v1.done`)
исправляет только прямые пары «Claude-ключ + не-родная модель»: правда следует из самой записи.
Что остаётся как есть (замер Глеба на копии боевых данных, ревью `a44fd2df`):

- **обратные пары**: `minimax` + `claude-opus-5-5` (сессия `65c02fe3`) и `deepseek` +
  `claude-sonnet-5` (сессия `cf0eb012`), ≈46 M токенов — источника правды в них нет, перевод
  по модели был бы догадкой в сторону завышения;
- **записи `claude`/`claude-N` + локальная qwen** (≈22 M токенов, 23 детали + 1 строка daily):
  остаются «дорого» — локальный движок на проде живёт в секции `LocalLlm` и в реестр
  `LlmProviders` не входит, резолв по модели даёт null (ревью `a44fd2df`, minor-3).

### Инварианты

- **расход Claude не занижаем**: stale сторонний ключ не приписывает родной ход стороннему;
  «родной Claude» судится по форме id модели (`LlmProviderRegistry.IsNativeClaudeModel`) ДО
  резолва по модели — запись настоящей подписки rekey не может увести к перехватчику;
- **`-direct` не теряем**: суффикс не срезается; прямые адаптеры пишутся one-shot-путём
  и в фильтр rekey не попадают;
- **класс и источник не разъезжаются**: ценовой класс и `isLocal` определяются по тому же
  ключу провайдера, который пишется в запись;
- **свой список Claude-ключей не заводим**: `SpendCostTiers` (`Core/Models/SpendCostTier.cs`) —
  единственный словарь, `IsClaudeKey` берётся из него.

### Объём разового пересчёта

Замер Глеба на копии боевых данных (живые `/srv/ccs/data/spend` не тронуты): в деталях
переключается 45 записей / ≈0,69 млрд токенов (`MiniMax-*` → `minimax`, `deepseek-v4-pro` →
`deepseek`), в daily — 51 строка (строки после смены ключа сливает `MergeByKey`, двойного
счёта нет). Прежняя оценка «≈74 записи» неверна: кандидаты — не переключаемые (в деталях
кандидатов 68, из них переключатся 45; в daily — 77, из них 51). Перед запуском на проде —
копия `data/spend` (как перед delta-backfill). Маркер `provider-rekey-v1.done` ставится
только после успешного прохода; при ошибке записи маркер не ставится и проход повторится.
Проход идёт до часового `ReclassifyLocalAsFree` — локальные записи того же запуска
становятся free.

### Транскрипт чатов «ключ подписки + сторонняя модель»

Такие чаты теперь идут в профиле провайдера. Перед resume транскрипт копируется туда
из профиля подписки (`ClaudeSession.CopyTranscriptToTurnRoot` → `TranscriptMigrator.TryMigrate`):
это копия, исходник не трогается; идемпотентно — файл уже в приёмнике, операция заканчивается.
Явная миграция (`SessionManager.MigrateProviderAsync`) ищет транскрипт в обоих корнях —
текущей пары и собственной подписки.
