# История решений: происхождение записей и импорт из репозитория (этап 4)

Макет: [decision-history-import-v1.html](decision-history-import-v1.html) (обе темы переключаются
кнопкой в шапке, действует на все разделы). Базовая панель и выгрузка —
[decision-history-v1.html](decision-history-v1.html) и [decision-history-proposal.md](decision-history-proposal.md);
здесь только дельта этапа 4: ручной импорт ветки `ccs/dossiers/v1` обратно в стор,
пометки происхождения и пары записей по одному коммиту.

## Проблема

Выгрузка этапа 3 отправляет историю решений в репозиторий, но обратного пути нет: участник,
подключивший общую папку позже, видит только свои записи — чужие «зачем» остаются недоступны,
хотя лежат в той же папке в ветке `ccs/dossiers/v1`. А когда обратное чтение появится,
у записей двух участников по одному коммиту нужно честно показать, где какая, — иначе список
превратится в загадку «почему два раза про одно и то же».

## Решение

**Импорт — зеркало выгрузки.** Кнопка в шапке острова панели: та же `IconButton size="sm"`,
иконка `Download` (lucide), стоит слева от «Выгрузить» (`Upload`) — пара «забрать / отдать»
читается по направлению стрелок. Запасной вариант без шапки (мобиль) — чип «Импорт» тем же
`chipStyle` в субхедере, рядом с чипом «Выгрузить». Гейт видимости тот же, что у выгрузки:
флаг `change-dossiers-recall` + git-репозиторий.

**Модалка импорта — брат `DossierExportDialog`.** Тот же `Modal width={MODAL_W.confirm}`,
переходы фаз внутри одного открытого окна, `closeOnBackdrop=false` на время git-операции.
Две кнопки действия по образцу экспорта: «Импортировать» (читает локальную ветку) и главная
«Забрать и обновить» (сначала fetch с remote). На мобиле пара схлопывается в одну главную
«Забрать и обновить» — тянуть remote всегда безопаснее устаревшей локальной ветки.

**Пометка происхождения — только у исключения.** Локальная запись — норма и остаётся чистой;
симметричный бейдж «Своя» превратил бы список в ленту одинаковых пилюль. Импортированная
получает бейдж «Из репозитория» в метастроке, после даты: фон `C.infoBg`, текст и иконка
`Download` 11px цветом `C.info`, `R.max`, `FS.xs`. Гамма `info` выбрана нарочно: accent занят
персонами, warning/danger сказали бы «что-то не так», а это нейтральная атрибуция. Автор
записи — тот, кто писал паспорт (человек или персона), остаётся в начале метастроки как обычно.
В компактной строке свёрнутой месячной группы пилюля не помещается — там только значок
`Download` 11px цветом `C.info` перед sha, с title «Из репозитория».

**Пара по одному коммиту — без склейки.** Обе записи про один коммит валидны, показываем обе
подряд (сортировка по дате коммита это гарантирует); связь читается по одинаковому mono-sha
в метастроках. Отдельный контейнер-рамка добавил бы уровень вложенности ради редкого случая.
У импортированной записи ссылки «Открыть чат / задачу» ведут в источники её автора: если они
недоступны этому инстансу — действует то же правило протухших ссылок этапа 1 (погашенный текст
вместо кнопки); «Показать изменения» жива всегда, она держится на коммите.

## Обязательные состояния — где смотреть в макете

| Состояние | Раздел макета |
|---|---|
| Кнопка импорта рядом с выгрузкой | §1 (шапка острова, Download слева от Upload) |
| Пометка «Из репозитория» + своя запись без пометки | §1, §2 (анатомия, обе разновидности) |
| Пара записей по одному коммиту | §1 (внизу списка), §3 (с раскрытой импортированной) |
| Импорт идёт | §4, вторая модалка: спиннер на нажатой кнопке, остальные disabled, диалог не закрывается |
| Импорт завершён | §4, третья модалка: счётчик новых записей + честное число совпадений |
| Ветки в репозитории нет | §4, четвёртая модалка: info-выноска, не danger — это отсутствие данных, не сбой |
| Ошибка импорта | §4, пятая модалка: danger-выноска + «Повторить» |
| Мобильная раскладка | §5: bottom-sheet, чипы «Импорт»/«Выгрузить» в субхедере, бейдж переносится с метастрокой |
| Обе темы | кнопка «Светлая/Тёмная» в шапке переключает все разделы |

## Отклонения от системы

Нет: все размеры, цвета и радиусы — существующие токены `design.ts`/`theme.css`
(полная таблица — §6 макета). Новых значений в шкалах не вводилось; обе темы получают
пометку бесплатно через CSS-переменные `--c-info`/`--c-info-bg`.

## Границы задачи

Бэкенд импорта (чтение ветки, коллизии, origin-маркеры в `DossierStore`) — отдельная работа
этой же волны; макет показывает целевой вид UI и тексты. Реализация панели и модалки — Кире
по этому макету. Автоматический импорт (без кнопки) в постановку не входил и в макете
не показан.
