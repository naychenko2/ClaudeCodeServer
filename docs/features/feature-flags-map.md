# Карта фич-флагов

> Реестр (source of truth) — в коде: `FeatureFlagCatalog.All`
> ([Models/FeatureFlag.cs](../../backend/ClaudeHomeServer.Core/Models/FeatureFlag.cs));
> ключи дублируются во фронте — const `FLAGS`
> ([lib/featureFlags.ts](../../frontend/src/lib/featureFlags.ts)). Механика: per-user
> override в `data/users.json` поверх дефолтов каталога, эффективные значения приходят
> с бэка (`/api/auth/me`, `/api/feature-flags`) и раздаются компонентам хуком
> `useFeature(FLAGS.key)`. Механику и инструкцию «как добавить флаг» держит раздел
> «Фич-флаги» [CLAUDE.md](../../CLAUDE.md).
>
> Механика резолва — [FeatureFlagService.cs](../../backend/ClaudeHomeServer/Services/FeatureFlagService.cs):
> каталог PLUS динамические флаги `module-{id}` (дефолт `true`) из `ModuleRegistry` —
> тумблеры внешних модулей рендерятся рядом, но в статический каталог не входят.
>
> **Карта снята 2026-10-08** — по 15 снятым флагам проверено, что в коде гейтов
> не осталось, а фичи работают у всех. Ссылка-пометка «за флагом …» в другом
> документе НЕ гарантия актуальности: снятые после dark launch флаги работают у
> всех безусловно, а упоминания о них в доках остаются (исторические — раздел
> [CLAUDE.md](../../CLAUDE.md) «Фич-флаги»).

## Сводная таблица

| Ключ | Что гейтит (кратко) | Почему остаётся | Ключ во фронте `FLAGS` |
|---|---|---|---|
| `workspace-destructive` | необратимое `files_delete` / `chats_delete` у workspace-сервера | постоянный предохранитель от необратимого удаления; не снимаем | есть |
| `spheres` | состав и зона персон сферы; команды `PersonaZone` и `ISphereDirectory` | ждёт v2-дизайна; фича пока не для всех | есть |

## Разделы по флагам

### `workspace-destructive` — Необратимое удаление

- **Описание (из каталога):** Claude может БЕЗВОЗВРАТНО удалять файлы проектов и
  чаты через инструменты рабочего пространства (files_delete, chats_delete) — только
  по явной просьбе. Персоне дополнительно нужна возможность «Удаление (опасно)».
- **Дефолт / стадия:** false / dev.
- **Почему остаётся:** постоянный предохранитель. Снятие делает разрушительные
  ручки доступными по умолчанию, а у них нет другого стопа — у человека должна
  быть сознательная кнопка «включить», пока процессы «Что удалится» не показаны
  рядом с действием.
- **Что за флагом:** секция `destructive` workspace-сервера (безвозвратные
  `files_delete` / `chats_delete`) монтируется в ход, только когда совпали: флаг
  владельца, tool-ключ `destructive` у персоны и профиль не «Только чтения»
  ([SessionManager.cs:3501-3504](../../backend/ClaudeHomeServer/Services/SessionManager.cs));
  регистрация терминала (PTY) по комментарию связана с тем же гейтом
  ([Program.cs:769, :777](../../backend/ClaudeHomeServer/Program.cs)). **Во фронте
  `useFeature` не найден** — ключ существует только в реестре `FLAGS`; гейт
  полностью серверный.
- **Ключ во фронте `FLAGS`:** есть (`FLAGS.workspaceDestructive`).

### `spheres` — Сферы проектов

- **Описание (из каталога):** Сфера = группа проектов с уставом, командой персон
  и полкой памяти; разрешение на вступление в зону персоны — через
  `PersonaZone` + `ISphereDirectory` (fail-closed).
- **Дефолт / стадия:** false / dev.
- **Почему остаётся:** ждёт v2-дизайна. UX и онбординг ещё не закрыты — пока
  фича только для тех, кто понимает её цену.
- **Что за флагом:** источник правды — [ADR-024](../adr/ADR-024-spheres.md) и
  [spheres.md](spheres.md). Ключ используется в `PersonaZone.IsEnabled` и
  `ISphereDirectory`; состав сферы и зону персон меняет только человек, MCP
  отказывает.

### `change-dossiers-recall` — Подсказки персон по паспортам

- **Описание (из каталога):** Персоны видят историю решений по коду, который
  правят, и не предлагают повторно то, что уже отвергли. А саму историю можно
  выгрузить в репозиторий отдельной веткой — отправка только по вашей кнопке.
- **Дефолт / стадия:** false / dev.
- **Почему остаётся:** ждёт замера качества паспортов. Recall паспортов влияет
  на префикс кеша и контекст хода — без замера «помогает или шумит» не снимаем.
- **Что за флагом:**
  - **Бэк:** MCP-инструменты `dossier_lookup` / `dossier_get` memory-сервера — гейт
    [SessionManager.cs:1213](../../backend/ClaudeHomeServer/Services/SessionManager.cs)
    (состав входит в отпечаток `tools/list`); пассивная секция паспортов в
    recall-промпте персоны
    ([PersonaRecallContributor.cs:87-88](../../backend/ClaudeHomeServer.Turn/PersonaRecallContributor.cs)).
  - **Фронт:** панель «История решений» — кнопки выгрузки/импорта ветки
    `ccs/dossiers/v1` ([DossierHistoryPanel.tsx](../../frontend/src/pages/workspace/DossierHistoryPanel.tsx)).
- **Источник:** [ADR-004](../adr/ADR-004-change-dossiers.md), §8 «Фич-флаги и
  выкатка» (флаг №2 двухфлаговой выкатки; этап 1 — флаг `change-dossiers` — из
  каталога уже снят).

## Побочные эффекты снятия

- **CLI-процесс перезапустится один раз у тех, у кого флаги были выключены**.
  Сигнатура MCP (`tools/list`) меняется — добавляются инструменты, которых раньше
  не было. CLI получает свежий список, поэтому перезапуск — нормальное поведение,
  а не сбой. Это одноразовое явление.
- **Автоархив чатов не включился у всех автоматически**: флаг `chat-auto-archive`
  не задавал порог `ArchiveAfterDays`, его по-прежнему задаёт человек в настройках
  проекта. Без заданного порога автоправило не работает — это не регрессия, а
  прежнее поведение.
