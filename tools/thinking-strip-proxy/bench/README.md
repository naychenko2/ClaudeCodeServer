# Стенд качества сжатия (bench/)

Воспроизводимая мерка: насколько сводка автосжатия сохраняет нужное. Часть плана «сжатие с
сохранением дословного (прокси → MiniMax)», шаг 2. Прокси (`proxy.py`) стенд не трогает.

Идея — как у Factory: после сжатия модель отвечает на вопросы о прошлой работе, ответы сверяют
с эталоном. Эталон строится по ПОЛНОЙ истории, отвечает по «сводка + сохранённый хвост».

```
build_corpus.py   транскрипты local-qwen -> корпус запросов сжатия     (шаг 1)
make_questions.py сильная модель -> вопросы и эталоны по полной истории (шаг 3)
run_bench.py      схема сжатия -> ответы локальной модели -> оценки 0–5 -> таблицы (шаги 2, 4, 5)
common.py         промпт сжатия CLI 2.1.301, постобработка сводки как в CLI, вызовы моделей
plugins/          плагины-схемы: plugin_truncate (контроль стенда), plugin_preserve (новая схема, шаг 6)
make_synthetic.py корпус-мод: маркеры реплик человека + синтетические поправки (шаг 6)
compare.py        сводка двух схем по повторам; calibrate_judge.py — калибровка смены судьи
baseline-old-2026-10-16.md   итог базовой линии нынешней схемы
```

## Запуск

Только стандартная библиотека python3. Данные — вне репозитория, в `$BENCH_HOME`
(по умолчанию `/srv/ccs/data/compact-bench`: там чужие чаты, в git они не едут).

```bash
cd tools/thinking-strip-proxy/bench
python3 -I build_corpus.py --count 12 --trigger any --max-est 800000   # корпус (один раз)
python3 -I make_questions.py --workers 4                               # вопросы (один раз, ~4 мин)
python3 -I run_bench.py --scheme old                                   # базовая линия (~18 мин)
python3 -I run_bench.py --scheme plugin:plugins/plugin_truncate.py     # любая другая схема
```

Всё кэшируется в `$BENCH_HOME/runs/<схема>/`: оборванный прогон доделывается тем же вызовом,
`--fresh` пересчитывает. Итог — таблица в stdout и `report.md` + `results.json` рядом с кэшем.

## Схема — параметр (`--scheme`)

| схема | что делает |
|---|---|
| `old` | тело запроса сжатия как есть в MiniMax-M3 (как `compact_body`/`open_compact` прокси); ключ и адрес — `COMPACT_UPSTREAM`/`COMPACT_KEY_FILE`/`COMPACT_KEY_PATH` |
| `actual` | сводка, которую в тот раз реально записал CLI (из транскрипта) |
| `dir:<каталог>` | готовые сырые сводки `<id>.txt` (на шаге 6 — выход нового конвейера) |
| `plugin:<файл.py>` | функция `summarize(item) -> сырой текст` (или `(текст, метаданные)`); `item` — запись корпуса |

Сырой текст схемы обрабатывается как в CLI: `<analysis>` вырезается, `<summary>` → «Summary:»,
текст вне тегов сохраняется, сверху — обёртка «This session is being continued…».

## Корпус

Запрос = история до границы `compact_boundary` минус `compactMetadata.preservedMessages`
(CLI оставляет их дословно) + инструкция сжатия (`common.compact_instruction`, текст вынут из
бинарника CLI 2.1.301, вариант `up_to` для сжатия с сохранённым хвостом). Запись корпуса
(`corpus/cNN.json`): `history` (сообщения в формате API), `preserved` (хвост), `humans`
(реплики человека с позицией), `actual_summary`, `meta`. Вопросы — `corpus/questions/cNN.json`.
**Это и есть фикстуры для шага 3.** Состав на 2026-10-16: 11 запросов, 136–594k токенов
истории, 76 вопросов.

## Вопросы и оценка

Типы: факты, артефакты, продолжение, решения и **поправки человека** (по одному вопросу о
реплике человека из середины истории — главный провал нынешней схемы). У каждого вопроса
эталон и дословная цитата-доказательство; вопросы, чья цитата не нашлась в истории подстрокой,
отбрасываются. Реплики «Продолжай», служебные вставки и уведомления за поправку не считаются.
Оценка 0–5 (судья сверяет с эталоном), «сохранено» = оценка ≥ 4. Для поправок дополнительно
считается дословность: доля 3-словных окон реплики человека, встречающихся в сводке.

Ответчик — локальная модель через прокси (`BENCH_LOCAL_URL`, по умолчанию `127.0.0.1:18021`),
генератор вопросов и судья — MiniMax-M3 (`BENCH_JUDGE_URL/KEY/MODEL` — заменить).

## Честные оговорки

- **Запрос реконструирован**, а не перехвачен: системный промпт сжатия и параметры CLI взяты по
  бинарнику (`system` короткий, без `tools`, `max_tokens` 20000, без `thinking`). Точное тело
  боевого запроса прокси в журнал не пишет. Токены истории — грубая оценка (1 токен ≈ 3 симв.);
  у запросов персон с большим системным промптом `preTokens` CLI заметно выше оценки (c02:
  136k против 276k).
- **Поправки с живым человеком редки.** Транскрипты local-qwen в основном чаты исполнителей: одно
  постановочное сообщение и «Продолжай». Запросов с настоящей поправкой — 6 из 11, вопросов о
  поправках 7 (в c01 — два). Для вывода «доля сохранённых поправок» это мало: смотреть на
  направление, не на третий знак. Расширять корпус — запустить `build_corpus.py` позже, когда
  накопятся чаты с человеком.
- **Шум.** Повтор «новая сводка + новые ответы» на 4 запросах дал разницу среднего по запросу
  до 0,6 (в среднем ~0,25): ответчик сэмплирует, прокси перебивает температуру на 0,7. Различия
  схем меньше ~0,3 по всем вопросам считать шумом. Судья и генератор вопросов — MiniMax-M3, та же
  семья, что пишет сводки: возможен перекос в пользу `old`.
- **Стенд проверен мутацией**: схема `plugin_truncate` (та же сводка, обрезанная до 1200 симв.)
  роняет среднее с 3,14 до 0,57 на подмножестве с поправками — мерка чувствительна.
- Новая версия CLI может поменять текст промпта сжатия — перечитать из бинарника
  (`CRITICAL: Respond with TEXT ONLY` → функции `JEe`, `OSn`).

## Шаг 6: сравнение схем при одном судье

`BENCH_JUDGE=local` — судья локальная модель (а не MiniMax); `--tag r1|r2` — повторы для шума;
`--corpus …/corpus-mod --out …/runs-mod` — корпус с маркерами и синтетическими поправками. Итог и
команды воспроизведения — [preserve-vs-old-2026-10-16.md](preserve-vs-old-2026-10-16.md).
