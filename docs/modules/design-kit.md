# ТЗ команде ядра AI Home: design-kit как MF-expose для внешних модулей

- Статус: **передано команде ядра** (проект AI Home, `C:\Sources\ClaudeCodeServer`; чат `8662402f`); уточнено по итогам дизайн-концепции и манифеста (@designer, 2026-07-25, `design/design-kit-manifest.md`).
- Основание: контракт `integration-contract.md` **§7.1, v1.5** (лежит рядом, неотъемлемая часть ТЗ).
- Заказчик: команда модуля «Семейный бюджет» (проект «Личные финансы»). Первый потребитель — `family-budget`; кит проектируется универсальным под будущие модули.
- Приёмка: эталонным модулем `module-echo` (расширяет заказчик — добавляет экран, использующий примитивы кита) и conformance-проверкой **CT-16**.

> Уточнения от манифеста (помечены ✦ ниже): имя remote-entry (R14), lucide-react shared (R15), self-contained IslandScaffold (R15), глобальные CSS-классы/keyframes как часть кита (R17), опциональный Snackbar (R18). Приняты архитектором заказчика (@architect).

## Зачем

Сегодня модуль-remote не может использовать дизайн-систему ядра. У ядра `vite.config.ts` публикует `shared: { react, react-dom }`, **но не имеет `exposes`** — проверено. Значит `Island`, `Modal`, `Button`, токены `C`/`FONT`/`R` модулю недоступны: их нет в MF-поверхности. Доступны только глобальные CSS-переменные (`--c-*`), имена с ними совпадают, тема переключается — но компоненты модуль вынужден дублировать своими силами.

Решение владельца системы: единый источник правды. Ядро экспонирует design-kit, модули потребляют его как remote. Тогда внешний модуль не расходится с ядром визуально ни сегодня, ни при будущем редизайне — и любой новый модуль получает готовую дизайн-систему, а не изобретает её.

## Что нужно сделать (R14–R16)

| # | Требование | Критерий приёмки | Затрагиваемый код / риск |
|---|---|---|---|
| R14 ✦ | **Expose токенов под фиксированным именем.** Опубликовать `frontend/src/lib/design.ts` через MF: `C, FONT, FS, R, SP, SHADOW, ISLAND, TB, Z, MODAL_W, CHAT_MAX_W, MOBILE_MAX, TABLET_MAX, FIELD, GROUP_COLORS` доступны модулям через `loadRemote('aihome_shell/design-kit')` — **имя remote-entry зафиксировано контрактом §7.1 v1.5** | Модуль импортирует `C.bgMain` и получает `'var(--c-bg-main)'` — то же значение, что и ядро | Тривиально: токены — константы и строки-ссылки на CSS-переменные, поведения нет |
| R15 ✦ | **Expose компонентов + lucide-react shared.** Самодостаточный bundle: `Island, IslandHeader, IslandScaffold (+ self-contained режим с `storageKey`, см. ниже), IslandSidebarSplitter, IslandSplitter, Modal, Button, IconButton, Field, Toggle, PillSwitch, ToolbarOverflowMenu, Menu, MenuItem, EmptyState, CanvasBackdrop, BackButton, ModalActions, ConfirmDialog, ICON_SIZE/ICON_STROKE/ICON_PROPS`. `lucide-react` — **shared singleton** с зафиксированной major-версией (из `package.json` ядра), наравне с react — иначе два инстанса библиотеки раздуют бандл и рассинхронят иконки. Модуль импортирует иконки напрямую из `lucide-react`, кит реэкспортирует только `ICON_*` | CT-16: модуль рендерит remote-примитивы, вкладка монтируется, тема переключается, React-инстанс один; lucide shared | `components/ui/Island.tsx` — чистый лист. `Modal`/`ToolbarOverflowMenu` тянут react-dom portal; `IslandScaffold` — сплиттер-хуки. **Просим**: (а) kit entry реэкспортирует всё из единой точки (в т.ч. `PillSwitch`/`EmptyState`, что сейчас вне `ui/`); (б) добавить в `IslandScaffold` self-contained режим — компонент сам владеет сплиттером по пропу `storageKey` (≈10 строк), чтобы не экспозить хук `useSidebarDrag` наружу. Цель — expose-чанк не должен тащить половину оболочки |
| R16 | **Версионирование и изоляция.** Мажор design-кита = мажор `schemaVersion` (§7.1 v1.5). Смена состава экспорта (добавление/удаление токена или компонента) = мажор; в рамках мажора backward-compat (новые добавляются свободно). Компоненты рендерятся shared-React (один инстанс, §7.1), стили — на глобальных CSS-переменных. При несовпадении мажора модуль отказывается монтироваться с понятной ошибкой (как `schemaVersion`, §8) | При смене мажора модуль на старом корректно отказывается | `vite.config.ts` (новый `exposes` + `lucide-react` в `shared`), `lib/design-kit/index.ts` — единый entry кита |
| R17 ✦ | **Глобальные CSS как часть кита.** Примитивы из R15 завязаны на классы/keyframes из `index.css` ядра: классы `cc-overlay`, `cc-modal-card`, `cc-sheet-card` (Modal), `cc-iconbtn` (IconButton), `cc-spin`, `cc-shimmer-text`, `cc-smoke`; keyframes `cc-overlay-in`, `cc-modal-in`, `cc-sheet-in`, `cc-spin`, `cc-shimmer-text`, `cc-smoke`; скролл-хелперы `cc-scroll-x`, `cc-hide-scrollbar`, `cc-no-scrollbar`. Без них Modal рендерится без оверлея/анимации, спиннер кнопки не вращается. Просим **expose `index.css` целиком** (проще и надёжнее выверки подмножества) + `lib/theme.css` (`--c-*`, `--shadow-*`, `--canvas-*`) как обязательство — оба уже в DOM-контексте модуля сегодня, фиксируем контрактом | Шторка QuickAdd имеет оверлей + drag-handle + анимацию; IconButton — стиль `cc-iconbtn`; спиннер вращается | `index.css`, `lib/theme.css`; гарантия наличия в DOM-контексте модуля |
| R18 ✦ | **Snackbar (опционально, GAP кита).** Общего toast-примитива у ядра нет, а он нужен не только бюджету (undo после действий, подтверждения) — задачи/заметки ядра тоже выиграют. Спека: `{ message, action?: {label, onClick}, duration?=5000 }`, позиция bottom-center над FAB (≤600) / bottom-right (≥601), токены `SHADOW.dropdown`/`C.bgCard`/`C.textPrimary`. **Fallback** (если ядро откажет): модуль строит свой Snackbar на токенах — работает, но паттерн разъедется между модулями | Если добавляете — модуль использует общий; если нет — модуль строит свой, фиксируем как риск | Новый примитив в ките |

## Порядок исполнения

**R14** (токены, тривиально) → **R17** (CSS-гарантии — параллельно, даёт визуальную полноту) → **R15** (компоненты + lucide shared — основная работа) → **R16** (версионирование) → **R18** (Snackbar, опционально).

## Регрессионные требования (обязательные)

1. Все изменения — **аддитивные**: существующие разделы ядра (Проекты/Чаты/Заметки/Персоны) используют те же примитивы и должны работать без изменений; никаких правок в их коде.
2. Прогон тестов ядра (`ClaudeHomeServer.Tests`) и сборка фронта (`tsc -b && vite build`) — зелёные.
3. PWA-сборка (`vite-plugin-pwa`, `injectManifest`) корректна: чанки design-кита не выпадают из покрытия и не ломают precache (см. прецедент R5 — remote-чанки модулей уже исключены из precache).
4. Ручной smoke: раздел «Проекты» и любая модалка/остров в нём — без визуального регресса.

## Вне объёма этого ТЗ

- **Доменная логика бюджета** (лента операций, отчёты, категории) — сторона заказчика; кит даёт примитивы, не экраны.
- **Таблицы и чарты** — лента-таблица десктопа и бары отчёта модуль строит сам на `div`/`table` + токены (у «Проектов» ядра тоже нет Table-примитива). В кит v1 не просим.
- **Тема/CSS-переменные** — `lib/theme.css` уже работает глобально; публикация через MF не требуется, но вхождение в R17 как обязательство — фиксируется.
- Сложные составные компоненты (ChatCard, FileExplorer, TaskBoard) — в кит не входят; модуль при необходимости строит их из примитивов сам.
