Карточки дефектов — эталон для волны 3: иконка, плашка, диалог, блоки деталей, тост

Эталон для UI-ревью карточек дефектов (волна 3, wt/otsenka-vnedreniya-bagtrekinga). Все цвета — существующие токены C.* из design.ts (значения обеих тем — в theme.css): C.textMuted для иконки Bug, C.dangerBg/dangerText/dangerBorder для плашки «Закрыт без проверки», C.bgWhite для карточек на дудл-холсте, C.borderLight для рамок. Сегмент «Задача | Дефект» — ui/SegmentedControl, поля ввода — ui/TextArea, диалог — ui/Modal. Никаких самодельных контролов.

Оба блока — белые карточки с C.borderLight, R=12, padding 14×18. Шаги — pre-wrap, Expected/Actual отбиваются разделителем C.borderLight сверху, каждый со своим uppercase-заголовком. 4. Тост отказа (NotificationToasts.tsx + cc-local-toast)

Шесть точек вызова (TaskBoard, TaskDetailsPane×3 — статус/подзадача/сохранение, TaskHoverCard×2 — статус/подзадача) используют один формат: showToast('Не удалось …', e.message ?? 'Сервер отклонил изменение', 'error'). Контракт: kind='error' → рамка C.dangerBorder, заголовок и текст в C.danger/dangerText. Плитка аватара: для kind='error' нет NotificationKind, поэтому fallback в KIND_META.info и иконка «ℹ» — но цвет danger-рамки и сам заголовок читаются как ошибка. Это единообразно во всех шести точках.
