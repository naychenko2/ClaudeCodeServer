## Шаги

### Шаг 1. Инструмент `ui_probe` — замер интерфейса цифрами

**Что.** Новый инструмент MCP в тулсете `tests` вертикали `ClaudeHomeServer.TestRuns` (рядом с `run_tests`). Вход: `url` стенда **или** `service` из панели «Сервисы» (как у `start_stand` в `DevToolset`), `path` маршрута, `viewports` (по умолчанию `[360, 1280]`), необязательный `selector` для сужения. Выход — JSON с числами, без скриншотов и без суждений:
- интерактивные элементы (`button`, `a[href]`, `input`, `[role=button]`, `[tabindex]`) с любой стороной меньше порога (по умолчанию 40 px): селектор, размеры, ширина экрана;
- горизонтальное переполнение документа и контейнеров (`scrollWidth > clientWidth`);
- обрезанный текст (`overflow: hidden` + переполнение);
- ошибки консоли и упавшие сетевые запросы за время загрузки;
- базовая доступность: интерактивные элементы без доступного имени.

**Как.** Headless Playwright из `frontend/node_modules` (уже есть у Веры), один процесс на вызов, общий сторож очереди сборок как у `run_tests` (потолок 9 минут, «Стоп»). Вход по JWT стенда — как у прокси `/preview/**`.

**Доступ.** Инструмент добавляется в `KeepMcpTools` профилей `local-qwen` и `LightProfile` (`appsettings.json`, ~:472 и ~:506) — у локальных исполнителей он есть, полный Playwright на шаге по-прежнему закрыт. Имя сверяет `KeepMcpToolsConfigTests`.

**Инварианты.** Инструмент только читает стенд; никаких правок файлов. Стенд поднимает человек или `start_stand`, `ui_probe` сам процессы не порождает. Пороги — параметры вызова с умолчаниями, не константы проекта.

**Готово, когда.** Исполнитель на шаге и Глеб на ревью получают одинаковые цифры по одному маршруту; Вера подтверждает совпадение с ручным замером на 360. Возврат вида «34 вместо 40» невозможен без расхождения цифр.

**Кто.** Тимур (тулсет, очередь, доступ), Вера (сверка с ручным замером).

### Шаг 2. Потребители правленого файла приходят в ход сами

**Что.** Хук `PreToolUse` с matcher `Edit|Write` в per-run настройках CLI, которые сервер уже генерирует (`ClaudeRuntimeSettings.cs`, ~:136–150, там уже есть хук на `Bash`). При **первой** правке файла хук спрашивает граф кода (`GET /api/codegraph/neighbors`, `CodeGraphController.cs:167`, направление `in`) и возвращает в ход `additionalContext`: кто импортирует/вызывает файл, какие тесты его покрывают, не больше 20 строк; повторная правка того же файла в этом ходе — молчание. Нет графа или файл вне графа — хук молчит, ход не тормозит.

**Инварианты.** Хук не блокирует правку (только контекст). Граф worktree прогревается при `AttachWorktreeAsync` (merge `5a24dc4f`): пока строится — ответ по основному дереву с пометкой `BuildingNote`, как у `CodeGraphToolset`. Таймаут запроса 3 с, иначе молчание.

**Готово, когда.** В транскрипте шага Киры перед правкой `WorkspacePage.tsx` стоит список его потребителей; на C#-файле с 50+ зависимыми список обрезан до 20 строк с пометкой «ещё N».

**Кто.** Тимур.

### Шаг 3. Критерии приёмки и свидетельства в задаче

**Что.**
- `TaskItem` (Core, `Models/TaskItem.cs`) получает `Acceptance: List<AcceptanceCriterion>` (`Id`, `Text`) и `Evidence: List<AcceptanceEvidence>` (`CriterionId`, `How`, `Result`). Бэкап: добавление полей, `BackupSchema.Version` не трогаем.
- `tasks_create`/`tasks_update` в `TasksToolset` принимают `acceptance`; `tasks_complete` у задачи с непустым `acceptance` требует `evidence` по **каждому** критерию — иначе `Deny` с перечнем незакрытых (fail-closed, та же форма, что у `verification` дефекта). REST-паритет в `TasksController`.
- Карточка доклада постановщику (`TaskExecutionService.BuildDelegationReportText`, ~:1914) и карточка задачи на фронте показывают таблицу «критерий → свидетельство».
- Контракты (через Софью): Егор — критерии только измеримые («кнопка ≥ 40 по обеим сторонам на 360», «`ui_probe` по маршруту X без находок», «тест Y красный на мутации Z»), а не «удобно на мобиле»; Глеб — проверяет свидетельства и расхождения, а не выводит требования заново; исполнители — свидетельство по критерию обязательно.

**Инварианты.** Задачи без `acceptance` работают как раньше (обратная совместимость, старые задачи не ломаются). Персона-исполнитель не может удалить критерий через `tasks_update` (только постановщик/человек) — иначе гейт обходится.

**Готово, когда.** Задача с тремя критериями не закрывается без трёх свидетельств; доклад показывает таблицу; на мутации «пропустить проверку evidence» тест красный.

**Кто.** Тимур (Core, Tasks, тулсет, контроллер), Полина (карточки), Софья (контракты Егора, Глеба, исполнителей).

**Что.** Правило в контракт Егора: шаг фронта для локальной модели — не больше четырёх файлов и один компонент; больше — дробить или сразу Полине. Серверного гейта не делаем: размер известен только после работы. Это текст контракта, применяется сразу, до планирования остальных шагов.

## Порядок и зависимости

Шаги 1 и 2 независимы — параллельно. Шаг 3 — самый кросс-слойный (Core → Tasks → тулсет → фронт), идёт после 1, потому что критерии вида «`ui_probe` без находок» опираются на инструмент. Шаг 4 — сразу.

## Риски

- `ui_probe` превратят в «посмотри скриншот и оцени» — тогда локальная модель снова судит на глаз. Держать выход числовым.
- Хук на каждую правку тормозит ход — таймаут 3 с и молчание при ошибке, один запрос на файл за ход.
- Критерии напишут неизмеримо — тогда гейт свидетельств бесполезен. Качество критериев — зона Егора, проверяет Глеб на первых трёх задачах.

## Чего не делаем

- Тест на тач-цели под наш проект — закрывает один симптом в одном репозитории.
- Смена локальной модели — три из четырёх причин повторялись на старой.
- Полный Playwright исполнителю на шаге — тяжёл и медлен для локальной модели.

**Оговорка о выборке:** база — 7 ревью, это снимок, а не статистика; разница в один возврат от шума неотличима. Поэтому ведутся три числа: возвраты/ревью, доля по причине (ноль виден и на малой выборке) и находки `ui_probe`.
