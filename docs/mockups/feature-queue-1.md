# Очередь фич — макет 1 (подписи и действия)

Макет: [feature-queue-1.html](feature-queue-1.html). Вверху переключатели темы, состояния и меню ⋯.
Привязка: эпик «Очередь фич» `ec0a21ff`, задача макета `3ff51ca0`, шаг, который пользуется макетом, — **Q5** (фронт, lane=front).
Контракт — заметка «Волна 6 «Обзор фич» — разрез очереди фич (Александр, 25.10)», §1–§8. Образец паузы — [feature-hold-1.md](feature-hold-1.md).

## Сценарий и проблема

Одна фича уже идёт, и человек заводит вторую. Запускать её сейчас он не хочет: фичи столкнутся на мерже. Остановить её навсегда тоже не хочет. Ему нужно «запусти, когда освободится место». Потом он заглядывает в список и хочет видеть, какая по счёту его фича, а не гадать, почему она «на паузе».

Очередь — это пауза с другой причиной (`state = paused`, `holdReason = queue`). Поэтому **тон у неё тот же, что у паузы**, тревоги нет. Различаются глиф и слова. Никакого нового `state` нет.

## Подпись «в очереди · N из M»

Один хелпер на все места, например `queueLabel(run | row)` рядом с `featureRunStatusTag`. Источник — `holdReason === 'queue'` и вычисляемое `queue: { position, length }`. Фронт позицию не считает.

| Место | Компонент | Как выглядит |
|---|---|---|
| Шапка страницы | `FeatureStatusTag` (тег `hold`) | глиф очереди 10 px + «в очереди · `2 из 3`» |
| Плашка группы | `FeatureGroupHeader` | глиф `queue` 14, статус «в очереди · `2 из 3`», `C.textPrimary`/600, **кромки слева нет** |
| Рельса в чате | `FeatureBanner` + `statusPhrase` (pillModel) | bold «В очереди», post « · 2 из 3»; активный сегмент `FeatureRail` — `C.textMuted` |
| Пилюля фичи | `buildPillModel` (тот же `statusPhrase`) | так же, как рельса |

- Цифры `N из M` набираются `FONT.mono`, чтобы при пересчёте не прыгала ширина.
- Нет `queue` (бэк ещё не отдал) — подпись «в очереди» без цифр. Нули не показываем.
- `FeatureRail`: новый проп `waiting?: boolean`. При нём у `active` фон `C.textMuted` вместо цвета тона. `aria-label` — «Этап: {этап} · в очереди N из M».

### Тег и глиф

- Тег — тон `hold` без изменений: фон `C.bgInset`, текст `C.textPrimary`, кромка `inset 0 0 0 1px C.border`, `FS.xs`/600, строка 16, поля `SP.xxs SP.xs`, `R.sm`.
- Глиф тега (10 px, `currentColor`): три полосы 12×2.4 (rx 1.2) по y 2.5 / 6.8 / 11.1. Две нижние — `opacity .55`.
- `FeatureGlyph` `queue` (16×16 viewBox): круг r 7, заливка `C.bgInset`, обводка `C.textMuted` 1, как у `hold`. Внутри три полосы 6.8×1.6 (x 4.6, y 4.4 / 7.2 / 10, rx 0.8). Верхняя `C.textSecondary`, две нижние `C.textMuted`.
- Лучше lucide: `ListOrdered` близок, но в 10 px цифры превращаются в шум. Рисованный глиф держит семью с `hold`.

## Состояния

| Состояние | Данные | Тег | Блок на странице (`FeaturePageAlert`) | Мини-полоса |
|---|---|---|---|---|
| не в очереди | `hold` нет / `manual` / `draft` | как сейчас | как сейчас | как сейчас |
| в очереди | `paused`, `queue`, `queue{2,3}` | «в очереди · 2 из 3» | **«Фича в очереди: вторая из трёх.»** Поставили вы {dur} назад. Шаги не запускаются.<br>`sub`: «Запустится сама, когда одна из идущих фич проекта закончится или уйдёт на мерж. Прерванные шаги продолжатся с того же места.» | открытый сегмент `queued` растёт к правому краю; итог «в очереди {dur}» |
| ждёт запуска | то же + `queue.slotFree` (см. API) | «запускается из очереди» | **«Место освободилось — фича запускается.»** Обычно это несколько секунд.<br>`sub`: «Если строка не сменилась за минуту — запустите вручную через ⋯ → «Запустить вне очереди».» | как «в очереди» |
| запущена из очереди | `running`, журнал `hold_cleared(queue, by=queue)` | «идёт · {этап}», отдельной плашки нет | нет | сегмент `queued` закрыт, за ним работа; итог «простояла в очереди {dur}» |

- Блок «в очереди»: фон `C.bgInset`, рамка `1px solid C.border`, `R.lg`, глиф `queue` 14, `role="status"`, `aria-live="polite"`. Строка `sub` — `FS.sm`, `C.textSecondary`.
- Порядковое слово для позиции 1–10: «первая», «вторая», … «десятая». Дальше — «{N}-я». Длину очереди пишем словами: «из трёх».
- «Ждёт запуска» без признака `slotFree` не рисуем: фича идёт как «в очереди · 1 из N». Это честнее, чем гадать.
- «Запущена из очереди»: событие в «Хронологии» (`BuildEvents`) — «Фича запущена из очереди · простояла {dur}». Глиф `run`, текст `C.textPrimary`.
- В шапке у фичи в очереди **главной кнопки нет**. «Снять паузу» не показываем: это и есть «вне очереди», только без предупреждения.

### Сегмент мини-полосы `queued`

Новый `SegmentKind` `queued` в `kindBackground` (`FeatureStatsBits.ts`):
`repeating-linear-gradient(90deg, ${C.textMuted} 0 1px, transparent 1px 4px), ${C.bgInset}`.
Засечки «по порядку» не путаются с диагональной штриховкой `notWorking`. Текст поверх — `C.textPrimary`. У открытого сегмента (`timeline.current`) — правая кромка `inset -2px 0 0 C.textSecondary`. Данные — `totals.queued` и интервал `held(queue)..hold_cleared(queue)` от бэка.

## Действия в ⋯

| Пункт | Когда | Ручка | Подтверждение |
|---|---|---|---|
| «В очередь…» (иконка lucide `ListEnd`) | `running`, `waiting`, `stopped`, `idle`, `not_started`, `draft`, `paused`+`manual` | `POST hold { reason: 'queue' }` | только если идут ходы |
| «Вынуть из очереди» (`ListX`) | `holdReason = queue` | `POST hold { reason: 'manual' }` | нет |
| «Запустить вне очереди…» (`Zap`) | `holdReason = queue` | `DELETE hold` | **всегда** |

- **Где «В очередь» нет:** `merge_pending` (уже уступила слот), `merging`, `merged`, `closed`.
- Подсказка под «В очередь…» (`sublabel`) — «Прервёт N идущих шагов — продолжатся при запуске из очереди», только при N > 0.
- Подсказка под «Вынуть из очереди» — «Фича встанет на паузу, место в очереди освободится».
- Подсказка под «Запустить вне очереди…» — «В обход порядка и лимита одновременно идущих фич».
- **Отдельный тон «Запустить вне очереди…».** Пункт стоит последним в группе действий, его отделяют черты сверху и снизу. Подпись и иконка — `C.warningText`. В `OverflowItem` нужен новый флаг `warning?: boolean` рядом с `danger`: те же правила, другой цвет. Не `danger`: действие обратимо и ничего не ломает.
- Порядок на 360: «В очередь…», «Поставить на паузу…», затем «Скопировать ветку» и «Открыть эпик». В очереди: «Вынуть», черта, «Запустить вне очереди…», черта, остальное. Пункты шторки — 44 px.
- На 1280 «В очередь…» — тоже в ⋯. Кнопку «Пауза» в шапке не трогаем.

**Решение, которое стоит проверить Александру.** В постановке «Вынуть из очереди» описано как «снять удержание вручную». Но `DELETE hold` запускает фичу, то есть это то же, что «Запустить вне очереди». Поэтому «Вынуть» я нарисовала как переход `queue → manual` (разрез §7: «вынуть из очереди и держать»). Ручка та же, `POST hold`, новых нет. Фича встаёт на паузу: из очереди ушла и не стартовала. Если задумано иначе — меняется одна строка таблицы.

### Подтверждения (`Modal`, `MODAL_W.confirm` = 380)

**«Поставить фичу в очередь?»** — только при идущих ходах:
- «Идущие шаги прервутся сразу: **{Персона} · {stepRef}** и …»
- `C.textSecondary`: «Фича встанет в конец очереди и запустится сама, когда до неё дойдёт черёд, — прерванные шаги продолжатся с того же места.»
- Кнопки: ghost «Отмена», primary «В очередь».

**«Запустить вне очереди?»** — всегда:
- «Фича стоит в очереди {порядковое}. Запуск в обход очереди поднимет её сразу, **сверх числа одновременно идущих фич**, заданного для проекта.»
- `C.textSecondary`: «Остальные фичи очереди сохранят порядок. Прерванные шаги продолжатся с того же места.»
- Кнопки: ghost «Отмена», primary «Запустить вне очереди» с иконкой `Zap`.

Общее для обеих: фокус при открытии на «Отмена», Esc закрывает. На 360 у кнопок высота 40, при нехватке места футер переносится.

### Кнопки и ответы

- loading — `Button loading`: «Ставлю в очередь…», «Вынимаю…», «Запускаю…». Повторный клик заблокирован. hover и focus — штатно у `Button`/`ToolbarOverflowMenu` (`C.bgSelected`, `SHADOW.focus`).
- Тосты успеха:
  - «Фича в очередь» → «Фича в очереди» / «{Порядковое} из {M}. Запустится сама, когда освободится место.»
  - Если бэк снял удержание сразу (место было свободно) → «Место было свободно» / «Фича запущена сразу, очередь не понадобилась.» Как узнать: после ответа `hold` уже `null`.
  - «Вынута из очереди» / «Фича на паузе. Вернуть в очередь или снять паузу — на странице фичи.»
  - «Фича запущена вне очереди» / «Продолжены N шагов, куратор в курсе.» При N = 0 — «Куратор в курсе.»
- Ошибка 409: тост с причиной из ответа. Фолбэк для `merging` — «Мерж уже идёт — его не останавливают посреди». Прочее — «Не получилось: {сообщение}».
- Оптимистично тег не меняем: страница обновится по событию агрегата.

## Карточка оркестратору при автоснятии

Отдельного компонента нет. Это та же авто-карточка (`AgentMessageView`, «Автоматически») в ключевом чате, что и «Пауза снята». Меняется только текст ветки `holdReason == queue` в `ResumeFeatureTurnsAfterHold`:

- продолжены шаги: «Фича запущена из очереди: продолжены N шагов. Разбери доклады, накопленные за ожидание.»
- шагов не было (фича стояла с черновика): «Фича запущена из очереди: удержание снято, фича активна. Начни конвейер по плану; разбери доклады, накопленные за ожидание.»
- вторая строка, если соседняя фича на `merge_pending` (смягчение из разреза §5): «Фича «{имя}» ждёт мержа: после её мержа сверь ветку с master.»

Ветки про `expired` такие же, как у паузы, только начинаются с «Фича запущена из очереди: …». Это текст бэка (шаг Q3), фронт его не трогает.

## Мобила и тёмная тема

- 360: тулбар держит только ⋯ (40). Тег — в мете, блок состояния — во всю ширину. Шторка ⋯: пункты 44, подсказки `FS.sm` `C.textMuted`. Плашка в чате переносит действие на вторую строку.
- Тёмная тема: `C.bgInset` темнее `C.bgWhite`, поэтому тег и блок выглядят утопленными, а кромка `C.border` держит контур. Засечки `C.textMuted` на `C.bgInset` различимы. `C.warningText` в тёмной теме — `#E7B96E` на `C.bgWhite`, контраст держится.
- Проверено в макете: 360 и 1280, обе темы, все четыре состояния, меню открыто и закрыто. Переполнений и ошибок консоли нет (прогон в headless Chromium).

## Тексты: чего не обещаем

- Лимит мягкий. Слова «одновременно идущих фич» — да. «Очередь держит GPU / нагрузку» — нет.
- Будущая подпись настройки (v1 — конфиг, UI нет): «Одновременно идущих фич».
- **Перестановки в v1 нет**: ни ручки для перетаскивания, ни пункта «Поднять выше». Перепоставить в конец = вынуть и поставить заново.

## Чего нет в API сейчас (для бэка)

- `queue?: { position, length }` в `FeatureRun` и `FeatureIndexRow` — по контракту, шаг Q1.
- `queue.slotFree?: boolean` — для состояния «ждёт запуска». Без него состояние не рисуется (см. выше). Предлагаю добавить в Q1 рядом с `position`: функция `OccupiesSlot` и лимит уже под рукой.
- `totals.queued` и интервалы `queued` в таймлайне — шаг Q3.
- Признак автоснятия в событиях ленты (`by: "queue"`) — шаг Q3.
