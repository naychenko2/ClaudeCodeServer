# Видео

Прямые эфиры телеканалов и лента подписок YouTube — панелью рельсы и центральным
островом, рядом с работой. Отдельного раздела хаба нет (см. «Панель и центральный
остров»).

## Зачем именно так

Задача звучала как «панель, где я авторизуюсь в свой аккаунт и смотрю, плюс российские
каналы». Разведка показала, что буквально это не реализуемо, и всё построено вокруг
двух ограничений, которые снять нельзя.

**Встраиваемый плеер YouTube всегда анонимен.** Персонализация в него не пробрасывается
ни при каких настройках: сторонние куки режет браузер, а сам embed по устройству не тянет
сессию аккаунта. История просмотра закрыта и в Data API (`activities` не отдаёт watch
history с 2016 года). Поэтому провайдер отвечает за КАТАЛОГ — подписки и что на них
вышло, — а воспроизведение отдаётся штатному embed. Просмотр в аккаунте не засчитывается.

**Видеопоток идёт мимо сервера.** При embed браузер тянет видео напрямую с
`googlevideo.com`, инстанс в этой цепочке не участвует вовсе. Значит замедление YouTube
ловит клиент, и серверный прокси его не лечит: через egress-прокси у нас едут только
метаданные (единицы килобайт). Обход блокировок остаётся на стороне устройства —
осознанная граница ответственности, а не недоделка.

## Источники

| Источник | Что даёт | Обход блокировок |
|---|---|---|
| `smotrim` (ВГТРК) | 20 телеканалов с программой передач, три из них играют внутри | не нужен |
| `youtube` | лента подписок, плеер embed | нужен на клиенте |

### Почему СМОТРИМ, а не Rutube или «Витрина ТВ»

Проверено живым браузером в августе 2026:

- **Rutube** транслирует те же федеральные каналы, но встраивание эфира запрещает
  правообладатель: `rutube.ru/play/embed/{id}` для ТВ-канала отвечает заглушкой
  «Видео можно посмотреть только на RUTUBE». Обычные ролики при этом встраиваются.
- **«Витрина ТВ»** — единый легальный вещатель федеральных каналов в интернете, но её
  плеер и SDK раздаются только по B2B-договору.
- **СМОТРИМ** отдаёт плеер без `X-Frame-Options` и `frame-ancestors` — единственный
  проверенный путь смотреть федеральные каналы внутри своего интерфейса.

### Каталог СМОТРИМ и признак играбельности

Эндпоинта со списком каналов у сервиса нет (`/api/v1/channels` → 404), поэтому каталог
из 20 id зашит таблицей в [SmotrimCatalog.cs](../../backend/ClaudeHomeServer/Services/Video/SmotrimCatalog.cs)
в порядке кнопок телевизора (первый и второй мультиплексы РТРС). Названия там — фолбэк
на случай, когда карточка канала не ответила: **список обязан отрисоваться целиком даже
при частичном отказе**, иначе один таймаут выносит весь каталог.

Собственный поток (`streams.m3u8` в карточке) есть только у каналов ВГТРК — Россия 1,
Россия 24, Россия К. Остальные 17 на самом сайте играются плеером «Витрины» по
домену-реферреру (`player_referer_hostname=smotrim.ru`). **Признак `Embeddable`
вычисляется из ответа, а не хардкодится списком id** — сегодня их три, завтра может
стать больше. Каналы без потока показываются карточкой с программой передач и уводят
на сайт сервиса.

Подделывать реферер, чтобы получить поток «Витрины», мы не будем: защита стоит ровно
против этого.

## Устройство

Источники живут за `IVideoProvider` и реестром `VideoProviderRegistry` — контроллер
знает про них только ключ, новый источник добавляется регистрацией в DI. Ненастроенный
провайдер (пустые ключи) вкладку не получает вовсе, как выключенный `LlmProvider`.

**Egress-прокси по умолчанию включён** для всех HTTP-клиентов приложения, и для этого
раздела разница принципиальная:

- клиент СМОТРИМ — `.WithoutEgressProxy()`: сервис российский, через заграничный прокси
  он как минимум не обязан отвечать;
- клиент YouTube — БЕЗ этого вызова: его API из России напрямую недоступен.

Отказы разведены классами (`VideoFailure`), и каждому в интерфейсе отвечает своё пустое
состояние: «подключите аккаунт», «кончились запросы», «сервис не отвечает». Общая
формулировка заставляла бы человека гадать, что нажимать.

Списки запрашиваются с `live: true` — офлайн-кэш здесь вреден: у карточки есть поле
«сейчас в эфире», и подставленный из IndexedDB ответ показывал бы передачу получасовой
давности как текущую.

Кнопка «Обновить» шлёт `refresh=true`, и провайдер пропускает ЧТЕНИЕ кеша (запись
остаётся). Без этого нажатие не меняло бы ничего — а жмут её как раз тогда, когда пусто.

### Что здесь легко сломать

- **Пустой список ≠ отсутствие содержимого.** Если сервис не ответил, а лента пуста,
  провайдер обязан вернуть отказ, иначе панель скажет «свежих роликов нет» при лежащем
  YouTube. Неполный сбор кешируется на минуту, а не на полный TTL: вернувшийся сервис
  не должен ещё полчаса показываться огрызком.
- **`NeedsAuth` — только на 401.** У 403 причин много (закрытый канал в подписках даёт
  `playlistItemsNotAccessible`), и «подключите аккаунт» отправило бы человека
  переподключать живой аккаунт в тупик.
- **Query внутри хеша.** Возврат из Google приходит на `#/chats?connect=ok`, поэтому
  `parseHash` срезает `?` ДО разбора сегментов. Без этого первым сегментом становится
  `chats?connect=ok`, роутер не узнаёт экран и молча уводит на дашборд.
- **Плашка поверх обложки — токен `C.mediaScrim`**, а не `C.glass`: последний зависит от
  темы и в светлой становится белым, отчего белый значок на белом логотипе исчезает.
  Тот же принцип, что у чёрных полей вокруг кадра, — это свойство медиа, а не интерфейса.

## Панель и центральный остров

Отдельного раздела хаба у видео НЕТ — всё живёт рядом с работой:

- **панель `video`** в рельсе — сам эфир. Это фоновый просмотр. Есть и в проекте
  (`WORKSPACE_KEYS`), и в разделе «Чаты» (`CHAT_KEYS`), домашняя зона правая:
  слева список чатов, и эфир отнимал бы место у навигации.
- **центральный остров** — тот же, где открывается файл. В нём показывают кадр
  крупно ИЛИ выбирают канал в каталоге (`VideoPicker`: телеканалы и лента
  подписок, кнопка в шапке панели «Видео»).

**В теле панели — только кадр.** Полоса каналов живёт в ЛЕВОМ слоте шапки
(`PanelHeaderSlot side="left"`) — это переключатель вида, «что смотрим», и у имени
панели он читается как продолжение заголовка. Панель узкая, и каждый её пиксель
нужен кадру. Следствие, которое пришлось закрыть отдельно: контролы шапки в покое
приглушены, то есть **до наведения каналов не видно** — пустой кадр упирался бы
в «выберите канал» без единой кнопки рядом. Поэтому в пустом кадре стоит явная
кнопка «Выбрать канал», открывающая каталог.

**Панель отражает то, что реально идёт**, а не только собственный выбор: канал,
выбранный в КАТАЛОГЕ, панель своим не считала и писала «выберите канал», пока эфир
шёл в двух шагах правее. Теперь отображаемый канал — это `staged?.channel ?? own`,
а свой плеер панель заводит только под own (уехавший кадр рисуют центр или окно).

Каталог успел побывать разделом хаба и панелью рельсы; и то и другое мимо. Раздел
уводил из работы — удалён целиком (вместе с `HubTab`, экраном в `nav.ts` и маршрутом
`#/video`), чтобы не осталось двух входов в одно и то же. Панель рельсы узкая, а
каналы выбирают ГЛАЗАМИ, по обложкам, — потому каталог и переехал в центр.

**Инвариант: центральный остров занимает РОВНО ОДИН обитатель** — кадр или каталог.
Правило живёт одной точкой (`getVideoCenter`), а не складывается на каждой странице
заново: две страницы неминуемо разошлись бы в трактовке. Открытие каталога возвращает
развёрнутый кадр в панель (там он и продолжит идти), разворот кадра закрывает каталог,
а плавающее окно не трогает ни то ни другое — оно не в центре.

**Три места показа.** Кадр в панели маленький — она для фона. Из панели канал
переносится в одно из двух мест, и обратно в панель возвращается тем же нажатием:

| Режим | Что это | Переживает переход между страницами |
|---|---|---|
| панель | кадр в рельсе, фоном | — (живёт внутри страницы) |
| центр | остров во ВСЮ ширину центра (кадр или каталог) | нет |
| плавающее окно | двигают за шапку, тянут за угол | **да** |

**Центр видео занимает всю ширину — и кадр, и каталог.** Кадр успел побывать вторым
островом рядом с лентой (split, как у файла) — не прижилось: в узкой половине от него
мало толку, а разворачивают его как раз тогда, когда хотят СМОТРЕТЬ, а не переписываться.
Для «смотреть краем глаза, продолжая работать» есть панель рельсы, она рядом. У каталога
причина та же по форме, но своя по сути: каналы выбирают глазами, по обложкам, и в
половине ширины остаётся одна карточка в ряд, а во всю — четыре, то есть весь список из
20 почти без прокрутки. Свернуть — крестиком или Escape.

**Выбор канала в каталоге отправляет эфир в БОКОВУЮ ПАНЕЛЬ, а каталог оставляет
открытым.** Выбор канала — не конец дела, а перебор: закрывать ради него единственное
место, где виден весь список, незачем; эфир идёт сбоку, и следующий канал выбирают тут
же. Исключение — плавающее окно: если смотрят в нём, канал подхватывает оно (окно и есть
«где смотрят»).

Отсюда требование к состоянию: **канал боковой панели живёт в СТОРЕ, а не внутри самой
панели**. Каталог стоит в центре и до локального состояния панели не дотянулся бы. Там же
закрывается и вторая дыра: панель могла быть закрыта или лежать в ящике рельсы, и канал
ушёл бы в невидимое место — поэтому стор просит показать панель событием
(`VIDEO_PANEL_EVENT`), а являет её страница: раскладка — её епархия, стор про зоны и
рельсы ничего не знает.

**«Вернуть кадр в панель» реально возвращает кадр**, а не гасит его: канал, который
смотрели в центре или в окне, переезжает в панель и продолжает идти там. Это касается
всех путей — кнопки, крестика, Escape, прихода каталога и занятия центра файлом.

**Шапка острова общая у кадра и каталога, и устроена как шапка панели рельсы.**
Содержимое кладёт свои контролы через тот же `PanelHeaderSlot` — остров даёт этот слот
сам (`PanelHeaderSlotContext`), поэтому «Обновить» и переключатель ТВ/YouTube живут
в ШАПКЕ, а тело остаётся целиком под обложки; своего механизма «поднять кнопку наверх»
заводить не пришлось. Закрытие — не отдельной кнопкой справа, а **крестиком поверх
иконки слева, под курсором**: тот же приём, что у панелей (`PanelShell`), шапка не
тратит на него места. Наведение слушается НАТИВНО — контролы приезжают порталом, и с
react-пропсами переход курсора на кнопку читался бы как уход с шапки, отчего крестик
мигал бы.

**Остров уступает чужим режимам.** Открыли файл, задачу, доску, граф — эфир уходит
обратно в панель, каталог закрывается. Страница публикует занятость центра одним
вызовом `setVideoCenterBlocked`, а не колбэком в каждом из девяти открывателей: те
раскиданы по `WorkspacePage`, и один забытый вызов дал бы два острова в одном месте
раскладки.

Знать про занятость обязан именно СТОР, а не только страница. Первая версия гасила
эфир эффектом по признаку «центр свободен», и у неё была дыра: центр, занятый
**заранее**, признака не менял — эффект не срабатывал вовсе. Нажатие «развернуть
в центре» при открытом файле проходило молча: панель снимала свой плеер (кадр же
«уехал»), центр рисовал файл, и эфир пропадал целиком, без единого следа на экране.
Теперь запрет живёт в сторе: он и выселяет видео при занятии центра, и **гасит обе
ведущие туда кнопки** — «развернуть в центре» и «все каналы и лента», с подсказкой,
почему они недоступны. Кнопка «в центр» в плавающем окне гейтится тем же признаком
(вместе с проверкой, что у экрана вообще есть центр).

**Кнопки паузы нет ни в панели, ни в центре.** У прямого эфира паузы не бывает: кадр
пришлось бы снять целиком, а вернувшись — попасть в текущую минуту. «Пауза», после
которой нет продолжения, только врёт; для того же эффекта есть крестик.

**Плавающее окно рендерится в `App`, НАД страницами** — это единственный режим, который
переживает переход между проектами и разделами: кадр не размонтируется, эфир не
начинается заново. Панель и центральный остров так не умеют, они часть страницы. Пропорция 16:9
держится жёстко (тянут только ширину, высота считается), геометрия хранится в
`localStorage` и приводится в границы экрана при каждом изменении размера окна браузера —
иначе окно, пережившее смену монитора, оказалось бы за краем и стало недоступно.

Отдельная деталь: **на время перетаскивания экран накрывается прозрачным слоем**. Курсор
идёт над чужими iframe (само видео, «Сервисы», проброс телеметрии), а те съедают
`pointermove` — без слоя жест обрывается на первом же кадре под курсором.

Состояние держит [videoStage.ts](../../frontend/src/lib/videoStage.ts) — общий стор,
а не состояние страницы: режим переключает панель (она в рельсе), а рисуют центр
(`ChatsPage` / `DesktopWorkspace`) и окно (`App`). **Живой кадр в продукте ровно один:**
панель снимает свой плеер, как только канал ушёл в центр или в окно, — два живых iframe
одного эфира дают два звука внахлёст.

В полосу каналов панели попадают **только играбельные** — карточки-ссылки на чужой
сайт в узкой колонке смысла не несут; они остаются в каталоге.

### Звук: почему «снимаем», а не «приглушаем»

Плеер СМОТРИМ **не слушает `postMessage`** от родительской страницы и не принимает
параметров звука в адресе — проверено по его коду. Управлять громкостью чужого iframe
браузер не даёт. Поэтому на время, когда звук занят продуктом, эфир **снимается**
(iframe размонтируется), а вместо кадра стоит подпись «Эфир приостановлен — идёт
разговор». Для ПРЯМОГО эфира это честная замена приглушению: вернувшись, попадаешь
в текущую минуту, а не в пропущенную.

Занятость звука сообщает [audioFocus.ts](../../frontend/src/lib/audioFocus.ts) —
маленький стор с подпиской. Клеймят его две стороны: `lib/tts` (озвучка ответа, включая
штатное окончание очереди, а не только `stopSpeaking`) и `ChatPanel` (весь режим
разговора целиком, включая паузы между репликами — микрофон в них открыт). Опрос
`isSpeaking()` в таймере был бы дешевле, но реакция запаздывала бы на такт опроса.

Для ленты YouTube снимать плеер не нужно: у него есть
штатный API управления, там уместен настоящий mute без потери позиции.

## Квота YouTube

Суточный лимит Data API — 10 000 единиц, поиск стоит 100 за запрос, поэтому поиском
лента не строится вовсе:

1. `subscriptions.list` — подписки (1 единица за страницу по 50);
2. плейлист загрузок выводится из id канала (`UC…` → `UU…`) — вызов `channels.list`
   ради этого не нужен, при сотне подписок он стоил бы сотню единиц;
3. `playlistItems.list` — по 1 единице на канал.

Обход ограничен `Video:YouTube:MaxFeedChannels` (по умолчанию 40), срезанное пишется
в лог: «показали всё», когда показали не всё, — худший вид молчания. Лента кешируется
на `Video:YouTube:FeedTtlMinutes` (30).

## OAuth и его подводный камень

Токены лежат в общем per-owner сторе секретов (`McpSecretStore`) под фиксированным id
`video-youtube`. Стор не привязан к MCP по сути — это хранилище значений с полями OAuth,
уже исключённое из облачного архива через `BackupPaths.SecretFileNames`; заводить второй
такой же было бы дублем.

**Следствие:** восстановление бэкапа на другой машине подключение не перенесёт —
секреты в облачный архив не уезжают, аккаунт придётся подключить заново.

**Статус приложения в Google — обязательно `In production`.** Пока OAuth-приложение
в режиме Testing, refresh-токен протухает через 7 дней, и лента молча умирает раз
в неделю: раздел покажет «подключите аккаунт» при живых ключах.

Лечится кнопкой `Publish app` на экране `Audience`, и **верификация для этого не нужна**.
Скоуп `youtube.readonly` считается чувствительным, поэтому у неодобренного скоупа
в Production остаются две вещи: экран «Google не проверил это приложение» при подключении
и потолок в 100 пользователей. Для личного инстанса ни то, ни другое роли не играет,
а 7-дневное протухание снимается. Верификация (подтверждение домена, политика
приватности) нужна только чтобы убрать предупреждение и снять потолок.

Что всё равно отвяжет аккаунт: полгода без единого обращения к API (политика Google
для простаивающих токенов) и ручной отзыв доступа в настройках аккаунта.

Возврат из согласия (`/api/video/youtube/callback`) анонимный: это переход браузера,
нашего токена в нём нет — владелец опознаётся по одноразовому `state`, выданному при
старте входа и живущему 10 минут в памяти процесса.

Отключение аккаунта отзывает токен У GOOGLE (`oauth2/revoke`), а не только стирает
запись: иначе выданный доступ остался бы висеть в настройках аккаунта человека, который
его отключил. Отзыв — best effort: не прошёл, запись всё равно удаляется.

## Настройка

Секция `Video` в `appsettings.Local.json` (образец — `appsettings.Local.example.json`):

```json
"Video": {
  "YouTube": {
    "ClientId": "<client-id>.apps.googleusercontent.com",
    "ClientSecret": "GOCSPX-<секрет>",
    "RedirectUri": "http://localhost:5000/api/video/youtube/callback"
  }
}
```

Ключи берутся в Google Cloud Console: включить **YouTube Data API v3**, на экране
согласия добавить скоуп `youtube.readonly` и себя в Test users, затем создать
**OAuth client ID** типа Web application. В нём обязательно зарегистрировать все
адреса возврата — они должны совпадать с `RedirectUri` посимвольно:

- `http://localhost:5000/api/video/youtube/callback` — локальная разработка;
- адрес боевого инстанса с тем же путём.

Пустые ключи выключают только вкладку YouTube — эфиры телеканалов работают без них.

## API

| Метод | Назначение |
|---|---|
| `GET /api/video/providers` | доступные источники и какой просит вход |
| `GET /api/video/channels?provider=&refresh=` | каналы: телеканалы или подписки |
| `GET /api/video/feed?provider=&channelId=&refresh=` | лента роликов (сводная или по каналу) |
| `GET /api/video/youtube/auth-url` | адрес согласия Google |
| `GET /api/video/youtube/callback` | возврат из согласия (анонимный, по `state`) |
| `POST /api/video/youtube/disconnect` | отключить аккаунт |
