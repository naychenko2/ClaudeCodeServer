# Уборка карты проекта — тексты интерфейса и продуктовые решения

**Статус:** реализовано, за фич-флагом `project-map-hygiene` (`Default: false`, dark launch).
**Источник правды по контракту и разведке кода:**
[docs/research/project-map-hygiene-plan-2026-09.md](../research/project-map-hygiene-plan-2026-09.md)
(редакция 3, там же — таблица Майи с текстами и полный контракт записи).
**Вердикт финального ревью:** ПРИНЯТО (Александр, 22.09.2026, заметка проекта «Финальное
ревью фичи „уборка карты проекта" — вердикт»); 421 тест зелёный.

**Польза одной фразой:** корневой `CLAUDE.md` грузится в контекст каждой сессии — кнопка
показывает, что в нём раздулось, что протухло и что можно свернуть в ссылку, вместо того
чтобы узнавать об этом по счёту токенов постфактум.

## 1. Как это устроено (для чтения текстов интерфейса)

Две фазы, разделённые намеренно:

1. **Сканер** — детерминированный код, без модели и без трат. Мгновенно считает размер
   (строки/байты/≈токены), длинные секции, мёртвые ссылки, вложенные карты, мёртвые
   `@`-импорты. Эта половина отчёта не ждёт модель и показывается сразу.
2. **Формулировки модели** — one-shot по **отчёту сканера**, а не по самому файлу: сам файл
   (~33 000 токенов у нашей карты) в окно дешёвого профиля не влезает, отчёт сжат в 40 раз.
   Модель не открывает `CLAUDE.md`, она комментирует уже посчитанные факты.

**Механические правки формирует сканер, а не модель.** Это не соглашение, а форма ответа:
из JSON модели разбираются ровно три поля — `id`, `severity`, `modelSays`. Патч (`apply`),
факт, якорь и вид находки в схеме разбора отсутствуют — модели неоткуда их подделать, даже
если она попытается. Предложение с `id`, которого нет в свежем скане, выбрасывается целиком.

## 2. Тексты интерфейса

### 2.1. Вход первый — настройки проекта

Аккордеон «Карта проекта (CLAUDE.md)» в `EditDialog`, сводка в заголовке аккордеона:

| Состояние | Текст |
|---|---|
| Загрузка | Проверяю размер карты и состояние ссылок… |
| Ошибка сети | Сервер не ответил — попробуйте ещё раз. / кнопка «Проверить снова» |
| Карты нет | В корне проекта нет `CLAUDE.md`. Ассистент сам создаст его при первом знакомстве с проектом. |
| Карта в порядке | сводка аккордеона: «Карта в порядке» |
| Есть замечания | сводка аккордеона: «N замечание/замечания/замечаний»; кнопка «Проверить карту проекта» |

Подзаголовок модалки — дословно по таблице Майи: **«CLAUDE.md · N строк · N КБ · ≈N токенов
в каждой сессии»**.

### 2.2. Вход второй — снимок промпта чата

Кнопка **«Прибраться»** в строке корневого `CLAUDE.md` в `PromptSnapshotDialog` (панель «Что
уехало в контекст этого хода»). Это горячий путь: человек уже смотрит, кто съел контекст, и
видит карту на 98 КБ — вопрос «а что тут можно прибрать» возникает ровно в этот момент.

### 2.3. Модалка «Уборка карты проекта»

Шапка — три метки: «N секций/секции длиннее N строк» (warning), «N мёртвая/мёртвых
ссылка/ссылок» (danger), «Ориентир: до N строк[· превышен]» (neutral). Процента «N % от
нормы» нет намеренно — у большого проекта карта объективно больше, и приговор в процентах
обесценивает отчёт.

Тело — один список, **две группы, не табы**: «Правки в один клик · N» (у предложения есть
готовый `apply`) и «Работа для чата · N» (кнопка «Разобрать моделью» / «Переразобрать»,
пока идёт — «Модель думает»). У предложений без `apply` чекбокса нет вовсе — галочка, которая
ничего не делает, врёт сильнее любой подписи. Подвал «Ещё в проекте» — вложенные карты
справочно, без плашек и без действий (вложенная карта — не дефект, а правильный приём).

Пустые и особые состояния:

| Состояние | Текст |
|---|---|
| Карты нет | Карты проекта пока нет. Ассистент создаст её при первом знакомстве с проектом. |
| Замечаний ноль | Карта в порядке |
| Модель не ответила / битый JSON | «Модель не дала формулировок: …» + кнопка «Повторить» (факты сканера остаются на экране) |
| Файл изменился с момента скана (409) | «Файл изменился после проверки — отметки могут указывать на старые строки.» + «Проверить заново» |
| Применили частично | «Применили N правку/правок.» / «Не вышло: N правка/правок.» с построчными причинами |

Причины отказа применения — человеку, не кодом: «якорь не найден в карте (правку уже
внесли или текст переписали)», «якорь встречается несколько раз — куда писать решает
человек», «предложения с таким id нет в свежем скане», «механической правки у этого
предложения нет по его виду».

Кнопка футера — **«Применить отмеченное · N»**, активна только когда что-то отмечено
(чекбоксы по умолчанию сняты — предотмеченная галочка не «явное утверждение человека»);
рядом — «Отметить все» / «Снять отметки».

## 3. Почему вынос секции кнопкой не делается никогда

Кнопкой применяется ровно один вид находки — мёртвая ссылка с одним кандидатом и уникальным
якорем вне ```-заборов. Вынос длинной секции в `docs/*` — содержательная работа: решение,
пересказывает ли раздел уже существующий документ или фиксирует инвариант, оплаченный
инцидентом, принимает человек, а не эвристика. Цена ошибочного автоматического выноса —
потеря знания, которое стоило продукту реального инцидента; это дороже, чем польза от лишней
кнопки. Той же причиной объясняется отсутствие фонового процесса, который «сам следит за
гигиеной»: измеримого критерия «знание не потеряно» нет, а есть только человек, который
может это оценить.

## 4. Фич-флаг

`project-map-hygiene` (`FeatureFlagCatalog`, `Default: false`, `Stage: "dev"`). Гейтит
**запись и модель** (`review`, `apply` — 404 при выключенном флаге, «фичи не существует»,
а не 403); `scan` открыт без гейта — он ничего не меняет и не стоит денег. Пока флаг
выключен у пользователя, ручка `apply` для него недостижима даже прямым запросом — открытая
ручка записи в `CLAUDE.md` при незавершённой фиче была бы лишним риском.

## 5. «Что нового»

Продуктовая история «Что нового» — AI-сводка коммитов по дням, а не список ручных записей;
коммиты волн уже попадут в неё автоматически как обычные изменения кода. Отдельного,
пользовательского анонса фичи сейчас не нужно: флаг выключен по умолчанию (`Stage: "dev"`),
значит для подавляющего большинства пользователей фичи не существует — анонсировать нечего.
Решение — то же, что у соседних dark-launch флагов (`chat-auto-archive`, `mcp-catalog`,
`visual-plan`): анонс имеет смысл после снятия флага, когда фича действительно доступна.
