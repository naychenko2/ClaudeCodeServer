# Адаптивный UI планшета — предложение

Макет: [tablet-adaptive-v1.html](tablet-adaptive-v1.html) (пять состояний A–E, переключатель темы, фреймы 768/480).

## Проблема

Пользователь работает на планшете в портрете (~768px, диапазон 601–1199px — «tablet» по `breakpoints.ts`). Четыре сценария ломаются:

1. **Левая панель чатов** открывается в потоке и сжимает ленту: панель 300px на окне 768px съедает 39% ширины, текст чата перестраивается, чтение сбивается.
2. **Правые панели** (Файлы, Документация) открываются оверлеем, но уползают за нижний край экрана: скролла нет, низ панели недостижим.
3. **Пилюли разделов** («Чаты | Проекты | Календарь | Заметки | Персоны») не влезают и налезают друг на друга.
4. **Хедер чата** переносит чипы контекста/стоимости на 2–3 строку (высота съедает ленту), а **гит-бар** (`ProjectGitBar`: ветка/worktree, diff, «Зафиксировать», «Опубликовать N») держит десктопную версию целиком — 51px + поля ≈ 69px по вертикали и длинные подписи кнопок по горизонтали.

Корень общий: диапазон 601–1199px в этих четырёх местах идёт по десктопной ветке, хотя готовые компактные механики в коде уже существуют — они просто не включены для планшета.

## Принцип решения

Не строим новых механик — **расширяем существующие на диапазон планшета**. Почти в каждом месте решение уже лежит рядом и работает на мобиле:

| Проблема | Существующая механика | Что делаем |
|---|---|---|
| #1 Левая панель | drawer-режим правой `PanelZone` (compact) | Включаем левой зоне + правило 30% |
| #2 Уползание drawer | контракт высот `PanelSlot`/`PanelShell` | Добавляем `minHeight: 0` в цепочку + форс-fill |
| #3 Пилюли | `PillSwitch.autoCompact` + мобильная скролл-полоса | Включаем обе ступени на планшете |
| #4а Хедер | `MobileCombinedBadge` + wide-поповер `BadgeShell` | Порог `isMobile` → `isCompact = isMobile \|\| isTablet` |
| #4б Гит-бар | иконки lucide внутри кнопок уже есть | Компактный вариант: 44px, действия иконками, подписи схлопнуть |

## Спецификация для реализации (Кира)

### Новый токен порога

`frontend/src/lib/breakpoints.ts`:

```ts
// Максимальная доля ширины окна, которую боковая панель может занять в потоке.
// Больше — панель открывается оверлеем (drawer), не двигая контент.
export const PANEL_INLINE_MAX_SHARE = 0.3
```

Правило: панель шириной `w` на окне `W` идёт inline, только если `w / W <= PANEL_INLINE_MAX_SHARE` (drawer, когда `W < w / 0.3`). Для панели ~300px это даёт порог 1000px — существующий `TABLET_INLINE_MIN = 1000` в `PanelZone.tsx:51` фактически совпадает; заменить литерал на производную от токена через `useWindowWidth()`.

### #1 Левая панель — оверлей (состояние A)

- `DesktopWorkspace.tsx:311-326` — левой `PanelZone` передать `compact={p.isTablet}` (у правой уже есть, строка 459).
- Оверлей: **без затемнения** — backdrop `PanelZone.tsx:1236` на планшете становится прозрачным клик-кетчером (`background: 'transparent'`), дим `C.overlay` остаётся только на мобиле ≤600px (там шит почти полноэкранный, модальность нужна). Панель читается как плавающая карточка: `boxShadow: SHADOW.modal` + рамка, z 14/15 как у правого drawer. Ширина `min(85vw, 380px)` — как у правого.
- Почему не «окна» под тулбары в диме: вырезать светлые дырки под хаб-бар/хедер чата/композер — лоскутно и хрупко (каждая новая полоса хрома ломает вырез); недимминговый drawer — стандартный slide-over планшета, хром остаётся живым.
- **Состояния:** тап вне панели (кетчер) и ✕ — закрытие; чат под drawer неподвижен и не гаснет (никакого reflow ленты, тулбары кликабельны); тёмная тема — без изменений (дима нет в обеих).

### #2 Правые оверлеи — полная высота (состояние B)

- `PanelZone.tsx` ~1190–1201 — drawer-стеку добавить `minHeight: 0` (главная правка: без неё flex-ребёнок растёт по контенту и выталкивает панель за пределы drawer, канвас с `overflow: clip` режет низ).
- В drawer-режиме форсировать `stretched/fill = true` для панелей (`renderPanel` ~803): drawer одноколоночный полноэкранный, fill-путь уже даёт контентной зоне `PanelShell` (`flex: 1, minHeight: 0, overflow: hidden`) собственный скролл.
- **Состояния:** шапка панели липкая сверху; скролл только в теле; длинный список файлов достижим до конца; пустая панель — empty state по центру, как inline.

### #3 Пилюли — двухступенчатая деградация (состояние C)

- Полный ряд на планшете — **только текст, без иконок** (как на десктопе): каждая иконка — это ~24px лишней ширины на пилюле, без них пять разделов влезают в 768px. Реализация: в `PillSwitch` иконка из опции рендерится только в compact — `showIcon = iconsOnly ? true : (effectiveCompact ? opt.value !== value : !autoCompact)` (`ui/PillSwitch.tsx:261`); скрытый эталон-пробник (`:218-225`) меряет текстовый ряд — иконку из него убрать. Опции `HubTabs` иконки по-прежнему несут — они нужны compact-режиму.
- Ступень 1: `HubTabs` на планшете получает `autoCompact` (`ui/PillSwitch.tsx:44-66` — скрытый полнотекстовый эталон + ResizeObserver; compact = иконки + подпись активного сегмента). **Порог срабатывания — раньше:** запас до края 6px → **24px** (`probe.offsetWidth > track.clientWidth - 24`, `:60`) — compact включается до того, как ряд визуально прижмётся к краям хедера.
- Ступень 2: не влезает даже compact → скролл-полоса из мобильной ветки `HubHeader.tsx:211-219`: `overflowX: auto`, `cc-no-scrollbar`, без переноса, fade-градиенты краёв `C.bgMain → transparent` + `ToolbarOverflowMenu` «Разделы» со всеми табами.
- Высота хедера не меняется (`TB.heightDesktop = 52`). Порог — существующий `isTablet` (`HubHeader.tsx:56-57`). Мобила (≤600px) не меняется: там compact включён сразу (`compact={mobile}`).
- **Состояния:** каждый сегмент — tap-цель ≥36px по высоте; активный таб в скролл-полосе автопрокручивается в видимую зону при смене раздела; у иконочных сегментов в compact — `title` с названием раздела.

### #4а Хедер чата — объединённый чип (состояние D)

- `ChatHeaderBar.tsx`: ввести `isCompact = isMobile || isTablet` и использовать вместо `isMobile` в `costBadges` (~1274): планшет получает `MobileCombinedBadge` (645–745) + `spendBadge`; отдельные `ctxBadge/providerCostBadge/FalCostBadge/GlifCostBadge` не рендерятся.
- Поповер — мобильный wide-вариант `BadgeShell` (fixed к правому краю, `width: min(340px, calc(100vw - 16px))`, `maxHeight: calc(100dvh - 130px)`, скролл) — уже реализован по флагу, прокинуть `isCompact`.
- `rightCluster` (~1347-1354): `flexWrap: 'wrap'` оставить только десктопу >1199px; на планшете одна строка, `titleMinW = 0` (заголовок многоточием), action-кнопки плотной группой как на мобиле.
- Тон чипа — худший из контекста/расхода (логика `worseTone` уже в `MobileCombinedBadge`); прогресс workflow втянут в чип, как на мобиле.

### #4б Гит-бар — компактная строка (состояние E)

Сейчас планшет попадает в десктопную ветку гейта `ChatPanel.tsx:1919` (`{project && !isMobile && !embedded && <ProjectGitBar …/>}`) и получает бар целиком: высота 51px + margin 10/8 ≈ 69px, кнопки «Зафиксировать» (с текстом и ChevronDown) и «Опубликовать N». На 768px это самая тяжёлая полоса над композером.

- `ProjectGitBar.tsx:95-102`: ввести `isCompact = isTablet` (из `useWindowWidth`/`breakpoints`); компактная геометрия — `height: 44`, `margin: '6px 0'`, `gap: 8`. Итого ~56px вместо ~69px.
- **Метка ветки — не трогаем** (`:104-121`): иконка `GitBranch`/`FolderGit2` 15px + mono-подпись с многоточием + бейдж `↓{behind}`. Это ценность бара («в какой ветке мы работаем»), её потеря хуже сэкономленных пикселей.
- Сегмент дерева хода (`:126-147`): `maxWidth: 220 → 140` на планшете, остальное как есть (пульс-точка `C.info`, title с путём).
- Diff-пилюля `+N/−M` (`:152-167`): без изменений, только `height: 28 → 32` под палец; клик-цель — вся пилюля.
- «Зафиксировать» (`:171-214`): на планшете — иконочная кнопка 36×36 (`TB.iconHitMobile`-плотность): только `Check` в `C.accent`, без подписи и `ChevronDown`. Тап открывает **то же** меню области коммита (`Menu` с «Только этот чат» / «Всё дерево» / «Стиль сообщений коммита…») — состав меню и `CommitPromptDialog` не меняются.
- «Опубликовать N» (`:217-233`): акцентная кнопка `height: 36`, содержимое — `CloudUpload` + mono-число N (без слова «Опубликовать»); `PublishDialog` по тапу без изменений.
- Строка ошибки (`:240-251`) — без изменений. На мобиле (≤600px) бар по-прежнему скрыт — там нет панели «Изменения».
- **Состояния:** все кнопки — tap-цели ≥36px; у иконочных кнопок обязателен `title` («Зафиксировать изменения», «Опубликовать (git push)»); длинная ветка режется многоточием до кнопок — кнопки `flexShrink: 0`, метка `minWidth: 0` (уже так).

**Ступень 2 — сворачивание по умолчанию (микрострока):**

- На планшете бар по умолчанию **свёрнут в микростроку** 28px (+ поля 4/4 ≈ 36px): иконка ветки 14px + mono-метка с многоточием + `↓behind`, справа индикаторы `+N −M` (тоны diff) и `↑ N` публикаций в `C.accent`, шеврон `ChevronDown` как подсказка «разворачивается». Вся строка — одна tap-цель (`role="button"`, `title="Показать гит-действия"`): тап разворачивает slim-бар.
- В развёрнутом slim-баре справа — шеврон `ChevronUp` 28px «Свернуть».
- Выбор запоминается в `localStorage` (`cc-gitbar-collapsed`); дефолт: планшет — свёрнуто, десктоп — развёрнуто (сворачивание десктопу тоже доступно тем же шевроном, но дефолт не меняем).
- Правило видимости (`:72`) усиливаем для планшета: `diff.files === 0 && !canPublish && treeActive` → только микрострока с веткой (ответ «где мы работаем» доступен всегда, но действий нет — и разворачивать нечего); совсем пусто → бар скрыт, как сейчас.
- Индикаторы в микростроке — не кликабельны по отдельности (одна зона тапа), действия — только в развёрнутом баре: на тач-экране дробить 28px на четыре цели нельзя.

### Общее

- **Токены:** всё из шкалы — `C.*`, `FS`, `SP`, `R`, `SHADOW`, `TB`, `Z`. Новых значений мимо шкалы нет; новый только токен порога `PANEL_INLINE_MAX_SHARE` в `breakpoints.ts`.
- **Тёмная тема:** правки геометрии и порогов, цветов не добавляем — обе темы работают через существующие переменные (в макете проверено переключателем).
- **Touch:** на планшете hover недоступен — все контролы получают tap-цели ≥36px; закрытие оверлеев — тапом вне панели (прозрачный клик-кетчер); скролл-полоса пилюль — свайп.
- **Переполнение текстов:** заголовок чата — многоточие (`titleMinW: 0`); длинные имена сессий/файлов в drawer — `text-overflow: ellipsis` (уже в компонентах).

## Проверка после реализации

1. `cd frontend; npx tsc -b` и `npm run lint:design` — зелёные.
2. Ручной прогон на 768px портрете: левая панель поверх чата; «Файлы» скроллятся до низа; пилюли compact → скролл-полоса на 480; хедер в одну строку, поповер чипа открывается и скроллится; гит-бар свёрнут в микростроку 28px, тап разворачивает slim-бар, тап по ✓ открывает меню области коммита, «Опубликовать» ведёт в `PublishDialog`, шеврон сворачивает обратно и выбор переживает перезагрузку.
3. Регрессия: десктоп ≥1200px и мобила ≤600px визуально не изменились.

Рассмотрен и отклонён плавающий чип поверх композера (0px): ложится на набираемый текст и плашку режимов, случайные тапы на touch.

- v5 (2026-08-16): правка по живому прогону — «тулбары в тени». Drawer-оверлеи на планшете теряют затемнение `C.overlay`: backdrop `PanelZone.tsx:1236` становится прозрачным клик-кетчером, хаб-бар, хедер чата и композер остаются подсвеченными и кликабельными при открытой панели. Дим оставлен только на мобиле ≤600px (шит почти полноэкранный). Альтернатива «дырки под тулбары в диме» отклонена: лоскутно, ломается на каждой новой полосе хрома.
- v6 (2026-08-16): паритет для раздела «Чаты» (глобальные чаты, `ChatsPage`). Планшетный оверлей-режим изначально охватил только проектный воркспейс: `DesktopWorkspace` передаёт панелям `compact={isTablet}`, а `ChatsPage` вызывает `PanelZone` без `compact` — список чатов и панели сессии на планшете оставались десктопными inline-панелями: вдавливали чат и сдвигали тулбары. Дополнение спеки: `ChatsPage` получает тот же контракт — `isTablet` из `useWindowWidth()` (формула как в `ChatHeaderBar.tsx:953`), `compact={isTablet}` обеим зонам, эксклюзив сторон через `chatPanels.use().setExclusive/markActive` зеркально `DesktopWorkspace.tsx:159-166`; комментарий «в разделах хаба эксклюзива нет» там же устаревает и правится. Отдельно зафиксировано: попапы тулбара в глобальных чатах в спец-обработке не нуждаются — `ChatPanel` там смонтирован с `key={activeChat.id}`, перемонтаж при переключении закрывает их сам.
- v7 (2026-08-16): правки по живому прогону на проде. **(а) Дровер списка не закрывается после выбора чата.** Сценарий: на планшете открываешь дровер со списком чатов/сессий, тапаешь другой чат — чат на фоне переключился, а дровер остался: второй тап в сторону или на крестик. Причина: `tabletPanels` — внутренний стейт `PanelZone`, закрывается только тапом по backdrop (`PanelZone.tsx:1236`), крестиком (`:798/:815`) и эксклюзивом сторон (`:432`); выбор элемента списка его не трогает. Спека: в compact-режиме смена активной сессии (`DesktopWorkspace`, `session.id`) или активного чата (`ChatsPage`, `activeChat.id`) закрывает открытые tablet-дроверы обеих сторон — при ЛЮБОМ источнике смены (список, уведомление, диплинк): дровер лежит поверх контента, и после навигации пользователю нужен сам чат, а не список. Обратное не верно: навигация внутри контентных панелей (открытие файла в «Файлах») дровер НЕ закрывает — контент показывается в самой панели. Канал — на реализации: предложение — действие «закрыть compact-стек» в сторе `panelStackState`, вызываемое эффектом страницы на смену id; в persist оно попадать не должно (tabletPanels и так не персистятся). **(б) Компактные пилюли не появляются вовсе.** Причина — мёртвая ветка: `HubTabs.tsx:99` передаёт `compact={mobile}` (на планшете это `false`), а `PillSwitch.tsx:50` считает `effectiveCompact = compact ?? (autoCompact ? overflowCompact : false)` — explicit `false` не nullish, поэтому autoCompact никогда не применяется, детект переполнения (v4) не работает. Спека: семантика «compact форсирует, autoCompact добавляет детект» — `effectiveCompact = compact || (autoCompact && overflowCompact)`; мобила (`compact=true` без autoCompact) и десктоп (оба false/undefined) не меняются.
- v8 (2026-08-16): правка по живому прогону на проде — **inline-сайдбар чатов не переживает переключение проекта.** Сценарий: на широком планшете (≥~1000px, альбом iPad ~1194px — панель стоит inline, выглядит как десктопный сайдбар, НЕ попапом) открываешь панель «Чаты», переключаешь проект в доке — панель закрыта, хотя раньше оставалась открытой. Причина — расслоение состояния в compact-режиме `PanelZone`: открытость панели живёт ТОЛЬКО в локальном `useState tabletPanels` (открытие — `placeHere` → `setTabletPanels`, `:369-372`; чтение — `tabletKeys`/`openKeys`/`openZoneOf`, `:194-195/:298`; закрытие — `:810/:827`), а `tabletInline` (:168) решает лишь РЕНДЕРИНГ (inline vs drawer), но не место хранения. `WorkspacePage` перемонтируется на каждую смену проекта (`key={project.id}` в App, комментарий `WorkspacePage.tsx:1239`) → `PanelZone` перемонтируется → `tabletPanels = []` → панель закрыта. Дополнительно сигнал v7 `closeCompactSignal` (эффект `:441-445`) чистит `tabletPanels` на смену активной сессии — для inline-панели это тоже неправомерно. До планшетной фичи (8a6b509d) compact у левой зоны не было, и открытость лежала в персистируемой раскладке стора — поэтому «раньше работало». **Спека: развести compact по признаку `tabletInline`.** Вводится производная `compactOverlay = compact && !tabletInline`; весь эфемерный стейт ключуется на неё, а не на `compact`:

- v10 (2026-08-17): **таббар должен занимать всё свободное место хедера, «⋯» — только по факту нехватки.** Репорт со скриншота планшета: справа от пилюль до колокольчика остаётся заметная пустота, но ряд свёрнут до 3 табов + «⋯». Две независимые причины, обе в `HubHeader.tsx`.
  - **Причина 1 — замер по контенту вместо контейнера (главная).** Решение считается как `probeFull.offsetWidth > trackRef.clientWidth − 24` (`:96`), но `trackRef` (`:265-268`) — flex-элемент **без `flex: 1`**, его ширина равна ширине собственного содержимого. В откатной ветке трек содержит 3 таба (≈150px), эталон полного набора ≈260px, поэтому условие истинно ВСЕГДА и обратный переход к 5 табам физически невозможен: планшет залипает в откате на любой ширине. Осцилляция v9-доработки была устранена ценой этого залипания.
  - **Причина 2 — три конкурирующих `flex: 1`.** Левая секция (`:247`) и правая (`:332`, `flex: isMobile ? 'none' : 1`) растут наравне с центром, поэтому свободное место делится на три доли: правая держит пустоту перед колокольчиком (её контент прижат `justifyContent: 'flex-end'`), а центру достаётся около трети ширины окна вместо всего остатка.
  - **Спека.** (1) На планшете растёт только центр: левая секция — `flex: isTablet ? '0 1 auto' : 1` (по содержимому, сжимается за счёт крошки — у неё уже `maxWidth: 150` + ellipsis и `minWidth: 0`); правая — `flex: (isMobile || isTablet) ? 'none' : 1`; центр (`:264`) остаётся `flex: 1, minWidth: 0` и забирает весь остаток. (2) Замер переносится с трека на **центр-контейнер**: отдельный `centerRef` на элементе `:264`, условие `probeFull.offsetWidth > center.clientWidth − 24`, `ResizeObserver` наблюдает центр. Трек со скроллом (ступень 2) остаётся как есть — он внутренний. (3) Скрытый эталон переезжает из трека в центр-контейнер (центру дать `position: 'relative'`): внутри `overflow-x: auto` абсолютный эталон раздувает `scrollWidth` трека, хоть и невидим.
  - **Почему это не вернёт осцилляцию.** Ширина центра при `flex: 1 1 0%` + `minWidth: 0` не зависит от его содержимого: и трек (скроллится), и кнопка «⋯» (`flexShrink: 0` внутри центра) на неё не влияют — центр определяется только шириной окна и секциями по краям, которые от ветки не зависят. Значит `compactOverflow` становится чистой функцией ширины окна: обе ветки дают один и тот же ответ на одной ширине, самоподдерживающегося цикла нет. Гистерезис v9 (за счёт ширины «⋯») больше не нужен и исчезает вместе с ним; зазор 24px остаётся буфером на дребезг при протяжке ресайза.
