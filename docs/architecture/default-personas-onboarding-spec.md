## Goal
Каждый новый чат, создаваемый человеком, начинается с персоной — «безликого» общения с AI в продукте больше нет. Для этого система гарантирует существование персон по умолчанию: личная дефолт-персона пользователя создаётся в обязательном чат-онбординге первого логина (пользователь рассказывает о себе и своих задачах), проектная персона-«руководитель проекта» — в обязательном чат-онбординге создания проекта. Дефолт-персоны — полноценные помощники по настройке системы: они умеют создавать и настраивать другие персоны, проекты и окружение. Руководитель проекта дополнительно служит входной точкой в командные механики: анализирует поставленную задачу, предлагает релевантную механику из «Обсудить с командой» и запускает её по подтверждению. Лицо продукта персонализируется: аватар релевантной персоны заменяет нейтральные AI-иконки (кнопка AI-хаба, wait-индикатор, пустой чат, кружок в ленте).

## Constraints
- Инвариант действует только на **новые чаты людей** через UI. Существующие чаты без персоны живут как есть; служебные сессии (исполнители задач без персоны, one-shot вызовы) не затрагиваются.
- Оба онбординга **обязательные, без кнопки «Пропустить»**.
- Ретро-путь: существующему пользователю визард показывается при следующем логине; существующему проекту — при первом открытии после релиза.
- Онбординг — **живой чат-интервью**, не формы: AI расспрашивает, по итогам сам создаёт персону (имя, роль, характер, аватар) и показывает результат на подтверждение.
- Каскад интервьюеров: первый логин ведёт системный «мастер настройки» (системный промпт, без персоны) → создаёт личную дефолт-персону, которая «просыпается» и здоровается в этом же чате. Онбординг проекта ведёт **личная дефолт-персона** пользователя → создаёт руководителя проекта.
- Дефолт-персона — **не новый тип сущности**: обычная персона с признаком «дефолтная» и предзаполненным профилем: Specialty=Coordinator, Access=Full, включённый модуль personas-manage, автопривязки (задачи, заметки, персоны проекта).
- Жизненный цикл: дефолтную персону можно сменить на любую подходящую по зоне; удалить текущую дефолтную можно только выбрав преемника. Остаться без дефолта нельзя.
- Мост в механики: **автозапуска нет** — персона предлагает механику одной кнопкой, запуск после подтверждения пользователя. Предлагает в любой релевантный момент разговора; при отказе решает задачу сама и повторно в этом разговоре не навязывает.
- Аватары: правило «в чате — текущая персона чата; в контексте проекта вне чата — дефолт-персона проекта; глобально — личная дефолт-персона» применяется во всех 4 местах (AiLauncher, WaitingIndicator, EmptyState, ChatItemView); нейтральная иконка — только fallback до прохождения онбординга.
- Анимация аватара в wait-индикаторе: дизайнер прорабатывает **несколько вариантов** (по духу — как текущий «дымок») и согласует с владельцем до реализации.
- Релиз: **всё одним релизом за фич-флагом**, включаем по полной готовности.

## Non-Goals
- Миграция существующих чатов без персоны (не переводим на дефолт-персону).
- Персоны для служебных/фоновых сессий и one-shot вызовов.
- Поэтапный выкат компонентов (решение: один релиз).
- Полностью автономный запуск командных механик без подтверждения.
- Изменение самих командных механик — используем существующий реестр (`teamMechanics.ts`) как есть.

## Acceptance Criteria
- [ ] Новый чат (в проекте и вне проекта) невозможно создать без персоны: UI всегда подставляет дефолт-персону контекста или явно выбранную.
- [ ] При первом логине нового пользователя открывается обязательный чат-онбординг; на выходе существует личная дефолт-персона, подтверждённая пользователем (имя, роль, характер, аватар).
- [ ] Существующий пользователь без дефолт-персоны получает тот же визард при следующем логине; пропустить нельзя.
- [ ] При создании проекта запускается чат-онбординг с личной дефолт-персоной; на выходе — персона-руководитель проекта, назначенная дефолтной для проекта.
- [ ] Существующий проект без руководителя получает визард при первом открытии после релиза.
- [ ] Дефолт-персоны создаются с Specialty=Coordinator, Access=Full, включённым personas-manage и автопривязками — и реально могут создавать/править других персон из чата.
- [ ] Смена дефолт-персоны доступна в настройках; удаление текущей дефолтной требует выбора преемника (проверяется на бэке).
- [ ] В чате с руководителем проекта постановка задачи, подходящей под механику, приводит к предложению с кнопкой запуска; подтверждение запускает механику, отказ — персона решает сама и не повторяет предложение в этом разговоре.
- [ ] Аватар релевантной персоны отображается вместо нейтральной иконки в AiLauncher, WaitingIndicator, EmptyState и ChatItemView по правилу контекста; до онбординга — текущие нейтральные иконки.
- [ ] Анимация аватара в wait-индикаторе реализована по варианту, согласованному владельцем из предложенных дизайнером.
- [ ] Вся фича — за одним фич-флагом (реестр `FeatureFlagCatalog.All` + `FLAGS`), по умолчанию выключена.

## Technical Context
- Чат создаётся без персоны: `api.sessions.create` / `api.chats.create` (frontend/src/lib/api.ts:852-890) — параметра personaId нет; персона назначается постфактум (`PUT {sessionId}/persona`, SessionsController.cs:63). Персона-чат: `POST /personas/{id}/chats` → `SessionManager.CreatePersonaChatAsync`.
- Онбординга нет: LoginPage — чистая форма; `User` (Models/User.cs) без флага первого входа. Понятия «персона по умолчанию» нет ни в User, ни в Project.
- Создание проекта — модал `AddProjectDialog.tsx`, не wizard; `Project` (Models/Project.cs) без поля дефолт-персоны.
- Персоны: `Persona` (Models/Persona.cs) — Scope Global/Project, Access, Tools, Bindings, Specialty, Contract, Avatar; модуль **personas-manage** уже существует (PersonaBindingsService.cs:45-62, дефолт включён у Coordinator/Secretary); AI-генерация персоны — `ai/quick-create` (PersonasController.cs:572), автогенерация аватара через fal (`TryAutoGenerateAvatarAsync`).
- Командные механики: реестр `frontend/src/features/team/teamMechanics.ts` — каждая механика = сообщение со скиллом (`/panel-of-experts`, `/oh-my-claudecode:*`) или promt-обвязка; серверная только «Командная реализация» (`PUT /chats/{id}/team-implement`). Персоне нужен промпт-слой со списком механик, чтобы предлагать их.
- Нейтральные AI-иконки: `AiLauncher.tsx` (кнопка хаба), `WaitingIndicator.tsx` (логотип с дымком, `cc-smoke`), `EmptyState.tsx` (favicon 46px), `ChatItemView.tsx:501-513` (серый робот). Аватар персоны — `PersonaAvatar.tsx`.
- Фич-флаги: `FeatureFlagCatalog.All` (C#) + `FLAGS` (lib/featureFlags.ts), тумблер рендерится сам.
