# ADR-009: Контракт формата маршрута локального действия (`local-actions.json`)

**Статус:** Принято
**Дата:** 2026-08-12
**Автор:** Александр (тимлид/архитектор)
**Область:** значение маршрута места применения модели — то, что хранится в
`data/local-actions.json`, приходит в `PUT /api/admin/local-actions/{key}` и показывается
в разделе «Поставщики моделей»
**Связанные:** [ADR-007](ADR-007-model-preset-chains.md) §3 (`preset:{id}` как значение
лексики маршрутов), [model-resolution-and-fallback.md](model-resolution-and-fallback.md)
(резолв модели и фолбэк), [docs/architecture/llm-providers.md](../architecture/llm-providers.md),
[docs/features/model-presets-and-tiers.md](../features/model-presets-and-tiers.md)

Этот документ — **единственный источник истины по формату значения маршрута** для бэкенда
и фронта. Лексика описана не «как задумано», а как её фактически разбирает исполнитель;
при расхождении документа с кодом расхождение считается дефектом документа либо кода, но
не поводом завести третью трактовку.

## Контекст

Маршрут — строка, которой админ отвечает на вопрос «кто выполняет это место». Она проходит
через четыре разных парсера, живущих в трёх файлах, и ни один из них не отвергает
незнакомое значение: всё, что не опознано, трактуется как **id модели**. Поэтому опечатка
(`strong` вместо `tier:strong`, `Direct:…` вместо `direct:…`, имя пресета вместо его id)
не падает, а тихо
превращается в несуществующую модель: первый шаг цепочки не срабатывает, вызов уезжает
на страховку, а в UI настройка выглядит применённой. Симптом на проде — «настройка не
работает», диагноз — только по warning'у в логе `модель {Model} недоступна, иду дальше
по цепочке`.

Точки разбора (все, ничего кроме них):

| Что разбирает | Где |
|---|---|
| Форму маршрута целиком | [`LocalActionRouter.Parse`](../../backend/ClaudeHomeServer/Services/Llm/LocalActionRouter.cs) |
| Слот тира | [`LocalActionOverridesStore.ParseTierRoute`](../../backend/ClaudeHomeServer/Services/Llm/LocalActionOverridesStore.cs) |
| Ссылку на пресет | [`IsPresetRoute` / `ParsePresetRoute`](../../backend/ClaudeHomeServer/Services/Llm/LocalActionOverridesStore.cs) |
| Префикс прямого адаптера | [`CloudCheapClient.IsDirectRoute` / `StripPrefix`](../../backend/ClaudeHomeServer/Services/Llm/CloudCheapClient.cs) |
| Ту же лексику для агентных мест | [`ModelAssignmentResolver.ExpandStep`](../../backend/ClaudeHomeServer/Services/Llm/ModelAssignmentResolver.cs) |

```
   запись                        чтение (на каждом фоновом вызове)
   ------                        ---------------------------------
   PUT /api/admin/                 LocalActionOverridesStore.TryGet
   local-actions/{key}                        |
        |                                     v
        v                          LocalActionRouter.Resolve
   валидация (эта ADR)              admin -> config -> дефолт каталога
        |                                     |
        v                                     v
   local-actions.json  ------------>  Parse: 8 форм, иначе "id модели"
                                              |
                                              v
                                CheapTextRunner: выбранное -> локаль -> claude
```

## Решение

### 1. Восемь допустимых форм значения

Ровно восемь. Всё, что вне списка, синтаксически валидным маршрутом **не является**,
даже если система сегодня его молча проглатывает.

| # | Форма | Что означает | Во что разбирается |
|---|---|---|---|
| 1 | `local` | локальная модель Ollama (`OllamaClient.TextModel`) | `RouteKind.Local` |
| 2 | `claude` | легаси v1 «обычная модель, не локаль» | `RouteKind.Tier`, `ModelTier.Medium` |
| 3 | `default` | легаси v1, синоним `claude` | `RouteKind.Tier`, `ModelTier.Medium` |
| 4 | `tier:strong` | слот «Сильная» владельца действия | `RouteKind.Tier`, `Strong` |
| 5 | `tier:medium` | слот «Средняя» | `RouteKind.Tier`, `Medium` |
| 6 | `tier:weak` | слот «Слабая» | `RouteKind.Tier`, `Weak` |
| 7 | `preset:{id}` | ссылка на именованную цепочку (ADR-007 §3) | цепочка; для фонового места — её первый непустой шаг, разобранный по этой же таблице |
| 8 | `{id модели}` | конкретная модель настроенного провайдера, ровно как в каталоге `/api/models` | `RouteKind.Model` |

Про форму 7 у фонового места: `LocalActionRouter.Resolve` разворачивает её через
`SpecialtySettingsStore.ExpandChain(route, ownerId: null)` — то есть **по общим пресетам,
без личного слоя владельца** (отсюда ограничение §4). Битая ссылка (пресет удалён) —
fail-open: шагов нет, место падает на дефолт каталога, в лог уходит warning. Полный цикл
шагов пресета фоновому месту не ведётся: берётся первый шаг, дальше работает штатная
цепочка «выбранное → локаль → claude».

**`direct:{id}` — не девятая форма, а подвид восьмой.** `Parse` его не различает: маршрут
остаётся `RouteKind.Model`, а префикс читается позже и означает только **транспорт** —
прямой HTTP-адаптер вместо запуска через claude CLI (`CheapTextRunner.TryDirectAsync`).
Отсюда правило: `direct:` пишется слитно с id модели агрегатора (`direct:nvidia/nemotron:free`),
и «просто модель» и «та же модель через direct:» — два разных валидных значения с разной
стоимостью и разным поведением.

**Префикс обязателен и является частью значения.** `tier:`, `preset:`, `direct:` — не
украшение и не подсказка UI: без префикса строка попадает в форму 8 и трактуется как id
модели. `strong` — это «модель с именем strong», а не сильный слот.

### 2. Правила сопоставления (регистр, пробелы) — как в коде, а не как удобно

Парсеры несимметричны, и это часть контракта, а не деталь реализации:

- **`local` / `claude` / `default`** — сравнение в `Parse` через `switch` по строковым
  константам: **регистрозависимое, без trim**. `Local`, `LOCAL`, `" local"` → форма 8.
- **`tier:*`** — `ParseTierRoute` приводит к нижнему регистру, но **не триммит**:
  `TIER:STRONG` валиден, `"tier:strong "` — нет. Внешний пробел снимается раньше, на
  записи (`Set` делает `route.Trim()`), поэтому в сторе его не бывает; на значениях из
  других источников гарантии нет.
- **`preset:*`** — `IsPresetRoute`/`ParsePresetRoute` **триммят и игнорируют регистр
  префикса**; `{id}` сохраняется в исходном регистре (сравнение с пресетом —
  `OrdinalIgnoreCase`). `preset:` без id — не ссылка (и не бывает в сторе: запись такое
  отвергает).
- **`direct:*`** — `IsDirectRoute` сравнивает `Ordinal`, **регистрозависимо**: `Direct:…`
  прямым вызовом не считается и уедет в CLI под именем модели `Direct:…`.
- **Ключ действия** (не значение) — `OrdinalIgnoreCase` в словаре стора; неизвестный ключ
  отвергается и на записи, и при загрузке файла.

Канонический вид, который обязаны писать все каналы записи: **строка без внешних пробелов,
служебные литералы и префиксы — в нижнем регистре, id модели/пресета — ровно как в
каталоге/сторе пресетов**.

### 3. Примеры

Валидно:

```
local
tier:strong
tier:weak
preset:6f1c0f6a-6d1b-4a2f-9a1f-9a51e0b0d3c1
claude-haiku-4-5-20251001
glm-5.2[1m]
direct:nvidia/nemotron:free
claude            (легаси, читается как tier:medium)
```

Невалидно (и почему):

```
strong                  нет префикса tier: -> «модель с именем strong»
Сильная                 подпись UI, а не значение
tier:strongest          нет такого слота -> «модель tier:strongest»
tier: strong            пробел внутри -> ParseTierRoute не узнаёт
"tier:strong "          хвостовой пробел -> ParseTierRoute не узнаёт (в сторе не бывает)
Direct:nvidia/nemotron  префикс direct: регистрозависим -> уедет в CLI как имя модели
preset:                 ссылка без id
preset:Быстрая          имя пресета вместо его id
gpt-4o-mini             id, которого нет в каталоге /api/models (или провайдер не настроен)
""  /  "   "            пустое значение
true / false            формат v0 (только в файле стора, см. §5)
```

Важно: невалидность формы **не равна** отказу системы. Формы 1–8 — то, что описано;
остальное сегодня разбирается как форма 8 и деградирует молча. Именно это и делает
валидацию на записи обязательной (§6).

### 4. Ограничения не по форме, а по месту

Форма может быть валидной, а для конкретного места — недопустимой:

- **Агентные места** (`LocalAction.Agentic`: новый чат, чат персоны, исполнитель задач,
  сабагенты, LLM-канал модулей) не принимают `local` и `direct:*` — им нужна модель с
  инструментами CLI. Отклоняется на записи
  ([`LocalActionsAdminController.Set`](../../backend/ClaudeHomeServer/Controllers/LocalActionsAdminController.cs)),
  а при чтении такие значения игнорируются и место падает на дефолт каталога
  (`ModelAssignmentResolver.ResolveRawRouteWithSource`, `ExpandStep`).
- **`preset:{id}` для места каталога — только ОБЩИЙ (глобальный) пресет**: назначение
  места одно на всех, личный пресет у другого пользователя стал бы битой ссылкой
  (`Set`, проверка по `specialty.Snapshot.Global.Presets`).
- **`tier:*` запрещён в ячейках матриц** персоны и специальности — ячейка уже адресована
  уровнем (`SpecialtySettingsStore.ValidateTemplateSettings`).
- **Шаг пресета не может быть `preset:*`** — вложенность запрещена (`ValidateLayer`,
  ADR-007 §1).

### 5. Чтение старых записей: fail-open, и это осознанно

`LocalActionOverridesStore.Load` при старте:

1. **Отсеивает ключи, которых нет в каталоге** (действие переименовали/удалили) — с
   warning'ом; значение теряется, а не мигрирует.
2. **Мигрирует формат v0** — булево значение файла: `true` → `local`, `false` → `claude`
   (то есть по §1 читается как `tier:medium`). Миграция происходит в памяти и
   закрепляется на диске при следующей записи.
3. **Значения не валидирует.** Битая строка доживает до `Parse` и становится формой 8.
4. Нечитаемый/битый JSON — весь файл игнорируется, сервер стартует без оверрайдов
   (warning в лог).

Из легаси-форм 2 и 3 **стор ничего не переписывает**: их трактовка живёт только в
читателях (`Parse`, `ExpandStep`). Отсюда асимметрия, которую надо помнить: значение
`claude` из **стора** даёт `RouteKind.Tier(Medium)`, а `Ollama:Actions:{key} = false`
из **конфига** даёт `RouteKind.Claude` — «модель самого действия из его конфига», без
слота. Один и тот же на вид выбор через разные источники ведёт к разным моделям.

Fail-open на чтении сохраняется намеренно: читатель сидит на горячем пути (стор читается
на **каждом** фоновом вызове, чтобы тумблер действовал без рестарта), а фоновое действие
обязано оставаться живучим — упасть на локаль и claude лучше, чем отказать. Строгий
читатель, отвергающий незнакомое значение, обрушил бы фон при любой рассинхронизации
версий стора и кода.

### 6. Валидация — на записи. Полностью

**Правило: маршрут проверяется в момент сохранения; после сохранения любое значение в
сторе считается валидным по построению.**

Почему не на чтении:

- **Стоимость.** Чтение — горячий путь каждого фонового вызова; валидация модели требует
  каталога `/api/models` (сетевой опрос провайдеров с кешем) и снимка пресетов. На записи
  это один клик админа, на чтении — каждый вызов.
- **Адресат ошибки.** На записи ошибку видит человек, который её сделал, и в момент, когда
  ещё помнит, что нажимал: `400` с текстом в диалоге. На чтении «получателя» нет —
  остаётся warning в логе, который прочитают через неделю, разбирая «почему настройка не
  применяется».
- **Наблюдаемость.** Отказ на чтении неотличим от штатной деградации цепочки (та же
  ветка «шаг не сработал → идём дальше»), то есть не даёт ни сигнала, ни точки останова.
- **Обратная совместимость.** Строгое чтение конфликтует с §5: старые и легаси-значения
  обязаны читаться, а вновь записываемые — обязаны быть каноничными. Это два разных
  требования, и разводятся они только по границе записи.

Что валидирует запись сегодня
([`LocalActionsAdminController.Set`](../../backend/ClaudeHomeServer/Controllers/LocalActionsAdminController.cs)):
известность ключа действия (иначе 404), непустое значение, пригодность формы для места
(§4), существование пресета среди общих, а для формы 8 — что провайдер модели настроен и
что модель есть в каталоге (`ValidateModelAsync`). Формы 1–3 и `tier:*` пропускаются мимо
проверки модели — их проверяет само сопоставление литерала.

**Дыра, которую эта ADR фиксирует как известную:** валидацию проходит только путь
`PUT /{key}`. Мимо неё идут:

- `LocalActionOverridesStore.SetMany` (массовое применение пресета) — проверяет лишь
  известность ключа и непустоту значения;
- прямая правка `data/local-actions.json` руками;
- секция конфига `Ollama:Actions` — там формат вообще другой (`bool`), неизвестные ключи
  логируются, значения не-bool молча отбрасываются.

Первый пункт — единственный, который реально пишет мусор от лица продукта: набор маршрутов
пресета собирается кодом, и опечатка в нём попадёт в стор без единой проверки. Закрывать
его следует переносом проверки формы в стор (общий валидатор формы, вызываемый и из `Set`,
и из `SetMany`), оставив дорогую проверку «модель есть в каталоге» на уровне контроллера.

### 7. Что это означает для фронта

Фронт **не заводит собственную лексику**. `routeTier` / `routeLabel` /
`TIERS[*].route` в [`modelProvidersShared.ts`](../../frontend/src/lib/modelProvidersShared.ts)
обязаны совпадать с §1 буква в букву; подпись («Сильная», «Локальная») — это отображение
значения, а не значение. Любая автоподстановка префикса в UI (выбрал модель — отправили
её id; выбрал слот — отправили `tier:{slot}`) обязана давать канонический вид из §2 и
не освобождает бэкенд от проверки: UI — удобство, контракт держит запись.

## Последствия

- Появляется однозначный ответ на вопрос «валидно ли это значение», не требующий чтения
  четырёх парсеров.
- Легаси-формы 2 и 3 остаются в лексике навсегда (пока в сторах есть такие записи) — они
  не запрещаются, но **не должны записываться заново**: канонический эквивалент —
  `tier:medium`.
- Fail-open чтения сохраняется, то есть кривое значение, попавшее в стор в обход записи,
  по-прежнему деградирует молча. Единственная защита — сузить каналы записи (§6).
- Асимметрия `claude` (стор) vs `Ollama:Actions=false` (конфиг) остаётся; менять её здесь
  не предлагается — это отдельное решение с миграцией конфигов развёртывания.
