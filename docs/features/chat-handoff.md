# Перенос в новый чат

Кнопка «Перенести в новый чат» в секции «Кэш промпта» поповера пилюли шапки и то же действие
в тосте «Кэш промпта скоро остынет». Новый чат знает, о чём был разговор, и **не платит
холодную перезапись всей истории** в кэш промпта: он стартует с короткой передаточной записки,
а не с транскрипта целиком.

## Два пути

| Путь | Кто пишет записку | Статус |
|---|---|---|
| **Холодный** | дешёвый раннер, место `chat-handoff`, по транскрипту из `history.json` | сделан (этот документ) |
| **Горячий** | сам чат, пока его кэш тёплый — тем же промптом передачи | фаза C плана, не сделан |

Промпт передачи один — `ChatHandoffService.BuildPrompt`. Горячий путь обязан брать его же,
а не заводить второй: две формулировки разъедутся, и записки двух путей станут разными по
составу.

## Почему не ветвление и не `--fork-session`

Ветка (`POST /api/chats/{id}/branch`) и `--fork-session` копируют транскрипт CLI — новый чат
продолжает **ту же** историю, и первый же его ход переписывает в кэш весь префикс. Ровно этой
перезаписи перенос и избегает. Поэтому преемник создаётся **без resume**: новый
`ClaudeSessionId` выдаст первый ход, в памяти модели — только записка.

Общая часть с ветвлением — `SessionManager.CreateSuccessorChatAsync`: выбор фабрики
(персона / проект / чат вне проекта) и наследование полей §11 из
[chat-branching-2026-09.md](../research/chat-branching-2026-09.md) — модель, провайдер, effort,
контекст, голос, тишина уведомлений, opt-out паспортов. Не наследуются `AutoAllowTools`,
срок жизни, worktree, архив. Отказы тоже общие (`EnsureSuccessorAllowed`).

## Почему черновик, а не автоотправка

Записку пишет дешёвая модель по транскрипту, урезанному до 60k символов (голова + хвост).
Она может упустить важное или сформулировать неточно, и человек должен успеть её поправить
до первого хода. Поэтому `draft` кладётся в черновик композера нового чата
(`lib/drafts.setDraft`) — так же, как текст сообщения при ветвлении `beforePrompt`.

Последняя строка черновика пишется кодом, не моделью: id старого чата и подсказка «детали —
через chats_history». У временного чата добавляется предупреждение, что ссылка умрёт вместе
с ним — преемник срок жизни не наследует.

## Матрица

| Чат | Перенос |
|---|---|
| обычный, с персоной, проектный | ✅ |
| архивный | ✅ (старый остаётся в архиве) |
| временный | ✅ (новый не временный, в записке — предупреждение) |
| сторонняя модель, голосовой режим | ✅ (на фронте кнопки нет, пока статус кэша `unknown`) |
| локальный проект | ✅ (история на платформе, транскрипт CLI не нужен) |
| групповой, «Командная реализация», отдельный worktree | ❌ 409 |
| пустой | ❌ 409 «переносить нечего» |
| место `chat-handoff` назначено на локальную модель | ❌ 409 с причиной |

Пункт «десктопный чат» из плана отпал: такого вида чата больше нет (`Session.DesktopChat`
удалён вместе с «руками» ADR-008), отказывать нечему.

## Место `chat-handoff`

`LocalActionCatalog`: профиль `Large` (вход до 60k символов), `DefaultLocal: false`,
`CloudNumPredict: 4096`. Если админ всё же назначит месту локаль, сервис **не зовёт модель
вовсе** и отвечает отказом с причиной: окно локали (16k) и её 1024 токена вывода записку не
вывозят, а обрезанная передача хуже честного отказа. Исполнителя места видно и можно сменить
в диалоге «Поставщики моделей», группа «Сессии».

## Инварианты

- Старый чат только читается: `UpdatedAt`, архив, сводка карточки не меняются.
- Отказы (группа, штаб, worktree, локаль) проверяются **до** модели — не платим за записку,
  которую некуда положить. Пустой чат отсекается до модели по пустому транскрипту.
- Двойной клик — 409 (`_inFlight`), переносы одного владельца идут по одному (семафор), как
  у `ChatDigestService`.
- Владение — `GetOwned` (проектные сессии тоже), не `OwnedChat`.

## Где в коде

- `backend/ClaudeHomeServer/Services/ChatHandoffService.cs` — сервис, промпт, черновик.
- `SessionManager.CreateHandoffChatAsync` / `EnsureHandoffAllowed` — преемник и отказы.
- `ChatsController.Handoff` — `POST /api/chats/{id}/handoff` → `{ chatId, projectId, draft }`.
- `frontend/src/lib/chatHandoff.ts` — доступность кнопки (зеркало серверных отказов);
  `ChatHeaderBar` — кнопка и действие тоста; `ChatPanel.handleHandoff` — черновик и навигация.
- Тесты: `ChatHandoffServiceTests`, `ChatsControllerHandoffTests`, `chatHandoff.test.ts`;
  витрина — образцы «перенос…» в разделе пилюли UI-кита.
