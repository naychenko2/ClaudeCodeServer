# Замер: окупится ли «слой опыта» в памяти исполнителей (2026-10-18)

Вход для [ADR-032](../adr/ADR-032-executor-experience-and-memory-versions.md). Идея слоя опыта взята из Hy-Memory (Tencent Hunyuan, Apache-2.0): после сессии с инструментами извлекаются записи «задача → решение → граница применимости → уверенность», при следующей похожей задаче они подтягиваются в контекст исполнителя.

Вопрос замера: сколько шагов исполнителей сэкономил бы такой слой на наших реальных задачах — и сколько бы испортил.

## Итог

| Метрика | Значение |
|---|---|
| Целевых задач | 20 (случайно, seed `20261018`) |
| Вызовов инструментов в них | 1836 |
| Целей хоть с какой-то пользой, идеальный поиск | **14/20** |
| Целей с пользой ≥5 вызовов, идеальный поиск | **7/20** |
| Сэкономлено вызовов, идеальный поиск | **122 (6,6%)**; без одного выброса T098 — 77 (4,5%) |
| Целей с пользой, реалистичный поиск (BM25 по заголовку и постановке, топ-5) | **6/20** |
| Сэкономлено вызовов, реалистичный поиск | **59 (3,2%)** |
| Вредных записей (устарели или противоречат реальности) | **11 на 7 целях из 20** |
| Доля пользы от граблей окружения и тестовой инфраструктуры | **91%** (111 из 122 вызовов, 19 записей) |

Порог, названный до замера: «меньше 20–25% целей с попаданием — закрываем». Формально он пройден (30–70% целей в зависимости от поиска). По существу картина другая, чем у Hy-Memory:

1. **Польза — не в опыте конкретных задач, а в граблях окружения.** Как поднять стенд из worktree, как остановить процесс, когда `pkill` запрещён хуком, что `cd` в Bash сохраняется между вызовами, как правильно считать тесты, как передать `files` в vitest через `run_tests`. Это 91% экономии. Знание кода конкретной фичи дало 11 вызовов на 20 задач.
2. **Поиск по тексту задачи эти грабли не находит.** Медиана ранга полезной записи — 26-е место при пуле 74–186 записей: постановка «перенеси тесты Llm» не похожа на запись «как правильно считать `--list-tests`». Реалистичный поиск вдвое хуже идеального.
3. **Автоматический опыт без проверки вреден в каждой третьей цели.** Устаревшее (`E077` — «у мусора нет повтора», исправлено коммитом `f3bd64489`), неверно обобщённое (`E014`/`E020` — «`run_tests` в worktree смотрит в master», в целях работало), противоречащее друг другу (`E034` «считай по slnx» против `E041` «по slnx недетерминированно, считай по проектам» — на T116 первый способ стоил ~30 вызовов).

## Дополнительно: подсказка в момент ошибки и CLAUDE.md

**Самая дорогая грабля уже была в CLAUDE.md.** На T098 исполнитель потратил ~70 вызовов на стенд, поднятый без `ASPNETCORE_ENVIRONMENT=Development` и не из того каталога. Ровно это написано в `CLAUDE.md`, строка 38. Значит, знание в длинном постоянном контексте (525 строк) не гарантирует, что его применят. Это довод против варианта «просто дописать грабли в CLAUDE.md» и одновременно риск для любой постоянной вставки.

**Реактивный поиск** (`reactive.py`): запрос — текст ошибки инструмента плюс предшествующий вызов, BM25 по тому же пулу, топ-3 выше порога.

| Порог | Подсказок на 20 целей | Полезных записей найдено | Экономия, вызовов | Точность |
|---|---|---|---|---|
| 0 | 984 (~49 на задачу) | 15 из 27 | 73 | 8,5% |
| 15 | 225 (~11) | 11 | 66 | 8,4% |
| **20** | **72 (~4)** | **9** | **61** | **19,4%** |
| 25 | 32 (~2) | 6 | 51 | 25,0% |

На пороге 20 реактивный канал даёт столько же, сколько поиск по постановке (61 против 59 вызовов). Но подсказки приходят в момент спотыкания, и их около четырёх на задачу, а не пять записей в стартовом контексте. Оговорка: проверено, что запись нашлась по какой-то ошибке цели, но не то, что эта ошибка случилась раньше дорогого эпизода.

## Методика

1. **Данные.** Закрытые задачи проекта AI Home с `ClaudeResult=success`, у которых сохранился CLI-транскрипт исполнителя. Транскрипт сопоставлен с задачей по трейлеру `CCS-Session`/`CCS-Task` в первом сообщении (`map.py`). Нашлось 123 задачи, все — 17–18 октября: более старых транскриптов исполнителей на диске нет (причину не выяснял — вероятно, чистка сессий исполнителей по TTL).
2. **Выжимки** (`digest.py`): постановка, итог, ход работы (вызовы инструментов, ошибки, реплики), до 45 тыс. символов; длинные — голова и хвост, середина опущена.
3. **Извлечение опыта** (`extract_prompt.md`): 10 агентов на Sonnet (близко к дешёвой модели, которая делала бы это в проде), каждая задача отдельно, 0–3 записи с жёстким порогом ценности. Итог: **186 записей из 117 задач**, у 15 задач — ноль, медиана confidence 0,65 (`all_exp.json`).
4. **Цели:** 20 случайных задач из T040–T122, чтобы у каждой было ≥40 предшественниц (`targets.json`). Пул опыта цели — только записи из задач, начатых раньше неё: утечки будущего нет.
5. **Судьи** (`judge_prompt.md`): 4 агента на Opus. Польза засчитывается, только если в ходе цели есть конкретный эпизод, где исполнитель тратил шаги на то, что запись покрывает, и этого нет в постановке. Отдельно — вредные записи (`judge/*.json`).
6. **Реалистичный поиск** (`retrieval.py`): BM25 по `task + search_keys + solution`, запрос — заголовок и первые 2000 символов постановки, засчитывается топ-5.

Артефакты и скрипты — [experience-layer-measure/](experience-layer-measure/). Выжимки транскриптов в репозиторий не положены: это сырые чаты.

## Ограничения

- **Окно 30 часов, 123 задачи, плотные серии** одних фич (плагины, TestKit, PipelineFlow, прокси). Это скорее верхняя граница пользы: соседние задачи похожи сильнее, чем в среднем.
- **20 целей** — маленькая выборка; один выброс (T098, 45 вызовов) даёт треть экономии.
- **Оценки экономии — суждение модели** по выжимке, а не прогон с опытом и без. Середина длинных выжимок опущена, часть эпизодов судьи не видели.
- **Не проверено, прочёл бы исполнитель запись** в контексте и последовал ли бы ей.

## Воспроизвести

```bash
mkdir -p /tmp/expmeasure/{dig,exp,pool,judge}
cp docs/research/experience-layer-measure/*.{py,md,json} /tmp/expmeasure/
python3 -I /tmp/expmeasure/map.py      # транскрипты ↔ задачи (данные прода: /srv/ccs/data)
python3 -I /tmp/expmeasure/digest.py   # выжимки
# извлечение: extract_prompt.md агентами по пачкам → exp/B*.json; пулы и судьи — judge_prompt.md
python3 -I /tmp/expmeasure/retrieval.py
```

Транскрипты исполнителей на диске держатся недолго, поэтому повтор на тех же задачах, скорее всего, невозможен — только на свежем окне.
