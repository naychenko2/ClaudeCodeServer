# «Стенды» — три уровня показателей и компактный ИБП (макет v4)

- **Фича:** 95767ea1-dcfd-406a-abdb-caf3e34417a0
- **Статус:** черновик
- **Файлы:** local-model-hardware-cluster-v4.html

Привязка: задача Д1 `924d75bb-89ff-4cee-a014-c4c7fcfe5c42`, архитектурный разрез А1
`a1a32403-6ad9-4279-b6a9-74e2e2201442`; `stepRef` не задан, роль задачи — `design`.
Это отдельный макет рядом с v3, а не новая реализация вкладки.

## Сценарий и проблема

Админ открывает «Локальные модели → Стенды», чтобы за несколько секунд понять, жив ли узел,
не перегрет ли он и есть ли запас питания. Сейчас одинаковые `HwTile` уравнивают загрузку CPU,
температуру воды и аптайм, а четыре плитки ИБП со спарками занимают место раньше главного ответа.

## Решение

В макете три визуальных уровня. Сначала два нейтральных крупных KPI — загрузка CPU и память;
ниже средние текущие температуры GPU/CPU; вторичные датчики собраны в компактные строки закрытой
секции. Тревога не исчезает при свёртке: имена и значения жёлтых/красных вторичных датчиков
остаются в её приписке. У ИБП крупным остаётся только заряд, остальное читается одной строкой,
а четыре истории открываются по требованию.

В шапке прототипа переключаются шесть состояний, светлая/тёмная/обе темы и ширины 380/360/320.
Узлы, обе свёртки, окна и семейства `TempChart` кликабельны. При первом открытии обе свёртки закрыты.

## Спецификация для реализации

### Порядок блоков

1. Существующая `FarmSummaryCard` — без изменения состава.
2. Компактная карточка `UpsCard`.
3. Отдельный `DisclosureSection` «Динамика за 15 мин» для ИБП.
4. При молчании выбранного узла — существующий `StaleBanner`.
5. `StandCard`: KPI первого уровня и температуры второго.
6. Отдельный sibling `DisclosureSection` «Другие датчики» — после `StandCard`, до `TempChart`.
7. Самостоятельный `TempChart`; далее существующие `GpuDetailCard` и `EngineCard` без перекомпоновки.

Не вкладывать `DisclosureSection` внутрь `StandCard` или `UpsCard`: оболочка секции — самостоятельный
`C.bgWhite`-остров с `C.borderLight` и `R.xl`, а не карточка в карточке.

### Уровень 1 — крупные KPI

- Сетка: `repeat(2, minmax(0, 1fr))` на всех проверяемых ширинах; у плиток и содержимого `minWidth: 0`.
- Плитка: `C.bgCard`, граница `C.borderLight`, `R.xl`, паддинг `SP.md`.
- Подпись: `FS.xs`, 600, `C.textSecondary`; значение: `FONT.mono`, `FS.h1`, 600, `C.textHeading`.
- «Загрузка CPU»: `report.cpuLoadPerc`, `%`. Истории загрузки нет — плейсхолдер или температурный
  спарк вместо неё не подставлять.
- «Память»: `nodes[kind=ram].detail.usedPerc`; деталь `usedGb из totalGb ГБ`; под KPI —
  существующий `Sparkline` из `spark15m`, `C.info`. У RAM `sensor='none'` означает отсутствие
  температурного датчика и не отменяет валидную занятость.
- У CPU и RAM нет бэкенд-уровня: фон, рамка и значение нейтральные, точку `C.success` не добавлять.

### Уровень 2 — температуры сейчас

- Сетка: две колонки `minmax(0, 1fr)`; плитка — `C.bgCard`, `C.borderLight`, `R.lg`, `SP.sm`.
- Значение: `FONT.mono`, 20 px, 600; подпись и деталь — `FS.xs`/`FS.xxs`.
- GPU: текущее значение памяти, при её отсутствии — ядро с явной пометкой; деталь «ядро N ·
  гор. точка M». CPU: общая температура, `ccdC` мелкой деталью.
- Индивидуальных спарков нет: историю всех температур даёт `TempChart`.
- `warn`: `C.warningBg` / `C.warning` / `C.warningText`; `danger`: `C.dangerBg` /
  `C.dangerBorder` / `C.dangerText`; `ok` не заливает плитку, точка — `C.success`.

### Уровень 3 — «Другие датчики»

- Существующий управляемый `DisclosureSection`, по умолчанию `open=false`; тело остаётся
  смонтированным и скрывается через `display:none`.
- Внутри не `HwTile`, а строки: имя — значение; ниже деталь — состояние. Разделитель
  `C.borderLight`, вертикальный ритм `SP.sm`, текст `FS.xs`/`FS.xxs`.
- Состав: VRM, плата, чипсет, вода, системные диски, диск кэша, вентиляторы корпуса, аптайм.
  Только у диска кэша остаётся спарк заполненности (`C.info`), потому что его ряда в `TempChart` нет.
- В закрытой `meta`: тревожные датчики именами и значениями, затем счётчик без данных, если он есть.
  Без тревог — `N показателей · M без данных`. Порядок строк не пересортировывать по тревоге.
- «нет данных» и «датчика нет» — `C.textMuted`, курсив; нулевые значения выводятся числом.

### Компактный ИБП

- Шапка: название и существующая плашка `upsPill` с `role=status`: «от сети», «от батареи»,
  «батарея садится», «перегрузка», «ИБП молчит».
- Строка `upsSummary` остаётся текстом: выходное напряжение и температура внутри, без новых плиток.
- Одна крупная KPI «Заряд» по той же геометрии первого уровня; окраска только при `lowBattery`
  по `powerLevel`. Главный показатель не меняется при переходе сеть/батарея.
- Ниже одна полоса из трёх ячеек `repeat(3, minmax(0, 1fr))`: нагрузка `%` + `≈ Вт`, сеть `В` + `Гц`,
  батарея `В` + номинал. Общий фон `C.bgCard`, `R.lg`; разделители `C.borderLight`, отдельных карточек нет.
- Отдельный закрытый `DisclosureSection` «Динамика за 15 мин»: четыре подписанных `Sparkline`
  (заряд, нагрузка, вход, батарея), две колонки `minmax(0, 1fr)`, без повторения крупных текущих чисел.
  `batteryDeciVSpark15m` перед отображением делить на 10; `null` — разрыв линии.

### Состояния, мобильная ширина и темы

- Окраска использует только пришедшие `level`, `loadLevel`, `powerLevel`; новых числовых порогов нет.
- При `stale/down` последние значения — `C.textMuted`, точки — `C.track`, тревожные заливки снимаются;
  баннер/плашка и время молчания остаются. Молчащий узел не становится зелёным по прошлому `level='ok'`.
- На 320 px две KPI остаются в двух колонках; длинные детали переносятся, горизонтальной прокрутки нет.
  Кнопки обеих секций — минимум 44 px; `meta` переносится без многоточия.
- Все цвета берутся из перечисленных `C.*`, поэтому светлая и тёмная темы используют одну разметку.
  Focus-visible — `SHADOW.focus`, active — `SHADOW.press`; новых анимаций, кроме поворота chevron, нет.
- Прогон приёмки: обе темы; 380/360/320; норма, жёлтый/красный уровень, молчащие узел и ИБП;
  сценарий с настоящими `0` и отдельными `null`; открытие/закрытие обеих секций мышью и клавиатурой.
