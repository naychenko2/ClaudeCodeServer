# Вкладка «Доступ» в разделе «MCP-серверы»: список исключений вместо двух матриц

Макет: [mcp-access-v1.html](mcp-access-v1.html) — самодостаточный, открывается двойным кликом.
Переключатели в верхней полосе: тема, мобильная раскладка 390px и все состояния экрана
(норма, исключения, стресс, загрузка, ошибка, пусто, диалог удаления).

## Проблема

Сейчас вкладка — две таблицы ([McpAccessMatrix.tsx](../../frontend/src/features/mcp/McpAccessMatrix.tsx)):
«сервер × проект» с тумблером в каждой ячейке и read-only «персона × сервер».
На боевых данных владельца это не работает:

| Ось | Данных на проде | Что получается |
|---|---|---|
| Проекты | **38** | 38 колонок в горизонтальном скролле, нужный проект глазами не найти |
| Персоны | **149** | простыня из 149 строк с галочками, править всё равно нельзя — только студия |
| Свои серверы | **1** | матрица «много на много» строится ради одной строки |
| Исключения | **0 проектов, 0 персон** | 99% решётки показывает «включено» — иголки в стоге нет вовсе |

Корень: экран рисует **полное декартово произведение**, хотя модель данных — deny-list.
`Project.McpServersOff` и Off-привязка персоны `mcp:<ключ>` — это **исключения из «доступно
везде»**. Пустой deny-list — норма, и норма должна занимать одну строку, а не 38 колонок.

## Решение

Ось экрана — **сервер**, содержимое — **только исключения**.

```
+--------------------------------------------------+
| ГДЕ СЕРВЕР ВЫКЛЮЧЕН                              |
| Свой сервер доступен везде, пока не выключен...  |
|                                                  |
| +---------------------------------------------+  |
| | Miro   свой        http   [2 исключения]    |  |
| |---------------------------------------------|  |
| | (o) НСИ Каталог           [Вернуть доступ]  |  |
| |     Проект                                  |  |
| |---------------------------------------------|  |
| | (o) Вера                        Студия ->   |  |
| |     Персона · QA-тестер                     |  |
| |---------------------------------------------|  |
| | [ (o) Выключить в проекте  v ]              |  |
| +---------------------------------------------+  |
|                                                  |
| +---------------------------------------------+  |
| | Файловый сервер  свой  stdio [Доступен      |  |
| |                               везде]        |  |
| | Исключений нет: сервер едет в ходы всех 38  |  |
| | проектов и доступен всем 149 персонам.      |  |
| | [ (o) Выключить в проекте  v ]              |  |
| +---------------------------------------------+  |
|                                                  |
| Доступ персоны задаётся в её студии — здесь он   |
| только виден.                                    |
+--------------------------------------------------+
```

Как закрываются сценарии из постановки:

1. **«Кому сейчас недоступен мой сервер?»** — плашка в шапке карточки даёт ответ, не читая
   ничего дальше: «Доступен везде» или «N исключений». Ниже — поимённо, кто именно.
2. **«Выключить в конкретном проекте»** — кнопка «Выключить в проекте» открывает пикер с
   поиском по 38 проектам. Печатаешь три буквы — попадаешь. Уже выключенные помечены
   в списке; повторный клик возвращает доступ (одна поверхность на оба направления).
3. **«Кого заденет удаление»** — карточка и есть ответ на этот вопрос, а диалог удаления
   перечисляет то же самое списком, а не одной строчкой (кнопка «Диалог удаления» в макете).
4. **Пустое состояние = норма.** Ноль исключений — это не пустая таблица, а фраза
   «Исключений нет: сервер едет в ходы всех 38 проектов и доступен всем 149 персонам».
   Числа 38/149 здесь — не украшение: они подтверждают, что данные загрузились.

Что уходит: матрица «персона × сервер» на 149 строк. Персоны остаются, но **только те,
у кого сервер выключен** — то есть обычно ни одной. Инвариант «правится в студии» не
меняется: у строки персоны нет тумблера, только ссылка «Студия →».

## Спецификация для Киры

### Раскладка

- Файл — тот же `McpAccessMatrix.tsx` (имя лучше сменить на `McpAccessTab.tsx`), обе таблицы
  и `wrapStyle`/`thStyle`/`tdStyle`/`nameCellStyle` удаляются целиком.
- Корень: `display:flex; flexDirection:column; gap: SP.sm` — как сейчас.
- Заголовок секции — `groupHeaderStyle` из `lib/modelProvidersShared`, текст «Где сервер выключен».
- Подсказка под ним — существующий `hintStyle` (`FS.xs` / `C.textMuted`).

### Карточка сервера

Одна на каждый элемент `data.servers` (порядок как на вкладке «Серверы»).

| Слой | Токены |
|---|---|
| Карточка | `background: C.bgWhite`, `border: 1px solid C.border`, `borderRadius: R.xl`, `overflow:'hidden'`, **`flexShrink: 0`** |
| Шапка | `padding: '11px 13px'`, `gap: SP.sm`; имя `13.5/600 C.textHeading` + `ellipsis` + `title` |
| Бейдж «свой»/«наследство» | как в `McpServerList` (`Badge tone="own" / "legacy"`) |
| Транспорт | `FONT.mono`, `10.5`, рамка `C.border`, `R.sm` |
| Плашка «Доступен везде» | `background: C.bgSelected`, `color: C.textSecondary`, `R.pill`, `FS.xs/700` |
| Плашка «N исключений» | `background: C.infoBg`, `color: C.info` — «к сведению», не ошибка |
| Плашка «Выключен целиком» (`server.enabled === false`) | `C.warningBg` / `C.warningText`, вся карточка `opacity: .62` |
| Строка исключения | `padding: '9px 13px'`, `borderTop: 1px solid C.borderLight`; иконка в квадрате 26 `R.md` на `C.bgPanel` |
| Футер | `borderTop: 1px solid C.borderLight`, внутри `Button variant="ghost" size="md"` |

**`flexShrink: 0` на карточках обязателен.** Контейнер вкладки — flex-колонка со скроллом,
и без него карточки сжимаются: нижние строки уезжают под собственную границу (в макете это
воспроизводилось и было исправлено — см. «Итерации»).

Accent в карточке не используется нигде, кроме ссылки «Студия →» и раскрывашки «Показать
ещё» — главного действия на этом экране нет, оранжевый тут был бы шумом.

### Строки исключений

- Проект: иконка `Ban` (lucide, `ICON_SIZE.sm`), заголовок — имя проекта (ellipsis + `title`),
  подпись «Проект», действие — `Button variant="ghost" size="sm"` «Вернуть доступ» →
  `data.setProjectOff(project, server.key, false)`.
- Персона: иконка `User`, заголовок — имя, подпись «Персона · роль», действие — текстовая
  ссылка «Студия →» (`C.accent`, подчёркнутая), поведение как сейчас: `navPush({screen:'personas',
  persona: id})` + `onClose()`. **Тумблера у персоны нет и не появляется.**
- Порядок: сначала проекты, потом персоны.
- Больше 5 строк — показываем 5 и кнопку «Показать ещё N исключений» (`C.accent`, `FS.xs/600`,
  на всю ширину, `borderTop`), в раскрытом виде — «Свернуть». Проверено на 12 исключениях.

### Пикер проекта

- Десктоп: `Menu` с `anchor={rect кнопки}` (он уже рисуется порталом с `position:fixed` —
  именно то, что нужно внутри скролл-контейнера модалки), ширина ~300, `maxHeight` 300.
- Мобила: `Modal` (он сам становится bottom-sheet ниже `MOBILE_MAX`) с тем же содержимым.
  Отдельной вёрстки шторки писать не надо.
- Содержимое: заголовок «В каком проекте выключить «<сервер>»?», `TextField` с автофокусом
  и placeholder «Поиск по 38 проектам», список строк, подпись внизу «Выключенный проект в
  списке помечен — повторный клик вернёт доступ».
- Фильтр — подстрока без учёта регистра по `project.name`. Клавиши: ↑/↓ по списку, Enter —
  выбор, Esc — закрыть.
- Уже выключенные — с чипом «выключен» (`C.infoBg`/`C.info`); клик по ним снимает исключение.
- Пустой результат поиска: «Ничего не нашлось / Проверьте написание названия проекта».
- Запись — существующий `data.setProjectOff` (оптимистично + счётчик `saveSeq`, уже есть).

### Состояния

| Состояние | Что показываем |
|---|---|
| `data.servers === null` | 2 скелетон-карточки (полосы `C.textMuted` при `opacity ~.16`, пульсация 1.3s) + строка «Смотрим, где сервер выключен…» |
| Ошибка (`data.error`) | плашка `C.dangerBg`/`C.dangerBorder`/`C.dangerText` с кнопкой «Повторить» → `data.reload()`; общая плашка ошибки модалки остаётся как есть |
| Своих серверов нет | `EmptyState compact` с иконкой `Plug`: «Своих серверов пока нет» + «Настраивать доступ пока не к чему: встроенные серверы продукта доступны всегда и не выключаются» + кнопка «Добавить сервер» (→ вкладка «Добавить») |
| Проектов нет (`data.projects.length === 0`) | кнопка «Выключить в проекте» `disabled`, рядом подпись «Проектов пока нет — сервер доступен во всех чатах вне проектов» |
| 1 сервер, 0 исключений | одна карточка в три строки — весь экран (главный кейс прода) |
| 38 проектов / 149 персон | в карточку попадают только выключенные; полный список проектов живёт в пикере с поиском |
| Длинные имена | одна строка + `ellipsis` + `title` на имени сервера, проекта, персоны |

### Мобильная раскладка

- Шапка карточки переносится: имя занимает всю строку, бейджи (свой/транспорт/плашка) уходят
  под него — иначе имя схлопывается до «Файловый серв…».
- Кнопка «Выключить в проекте» — на всю ширину футера.
- Пикер — bottom-sheet (см. выше), список с собственным скроллом до ~46vh.

### Тёмная тема

Все цвета — токены, отдельных значений не нужно. Проверено в макете: `C.infoBg`/`C.info`
на плашке «N исключений» и чипе «выключен» в тёмной теме читаются, `C.bgPanel` под иконкой
строки не сливается с `C.bgWhite` карточки.

### Диалог удаления (`McpServersModal`)

Сейчас — одна строка про персон. Предлагаю список «Что это заденет»:

- «выключен в N проектах — эти настройки исчезнут» (если `projectsOffCount > 0`);
- «выключен у N персон: Вера, Глеб» (если `personasOffCount > 0`, имена через запятую, после
  третьего — «и ещё N»);
- «во всех остальных проектах и у остальных N персон сервер просто пропадёт из инструментов»;
- существующая фраза про стирание секретов остаётся.

Данные для этого уже есть в `useMcpData` (`personasOffCount`, `projectsOffCount`, `personas`),
новых запросов не нужно.

### Чего делать НЕ надо

- Не добавлять на эту вкладку правку доступа персон — инвариант «правится в студии» держится.
- Не показывать встроенные серверы продукта: они доступны всегда, их отсутствие здесь —
  часть смысла экрана (об этом говорит подсказка сверху).
- Не заводить новых токенов: всё собрано из существующих `C`/`FS`/`SP`/`R`/`SHADOW`.

## Итерации правок

1. **v1, первая сборка.** Карточка сервера + список исключений + пикер с поиском.
2. **Срез нижних строк карточки.** На реальной высоте модалки карточки сжимались flex-ом и
   кнопка футера уезжала под границу. Лечится `flexShrink: 0` — вынесено в спецификацию
   отдельным пунктом, потому что в React-коде та же ловушка.
3. **Мобильная шапка.** Бейджи съедали имя сервера до «Файловый серв…» → на узком экране имя
   занимает отдельную строку.
4. **Меньше повторов в строках.** Подпись «Проект · сервер не едет в ходы этого проекта»
   дублировалась в каждой строке → осталось «Проект», объяснение живёт в подсказке сверху.
5. **Убрана подпись «Персоны — в студии персоны» из футера** — то же самое уже сказано
   внизу вкладки, в футере это был шум рядом с единственной кнопкой.
