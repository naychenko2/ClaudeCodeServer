# Фичи как сквозное измерение продукта — три варианта

Макет: [features-overview.html](features-overview.html). Один файл, сеть не нужна. Сверху служебная
панель: **Вариант** (А / Б / В), **Данные** («Обычно», «Все закрыты», «Нет фич»), тема, ширина 360 px и
кнопка **«Зайти в чат исполнителя»**, которая сразу ставит сценарий из постановки. Пунктиром
`C.accentMuted` обведено то, чего в продукте сейчас нет (галочка «новое пунктиром» это выключает).
Диплинки для скриншотов: `#a`, `#b`, `#c`, плюс `&m`, `&dark`, `&none`, `&closed`, `&chat=c9`.

Привязка: эпика и шагов ещё нет. Это проработка вариантов до разреза; `featureId`/`stepRef` появятся,
когда Софья заведёт фичу.

## Шаг 0. Как есть

Список чатов проекта (`SessionList`) — всегда дерево: чат-исполнитель висит под чатом-постановщиком
(`ParentSessionId` вычисляет `SessionTaskLinks` по `Session.TaskId → Task.SourceSessionId`).
Группировку меняет меню-кнопка «Дни / Теги / Темы / Без» (`ChatListToolbar`), поиск и фильтры
(статус, персона) спрятаны в поповер, архив — отдельный режим списка. Непрочитанность и статус хода
показаны не бейджами, а переливом фона карточки (`cc-unread`, `cc-tint--flow`). Баннеры встают между
шапкой и лентой (`ChatPanel`: «Этот чат в архиве», `ContinuationBanner`, `EscalationStickyBanner`).
Панели рабочей области переключаются рельсой иконок (`panelCatalog`): слева по умолчанию только
«Чаты», остальные справа и перетаскиваются между зонами; на мобиле вкладки — `PillSwitch` с «⋯».
«Задачи» — «Список / По дате / Доска», фильтры по статусу, исполнителю, приоритету и сроку; **фильтра по
фиче нет**. Фича сейчас видна только внутри одного чата: пилюля `TurnPlanPill` в режиме фичи и тело
режима (`FeatureModeBody` → `PipelineFlow`: 7 этапов, тоны `run/wait/stopped/loop`, ↺ по источникам,
пружина витков). Агрегат `FeatureRun` (`GET /api/tasks/features`) уже отдаёт всё для карточки:
`Stages`, `Now`, `Attention`, `ReturnsBySource`, `Lanes`, `StepsAccepted/StepsTotal`, `LastActivityAt`,
`Closed`, `Ready`, `Summary`. Порядок фич считает бэк, в 4 группах: тревога → идущие → прочие → закрытые.

## Общее для всех вариантов: плашка фичи

Сценарий, ради которого всё затевалось: **я открыл чат Дениса и не понимаю, где фича и где главный
чат**. Ответ одинаковый во всех трёх вариантах — плашка над лентой, в слоте баннеров `ChatPanel`
(там же, где «Этот чат в архиве»).

- **Что в строке:** глиф состояния (тот же словарь, что у пилюли: ромб — ждёт вас, квадрат — стоит,
  петля — доработка, кольцо — идёт) · название фичи · **мини-рельса** из 7 сегментов · текст статуса
  (`ждёт вас · мерж · 40 мин`, `стоит · Денис · 25 мин`) · счётчик `1/3 ↺1` · **роль этого чата**
  (`этот чат: Ш2 · бэк`) · справа кнопка **«Ключевой чат →»**.
- **В ключевом чате** вместо перехода стоит «Конвейер ▾». Он раскрывает под плашкой то же тело, что в
  меню пилюли (тревога с действиями, «Сейчас», 7 этапов, ↺ по источникам), и легенду. Если вы пришли из
  чата исполнителя, слева появляется «← Ш2 · бэк»: вернуться обратно тоже в один клик.
- **Тон фона:** ждёт вас — `C.infoBg`, стоит — `C.dangerBg`, закрытая — `C.bgInset` (второй план),
  остальное — `C.bgCard` с рамкой `C.borderLight`.
- **360 px:** плашка в одну строку высотой 44 px (глиф, название с многоточием, рельса, счётчик), справа
  тач-цель 40 px «→» — прямой переход. Тап по самой плашке открывает **шторку**: роль чата, большая
  кнопка «В ключевой чат фичи», конвейер и список чатов фичи.
- **Чат без фичи** — плашки нет, лента как сейчас.

Мини-рельса — это `PipelineFlow`, положенный набок. Пройден — `C.success`, активный этап длиннее (15 px
против 8) и красится в цвет тона (`textHeading` / `info` / `danger` / `warning`), впереди —
`C.progressTrack`, «нет в трекере» — пунктирный контур `C.dashed`, у закрытой фичи вся рельса
`C.textMuted` с прозрачностью .5. У каждого сегмента есть `title` «Ревью — сейчас», у рельсы —
`aria-label`.

## Вариант А · «Группы в Чатах» (минимум нового)

**Где живёт:** панель «Чаты», меню группировки получает пятый пункт **«Фичи»** рядом с «Днями»,
«Тегами» и «Темами». Новой панели нет, отдельного переключателя «Хронология / По фичам» тоже: «Дни» и
есть хронология.

- **Группа фичи** — заголовок-карточка: шеврон, глиф, название, счётчик `3/3 ↺2`, вторая строка —
  мини-рельса и статус. Фичи с тревогой несут левую кромку 3 px (`C.info` / `C.danger`). Внутри — её
  чаты по ролям: ключевой первым (метка `ключевой` в `C.accentLight`), затем разрез, шаги (`Ш2 · бэк`),
  ревью, проверка, финал. Строка чата — та же `ChatCard`, с переливом статуса.
- **Фильтры** — чипы с числами: Открытые · Ждут вас · Стоят · К мержу · Закрытые. Порядок групп —
  правило v2 с бэка, фронт его не пересортировывает.
- **Закрытые** — свёрнутая секция «Закрытые · 4 · на втором плане»: строки без карточки, текст
  `C.textSecondary`, статус `смержена 16.10 · 3 дн 6 ч`, рельса приглушена.
- **Без фичи** — обычные чаты ниже, своей секцией.
- **В «Днях»** у строки чата фичи вместо имени персоны стоит метка фичи (глиф + название). Это
  измерение видно и тому, кто «Фичи» не включал.
- **Пустые:** нет фич — `EmptyState` «Фич пока нет» и ниже чаты без фичи; все закрыты — зелёная строка
  «Открытых фич нет. Последняя смержена 17.10», «Закрытые» свёрнуты; фильтр пуст — «Под фильтр ничего
  не попало» с кнопкой «Показать открытые».
- **360 px:** экран списка, чипы в одну строку с прокруткой (высота 36), меню группировки — шторкой
  (как сейчас).

**Плюс:** ноль новых мест, работает на привычке «чаты — главное». Человек в любой момент видит, какие
фичи требуют его, и у каждой рядом её чаты. **Минус:** конвейер виден только мини-рельсой, детали — уже
в ключевом чате. В «Фичах» дерево меняет смысл: родитель — фича, а не чат-постановщик. Это надо явно
описать, иначе ручная группировка (`ParentOverrideId`) будет спорить с фичей.

## Вариант Б · Панель «Фичи» (отдельное место)

**Где живёт:** новая панель рельсы `features` (иконка lucide `Route`) в группе «проект», по умолчанию
слева рядом с «Чатами», с бейджем числа фич, которые ждут вас или стоят (`C.info`). Как любую панель,
её можно перетащить вправо. На мобиле «Чаты · Фичи» — вкладками `PillSwitch`.

- **Карточка фичи:** глиф, название, счётчик; ветка (mono); **подписанная рельса** — 7 сегментов с
  подписями «Разрез · План · Произв. · Ревью · Пров. · Финал · Мерж» (на 360 px подписан только
  активный этап); тревога плашкой (`C.infoBg` / `C.dangerBg`) или строка «Сейчас: Кира · Ш3 · 8 мин»;
  низ — аватары линий, «5 чатов», «Ключевой чат →».
- **Фильтры** — те же чипы; закрытые свёрнуты в «Закрытые · на втором плане» компактными строками.
- **Клик по карточке** открывает детали в той же панели (стрелка назад): «Ключевой чат» основной
  кнопкой, «Задачи в трекере →», тело режима фичи целиком, «Чаты фичи · 5», легенда.
- **Пустые:** нет фич — `EmptyState` с объяснением, что такое фича, и действием «Новая фича в чате с
  Софьей»; все закрыты — «Все фичи закрыты», «Закрытые» открываются по клику.

**Плюс:** самая полная картина. Это готовый фундамент для «табло» из целевого образа «Пульта куратора»
(curator-console-v2), только на реальных данных `FeatureRun`. **Минус:** ещё одно место, куда надо
ходить. Список чатов при этом о фичах не знает (вне плашки), а на мобиле вкладка «Фичи» конкурирует с
«Чатами» за первый экран. Доску по этапам (7 колонок) отвергла: на 360 px и в панели 340 px она не
живёт, а пустых колонок было бы больше, чем полных.

## Вариант В · «Сквозная плашка» (чат — вход)

**Где живёт:** список чатов не меняется. Каждый чат фичи несёт плашку (см. «Общее»), а в шапке чата
кнопка **«Фичи»** с бейджем открывает выпадающий **обзор «Все фичи»**: компактные строки (глиф,
название, счётчик, рельса, статус) в порядке v2, закрытые свёрнуты. Клик по строке — в ключевой чат
фичи. Ширина меню 380 px, на 360 px — во всю ширину.

- **Пустые:** нет фич — в меню «Фич пока нет»; все закрыты — «Открытых фич нет», бейджа на кнопке нет.

**Плюс:** минимум места, ноль новых панелей; ответ на «где я и куда вернуться» ровно там, где вопрос
возник. **Минус:** обзора всех фич, по сути, нет: меню — это быстрый прыжок, а не рабочее место.
Кнопка «Фичи» в шапке каждого чата — лишний шум в чатах, не связанных с разработкой.

## Сравнение

| | А · Группы в Чатах | Б · Панель «Фичи» | В · Сквозная плашка |
|---|---|---|---|
| Где фичи «все сразу» | в списке чатов, пятым пунктом группировки | отдельная панель рельсы | выпадающее меню из шапки чата |
| Глубина статуса | мини-рельса + статус | подписанная рельса, «Сейчас», тревога, тело конвейера | мини-рельса + статус |
| Чаты фичи рядом | да, внутри группы | в деталях фичи | нет (только в шторке на мобиле) |
| Закрытые на втором плане | свёрнутая секция | свёрнутая секция | свёрнуты в меню |
| Новое место в UI | нет | да | нет (кнопка в шапке) |
| Мобила 360 | естественно (экран списка) | вкладка рядом с «Чатами» | шторка с плашки |
| Цена во фронте | средняя: пятый режим `groupBy`, группа-заголовок, чипы | средняя-крупная: панель, карточка, детали, бейдж рельсы | малая: плашка + меню |
| Цена в данных | связь «чат → фича» (см. ниже) | фичи проекта + та же связь для плашки | связь «чат → фича» |
| Риск | спор «родитель-фича» и «родитель-чат» в дереве | ещё одно место; дублирует «Задачи» | шум в шапке у всех чатов |

## Рекомендация

**А + плашка, без кнопки «Фичи» в шапке. Б — вторая волна, если в ней появится действие, а не только
просмотр.**

Подозрение из постановки подтверждаю, с одной поправкой: из В беру **только плашку**, меню «Все фичи»
в шапке не беру. Его работу делает А: пункт «Фичи» в группировке и есть обзор всех фич, только там,
где человек и так выбирает, в какой чат идти. Кнопка в шапке каждого чата — второй вход в то же место и
шум для чатов вне разработки.

Почему А, а не Б, первой волной: в продукт приходят за чатом — список чатов открыт слева по
умолчанию, а все остальные панели живут справа. Фича для человека — способ собрать разбросанные чаты:
у «Рук» 84 задачи, и у каждой, ушедшей исполнителю, свой чат. А отвечает ровно на это и не заводит
нового места. Б станет нужна, когда у фичи появятся **действия
куратора** (ворота, «Принять», «Попросить Марка» задачей — см. «вынесено за волну» в контракте режима):
тогда это табло «Пульта куратора», а не дубль списка.

**Первая волна (малая-средняя):**
1. Плашка фичи во всех чатах фичи + «Конвейер ▾» в ключевом чате + «← назад» после перехода; на 360 px
   — шторка. Тело переиспользует `FeatureModeBody`/`PipelineFlow`, мини-рельса — новый маленький
   компонент рядом с `FeatureGlyphs`.
2. Пятый пункт группировки «Фичи» в `ChatListToolbar` + группа фичи в `SessionList` + чипы-фильтры +
   «Закрытые».
3. Метка фичи у строки чата в «Днях» — дёшево и сразу показывает измерение тем, кто группировку не
   менял.

**Вторая волна:** панель «Фичи» (Б) вместе с действиями куратора; фильтр «Задач» по фиче.

## Данных нет (список для Александра)

1. **Связь «чат → фича» для плашки.** Готовой нет: `GET /api/tasks/features?sessionId=` находит фичу
   только по `SourceSessionId`/`ExecutorLaunchedBySessionId` эпика, поэтому из чата исполнителя
   свою фичу не найти. Вывести её можно без нового хранения: `Session.TaskId → TaskItem.FeatureId`
   (исполнители, ревью, проверка, финал) плюс `epic.SourceSessionId` (ключевой). Предлагаю вычисляемые
   поля сессии на wire, `featureId` и `featureRole`, по образцу `ParentSessionId`/`TaskDone`
   (`SessionTaskLinks` поверх `ITaskLookup`, дописывает `SessionJsonConverter`). Альтернатива — собирать
   связь на фронте из `FeatureRun` (у задач есть `linkedSessionId`), но это тянет полные задачи всех фич
   в список чатов.
2. **«Ключевой чат» как понятие.** Сейчас это только `epic.SourceSessionId`. Если фичу завели не в том
   чате, где её ведёт оркестратор, плашка поведёт не туда. Нужно правило (`SourceSessionId`, иначе
   `ExecutorLaunchedBySessionId` первой задачи), а явное поле `KeySessionId` у эпика — только если
   понадобится «сделать ключевым» руками (вопрос 2).
3. **Фичи проекта.** `GET /api/tasks/features` без `sessionId` отдаёт все фичи **владельца**, фильтра по
   проекту нет. Для группы в «Чатах» и для панели нужен `?projectId=`. Для закрытых нужен облегчённый
   ответ без полных задач (у «Рук» их 84), иначе список тянет мегабайт ради серой строки.
4. **Чаты фичи без задачи** (консультации, ручной разговор человека про фичу) не связываются: у них нет
   `TaskId`. Нужна ручная привязка к фиче — первой волной не делаем, честно оставляем их «без фичи».
5. **Дерево против фичи.** Ручная группировка `ParentOverrideId` описывает родителя-чат; в режиме
   «Фичи» родитель — фича. Нужно правило: в «Фичах» ручной родитель не действует (или чат остаётся
   под ручным родителем внутри своей фичи).
6. **Хранение выбора.** Режим группировки и фильтр-чип — в `localStorage` (`cc_`), как фильтры списка
   сейчас; раскрытые группы — в памяти вкладки. Серверного хранения не нужно.
7. **Живое обновление.** Статус в плашке и в группе меняется по `task_changed` (стор `featureRuns`
   уже слушает его). Связь «чат → фича» на wire сессии устареет до следующей выдачи списка: при
   `task_changed` с `featureId` фронту нужно перечитывать сессию (или брать связь из стора фич).

## Итерации

- **v1** (2026-10-18) — три варианта, общая плашка, сценарий «чат исполнителя → ключевой чат → назад»,
  пустые состояния, обе темы, 360 px.
