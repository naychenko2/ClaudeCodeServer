# thinking-strip-proxy — прокси между claude CLI и vLLM локальной модели

Тонкий HTTP-прокси (`:18021` → vLLM `:18020`), который правит тело запроса ради
**prefix cache** движка и режима размышлений. Имя историческое: сейчас он делает больше, чем
вырезает размышления, но юнит и порт переименовывать дороже, чем объяснить (тот же случай,
что `preview`-ключи панели «Сервисы»).

Читает `Messages`-запросы Anthropic-роутера vLLM, всё остальное проксирует как есть, ответ
отдаёт потоком. **Fail-open по построению:** невалидный JSON, чужая структура тела,
незнакомая форма блока — пропускаем без правок. Перехват намеренно широкий (`except
Exception` с откатом на исходные байты): исключение при разборе оставило бы клиента вообще
без ответа, то есть опечатка здесь молча вешала бы ход пользователя.

Слушает `0.0.0.0`, а не `127.0.0.1`, потому что ходят через него и агенты из docker-песочницы.
Наружу машины порт при этом выставлять нельзя: за ним локальная модель без всякой аутентификации.

## Что он делает с телом запроса

| Фильтр | Зачем |
|---|---|
| `output_config` (при `THINKING_MODE=off`) | Любой `effort` включает `enable_thinking=true` в vLLM и перебивает серверный дефолт: ~100 с размышлений перед каждым шагом агента. |
| Напоминания `<total_tokens>N tokens left</total_tokens>` | Число меняется каждый шаг, vLLM сливает такие system-сообщения в верхний блок → кэш рвётся на ~14-тысячном токене (замер: ~20 с на шаг при 47k). |
| Повторные снимки `# Environment` | То же самое после каждого `cd` (~25 с на переход каталога). Первый снимок остаётся; повторный вырезается, только если он целиком «заголовок + пункты». |
| **Прунинг старых выводов инструментов** (`PRUNE_TOOL_RESULTS=on`) | Основную массу контекста дают выводы `Bash`/`Grep`/`Read` по 5–30 КБ. См. ниже. |

## Прунинг старых выводов

Содержимое блоков `tool_result` старше границы заменяется на фиксированный плейсхолдер
`[Old tool result content cleared]`; сам блок и парный `tool_use` остаются — модель помнит,
что она запускала, а результат при надобности перечитает. Так же устроены слой 1 самого
Claude Code, шаг `prune` у OpenCode и обрезка у Codex CLI.

**Инвариант — стабильность префикса.** Прокси заведён ровно ради неё: правка в середине
истории обрывает prefix cache, и ход платит полный пересчёт. Поэтому граница НЕ считается как
«последние N токенов» — так она съезжала бы на каждом ходу и ломала кэш сама. Граница
считается от **начала** истории (порядковый номер вывода не меняется при дописывании хвоста)
и **квантуется вниз по ступени в токенах** (`PRUNE_STEP_TOKENS`): префикс перестраивается раз
в ступень, а не каждый шаг. Прокси при этом остаётся **без состояния** — решение зависит
только от тела запроса, идентификатора сессии в нём нет.

**Всё меряется в токенах, ничего — в штуках вызовов.** Это не стилистика: 35 вызовов бывают и
20k токенов, и 200k, то есть в вызовах задача просто не измеряется. Ступень считается по тому
объёму, который реально будет обрезан (мелкие выводы её не двигают — экономии с них нет).

**Предпосылки, на которых держится инвариант** (нарушатся — будет разрыв кэша, не порча данных):

- **История append-only.** Порядок и размеры выводов от начала не меняются только при
  дописывании хвоста. Укоротится история (интерактивный rewind, правка на стороне сервера) —
  граница откатится на ступень, и префикс порвётся, пока объём не дорастёт обратно.
  Прерывание хода сюда не относится: CLI дописывает `tool_result` с `is_error`, история не
  укорачивается.
- **Системная часть не дрожит сильно.** Она входит в оценку контекста, но, в отличие от
  истории, не обязана расти. Поэтому в оценку она идёт огрублённой вниз до сотни тысяч
  символов: колебания секций промпта решение не меняют.

### Что именно режется — три вида

Разложение четырёх живых транскриптов 2026-09-22 по типам блоков:

| Тип блока | чтение файлов | обход мелких | разведка | **правка кода** |
|---|---|---|---|---|
| `tool_result` | **97.7 %** | **96.6 %** | 68.9 % | 30.8 % |
| `tool_use input`, из них Write/Edit | 0.3 % | 0.7 % | 12.0 % | **46.6 %** (36.3 %) |
| thinking | 0.4 % | 1.8 % | 14.6 % | 7.5 % |
| текст ассистента / человека | 1.7 % | 0.9 % | 4.5 % | 15.2 % |

Отсюда три вида обрезаемого, и все идут **в одну очередь** по порядку появления — ступень и
хвост считаются по общему объёму, а не по каждому виду отдельно:

- **`result`** — вывод инструмента: `content` блока `tool_result` → плейсхолдер.
- **`input`** — тело `Write`/`Edit`/`MultiEdit` в аргументах вызова, за флагом `PRUNE_INPUTS`,
  **выключено**. Без привязки к именам инструментов: в плейсхолдер уходят все строковые поля
  `input` длиннее `PRUNE_MIN_CHARS`, короткие (`file_path`) остаются. Обратимо: файл на диске.

  **Почему выключено — живой прогон 2026-09-22.** Модель прочитала файл, сказала «Let me
  write its analysis» — и записала на диск ровно строку `[Old tool input content cleared]`,
  32 байта вместо разбора на 15k. К этому моменту её предыдущий `Write` в истории выглядел
  как `{"file_path": …, "content": "[Old tool input content cleared]"}`, и она воспроизвела
  образец. **Выводы инструментов модель не копирует, а свой собственный текст — копирует.**
  Это меняет класс риска: обрезка `input` не просто теряет кэш, она **портит записываемые
  файлы**. Включать только с плейсхолдером, который модель не воспроизводит, и после живого
  прогона с несколькими `Write` подряд.
- **`thinking`** — старые размышления, за отдельным флагом `PRUNE_THINKING`: текст в
  плейсхолдер, подпись снимается (к новому тексту она не относится). Проверено живьём
  2026-09-22: CLI **шлёт** thinking-блоки обратно в теле запроса (в отладочном логе их число
  растёт с ходами), а vLLM **принимает** блок с плейсхолдером и без подписи — HTTP 200 и
  осмысленный ответ. Флаг оставлен отдельным на случай смены движка или шаблона модели.

Текст ассистента и реплики человека не режутся никогда: это ход мысли и постановка.

Не трогаем: свежий хвост объёмом `PRUNE_KEEP_TAIL_TOKENS`, выводы короче `PRUNE_MIN_CHARS`,
картинки и любые формы `content`, которые не разбираем, сообщения человека и блоки
`tool_use`. Если обрезка освобождает меньше `PRUNE_MIN_TOKENS` (оценка 4 символа на токен) —
не трогаем историю вовсе: ради мелочи префикс не рвём.

### Цена скачка границы — главный вывод замера (2026-09-22)

Скачок границы стоит **полного пересчёта хвоста истории**: на 180k контекста это 132 секунды,
а экономия на обычном шаге — доли секунды. Квантование снижает частоту скачков, но не их цену,
поэтому размер ступени решает всё. Замер на воспроизведении реального транскрипта (ступень
тогда мерилась в вызовах):

| Ступень, вызовов | Прогон 10 шагов | Холодный шаг | Скачок в прогоне | Prefix cache |
|---|---|---|---|---|
| без прунинга | 254.8 с | 198.5 с | — | 88.6 % |
| 10 | 283.7 с (**хуже**) | 116.0 с | 132.4 с | 77.9 % (**упал**) |
| 50 | **158.4 с** | 112.7 с | нет | 87.9 % |

Частая ступень даёт ≈13 с накладных на вызов — прунинг проигрывает сам себе, и критерий «hit
rate не упал» нарушается прямо на замере. Это нижняя граница выбора; верхнюю задаёт порог
срабатывания (следующий раздел).

### Когда прунинг вообще включается

Два условия, и они намеренно разведены по разным ручкам:

- **`PRUNE_MIN_CONTEXT_TOKENS` — «чат уже большой»**. Маленький чат не трогаем вовсе:
  автосжатие ему не грозит, а скачок границы он оплатил бы впустую.
- **Набралась ступень**: обрезаемого объёма не меньше `PRUNE_STEP_TOKENS`.

Ступень — она же порог первого срабатывания, и этого не избежать: непрерывная граница ползла
бы на один вывод каждый ход и рвала кэш каждый шаг, а раз граница ступенчатая — есть и первая
ступень. Важно лишь, чтобы порог мерился **в той же единице, что и задача**.

Ровно на этом мы обожглись. Пока ступень считалась в вызовах (защита 20 + квант 50 = порог 70
вызовов), живой прогон 2026-09-22 кончился худшим исходом: чат упёрся в **автосжатие на 53-м
вызове при 234k токенов** (5.9 минуты, 234k → 46k), а прунинг не включился ни разу —
`pruned_blocks: 0`. Контекстное условие было выполнено давно, мерка прошла 150k на 43-м
вызове; держал именно порог в чужих единицах.

Размер ступени выбран живым замером. При 50k граница на жирных выводах (один `Read` — 20k+
токенов) сдвигалась раз в пару шагов: за прогон 4 сдвига, каждый ценой полного пересчёта
(замерено два подряд — 158k и 98k токенов мимо кэша), hit rate просел с 81 % до 63 %. При
100k сдвигов вдвое меньше, а срабатывает прунинг почти так же рано — 164k против 156k мерки.

Поведение текущих дефолтов на реальных историях:

| История | Что делает |
|---|---|
| прогон со сжатием (234k, жирные `Read`) | включается на 35-м вызове при 152k, срезает ~83k токенов — за 18 вызовов до точки сжатия |
| чат исполнителя (133k) | молчит: контекст ниже порога |
| чат 035c3dd7 (217k, выводы по 1 КБ) | молчит: выводы дают лишь 69k из 217k, после защиты свежих 40k остаётся 21k — рвать кэш не за что |

Последняя строка показывает, зачем защита в токенах: **прежняя схема резала там свежие
выводы**, потому что защищала 20 штук, а 20 мелких выводов — это единицы тысяч токенов.

Почему 150k: автосжатие у локальной модели наступает где-то между 133k (чат исполнителя
22.09 дошёл дотуда без сжатия) и 318k (`preTokens` автосжатия там же). Более ранние границы
в транскриптах (54–79k, начало сентября) относятся к другой конфигурации стенда. Порог должен
лежать НИЖЕ точки сжатия, иначе прунинг не успеет ничем помочь.

Оценка контекста грубая — символы, делённые на 4, **вместе с системным промптом и тулсетом**:
без них мерка давала 71k против 133k настоящих токенов, у агента системная часть весит как
половина истории. Сверка на реальных историях: длинный чат — 226k по мерке против 217k по
факту prefill (±4 %), чат исполнителя — 90k против 133k (занижает, то есть включается позже,
что безопасно).

### Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `THINKING_MODE` | `off` | `off` / `on` / `budget` (последний требует патча роутера vLLM). |
| `THINKING_BUDGET` | `512` | Бюджет размышлений для `budget`. |
| `PRUNE_TOOL_RESULTS` | `off` | **Выключено по умолчанию**, `on` — включить прунинг. |
| `PRUNE_KEEP_TAIL_TOKENS` | `40000` | Сколько свежего вывода (в токенах) не трогать никогда. |
| `PRUNE_STEP_TOKENS` | `100000` | Ступень границы (токены). Она же порог первого срабатывания. |
| `PRUNE_MIN_CHARS` | `2000` | Ниже этого размера вывод не трогаем. |
| `PRUNE_MIN_TOKENS` | `20000` | Порог выгоды: меньше — не прунить вовсе. |
| `PRUNE_MIN_CONTEXT_TOKENS` | `150000` | Ниже этого размера контекста не включаемся совсем. |
| `PRUNE_INPUTS` | `off` | Резать ли тела Write/Edit. **Модель подражает плейсхолдеру** — см. выше. |
| `PRUNE_THINKING` | `off` | Резать ли старые размышления. Тот же риск подражания, не проверено. |
| `PRUNE_DEBUG` | `off` | Разбор каждого запроса в журнал. В лог попадает начало реплики — включать точечно. |
| `UPSTREAM_HOST`/`UPSTREAM_PORT`/`LISTEN_HOST`/`LISTEN_PORT` | `127.0.0.1`/`18020`/`0.0.0.0`/`18021` | Адреса. |

## Тесты

Без сети и без поднятого vLLM, одной командой из корня репозитория:

```bash
python3 -m unittest discover -s tools/thinking-strip-proxy
```

Покрыто: детерминизм, **неподвижность границы при дописывании хвоста** (главный тест —
он и защищает инвариант кэша), движение границы квантом, неприкосновенность последних
выводов, `tool_use` и реплик человека, идемпотентность, порог выгоды, сохранение формы
`content`, картинки, незнакомая структура тела.

## Развёртывание

Юнит живёт рядом с кодом и **запускает прокси прямо из рабочего дерева репозитория** —
копии расходятся, и за это мы уже платили (сломанная health-проба в неверсионируемом
`/opt/ccs/switch-release.sh` откатила удачную выкатку 2026-09-22).

```bash
sudo cp tools/thinking-strip-proxy/thinking-strip-proxy.service /etc/systemd/system/
sudo mkdir -p /etc/systemd/system/thinking-strip-proxy.service.d
sudo cp tools/thinking-strip-proxy/thinking-strip-proxy.service.d/mode.conf \
        /etc/systemd/system/thinking-strip-proxy.service.d/
sudo systemctl daemon-reload && sudo systemctl restart thinking-strip-proxy
```

Цена решения: прокси следует ветке рабочего дерева. На ветке, где этого файла ещё нет, он
падает и перезапускается каждые 2 секунды, пока файл не вернётся (`Restart=always`) —
отказ самовосстанавливающийся, но локальная модель на это время недоступна.

Путь `/home/an/Sources/ClaudeCodeServer` в юните зашит так же, как `/opt/ccs` в `ccs.service`.

## Замер

`measure_prune.py` проигрывает реальный транскрипт CLI как шаги агента (каждый следующий
запрос = предыдущий плюс дописанный хвост) и считает по `/metrics` движка, сколько токенов
попало в кэш. Соль в первом сообщении делает прогон холодным — иначе он паразитирует на
блоках предыдущего.

```bash
# поднять отдельный экземпляр рядом с живым (живой не трогаем)
PRUNE_TOOL_RESULTS=on LISTEN_PORT=18031 LISTEN_HOST=127.0.0.1 python3 proxy.py &
python3 measure_prune.py <транскрипт.jsonl> "метка" <соль> 10 18031

curl -s localhost:18031/__proxy/stats                 # обрезано блоков и символов
curl -s localhost:18020/metrics | grep prefix_cache   # queries/hits движка
```

Замеры **хода агента** (паузы, сжатия, стоп-мир) и кривая скорости модели живут отдельно —
[`tools/local-llm-measure/`](../local-llm-measure/README.md): они нужны и мерам, к прокси
отношения не имеющим. Там же собраны способы изолированного прогона и команды отката для
КАЖДОЙ ручки этого хозяйства, включая `PRUNE_*` и порог автосжатия.

`Prefix cache hit rate` = `hits_total / queries_total`. **Падение hit rate после включения
прунинга означает, что инвариант нарушен и прунинг в текущем виде вреден** — это главный
критерий, а не экономия токенов. Смотреть надо и на абсолютное число НЕ попавших в кэш
токенов: при прунинге знаменатель сам по себе меньше, и доля может обмануть.

Замер 2026-09-22 (транскрипт `035c3dd7`, 180k контекста, квант 50 против выключенного
прунинга): непопавших токенов 188k против 247k (−24 %), прогон 158 против 255 с, медиана шага
1.88 против 2.45 с, hit rate 87.9 против 88.6 %.

### Отодвигает ли прунинг автосжатие

Да. `compactMetadata.preTokens` в транскриптах совпадает с `usage` последнего ответа API
(318050 против 317088; 60790 против 60732; 53974 против 53462) — значит CLI считает занятость
окна по ответу API, а не по своей копии истории, и обрезка на стороне прокси откладывает
автосжатие. Цена одного автосжатия на локальной модели — 7.5 минуты.

Старая неверсионируемая копия жила в `/home/an/llm/thinking-strip-proxy/` (там же остались
`runs/EXPERIMENT.md` с журналом замеров режимов размышлений и `vllm-patch/`).
