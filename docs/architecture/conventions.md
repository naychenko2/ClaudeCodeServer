# Соглашения разработки

Развёрнутые правила работы с кодом, тестами и хранилищами. Выжимка со ссылкой сюда —
в разделе «Соглашения» корневого [CLAUDE.md](../../CLAUDE.md).

## Тесты: CI гоняет их на Linux

CI (`ubuntu-latest`, [.github/workflows/ci.yml](../../.github/workflows/ci.yml)) гоняет тесты на
Linux, а разработка идёт на Windows — тесты обязаны быть платформонезависимыми, иначе зелёные
локально они падают в CI.

**Ловушка 1 — пути.** `Path.IsPathRooted("C:\\…")` на Linux даёт `false`, поэтому
Windows-литералы там считаются относительными и проверки путей срабатывают не по тому правилу.
Пути в тестах строить от `Path.GetTempPath()` + `Path.Combine`, разделители не хардкодить.
Помнить и про остальное: регистрозависимость ФС, отсутствие `.exe`, недоступность WinAPI.

**Ловушка 2 — тайминги.** Раннер CI слабее рабочей машины и гоняет тесты параллельно, так что
ThreadPool там голодает: коллбэк `Timer`/фоновая задача приезжает много позже своего срока.
Слепая пауза (`await Task.Delay(500)` в расчёте на окно в 30мс) даёт плавающий провал вида
«collection is empty» — ждать надо **событие**, а не время: `TaskCompletionSource` +
`Task.WhenAny(tcs.Task, Task.Delay(таймаут))` со щедрым потолком (образец —
`WorkflowWatcherTests`, `SessionManagerTests`).

Сомневаешься — прогони набор в контейнере:

```powershell
docker run --rm -v "<репа>:/src" -w /src/backend mcr.microsoft.com/dotnet/sdk:10.0 dotnet test ClaudeHomeServer.Tests/ClaudeHomeServer.Tests.csproj
```

После этого пересобери локально: контейнер оставляет в `bin`/`obj` Linux-артефакты. Если `bin`
занят запущенным продуктом («Access to the path … is denied»), добавь `-p:ArtifactsPath=/tmp/artifacts`
— сборка уедет мимо рабочего дерева и гасить процесс не придётся.

## Категории тестов

Большинство — чистые юнит-тесты (Services, моки, in-memory), 1–50ms. Медленные — две группы:

- **Controllers** — поднимают `WebApplicationFactory` (полный HTTP-pipeline ASP.NET), 400–970ms.
- **GitServiceTests** — гоняют настоящий `git` CLI во временных репо, помечены
  `[Trait("Category", "Slow")]`, 500–720ms.
- Интеграционные MCP — HTTP-вызовы к MCP-серверам, 400–800ms.

Отдельная категория — **`Dns`**: тестам ридера и SsrfGuard нужен НАСТОЯЩИЙ резолв внешних имён
(`example.com`). На машине с системным прокси (Proxifier) DNS отдаёт вместо них локальный адрес,
`SsrfGuard` честно рубит его как loopback, и ~70 тестов валятся пачкой. Это среда, а не
регрессия — в CI они зелёные. Локально исключаются фильтром:

```powershell
cd backend; dotnet test --filter "Category!=Dns"   # чистый прогон на машине с прокси
```

Помечены классы `ReaderEmbedCheckTests`, `ReaderServiceTests` и точечно — сетевые тесты
`ReaderControllerTests` и `SsrfGuardTests`. Смысл метки не в отключении, а в том, чтобы
предсказуемо красные тесты не маскировали настоящую регрессию в остальных пяти тысячах.

На итеративную правку гоняй только релевантный набор:
`dotnet test --filter "FullyQualifiedName~SessionManagerTests"`. Медленные категории запускай
только при правках в покрываемом ими коде либо при действительной необходимости — полный прогон
перед коммитом/PR.

**Фон в тестах отключается явно.** `SessionManager` заводит таймер автосохранения, а внутри
`SaveSessions` живёт sweep-terminus — то есть фон меняет статусы сессий в произвольный момент,
включая промежуток между двумя ассертами. Вместе с глобальным `Session.TaskSourceSessionResolver`
(его переустанавливает конструктор каждого нового `TaskManager` в параллельном классе) это давало
плавающее падение `Sweep_ЖивойПотомокВГлубину` на полном прогоне — по отдельности ни один фактор
не воспроизводился. Лечится ключом `Session:AutoSaveSeconds = 0`, он уже стоит в `TestConfig.Build`
и в конфиге `SessionManagerTests`. Заводя новый фоновый таймер, сразу предусмотри способ его
выключить из конфига.

## Сторож регистрации подсистемы: где ему жить

У каждой вертикали с `IAppSubsystem` есть `*SubsystemRegistrationTests` — он ловит то,
чего не ловит больше ничто: разрыв связи с реальным DI-графом (снятая строка
`new XxxSubsystem()` в `Program.cs`, потерянный `ProjectReference` Main→вертикаль).
Сторожа границ и юнит-тесты вертикали проверяют ССЫЛКИ и логику, поэтому остаются
зелёными, а поломка выходит молчаливой: приложение стартует, контроллер отдаёт 500
на первом запросе. Минимум три проверки — стабильность `Key`/`Title`, состав
регистраций и резолв всех типов из РЕАЛЬНОГО графа через `TestWebApplicationFactory<Program>`.

Для вертикали, вынесенной в отдельный `.csproj`, стенду нужен `Program` из Main, и
способов дать его два — оба уже применяются:

- **тест в `ClaudeHomeServer.Tests/Composition/`** (Video, Yandex, Skills) — когда
  тестовая сборка вертикали намеренно не ссылается на Main (её тесты — чистый
  парсинг, без стенда);
- **`ProjectReference` на Main из своей `*.Tests`** (CodeGraph) — когда стенд ей нужен
  и для собственных тестов.

**Третий способ не изобретать.** По умолчанию бери первый: он не тянет Main в тестовую
сборку вертикали и потому не размывает смысл выноса. Второй — только если стенд нужен
самой вертикали, и тогда причина пишется комментарием прямо в её `.csproj`.

## Вынос вертикали: allow-list сторожа обязан сузиться вместе с кодом

Каждый вынос вертикали в отдельный `.csproj` заменяет прямые ссылки на швы —
и ровно столько же записей должно уйти из её allow-list в
`SubsystemBoundaryTests.Boundaries`. На практике этого не происходит само:
за Этап 5 мёртвые допуски пришлось снимать **три волны подряд** — Notes,
Knowledge и Tasks. Сторож при этом остаётся зелёным и выглядит рабочим,
хотя страхует поверхность шире реальной: вернувшаяся прямая зависимость
пройдёт молча, потому что разрешение уже стоит «на всякий случай».

**Проверять грепом бесполезно — он врёт в обе стороны.** На волне Tasks три
«упоминания» типов оказались текстом комментариев, а живую связь давала
регистрация в DI (`AddSingleton<DailyBriefingService>()`), которую текстовым
поиском видно плохо. Сторож читает IL, а не текст.

**Единственная надёжная проверка — мутация по каждому допуску:** убрать запись
из allow-list и прогнать
`dotnet test --filter "FullyQualifiedName~SubsystemBoundary"`.

- сторож остался зелёным → допуск **мёртвый**, снять;
- упал кейс этой вертикали → допуск **живой**, оставить и дописать
  комментарием, ЧТО именно его держит и при каком условии он снимается.

Второе так же важно, как первое: живой допуск без объяснения через месяц
неотличим от мёртвого, и следующий ревьюер либо снесёт его и уронит гейт,
либо оставит навсегда.

## Хранилища и проекты

- Хранилище проектов: `data/projects.json` рядом с executable.
- **Одна папка — один проект на владельца.** `RootPath` нормализуется при создании и смене папки
  (`Path.GetFullPath` схлопывает двойные разделители), а `ProjectManager.EnsureRootFree` отклоняет
  повторное подключение той же папки (400 «Эта папка уже подключена как проект …»). Причина:
  датасет знаний в Dify и запись `WorkspaceKnowledge` ключуются по `RootPath` — проекты-близнецы
  спорили бы за одну базу. У **разных** владельцев общая папка допустима: на этом держатся каскады
  «соседей по папке» (`GetByRootPath`).
- Метаданные сессий персистятся в `data/sessions.json`, история чата —
  `data/sessions/{claudeSessionId}/history.json`; процессы claude in-memory, resume через
  `--resume <claude-session-id>`.
- Новый вид записи истории (`StoredMessage`) регистрируется в трёх местах: `JsonDerivedType` в
  `StoredMessage.cs`, `PERSISTED_KINDS` в `chatReducer.ts` (сторож — `chatReducer.test.ts`) и,
  если у записи есть время, перекладка `timestamp → ts` в `normalizeHistory`. Отметка
  `interrupted` («Ход остановлен пользователем») пишется только на прерывании человеком
  (`SessionManager.Interrupt`, перебой ради его сообщения) — остановка исполнителя штабом и
  падение процесса её не оставляют.
- Path traversal защита: примитив спины `SafePath.Join`
  (`backend/ClaudeHomeServer.Core/Services/SafePath.cs`) — все пути через неё.
  `FileService.SafeJoin`/`SafeJoinPublic` — тонкие форвардеры к нему. Из вертикали зови
  Core-примитив напрямую: обращение через `FileService` — ссылка на чужую вертикаль,
  и сторож границ её ловит. Второй аргумент — путь ОТНОСИТЕЛЬНО корня: абсолютный на
  Linux станет относительным и приклеится к корню, то есть проверка «ссылка наружу»
  молча исчезнет (на Windows подмена незаметна — ловится только в CI).
- git diff/revert через `git` CLI; если не git-репо — возвращает null.

## Удаление чата уносит транскрипт claude CLI

Удаляется `{профиль}/projects/{уплощенный cwd}/{csid}.jsonl` плюс одноимённая папка сабагентов:
`SessionManager.DeleteTranscript` → `TranscriptMigrator.DeleteEverywhere`. Ищем во ВСЕХ профилях
(`LlmProviderRegistry.GetAllConfigRoots` + `sandbox-profiles/{ownerId}/*`), потому что переезды
между профилями (`TryMigrate`) и рабочими папками (`TryRelocateCwd`) намеренно оставляют копии.
Иначе переписка удалённого чата жила на диске до плановой уборки CLI (~30 дней).

**Инвариант:** удаляется только файл с точным именем `{csid}.jsonl` — никогда по маске, по времени
и никогда сама папка. Один `~/.claude` делят dev-, прод- и контейнерный инстансы плюс интерактивные
сессии самого пользователя (её слаг совпадает со слагом проекта, подключённого в CCS!), так что
«вычистить лишнее из папки» = снести чужую историю. Сборщика «сирот» по этой же причине нет.

**Гейт общего разговора.** Сессия, созданная с `resumeSessionId`, несёт ТОТ ЖЕ `ClaudeSessionId`,
поэтому история и транскрипт удаляются только когда на них не ссылается другой живой чат — иначе
у него пропадала лента (баг, описанный в `WorkspacePage.tsx`) и вся память `--resume`.

**Валидация.** `resumeSessionId` из тела запроса садится в `ClaudeSessionId`, а тот становится
именем папки `data/sessions/{csid}` и файла транскрипта, которые удаляются рекурсивно — поэтому
`StartNewSessionAsync` пропускает только `^[A-Za-z0-9_-]{1,128}$` (`TranscriptMigrator.IsSafeSessionId`),
иначе 400. Без гейта `resumeSessionId: ".."` означал бы `Directory.Delete` всей папки `data`.
Проверка на белом списке, а не через `Path.GetFileName`: тот пропускает `.` и `..`, а на Linux ещё
и `..\..\` целиком (обратный слеш там — легальный символ имени).

## Временные чаты

`Session.ExpiresAfterMinutes` (null — обычный чат), пресеты срока — часы в шапке чата и пункт меню
его карточки в списке; `ChatExpiryService` (тик 60с) удаляет чаты, неактивные дольше срока (кроме
статусов Working/Waiting); `DeleteAsync` чистит историю на диске и шлёт `chat_deleted`.

**Настройки чата не двигают `UpdatedAt`** (по нему идут сортировка списка, секции дерева и
непрочитанность): `SetExpiry` его не трогает, а `Update` ставит только при реальной правке
имени/модели/усилия/тегов. Чтобы отсчёт срока при этом не стартовал в прошлом, включение пишет
`Session.ExpiryAnchor` — дедлайн считается от него, если он позже активности
(`ChatExpiryService.CountFrom`, зеркало на фронте — `lib/expiry.ts`).

## Уведомления о ходе

Два уровня: общий рубильник браузера (localStorage + разрешение, тумблер в разделе «Уведомления»
перед строкой поиска) и мьют одного чата `Session.NotificationsMuted` (кнопка в шапке чата, пункт
меню карточки). Склейка — `lib/notify.ts`.

## Новое хранилище → сверься с бэкапом

Всё в `data/` попадает в архив по умолчанию (`BackupPaths.ShouldInclude` работает от обратного —
исключениями), поэтому думать надо, когда добавляешь:

1. **Кеш, лог или временный файл** в `data/` → добавь в исключения, иначе мусор поедет в облако.
2. **Секрет или ключ** → в `BackupPaths.SecretFileNames`, иначе он уедет в облачную папку вместе
   с архивом.
3. **Хранилище ВНЕ `data/`** (профили CLI, корень песочницы) → реши явно, бэкапить ли, и допиши
   в `BackupCore.CopyDataTo`.
4. **Не-JSON стор** (вторая БД и т.п.) → копирование файлом может дать протухший снимок, нужен
   свой способ (у SQLite — `BackupDatabase`).
5. **Критичный стор** → добавь в `BackupValidation.Validate`, иначе его порча не остановит
   восстановление.

Ломающее изменение формата любого стора = инкремент `BackupSchema.Version` (иначе старый код молча
обнулит стор при откате). Детали — [features.md](features.md#бэкапы-и-восстановление).

## HTTP-клиент к опциональной зависимости — через `AddQuietHttpClient`

[Core/Services/Http/QuietHttpLogger.cs](../../backend/ClaudeHomeServer.Core/Services/Http/QuietHttpLogger.cs).
Дефолтный логгер `IHttpClientFactory` печатает КАЖДЫЙ провалившийся запрос как Error со
стектрейсом, и погашенная зависимость (OTLP-коллектор, локальная Ollama) забивает консоль
портянками, в которых не видно настоящих ошибок. Тихий клиент даёт одну строку Warning с
последствием («Телеметрия не уходит») не чаще раза в 5 минут. Признак «опциональной»: вызывающий
уже умеет жить без неё — ловит ошибку и уходит в фолбэк.

## Разбор ```-заборов — только через `MarkdownFence`

[Core/Services/MarkdownFence.cs](../../backend/ClaudeHomeServer.Core/Services/MarkdownFence.cs) —
единственный примитив состояния ```-забора при построчном разборе markdown.
**Новый построчный разбор markdown обязан звать его, а не заводить свой флаг.**

Причина — в том, что наивное «переключить флаг на любом маркере» врёт ровно на
тех файлах, которые мы и разбираем (документация ПРО документацию):

- **Вложенный пример.** Внешний забор из четырёх бэктиков, внутри обычный ```
  — наивный флаг закроется на внутреннем, и весь остаток файла уедет в разбор
  как живой текст.
- **Незакрытый забор от опечатки** молча выкидывает остаток файла из разбора,
  и отчёт рапортует «всё здорово» — худший вид ошибки в сканере, который сам
  себя проверяет.

`MarkdownFence` работает по CommonMark: помнит СИМВОЛ и ДЛИНУ открывающего
маркера и закрывается только тем же символом длиной не меньше и без хвоста;
info-string бэктикового забора не имеет права содержать бэктик, поэтому
«``inline код`` в строке» забором не считается. Отступ до трёх пробелов
допускается, тройка посреди строки — обычный текст.

Живёт в спине (Core) не по случайности: его зовут и сканер карты проекта
(вертикаль `Docs` — `ProjectMapScanner`, `DocProperties`, `DocsIndexService`),
и раскрытие `@`-импортов CLAUDE.md (`ClaudeMdExpander` в Core). Третий комплект
правил неизбежно разошёлся бы с двумя первыми.

Тот же принцип «одно правило на обе стороны» действует и на фронте: стрижка
маркера `<voice>` в ленте и в санитайзере речи обязана одинаково игнорировать
блоки кода (см. [features.md](features.md), раздел «Голосовой режим чата»).

## Конфигурация: машинно-специфичное — в `appsettings.Local.json`

Локальные пути (`DefaultProjectsPath`, `McpConfigPath`), секреты и локальные
URL **не правим в отслеживаемых `appsettings*.json`** — там лежат общие
дефолты, и правка уедет в репозиторий, сломав сборку у всех остальных.

Своё кладём в `backend/ClaudeHomeServer/appsettings.Local.json` (он в
`.gitignore`, у каждого свой). Образец — `appsettings.Local.example.json`:
скопировать и вписать значения.

Порядок загрузки (последний переопределяет):

```
appsettings.json → appsettings.{Environment}.json → appsettings.Local.json
```

Подключается в [Program.cs](../../backend/ClaudeHomeServer/Program.cs) сразу
после `CreateBuilder` (`AddJsonFile("appsettings.Local.json", optional: true)`)
— важно именно там: побеждает последний добавленный источник, а любое чтение
`builder.Configuration` до этой строки вернёт значение из общего файла.
Файл необязателен: нет его — берутся дефолты из git.

**В окружении `Testing` файл не подключается сознательно.** Иначе боевые токены
подписок, `Dify:ApiKey` и ключи `LlmProviders` разработчика протекают в тестовые
хосты, а прогрев подписок запускает настоящий `claude` с боевым OAuth-токеном.

Отдельный случай — рубильники, которые не должны включаться «по умолчанию у
всех»: `PowerControl:Enabled` живёт только в машинном `appsettings.Local.json`
вне git (см. раздел «Питание машины» в карте проекта).

## Коммиты

- **Conventional Commits**: `type(scope): описание`
  (feat/fix/perf/docs/refactor/build/chore/ci/test/style).
- **Язык сообщений — русский** (в отличие от общего дефолта на английском).
- Атомарность: одно логическое изменение — один коммит.
- `commit`/`push` — только по явной просьбе. Исключение — ниже.

**Трейлер `Co-Authored-By`** называет модель, которая реально делала коммит
(«Claude Opus 4.8», «GLM 5.2»), а не фиксированную версию. Домен `noreply`
берётся по вендору модели:

| Вендор | Домен трейлера |
|---|---|
| Anthropic | `noreply@anthropic.com` |
| ZhipuAI (GLM) | `noreply@z.ai` |

Слова «Claude» в начале имени быть не должно, если модель не от Anthropic.

**Исключение из «только по явной просьбе» — цепочка задач-исполнителей в общем
worktree** (задача трекера с явно заданным `worktreePath`). Исполнитель
коммитит СВОИ файлы локально сам, атомарно, сразу как его собственные критерии
(тесты + review-consilium) зелёные — не дожидаясь отдельной просьбы. `push`, PR
и мерж в `master` — по-прежнему только по явной просьбе.

Причина — инцидент 2026-09-01: полностью отревьюенная работа пропала бесследно
между хопами задач. **Untracked-файлы не защищены ни `git reflog`, ни
`git fsck`** — у них нет ни одного объекта в базе git, ссылку на который можно
было бы восстановить. Поэтому окно между «работа готова» и «работа
закоммичена» в общем worktree равно окну необратимой потери, и закрывать его
обязан тот, кто работу сделал. Второе следствие того же инцидента: следующий
исполнитель в цепочке иначе стартует на грязном дереве, и его дифф включает
чужие правки — отдельный класс регрессий, которого не видит ни один сторож.
