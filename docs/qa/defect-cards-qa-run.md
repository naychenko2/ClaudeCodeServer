## Девять сценариев

### 1. Создание дефекта с одним заголовком — пройдено

REST `POST /api/projects/{id}/tasks {kind:"defect", title:"QA-S1…"}` без repro → 200,
`kind:"defect"` в ответе. На доске карточка со значком Bug (`aria-label="Дефект"` — 7 значков
на доске). Замечание (не дефект): диалог NewTaskDialog гейтит кнопку «Создать» заполненными
шагами у дефекта — осознанное сужение постановки волны 2; сервер заголовок один принимает.
Снимок: [01-board.png](../../.cc-attachments/qa-defects/01-board.png)

### 2. Отказ при создании сразу в Done — пройдено

Два входа, оба 400 `«Дефект нельзя создавать сразу в Done: путь прошёл проверку мимо работы.»`:
- `{kind:"defect", status:"done"}` → 400;
- `{kind:"defect", columnId:"done"}` → 400 (категория колонки резолвится).
Контроль: обычная задача с `status:"done"` создаётся (200) — см. также сценарий 8.

### 3. Отказ по review-колонке без шагов — пройдено (REST)

В проекте выставлены кастомные колонки (`PUT /api/projects/{id}/board-columns`), среди них
`{id:"rev", name:"На проверке", role:"review"}`. Дефект без repro → `PUT /api/tasks/{id}
{columnId:"rev"}` → 400 `«Дефект попадает в ревью без шагов воспроизведения: заполните
Repro.Steps.»`. После `PUT {repro:{steps:"…"}}` перевод в review проходит (200, `columnId:"rev"`).
UI-тост при drag-перетаскивании в review отдельно не гонялся (тост отказа в целом проверен
в сценарии 4); отображение кастомных колонок на доске UI не проверено (см. «Не проверено»).

### 4. Отказ при закрытии без вердикта — пройдено

REST: `PUT {status:"done"}` → 400 `«Дефект нельзя закрывать без Verification: либо заполните
Verification, либо используйте внутренний путь ClosedWithoutCheck.»`, статус задачи не изменился.
UI: карточка дефекта → «Готово» → тост «Не удалось изменить статус» с серверным текстом,
карточка не закрылась. Снимки: [02-details-s1.png](../../.cc-attachments/qa-defects/02-details-s1.png),
[03-toast-refusal.png](../../.cc-attachments/qa-defects/03-toast-refusal.png)

### 5. Закрытие с вердиктом — пройдено

`PUT {status:"done", verification:{notes:"Проверено на стенде…"}}` → 200. Сервер штампует
`verifiedAt` сам, `personaId:null` (человек; из REST-сессии без персоны). Статус `done`.

### 6. Закрытие галочкой в заметке с исходом «Закрыт без проверки» — пройдено

Проектная заметка с чекбоксами → `POST /api/notes/{id}/tasks/promote {line:0}` (задача-«человек»
из заметки всегда создаётся обычной — промоут не делает дефект) → `PUT /api/tasks/{id}
{kind:"defect", repro:{…}}` (конверсия вида) → `POST /api/notes/{id}/tasks/toggle {line:0,
done:true}` → задача `done`, `outcome:"closedWithoutCheck"`, `verification` нет. Плашка
«Закрыт без проверки» видна на карточке на доске. Снимок:
[04-closed-without-check.png](../../.cc-attachments/qa-defects/04-closed-without-check.png)

### 7. Снятие волной штаба с тем же исходом — частично

Код-путь в восстановленной волне 1 есть (`TeamWaveService.DropSubtaskAsync` пишет
`Outcome=ClosedWithoutCheck` для Kind=Defect, дизъюнкция DefectRules пропускает закрытие), но
единственный вход — SignalR `RespondTeamEscalationAsync` с открытой эскалацией живой практики
штаба; прямого REST-входа нет, живая волна на QA-стенде не поднималась. Механизм исхода
(Outcome ⇒ закрытие без Verification) проверен живьём сценарием 6. Тестовой страховки пути
нет — см. Д-2.

### 8. Незатронутость обычной задачи — пройдено

Обычная задача: создаётся сразу в Done (200), закрывается без вердикта (200), `kind:"task"`,
`outcome` нет. Задача из галочки заметки (без конверсии в дефект): закрылась тогглом, `outcome`
нет.

### 9. Перенос Kind и Repro в следующее повторение — пройдено

Дефект `recurrence:{type:"daily"}` + `dueDate` (спавн привязан к DueDate — без даты следующего
экземпляра не будет, это штатное поведение) + repro → закрытие с вердиктом → создан следующий
экземпляр серии: `kind:"defect"`, `repro.steps` сохранён, `verification`/`outcome` НЕ перенесены.

## Дефекты

### Д-1. Фильтр «Только дефекты» не применяется: чип есть, список не фильтруется (severity: средний)

**Шаги воспроизведения:**
1. Открыть доску задач с миксом обычных задач и дефектов.
2. Включить чип «Только дефекты».

**Фактический результат:** список не меняется: `defectsOnly` читается только внутри
`BoardToolbar.tsx` (стор + чип); строка применения в `TaskBoard.tsx`
(`if (defectsOnly && t.kind !== 'defect') return false;`), которую постановка волны 2 оставляла
«соседу по волне», не добавлена. Экспорты `setDefectsOnly`/`useDefectsOnly` без потребителей,
предикат не покрыт витестом.
**Ожидаемый:** на доске только открытые дефекты (`isOpenDefect`).

Карточка: 57443ba7-bd90-4a59-8215-c462a424f631

### Д-2. Нет автотеста на исход ClosedWithoutCheck при снятии подзадачи-дефекта волной (severity: мелкий)

**Шаги воспроизведения:**
1. `grep ClosedWithoutClose*` в `ClaudeHomeServer.Tests` — покрытие есть только в
   DefectRulesTests и TaskManagerTests.

**Фактический результат:** путь `TeamWaveService.DropSubtaskAsync` (кнопка «Снять»/«Пропустить»
карточки эскалации закрывает дефект с `Outcome=closedWithoutCheck`) не покрыт тестом; живой
прогон требует волны штаба (см. сценарий 7).
**Ожидаемый:** страховка тестом, как у пути галочки заметки.

Карточка: 0eb06e1a-1b63-4edf-9e38-f3e955b7248b

- Фич-флаг `defect-cards` (план, шаг 7) не реализован ни в одной волне: фича живёт безусловно,

  карточкой не оформляю (поломки нет, есть несоответствие плану).
