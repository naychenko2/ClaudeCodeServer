# Поле маршрута: состояние ошибки — предложение

**Макет:** [`model-route-error-state.html`](./model-route-error-state.html)
**Раздел:** «Поставщики моделей» (Модели и расход) · волна 1 из 3
**Связано:** валидация маршрута локального действия (бэкенд + UI), автоподстановка префикса, починка кривого сохранённого маршрута на проде.

## Проблема

Сейчас маршрут локального действия можно задать только через RoutePicker (выбор из списка), и
бэкенд принимает любой текст через `PUT /api/admin/local-actions/{key}` — формальной валидации
формата нет. На проде уже лежит кривой маршрут, введённый руками, и UI не показывает, что он кривой:
значение молча уходит в фолбэк, а владелец не знает, что настройка не работает.

Поле ввода маршрута в `ui/Field.tsx` тоже не имеет error-состояния — только лейбл, контрол и muted-хинт.
Поэтому для новой текстовой валидации нужно спроектировать состояние ошибки с нуля.

## Решение

Ошибка — отдельное состояние поля, не «красный фокус»:

| Элемент | Решение | Токены |
|---|---|---|
| Подсветка поля | рамка danger + мягкий danger-фон + danger focus-ринг | `C.danger`, `C.dangerBg`, `--shadow-focus-danger` |
| Текст ошибки | под полем, с иконкой CircleAlert; конкретный — называет, что не так и как починить | `C.dangerText`, `FS.sm` |
| Подсказка о формате | всегда видна под ошибкой, примеры моноширинные | `C.textMuted`, `FS.xs` |
| Кнопка «Сохранить» | `disabled`, пока значение невалидно | `Button primary` disabled (opacity .55) |
| Альтернатива | ссылка «Выбрать из списка» → RoutePicker (префикс подставляется сам) | — |

**Один производный токен:** `--shadow-focus-danger` — та же геометрия, что `shadow-focus`, но цветом
`C.danger` вместо `C.accent`. Заводится в `theme.css` для обеих тем; значения — в шапке макета.

**Формат маршрута** (из `LocalActionOverridesStore` / `CloudCheapClient`):
`tier:strong|medium|weak` · `preset:{id}` · `direct:{modelId}` · `local` · `{id модели}`.

### Тексты ошибок под вариант ввода

| Ввод | Сообщение |
|---|---|
| `tier:powerful` | «powerful» — такого уровня нет. Доступно: strong, medium, weak. |
| `strong` | Пропущен префикс. Уровень задаётся как `tier:strong` — выберите из списка. |
| `preset:` | Не указан пресет. После `preset:` нужен id, например `preset:eco-chain`. |
| `preset:old-name` | Пресет не найден среди общих пресетов. |
| `direct:` | Не указана модель прямого адаптера. После `direct:` — id модели. |
| `glm 4.7` | В id модели не может быть пробелов. |
| `claude-sonnet-55` | Модель отсутствует в каталоге. |
| `local` агентному месту | Локаль недоступна этому месту — нужна агентная модель. |

### Поведение

- Валидация — по `blur` и по изменению после первой ошибки (не на каждое нажатие — иначе краснеет во время набора).
- `aria-invalid="true"` + `aria-describedby` связывают поле с текстом ошибки.
- Сохранённый кривой маршрут подсвечивается danger-цветом прямо в строке списка действий — не маскируется под значение; клик открывает форму с предзаполненным значением и ошибкой.

### Состояния поля

`default` (пустое, placeholder с примерами) → `focus` (accent-ринг, ошибки ещё нет) → `error` (danger) → `valid` (тонкая success-рамка, кнопка активна — подтверждение живёт в ней, без отдельного «✓ ок»).

## Обе темы и мобила

- Цвета — `C.danger` / `C.dangerBg` / `C.dangerText` заведены в `:root[data-theme="dark"]`; контраст dangerText на bgCard ≈ 5.4:1 (AA).
- Мобила: нижняя шторка `R.sheet` на `C.bgMain`, поле во всю ширину, кнопки в столбик, tap-цели ≥ 40px. Отдельной тёмной вёрстки нет — те же токены.

## Итерации правок

1. **(текущая)** Первый проход: error в контексте формы (светлая + тёмная), таблица текстов ошибок, витрина состояний, сохранённый кривой маршрут, мобильная шторка в обеих темах, спецификация с токенами и поведением.
