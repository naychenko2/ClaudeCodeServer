## Дефекты

### Д-1. Регрессия: `DefectRules.EnsureNotClosedAtCreate` не проверяет `columnId` на создании (severity: средний)

**Шаги воспроизведения:**
1. Создать дефект через `POST /api/projects/{id}/tasks` с телом `{kind:"defect", title:"...", columnId:"done"}`.
2. Получить 200, в ответе `status="todo", columnId="done"`.
3. Открыть доску — дефект виден в Done-колонке со значком «Дефект», пользователь видит закрытый дефект

**Фактический результат:** дефект создан. `DefectRules.EnsureNotClosedAtCreate` проверяет только
`task.Status == TaskItemStatus.Done`; `columnId` не резолвится в категорию. В прошлом прогоне
этот путь отсекался — регрессия от `2c104cd0` или раньше.

**Ожидаемый:** 400 «Дефект нельзя создавать сразу в Done…», как для `status:"done"`.

Карточка: 4c700f32-915f-4ee1-afd7-c0acd91ccf48

### Д-2. Регрессия: дефект закрывается с пустым `verification.notes` (severity: средний)

**Шаги воспроизведения:**
1. Создать дефект с repro.
2. `PUT /api/tasks/{id} {status:"done", verification:{notes:""}}`.
3. Получить 200, задача закрыта, `verification.notes=""`.

**Фактический результат:** гейт `DefectRules.EnsureVerificationOnClose` пропускает пустой notes,
потому что проверяет только `Verification != null`. Закрытие с пустым вердиктом — минуя суть
«проверено и записано что нашли».

**Ожидаемый:** 400 «Дефект нельзя закрывать без Verification…», как для отсутствующего поля.

Карточка: 738e29e5-30ab-4ba6-8b10-5788fcdd69d2

### Д-3. Регрессия: галочка в заметке ставит `outcome="closedWithoutCheck"` обычной задаче (severity: средний)

2. `POST /api/notes/{id}/tasks/promote {line:0}` — задача kind="task".
3. **Не конвертировать в дефект.**
4. `POST /api/notes/{id}/tasks/toggle {line:0, done:true}`.
5. `GET /api/tasks/{id}` → `kind="task", status="done", outcome="closedWithoutCheck"`.

### 1. Создание дефекта с одним заголовком — пройдено

### 2. Отказ при создании сразу в Done — пройдено

Repro.Steps.»`. После `PUT {repro:{steps:"…"}}` перевод в review проходит (200, `columnId:"rev"`).
