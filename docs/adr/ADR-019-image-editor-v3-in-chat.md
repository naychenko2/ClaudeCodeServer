# ADR-019: Редактор картинок v3 — работа с картинкой в основном чате проекта

**Статус:** Принят, 2026-09-27. Волна 1 (швы ядра и хранилище нитей) — в коде.
**Дата:** 2026-09-27
**Основа:** [ADR-018](ADR-018-image-editor-v2.md) — редактор v2 (отдельный чат картинки). Этот ADR
его **заменяет** в части чата картинки (разделы 1–3 ADR-018): отдельного чата у картинки больше
нет, работа идёт в любом чате проекта. Поставщики, котировка, правки без ИИ, «Сохранить как…»,
персонажи и модульность редактора (ADR-018 §4–§10) остаются в силе.
**Входные артефакты:** макет [image-editor-v3-in-chat.html](../mockups/image-editor-v3-in-chat.html)
и записка [image-editor-v3-in-chat-proposal.md](../mockups/image-editor-v3-in-chat-proposal.md)
(раздел «Решения Андрея», коммит `e8d483f0`); архитектурный разрез Александра (задача трекера
`540d90c7`); сверка макета с дизайн-системой Майи (задача `d8774120`); решения Андрея 1–3 от
2026-09-27 по открытым вопросам разреза (раздел «Решения» ниже).
**Исполнители:** Денис (бэкенд), Кира (фронт), волны 1–4.

## Контекст

В v2 у картинки был свой чат «hero.png · правка» с окном редактора. В v3 окно уходит: картинка
выбирается «в работу» прямо в основном чате проекта, над композером появляется полоса «Картинки»,
результаты ложатся в ленту карточкой-стопкой («нитью»), холст открывается попапом.

Что мешает сделать это в лоб (сверено по ветке `feat/image-editor-v3-in-chat`, `e8d483f0`):

- Привязка v2 — поле ядра `Session.ImageChat`, меняют его методы `SessionManager` через шов
  `IImageChatSessions`. Поле фичи в Core-модели нарушает правило «новая фича — отдельный модуль»,
  а смена фокуса — настройка, которая не должна писать `sessions.json` и двигать `UpdatedAt`.
- Состояние редактора v2 (`ImageChatStateStore`) живёт в рабочей папке `data/image-editor` — это
  TTL-кеш на 7 дней вне бэкапа. Карточка в ленте живёт бессрочно, через неделю её шаги исчезли бы.
- Полиморфизм истории `StoredMessage` закрыт в Core: каждый новый `kind` — правка ядра, а
  незнакомый `kind` при выключенном модуле выпадает из ленты.
- Модуль не узнаёт об удалении и ветвлении чата: `ChatDeletedMessage` — событие для фронта, а не
  для подсистем.

## Решения Андрея (2026-09-27)

Три решения по открытым вопросам разреза. ADR их **не пересматривает**.

1. **Агент может сам брать картинку в работу и создавать черновик.** Это всегда видно: смена
   выбора пишется в ленту тихой строкой («Claude взял в работу: logo.png»), человек снимает выбор
   ✕. Взять вариант, откатиться и сохранить в проект может **только человек**. В инструменте
   `image_generate` параметр **`threadId` обязателен**: «Редактировать из дерева» разрешено посреди
   хода агента, и запуск «по текущему фокусу» ушёл бы не на ту картинку.
2. **Чаты картинки v2 уходят в архив.** Разовая идемпотентная миграция ставит
   **`ArchivedAt = now` и не меняет `UpdatedAt`** — отсюда `IsArchived = true` по общему правилу
   (`IsArchived = ArchivedAt != null && UpdatedAt <= ArchivedAt`). Признак выполненной миграции —
   аддитивный маркер **`SessionImageChat.MigratedAt`**. Транскрипт `{csid}.jsonl` и `--resume`
   сохраняются: первое же сообщение вернёт чат из архива, дальше это обычный чат проекта.
   **`BackupSchema.Version` остаётся 9**: поле аддитивное, формат существующих файлов не меняется;
   восстановленный старый бэкап мигрирует тем же кодом при старте (условие
   `ImageChat != null && MigratedAt == null`). Чат, который человек вернул из архива сам, повторно
   не архивируется — маркер уже стоит.
3. **Выбор полосы над композером запоминается на чат, а не на проект.** Ключ —
   **`cc-composer-strip:{sessionId}`** в `localStorage`, то есть на устройстве, не на сервере.
   **Правило старшинства** в сторе полос ядра: если в чате выбрана картинка (серверный фокус),
   открывается полоса «Картинки» независимо от запомненного выбора; без выбранной картинки
   открывается запомненная полоса чата; если её нет — Git. Правило покрывает vitest стора полос.

Разрез рекомендовал хранить выбор на проект и устройство; решение 3 это перекрывает. Остальные
рекомендации разреза приняты без изменений.

## Решение

### 1. Нить и фокус — хранилище модуля по `sessionId`, у `Session` новых полей нет

- `Threads/ImageThreadStore` в модуле `ClaudeHomeServer.ImageEditor`, файл
  `data/image-threads/{ownerId}/{sessionId}.json`. Корень отдельный от рабочей папки
  `data/image-editor`: TTL его не чистит, а бэкап подхватывает по умолчанию (весь `data/` едет в
  архив, исключена только рабочая папка).
- Содержимое: `focus` (id нити или `null`), `revision`, `threads[]`. У нити: `id`, `file` и
  `lineage`, `draftFolder` (черновик «Новая картинка»), `stacks[]`, `currentStackId`, `settings`
  (поставщик, модель, число вариантов, «размер оригинала»), `pendingJobId`, `createdAt`. У стопки:
  `stackId`, `steps[]` (id шагов `ImageEditStep`), `forkedFromStepId`, `old` («старая стопка» после
  отката и новой правки).
- **Каждая запись поднимает `revision`**; запись со старой ревизией — конфликт (`409` с актуальным
  состоянием), фронт перечитывает, а не затирает правку агента или другой вкладки.
- **Смена фокуса — настройка:** пишет только файл нитей, `sessions.json` не трогает, `UpdatedAt`
  не двигает, чат не поднимает в списке и не возвращает из архива.
- Персонаж — на проект (`CharacterStore`), при смене фокуса остаётся подключённым.
- Пиксели шагов лежат в рабочей папке, но живут столько же, сколько нить: чистка удаляет только
  шаги, на которые не ссылается ни один файл нитей (волна 2). Пропавший шаг карточка показывает
  «шаг устарел», а не 404.

REST модуля (гейты как у остальных ручек редактора: флаг `image-editor` и чужой проект — `404`;
чужой, несуществующий и не свой по проекту чат неотличимы — одинаковый `404`):

| Ручка | Что делает |
|---|---|
| `GET api/projects/{projectId}/image-editor/sessions/{sessionId}/threads` | нити чата, фокус, ревизия |
| `PUT api/projects/{projectId}/image-editor/sessions/{sessionId}/threads/focus` | `{ threadId \| null, revision }` → новое состояние; старая ревизия — `409`, чужая или несуществующая нить — `404` |

### 2. Швы ядра — общие, не «картиночные»

Модуль по-прежнему ссылается только на Core. Швы ниже понадобятся и будущим полосам «Видео» и
«Звук», поэтому в них нет ничего про картинки.

1. **`IChatFeed`** (`Core/Services/Composition/IChatFeed.cs`) —
   `AppendRecordAsync(sessionId, StoredModuleRecord, ct)`: запись в ленту чата вне хода. Адаптер
   `Services/ChatFeed.cs` в Main строится поверх `SessionManager.AppendStoredAsync`. Запись —
   **активность**: двигает `UpdatedAt` (как тихие строки v2) и возвращает `false`, если чата нет.
   Владение и проект проверяет вызывающий модуль (`ISessionDirectory`). Шов в волне 3 заменяет
   `IImageChatSessions` целиком.
2. **Универсальная запись истории `StoredModuleRecord`**, дискриминатор `module_record`:
   `{ module, recordType, data, fallback, timestamp }`, живая пара — `ModuleRecordMessage`
   (`type = "module_record"`) с теми же полями. `data` — произвольный JSON модуля, ядро его не
   разбирает. `fallback` — готовый текст строки на случай, когда модуль выключен или не знает
   `recordType`: лента рисует его вместо карточки. Поле называется `recordType`, а не `type`:
   `type` у живого сообщения уже занят типом события протокола, а формы истории и ленты обязаны
   совпадать. **Запись пишется в `history.json`, а не в транскрипт CLI — модель её не видит**, о
   событиях модуля она узнаёт из блока хвоста хода.
3. **События шины `session/deleted` и `session/branched`** (`SessionDeleted`, `SessionBranched` в
   `Core/Services/Turn/TurnEvents.cs`, карта — [ADR-013](ADR-013-turn-event-bus.md)). Notification:
   сбой подписчика гасится, удаление и ветвление не падают. Ход тут ни при чём, поэтому
   `TurnSeq = 0`. Модуль по удалению сносит файл нитей, по ветвлению копирует его под новый
   `sessionId` с теми же `threadId` — якоря в скопированном `history.json` продолжают разрешаться.

### 3. Как нить попадает в ленту

В `history.json` пишется **якорь** `module_record { module: "imageeditor", recordType:
"image_thread", data: { threadId, stackId } }` — по одному на стопку. Содержимое карточки (шаги,
варианты, прогресс) рисуется живьём из хранилища модуля (REST плюс событие `image_thread_changed`).
История остаётся только на дописывание. «Старая стопка»: при откате и новой правке текущая стопка
замораживается с `old: true`, её якорь остаётся на месте, в конец падает якорь новой стопки и тихая
строка «Шаги 3–5 не пропали…».

**`--resume` и компакция.** Нить в транскрипт CLI не входит. Модель узнаёт о ней из блока хвоста
хода (`ImageEditorStateContributor`, `InTurnTail: true`): нити чата, фокус, журнал «с прошлого
сообщения». После компакции и `--resume` блок собирается заново. В чате без нитей блока нет.

### 4. MCP `image-editor` под «нити + фокус»

Сервер едет во **все чаты проекта** владельца с флагом (условие `ProjectId != null` вместо
`ImageChat != null`). Фокус и нити на состав `tools/list` не влияют: без выбранной картинки
инструмент отвечает текстом отказа, а не исчезает (сторож `McpToolsetStabilityTests`).

| Инструмент | Что делает | При `ImageEditor:AgentLaunch=false` |
|---|---|---|
| `image_state` | нити чата, фокус, текущий шаг, настройки, идущая задача | есть |
| `image_focus {threadId\|null}` | взять картинку в работу или снять выбор — тихой строкой в ленте | есть |
| `image_new {folder}` | карточка-черновик «Новая картинка» и фокус на неё | есть |
| `image_generate {threadId, …}` | запуск; `threadId` обязателен (решение 1) | нет |
| `image_cancel {jobId}` | отмена | нет |
| `image_suggest_prompt` | как в v2 | есть |

Список автоматически разрешённых инструментов переезжает в `ImageEditorMcpContext` и проверяется в
`ClaudeSession.DecidePermission`. `IDelegatedTurnGate` (fail-closed) и `MaxLaunchesPerTurn = 2`
остаются. Прямой запуск из композера без агента — REST `jobs` с `sessionId` + `threadId`, тихая
строка `module_record { recordType: "image_launch" }` через `IChatFeed`.

### 5. Реестр полос над композером

Слот `composer-strip` в `registryCore.ts`: `id`, `title`, `icon`, `order`, `isAvailable(ctx)`,
компоненты `Status` / `Collapsed` / `Full`. Переключатель «Git ▾» рисует ядро один раз для всех
полос; Git — встроенный вклад ядра в тот же реестр. Автопереключение и возврат живут в сторе ядра
`composerStrips`, хранение выбора — по решению 3. Рядом слоты `composer-mode`, `composer-chip`,
`workspace-panel-def` и вариант `fullscreen` у `Modal`.

### 6. Что удаляется из v2 и что остаётся

Удаляется (волна 3): `ImageChatsController`, `ImageChatStateStore`, `ImageChatPathTracker`,
`IImageChatSessions` с `ImageChatDefaults`, адаптер `ImageChatSessions` в Main, методы чата картинки
в `SessionManager`, `SessionHub.SendImageChatMessage`, живые `ImageFileMovedMessage` /
`ImageLaunchMessage`; на фронте — окно редактора, `features/chat/imageChat/*`, `AppOverlaySlot`,
пропсы `ChatPanel` под чат картинки. Лишних флагов нет: ключ `image-editor` остаётся единственным.

**Не удаляется никогда:** `kind` `image_launch` / `image_file_moved` и `StoredImageSnapshot` в
полиморфизме `StoredMessage`, поле `Session.ImageChat` (только чтение, плюс `MigratedAt`): иначе
`history.json` и `sessions.json` старых чатов перестанут читаться. Держит golden-тест.

Остаётся: поставщики fal / Higgsfield / «Локальные модели», котировка, задачи и правки без ИИ
(SkiaSharp за `IImageRaster`), «Сохранить в проект» и «Сохранить как…», персонажи, версии файлов.

## Сторожа

- **Границы подсистем:** `IChatFeed` и `StoredModuleRecord` — в Core (`Services.Composition`,
  `Protocol`); модуль ссылается только на Core (`SubsystemBoundaryTests`, `IlBoundaryRegressionTests`).
- **Карта шины:** `session/deleted` и `session/branched` есть и в коде, и в карте ADR-013
  (`TurnEventsMapContractTests`).
- **Нить:** смена фокуса не двигает `UpdatedAt` и не пишет `sessions.json`; `409` на старой ревизии;
  чужой чат и чужая нить — `404` без отличия от несуществующих; удаление чата сносит нити, ветвление
  копирует их с теми же `threadId`.
- **История:** `module_record` переживает круг «запись → чтение» с произвольным `data`; golden
  `history.json` с `image_launch` / `image_file_moved` / `imageSnapshot` читается.
- Волны 2–4: стабильность `tools/list` при смене фокуса, `image_generate` без `threadId` — отказ,
  миграция (архив, `UpdatedAt` не изменился, маркер, повтор ничего не делает,
  `BackupSchema.Version == 9`), eslint-граница `features/imageEditor/**`, vitest стора полос.

## Последствия

- Ядро получает три общих шва вместо картиночных методов `SessionManager`; следующий модуль с
  записями в ленте обходится без правки полиморфизма истории.
- Старые чаты картинки не теряются и не мигрируют содержимое: транскрипты и бэкап целы, схема не
  растёт. Цена — карточка такого чата теряет значок «картинка».
- Выбор полосы на чат (решение 3) даёт разную раскладку в разных чатах одного проекта; фокус
  картинки всё равно старше запомненного выбора.
