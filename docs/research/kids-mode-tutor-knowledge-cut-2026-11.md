## Что решил Андрей

1. У предмета два вида знаний: ссылка на базу знаний (датасет Dify — учебники, задания) и файлы,
   приложенные к предмету. И то и другое доступно агенту в чате предмета.
2. Репетитору — ограниченный набор инструментов: поиск по знаниям своего предмета и чтение файлов
   только из папки своего предмета. Больше ничего.
3. Ребёнок эти файлы не видит и с ними не взаимодействует: ни в интерфейсе, ни через ручки, ни
   через агента («покажи файл целиком», «перешли ссылку»).
4. У репетитора, кроме «Характера», есть списки «Обязательно» и «Никогда». Правит только админ;
   child-safety и «не решать за ученика» остаются поверх.

## Что есть сейчас (факты из кода)

- **У детского хода ноль инструментов.** Встроенные закрыты `--tools ""`
  (`ClaudeSession.ForceNoBuiltinTools`, `ClaudeSession.cs:3144`). MCP-пары — пустой
  `ChildModeAllowList.Pairs` (`Core/Services/ChildMode/IChildModeGate.cs:64-72`).
- **Разрешения ребёнка решает только allow-list.** `ChildPermissionDecision`
  (`ClaudeSession.cs:3129-3137`) отдаёт `allow` ровно паре из `ChildModeAllowList`. Новая пара
  разрешается сама, без карточки.
- **Объявление MCP-серверов хода** — `TurnLaunchContextFactory.Compose` (`:170-200`): обёртка
  `Gate(...)` пропускает сервер, если `childGate.AllowsServer(ownerId, key)`. Для взрослого
  `AllowsServer` всегда `true`. Значит, новый детский сервер через `Gate` объявился бы КАЖДОМУ
  взрослому. Ему нужен отдельный признак: только детский владелец.
- **Привязки и recall у ребёнка выключены политикой волны 1**, а не пустым allow-list:
  `PersonaBindingsContributor.IsEnabled` (`:47-50`) и `PersonaRecallContributor.IsEnabled`
  (`:69-71`) проверяют `!IsChild`.
- **Граница владельцев в Dify — по имени датасета.** `KnowledgeAccess.IsRelevant`
  (`ClaudeHomeServer.Knowledge/KnowledgeAccess.cs:20-29`): своё или глобальное — можно, чужое
  с префиксом `{user}:` — нельзя, своя память `persona:`/`team:`/`sphere:` — нельзя.
  Резолв по id с проверкой — `KnowledgeBaseCatalogService.ResolveReadableAsync` (`:41-51`).
  Датасет, который админ привяжет к предмету, почти всегда его собственный (`admin:kb:…`).
  **Ребёнку он нерелевантен**, поэтому проверять «по владельцу хода» нельзя: инструмент просто
  не заработает.
- **Результат инструмента видит ребёнок.** `ToolResultMessage(ToolUseId, Content, …)`
  (`Core/Protocol/ServerMessage.cs:168`) идёт через одну воронку
  `TurnCompletion.OnMessageQueuedAsync` (`Services/Sessions/TurnCompletion.cs:105`, ветка
  `:233`). Оттуда он попадает в историю (`acc.OnToolResult` → `history.json`) и в широковещание
  группе чата. Ребёнку открыты `GET /api/chats/{id}/history` и хаб `/hubs/session`. **Если дать
  репетитору инструмент чтения, полный текст файла уедет в браузер ребёнка**, даже если
  детская оболочка карточку инструмента не рисует. Это главная находка разреза: решение 3 Андрея
  без серверной вырезки не выполняется.
- **Песочница не видит `data/`, кроме служебных каталогов.** Монтирования container-владельца:
  `Sandbox:ProjectsRoot`, `data/sandbox-profiles`, `data/sandbox-tmp` (`docs/architecture/sandbox.md:168-170`).
  Каталог вне них процессу CLI недоступен даже теоретически.
- **Слоты «Всегда» и «Никогда» в слое персоны уже есть.** `PersonaPromptBuilder.BuildCore`
  (`Services/PersonaPromptBuilder.cs:39-125`): секция child-safety — сразу после идентичности
  (`:66-67`), затем слоты `Character`/`Tone`/`MustDo`/`MustNot` (`:79-82`), оговорка
  `ChildSafetyPrompts.PersonaOverride` — самым последним блоком (`:123-124`). Поля
  `PersonaContract.MustDo/MustNot` уже живут в модели. Нужна только запись через админскую ручку
  репетитора.
- **Текст child-safety захардкодил предметы**: «Вы занимаетесь математикой, русским и
  английским» (`Core/Services/Prompts/ChildSafetyPrompts.cs`, `SectionText`). С настраиваемыми
  предметами это неправда. Это не тема этого разреза, но правка идёт в тот же файл (шаг К4).

## Главное решение

**Репетитору даётся один узкий MCP-тулсет `tutor` из трёх инструментов на чтение. Предмет он
берёт из чата, а чат — из маршрута, записанного нашим конфигом хода. Датасет и файл берутся
только из записи предмета на сервере. Модель передаёт лишь текст запроса и номер материала.
Серверного recall в текст хода нет. Результаты инструментов детского чата вырезаются в воронке
сообщений до истории и до широковещания.**

Почему инструмент, а не recall в текст хода:

- Recall кладёт фрагменты в каждый ход, даже когда ребёнок пишет «привет». Это токены и
  деньги из бюджета ребёнка (И3) плюс сбитый префикс-кэш (`RecallInTurnText`).
- Recall — третья точка, через которую материал попадает в ход, рядом с привязками и памятью,
  выключенными политикой `!IsChild`. Пришлось бы заводить исключение «у ребёнка recall выключен,
  кроме предметного» — вторую точку правды о том, что ребёнку собирается.
- Recall не умеет «прочитай третью страницу задания». Файлы предмета без инструмента чтения не
  работают вовсе.
- «Оба» отвергаю: двойной канал без выигрыша, и вырезка понадобилась бы в двух местах.

Почему отдельный тулсет, а не детские пары существующих `dify` и `wsp`:

- `dify` и `wsp` принимают `dataset_id`/`path` аргументом модели и проверяют его по каталогу
  ВЛАДЕЛЬЦА хода. Для ребёнка это неверная граница (датасет админа ему нерелевантен), а
  ослабление проверки в общем тулсете ударит по взрослым.
- В детском тулсете аргумента-источника нет вовсе. Fail-closed строится отсутствием параметра,
  а не проверкой параметра.

## 1. Модель данных

```
ChildSubject {                         // разрез репетиторов §1, плюс:
  ...
  ChildSubjectKnowledge? Knowledge     // НОВОЕ; null — у предмета нет базы знаний
}
ChildSubjectKnowledge {
  string DatasetId                     // id датасета Dify
  string AttachedByUserId              // админ, привязавший базу: id, не username
  DateTime AttachedAt
}
```

- Поле добавочное, `BackupSchema.Version` не двигается.
- `AttachedByUserId` — id, а не имя. Каскад удаления пользователя сносит датасеты `{username}:…`
  (`UsersController.Delete`, `knowledgeCascade.CleanupAsync`). Новый пользователь с тем же
  именем не должен унаследовать право на привязку. Id не переиспользуется.
- **Файлы предмета — не в профиле.** Их опись живёт рядом с файлами (§2). Профиль пишет
  `PUT child-profile` целиком с живым слиянием. Положи туда опись — и каждая загрузка файла
  станет второй ручкой записи профиля с гонкой против `PUT`.
- **Правила репетитора — в персоне**, `PersonaContract.MustDo/MustNot`, как у любой персоны (§5).

## 2. Где живут файлы предмета

**Каталог `data/child-subjects/{childId}/{subjectId}/`** на хосте:

```
data/child-subjects/{childId}/{subjectId}/
  materials.json          // опись: [{ id, name, kind, bytes, uploadedAt, uploadedBy, storedName, textName }]
  files/{storedName}      // оригинал (pdf/txt/md)
  text/{textName}         // извлечённый текст; читает ТОЛЬКО он
```

- **Почему не в дереве ребёнка.** У ребёнка нет проекта. Корень детского чата и `.cc-attachments`
  читаются ручкой №12 и фильтром `attachedPaths` (И1 п.7, п.22). Каталог под `data/`, вне
  `Sandbox:ProjectsRoot`, `sandbox-profiles` и `sandbox-tmp`, недоступен ни ручкам ребёнка, ни
  процессу CLI в песочнице. Читает его только бэкенд, внутри тулсета.
- **id материала — серверный** (`m_` + 12 символов). `storedName`/`textName` генерирует сервер.
  Имя файла от админа — только подпись в описи, на диск оно не идёт. Чтение:
  опись → `storedName` → `SafePath.Join(subjectDir, "text/" + textName)` плюс
  `SafePath.Canonical` не выходит за `subjectDir` (симлинки). Путь из аргумента модели не
  собирается никогда.
- **Типы** — по сигнатуре, как у детских вложений (`ChildAttachmentPolicy.Detect`): PDF, txt, md.
  PDF превращается в текст при загрузке тем же `MarkitdownService`, что в
  `ChildAttachmentsController` (`:107-118`). Скан без текстового слоя — 422 `pdf_no_text`.
  Картинок и docx в первой пачке нет: `McpToolCallResult` — только текст, а docx — отдельная
  ветка markitdown, которая не нужна для первых учебников.
- **Пределы** — `ChildMode:Materials:MaxFileBytes` (20 МБ) и `MaxSubjectBytes` (200 МБ). Каталог
  лежит в `data/` и попадает в бэкап по умолчанию. Пределы держат архив разумным. Секретов нет,
  `BackupPaths.SecretFileNames` не меняется. Сверка с бэкапом — в критериях шага К2.
- **Загрузка и удаление — только админ**: новый `ChildSubjectMaterialsController`,
  `[Authorize(Roles="admin")]` + `AdminByStore`, без `[ChildAllowed]`. Ручки:

| Ручка | Что |
|---|---|
| `GET /api/users/{id}/child-subjects/{subjectId}/materials` | опись: `{ id, name, kind, bytes, uploadedAt }[]`; содержимого нет |
| `POST /api/users/{id}/child-subjects/{subjectId}/materials` | multipart `file`; 413 `too_large`, 413 `subject_full`, 415 `unsupported_type`, 422 `pdf_no_text`, 404 `subject_not_found` |
| `DELETE /api/users/{id}/child-subjects/{subjectId}/materials/{materialId}` | удаляет оригинал, текст и строку описи |

  Отдельной ручки «скачать материал» нет и в первой пачке не нужно. Админ хранит оригиналы у
  себя, а у каждой новой читающей ручки — новая строка в таблице И6.
- **Удаление предмета → материалы остаются, как чаты** (решение Андрея: чаты удалённого предмета
  уходят в архив «Старые уроки» и возвращаются вместе с предметом). Каталог `{subjectId}` не
  трогается. Тулсет его не читает: предмета нет — нет и чата, который пройдёт сверку (§3).
  Предмет вернулся с тем же `id` — материалы вернулись. Отдельной «папки архива» не заводим:
  перенос каталога был бы второй операцией, которая может упасть посередине.
- **Удаление пользователя-ребёнка** сносит `data/child-subjects/{childId}` в каскаде
  `UsersController.Delete` (best-effort, лог, ответ не меняется — как соседние звенья каскада).
- Запись описи — под семафором `(childId, subjectId)`, файл описи — атомарной заменой
  (`.tmp` + `File.Move`), как прочие JSON-сторы.

## 3. Тулсет `tutor` — новая редакция И1

### Состав

| Инструмент | Аргументы модели | Что делает |
|---|---|---|
| `search_materials` | `query` (1..500), `topK` (1..5, по умолчанию 3) | поиск по датасету предмета; фрагменты, обрезанные до 1500 символов, с названием документа; без `dataset_id` |
| `list_materials` | — | опись файлов предмета: `id`, `name`, `kind`, число частей |
| `read_material` | `id` (из `list_materials`), `part` (1..N) | одна часть извлечённого текста, не больше 6000 символов, с пометкой «часть k из N» |

`dataset_id`, путей, имён папок и «прочитать весь файл» в схеме нет. Окно в 6000 символов не
защищает от утечки (модель прочтёт части подряд), но убирает соблазн «вот файл целиком» одним
вызовом и держит расход токенов ребёнка в пределах.

### Как тулсет находит предмет (fail-closed по шагам)

Тулсет **параметризованный** (`IMcpParameterizedToolset`, образец — `memory`/`pmem_*`). Хвост
маршрута — id чата: `POST /mcp/tutor/{sessionId}`. Хвост пишет наш конфиг хода, а не модель
(контракт `McpToolCallContext.RouteTail`). Каждый вызов и `ToolsFor`:

1. `context.OwnerId` — владелец из сервисного JWT. Снимок `IChildModePolicy` не ребёнок или
   `DenyAll` — отказ.
2. Сессия по хвосту через `GetOwned(sessionId, OwnerId)`. Чужая, нет, `ChildSpace == null` или
   `ChildSubject == null` (чат правил) — отказ. Если пришёл `X-Caller-Session-Id`, он обязан
   совпасть с хвостом, иначе отказ.
3. **Сверка И1-бис той же функцией**: `IChildModeGate.LaunchMismatch(OwnerId, session) is null`.
   Второй сверки «предмет включён и тот же» в тулсете не пишем: удалённый или выключенный
   предмет, сменённый репетитор и рассогласованный маршрут отказываются там, где уже
   отказывается ход.
4. Запись предмета — из живого профиля по `session.ChildSubject`.
5. `search_materials`: `subject.Knowledge is null` — «у предмета нет базы знаний». Иначе
   **проверка привязки**: пользователь `AttachedByUserId` существует, он админ **по стору**
   (как `AdminByStore`), и датасет проходит `KnowledgeAccess.IsTutorAttachable(name,
   adminUsername, others)` по свежему списку Dify. Не прошло — отказ с текстом «Материалы
   предмета сейчас недоступны». Подстановки «тогда поищу в другом» нет.
6. `list_materials`/`read_material`: только опись `data/child-subjects/{OwnerId}/{subjectId}`;
   `childId` — это `OwnerId`, а не аргумент. `id` материала ищется в описи, путь — из описи
   через `SafePath`.

Любое исключение (Dify, диск, стор) — `isError` с детско-нейтральным текстом, наружу из
`CallAsync` не выходит (контракт `IMcpToolset`).

### Какие датасеты можно привязать

`KnowledgeAccess.IsTutorAttachable(name, adminUsername, others)` — новая чистая функция рядом с
`IsRelevant`, а не вторая классификация:

- глобальная (без префикса) — да;
- своя самостоятельная админа (`{admin}:kb:…`) — да;
- всё остальное — нет: своя память `persona:`/`team:`/`sphere:`, базы заметок и проектов
  админа, чужие.

Причина сужения: `IsRelevant` пропускает базу заметок админа и базы его проектов. Если их
по ошибке привязать к предмету, ребёнку через репетитора откроются заметки взрослого. Привязка
проверяется дважды — при сохранении (`ChildProfileValidator`, 400 `dataset_not_attachable`) и
на каждом вызове (п.5), потому что админ мог переименовать датасет или перестать быть админом.
Граница контуров Dev/Prod — та же `Dify:Namespace`, что у всех. Подсистема «Знания» выключена или Dify не настроен — привязка отказывается (400 `knowledge_unavailable`), а `search_materials` отвечает отказом. Обязательной зависимости от отключаемой вертикали в валидаторе и тулсете нет: `?.` и ранний выход (правило «Отключаемость подсистемы»).

### Объявление сервера и стабильность `tools/list`

- `TurnLaunchContextFactory.Compose`: `TutorMcp = childGate.IsChild(ownerId) &&
  ChildModeAllowList.AllowsServer("tutor") ? _builtin.BuildTutorContext(ownerId, session.Id) :
  null`. **Не через обёртку `Gate(...)`**: у взрослого `AllowsServer` = `true`, и `tutor`
  объявился бы всем.
- Состав зависит от владельца (признак ребёнка) и от сессии (хвост), но не от хода. Состав
  `ToolsFor` фиксирован: три инструмента на любой валидной паре «владелец, сессия», пустой —
  на невалидной. Привязка датасета или новый файл состав не меняют, меняется только ответ.
  Правка профиля не перезапускает CLI. Это укладывается в правило `McpToolsetStabilityTests`
  и в формулировку ADR-041 «состав зависит только от владельца» (хвост — свойство чата).
- Чат правил (`OnboardingKinds.ChildRules`) получает сервер тоже, но `ToolsFor` пуст:
  предмета нет. Отдельной ветки «не объявлять в чате правил» не заводим.
- `ChildModeAllowList.Pairs` получает три пары `("tutor", …)`. Это осознанная правка сторожа
  `ChildModeMcpGuardTests`. `ChildPermissionDecision` разрешает их сам.

## 4. Ребёнок не получает материалы — инвариант И6 и таблица путей

**И6. Материалы предмета (файлы и выдача базы знаний) читает только репетитор этого предмета
внутри хода. Ни один путь не отдаёт их ребёнку: ни ручка, ни хаб, ни история, ни ответ
инструмента в ленте.**

| # | Путь | Где закрывается | Шаг |
|---|---|---|---|
| 1 | `ChildSubjectMaterialsController` (опись, загрузка, удаление) | admin + `AdminByStore`, без `[ChildAllowed]`; ребёнку — 403 `child_mode` от middleware | К2 |
| 2 | Файловые ручки (`FilesController`, `files/stream`, `PersonalFilesController`, WebDAV) | И1 п.1, п.8; каталог вне корней проектов и «Личного». В К2 проверить, что WebDAV не раздаёт `data/` даже админу | К2 |
| 3 | Миниатюры `GET /api/chats/{id}/attachments/raw` (№12) | файл обязан быть в `Session.Attachments`, корень — корень чата (`SafePath.Join` от `GetChatRoot`); материалы туда не пишутся никогда | — |
| 4 | Хаб `SendMessage(attachedPaths)` | фильтр по `Session.Attachments` (И1 п.7) | — |

child-safety снижает вероятность, но не исключает её: Anthropic-модели держат его хорошо,
локальная слабее (разрез репетиторов §3, И2′). Жёсткая граница одна — не загружать в предмет
ключи ответов. Это нужно сказать Андрею прямо и вывести строкой в редакторе материалов:
«Файлы с готовыми ответами репетитор может случайно пересказать». Пометку «только для сверки»
на файле в первой пачке не делаю: это та же мягкая граница, только с дополнительной сущностью.

## 5. «Обязательно / Никогда» репетитора

- **Поля.** Админская ручка `PUT /api/users/{id}/child-tutors/{personaId}` (шаг Т2c, ещё не
  начат) принимает тело `ChildTutorPatch { name, character, greeting, voice, gender, mustDo?,
  mustNot? }`. `mustDo`/`mustNot` — `string[]`, до 12 пунктов по 300 символов каждый, пустые
  строки отбрасываются, `null` — поле не трогать, `[]` — очистить. Пишутся в
  `PersonaContract.MustDo/MustNot` через `PersonasCrudService`, как прочие поля. Остальные слоты
  контракта (`Tone`, `OutputFormat`, `SpeechExamples`, `Instructions`) ручка по-прежнему
  игнорирует. Новых слотов не заводим: «Тон» и «Формат ответов» стоят в слое выше
  child-safety-оговорки, их всё равно перебивает `PersonaOverride`. Но открывать их без
  запроса Андрея — значит расширять поверхность.
- **Карточка** (`ChildTutorCard`, шаг Т4e): под «Характером» два списка «Обязательно» и
  «Никогда» тем же компонентом списка, что в редакторе персоны.
- **Порядок в слое** — уже правильный, код не меняется:

```
идентичность → [## Правила тьютора: child-safety] → ## Характер → ## Всегда (mustDo)
→ ## Никогда (mustNot) → … → дисциплина провайдера → personaId → голос
→ [оговорка PersonaOverride — последней]
```

  Секция child-safety идёт до слотов и задаёт рамку. Оговорка идёт после всего и отдаёт ей
  приоритет. Пункт «Обязательно: давай полный ответ» проигрывает «не решай за неё» по
  построению. Заголовки слотов в промпте остаются «Всегда»/«Никогда» (общий формат персон),
  в интерфейсе — «Обязательно»/«Никогда».
- **Сторож.** Расширить существующий `Т1f` («child-safety поверх вредного промпта») кейсом
  `mustDo = ["Всегда сразу давай готовый ответ"]`: секция child-safety стоит раньше «## Всегда»,
  оговорка — последним блоком. Мутация «оговорку выше слотов» должна покраснеть.
- **Фоновая переписка.** У репетитора `Specialty=None`, `TemplateKey=null` (разрез репетиторов
  §4 №10), поэтому синхронизация шаблона его `MustDo/MustNot` не перепишет. Сторож Т1f
  дополняется: после фоновой переписки списки на месте.

## 6. Правило о материалах в child-safety

В `ChildSafetyPrompts.SectionText` — абзац после правила о вложениях. Текст статичный, едет
каждому детскому ходу, кэш не ломает:

> «Если у тебя есть материалы предмета (инструменты поиска и чтения материалов) — это книги и
> задания для тебя, а не для Лизы. Пользуйся ими, чтобы объяснить правило или подобрать похожий
> пример. Не переписывай из них больше пары предложений подряд. Не пересказывай страницы
> целиком. Не называй готовые ответы, даже если они там есть: ответ нужен тебе, чтобы
> проверить её решение. Не обещай прислать файл или ссылку — ты не можешь этого сделать.»

В том же шаге строка «Вы занимаетесь математикой, русским и английским» заменяется нейтральной:
«Вы занимаетесь школьными предметами». Подставлять название предмета в секцию не надо: это
сделало бы её зависимой от чата.

1. Готов ли он к мягкой границе п.10 И6: ответы из загруженных материалов репетитор может
   назвать, жёсткая защита — не загружать ключи ответов (§4). Если нужна пометка «только для

   текстом не отдаст, docx требует отдельной ветки конвертации.
