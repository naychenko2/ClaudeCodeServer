# Панель персонажа · финал (Г + шкала сходства) — спецификация для фронта

Макет: [character-panel-final.html](character-panel-final.html). Он открывается без сервера. В шапке макета переключаются 5 состояний и их варианты, светлая и тёмная тема, ширина 380 / 320 и флаг меток фото.
Выбор и разбор вариантов — [character-panel-proposal.md](character-panel-proposal.md). Конвенция — [docs/design/guidelines.md](../design/guidelines.md).

Документ самодостаточный: все токены, контролы, состояния и тексты перечислены здесь поимённо. Если чего-то нет в тексте — не придумывай, спроси у Майи.

---

## 1. Сценарий и проблема

Человек открывает персонажа, чтобы тот был похож на себя на картинках. Сейчас `CharacterForm.tsx` — это девять блоков подряд, кнопка «Обучить» стоит на пятом экране прокрутки, а общая «Сохранить» непонятно что сохраняет.

**Решение:** карточка с лицом, именем, фразой-статусом, шкалой «Насколько похож» и **одной главной кнопкой**. Фото, версии, тонкая настройка, имя и удаление уходят в шторки. Каждая шторка сохраняет свою часть, общей «Сохранить» больше нет.

## 2. Что остаётся как есть

- Список персонажей `CharactersPanel.tsx`: строка, «В контекст», карандаш «Изменить». Меняется одна мелочь — подпись строки (§9.1).
- Логика и хуки не трогаются: `useLoraTraining`, `useLoraVersions`, `trainSectionView` (`loraTrainView.ts`), `trainingPhotos.ts`, `photos.ts`, `loraTrainTexts.ts`. Карточка **читает** их, а не пересчитывает.
- API персонажа: `createCharacter` / `updateCharacter` / `deleteCharacter`. Контракт обучения (ADR-026) и два набора фото не меняются.
- Общей папки фото из варианта Б **нет** — это отдельный вопрос (§12).

## 4. Состояния карточки

Состояние выводится из данных, своего флага не заводим:

- `photos` — `character.photos.length` (фото лица);
- `train` — число из `CharacterTrainingPhotos.onCount` (`null`, пока не известно);
- `view` — `trainSectionView(...)`;
- `versions` — снимок `useLoraVersions`;
- `own` — `character.local?.lora` (своя обученная версия).

| # | Состояние | Условие | Фраза | Шкала | Главное действие |
|---|---|---|---|---|---|
| 1 | Новый | `character === null` | — | не показываем | «Создать персонажа» (`CharacterCreate`) |
| 2 | С фото, не обучен | `view.kind === 'form'`, нет подключённой версии | `say.ready` / `say.needTrain(k)` | 1–2 деления | «Обучить персонажа» или «Добавить фото для обучения» |
| 3 | Идёт обучение | `view.kind` ∈ `queued`, `running` | `say.running` / `say.queued` | 3-е деление = ход | блок хода с «Отменить обучение» |
| 4 | Обучен | есть версия `connected`, или `own`, или `view.kind === 'done'` | `say.trained(title)` / `say.trainedOwn` | 3 деления | «В контекст чата» |
| 5 | Ошибка | `view.kind === 'failed'` | `say.failed` / `say.failedAllRejected` / `say.failedLost` | 2 деления, 3-я подпись — «Не получилось» | «Попробовать снова» или «Заменить фото для обучения» |

Особые виды `trainSectionView` в зоне главной кнопки (тексты — из `TRAIN_TEXT`, тон `Notice` указан):

| `view.kind` | Что показываем вместо главной кнопки |
|---|---|
| `loading` | `Button` primary lg `fullWidth` `loading`, `disabled`; под кнопкой — `TRAIN_TEXT.loading` |
| `off` | `Notice tone="info"`: `TRAIN_TEXT.disabled`; кнопки нет |
| `noLocal` | `Notice tone="warning"`: `TRAIN_TEXT.noLocal`; кнопки нет |
| `busyOther` | `Notice tone="info"`: `view.text`; для админа (`canStopForeign`) — `Button ghost sm` «Остановить чужое обучение» с прежним подтверждением |
| `busyMine` | `Notice tone="info"`: `TRAIN_TEXT.busyMine` |
| `form`, `reason === 'trigger'` | кнопка «Обучить персонажа» `disabled`; под ней — `hero.fixTrigger` со ссылкой-кнопкой `ghostAccent xs` «Тонкая настройка» (открывает шторку) |
| `form`, `stopped` | над кнопкой `Notice tone="info"`: `TRAIN_TEXT.stopped` |
| `form` / `done`, `photosChanged` | над кнопкой `Notice tone="warning"`: `TRAIN_TEXT.photosChanged` |
| `done`, `first === false` (новая версия не подключена) | над «В контекст чата» — `Notice tone="info"`, `title` = `TRAIN_TEXT.doneNewTitle`, текст `doneNewBody`, `action`: `Button secondary sm` «Подключить» + `Button ghost sm` «Оставить прежнюю» (прежняя логика `dismissedRunId`) |
| `done`, `first === true` | один раз — `Notice tone="info"` `doneFirstTitle` / `doneFirstBody`, закрывается крестиком |

## 5. Раскладка карточки (`CharacterCard`)

Сверху вниз, контейнер `display:flex; flex-direction:column; gap: SP.lg; padding: SP.md`. Прокрутка у панели.

1. **Строка навигации:** `BackButton` «Все персонажи» (`title="К списку персонажей"`) слева, справа `IconButton size="sm"` «⋯» (`ariaLabel="Ещё"`). Он открывает `Menu` с пунктами `MenuItem`:
   - «Имя и описание» (иконка `Pencil`);
   - «Фото» (`Image`);
   - «Версии» (`Layers`) — только если версий больше нуля;
   - «Тонкая настройка» (`SlidersHorizontal`);
   - `MenuSep`;
   - «Удалить персонажа» (`Trash2`, `danger`).
2. **Коллаж** — `display:grid; grid-template-columns: 2fr 1fr; gap: SP.xs`. Слева главное фото (`photos` с `primary`, иначе первое), справа два следующих в колонку.
   - Каждое: `<img>` с `object-fit: cover`, `border-radius: R.lg`, `border: 1px solid C.border`.
   - Если фото больше трёх, на третьем лежит затемнение `C.mediaScrim` с текстом `+N` (`FS.md`, 600, `C.onDark`), где N — остаток фото лица.
   - Фото 1 → одно на всю ширину, `aspect-ratio: 1`, не выше 240px. Фото 2 → два столбца 2fr/1fr, правый одной ячейкой.
   - Десктоп: главное `aspect-ratio: 1`. Мобила: весь коллаж `height: 168px`, главное `height: 100%`, чтобы главная кнопка оставалась в первом экране шторки.
   - Клик по коллажу открывает шторку «Фото».
3. **Имя и фраза** — колонка `gap: SP.xs`.
   - Имя: `FONT.serif`, `FS.h2`, `C.textHeading`, `line-height: 1.2`, `overflow-wrap: anywhere` (длинное имя переносится, не режется).
   - Фраза: `FS.md`, `C.textPrimary`, `line-height: 1.45`. Выделение `<b>` — `C.textHeading`. В состояниях 4 и 5 перед фразой стоит `Badge size="sm"`: `tone="success"` с `Check` и текстом «Обучен» либо `tone="danger"` «Ошибка».
   - В состоянии 4 при подключённой своей версии под фразой идёт строка-подпись LoRA (§8.4).
4. **Шкала «Насколько похож»** — `LikenessMeter` (§6). Только в состояниях 2–5.
5. **Главное действие** — `CharacterHero` (§7).
6. **Тихие чипы** — `display:flex; flex-wrap: wrap; gap: SP.xs`. Все — `Chip` (variant `soft`, `touch` на мобиле):
   - «Фото» и число: иконка `Image` `ICON_SIZE.xs`, число жирным `C.textPrimary`, число = фото лица + фото для обучения. Если `train < TRAIN_MIN` или в состоянии 5 «ни одно фото не подошло», справа `Dot` цвета `C.warning`, `title` — `chips.photosNeed`.
   - «Версии» и число — только если версий больше нуля.
   - «Тонкая настройка».

## 6. `LikenessMeter` — шкала из варианта Б

Это ступени, а не процент сходства: метрики сходства в продукте нет, выдумывать её нельзя. Подпись группы — `role="group"`, `aria-label="Насколько похож"`.

- Заголовок: `FS.sm`, 600, `C.textSecondary` — «Насколько похож».
- Полосы: `display:grid; grid-template-columns: repeat(3, minmax(0,1fr)); gap: SP.xs`. Каждая — `ProgressBar` из кита (4px, дорожка `C.track`).
- Подписи под полосами — та же сетка. В каждой ячейке две строки: заголовок `FS.xs` 600 и пояснение `FS.xs` `C.textMuted`, `line-height: 1.3`. Перенос разрешён, многоточия нет.

| Деление | `ProgressBar` | Заголовок и цвет | Пояснение |
|---|---|---|---|
| 1 | `value=100 tone="success"`, если `photos ≥ MIN_PHOTOS`, иначе `value=0` | «Узнаётся»: `C.successText` при 100, иначе `C.textSecondary` | `meter.facePhotos(photos)` |
| 2 | `value=100 tone="success"`, если `train ≥ TRAIN_MIN`; иначе `value=0` | «Можно обучать»: `C.successText`; если делений 1 заполнено, а 2 нет — `C.accent` (это следующий шаг) | `meter.trainPhotos(train)` или `meter.trainNeed(train, TRAIN_MIN)` |
| 3 · не обучен | `value=0` | «Заметно похож», `C.textSecondary` | `meter.afterTrain` |
| 3 · в очереди | `value=8 estimate` | «В очереди», `C.accent` | `meter.queued` |
| 3 · идёт | `value=view.percent ?? 8`, `estimate`, если `percent === null` | `meter.running(percent)`, `C.accent` | `view.etaText` в виде `meter.eta(time)` или пусто |
| 3 · обучен | `value=100 tone="success"` | «Заметно похож», `C.successText` | `meter.trainedOn(date)`; у своей версии — `meter.own` |
| 3 · ошибка | `value=0` | «Не получилось», `C.dangerText` | `meter.retry` |

Пока `train === null`, деление 2 рисуется `value=0`, а пояснение — «…». Сдвигов раскладки быть не должно.

Сейчас у него только размеры `xs`/`sm`; логику (роль референса, причины отказа) не дублируем, а добавляем в `ContextAddButton` размер `lg`: он рисует `Button primary lg fullWidth` с этими подписями. ## 8. Шторки

Все шторки — `Modal` из кита: на десктопе модалка по центру, на мобиле нижняя шторка с ручкой (кит переключает сам). Самодельных оверлеев не делаем. В макете шторки нарисованы внутри панели только ради наглядности.

| Шторка | `width` | Заголовок | Низ |
|---|---|---|---|
| Фото | `MODAL_W.form` | `sheet.photos(name)` | нет: всё сохраняется сразу |
| Версии | `MODAL_W.form` | `VERSIONS_TEXT.title` + счётчик «N из 5» `FS.sm` `C.textMuted` | нет |
| Тонкая настройка | `MODAL_W.form` | «Тонкая настройка» | `ModalActions`: «Отмена» (ghost) и «Сохранить» (primary) |
| Имя и описание | `MODAL_W.form` | «Имя и описание» | `ModalActions`: «Отмена» и «Сохранить»; без имени «Сохранить» `disabled` |
| Подтверждения | `ConfirmDialog` (`MODAL_W.confirm`) | — | — |

Пока идёт сохранение, кнопка «Сохранить» `loading`. Ошибка сохранения — строка `FS.sm` `C.dangerText` над `ModalActions`, шторка остаётся открытой, введённое не теряется.

### 8.1 Шторка «Фото»

Два раздела, между ними `border-top: 1px solid C.divider; padding-top: SP.md`. У каждого раздела шапка: заголовок `FS.base` 600 `C.textHeading` и справа счётчик `FS.sm` `C.textSecondary`. Под шапкой подсказка `FS.sm` `C.textMuted` — она объясняет, **зачем** этот набор.

#### 8.1.1 «Лицо для узнавания» (`CharacterFacePhotos`)
- Счётчик `faces.counter(n)` → «5 из 10».
- Подсказка: `faces.hint`. Если флаг меток включён, к ней добавляется `faces.hintLabels`.
- Сетка: `grid-template-columns: repeat(auto-fill, minmax(72px, 1fr)); gap: SP.sm`. На 320px получается 3 колонки, в шторке 440px — 4–5.
- Ячейка — `<button>` (без флага меток — `<div>`): фото `aspect-ratio:1`, `R.lg`, рамка `C.border`.
  - На первом фото — бейдж «Основное», как сейчас в `CharacterForm` (`C.accent` / `C.onAccent`, `FS.xs`, `R.sm`).
  - В правом верхнем углу — `IconButton size="xs" variant="media"` «Убрать фото» → `ConfirmDialog` (§10.6).
  - При `photos === MIN_PHOTOS` кнопка «Убрать» `disabled`, `title` = `faces.minReached`.
  - Под фото — подпись меток (§8.1.2).
- Последняя ячейка — `Button variant="dashed" size="sm"` с иконкой `Upload` и текстом «Ещё фото» (при нуле фото — «Загрузить»). Она `disabled`, пока не стоит галочка согласия, `title` = `faces.consentFirst`. При 10 фото ячейки нет.
- Под сеткой — `Notice tone="warning" icon={ShieldAlert}` с текстом согласия (§10.3). Под ним — `Checkbox` с подписью «Понимаю, у людей на фото есть согласие».
- **Загрузка сразу сохраняет:** `updateCharacter` с новыми `photos`. На время загрузки на месте новых ячеек стоят заглушки: фон `C.bgInset`, `R.lg`, по центру «Загружаем…» `FS.xs` `C.textMuted`, а кнопка «Ещё фото» — `loading`. После загрузки галочка **сбрасывается** — согласие не запоминается, как сейчас.
- **Удаление сразу сохраняет:** `updateCharacter` с `removePhotos`.
- Ошибки загрузки — строка `FS.sm` `C.dangerText` под сеткой, тексты прежние из `CharacterForm.addFiles`.

#### 8.1.2 Метки фото — за флагом `character-smart-photos`

Только у фото лица. У фото для обучения меток нет (ADR-026: этот набор не размечаем).

**Подпись под фото** (`PhotoLabelChips`, режим подписи): `FS.xs`, `line-height: 1.3`, не больше 2 строк (`-webkit-line-clamp: 2`), `overflow-wrap: anywhere`.

| Состояние метки | Текст | Цвет |
|---|---|---|
| авторазметка (`LabelSource=auto`) | `labels.caption(angle, emotion)` → «Вполоборота · улыбка» | `C.textSecondary` |
| ручная правка (`human`) | то же | `C.textPrimary` |
| идёт разметка | «Размечаем…» | `C.textMuted`, курсив |
| нет меток / модель отказала | «Без меток» | `C.textMuted` |

Наклон в подписи не показываем, он виден в редакторе.

**Редактор меток** (`PhotoLabelChips`, режим редактора) открывается по нажатию на фото. Это **не** вложенная модалка, а карточка прямо под сеткой.
- Выбранное фото: рамка `C.accent` + `SHADOW.focus`, `aria-pressed="true"`.
- Карточка: `background: C.accentLight; border: 1px solid C.accentMuted; R.lg; padding: SP.md; gap: SP.sm`.
- Шапка: «Фото N» (`FS.base` 600) и `IconButton size="sm"` × «Закрыть метки».
- Поля (`Field`):
  - «Ракурс» — `InlineSegmented` (`isMobile`): Анфас / Вполоборота / Профиль;
  - «Наклон головы» — `InlineSegmented`: Прямо / Вверх / Вниз;
  - «Эмоция» — `Select`: Спокойное / Улыбка / Смех / Серьёзное / Грустное / Удивлённое.
- Под полями — строка-источник `FS.xs` `C.textMuted` с иконкой `ICON_SIZE.xs`:
  - авто: `Sparkles` + `labels.srcAuto`;
  - ручная: `Pencil` + `labels.srcHuman`;
  - нет меток: без иконки, `labels.srcNone`.
- Внизу — `Button ghost sm` `Trash2` «Убрать фото» (то же подтверждение, что у крестика).

## 12. Открытые вопросы

1. **Согласие у загрузки (Софья).** В Г галочка переезжает к месту загрузки фото лица: в создании и в шторке «Фото». Её ставят перед каждой загрузкой и сбрасывают после, правило «не запоминается» сохраняется. До сих пор галочку ставили при каждом сохранении формы. Нужно решение Софьи: текст сверяет приёмка. Отдельно: для фото **для обучения** согласия как не было, так и нет. Они не уходят наружу, но это фото людей — оставляем так?
2. **Строка Higgsfield перед Soul ID (Андрей/Софья).** «Сервисы рисования · Higgsfield · По фото» — заготовка под Soul ID (`providers.higgsfield` в манифесте). Предлагаю пока не показывать: строка без действия только путает. В макете она нарисована пунктиром с пометкой «открытый вопрос».
3. **Одно поле «Слово-метка» вместо двух (Денис).** Слово-метка обучения и `local.trigger` своей версии сейчас хранятся раздельно. Для одного поля нужно решить, какое значение главное при расхождении. До решения Кира делает два поля (§8.3).
4. **Метки у существующих фото.** По плану умных фото бэкфилл идёт в фоне автоматически (решение Андрея). Значит, у старых персонажей подписи «Размечаем…» появятся без участия человека. Текст согласия про разметку видят только при новых загрузках. Это осознанное решение из плана (риск 2 у Егора), здесь просто отмечаю, как оно выглядит в интерфейсе.
5. **После создания — карточка, а не список** (§9.2.8). Меняет привычный путь: сейчас форма закрывается в список. Предлагаю так, чтобы человек сразу видел следующий шаг. Нужно согласие Софьи.

## 13. «Что нового» (проект пункта, выпускает Софья)

> **Персонаж — одна карточка вместо длинной формы.** Открываете персонажа — видите его лицо, шкалу «Насколько похож» и одну кнопку с тем, что делать дальше: добавить фото, обучить, положить в контекст чата.
