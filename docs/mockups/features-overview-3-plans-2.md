## Сценарий

Андрей читает план фичи и хочет тут же посмотреть, как выглядит то, что в плане описано. Сейчас макет надо искать
в дереве файлов по имени, и непонятно, какая версия последняя и утверждена ли она. На вкладке макеты лежат рядом
с планами: последняя версия сверху, статус виден сразу, открытие — в один клик.

## Что на вкладке

- **Название — «Планы и макеты»**, счётчик = документы + макеты (по одному на группу версий).
- **Список (1280 — слева, 360 — во всю ширину):** две группы, «Документы · N» и «Макеты · N».
  Строка макета: миниатюра-заглушка по типу (страница · панель · попап · карточка; это рисунок из токенов, а не
  скриншот), название, «тип · дата · N версий», статус-чип, у несмёрженного — «не в master».
- **Карточка макета (справа на 1280, отдельным экраном на 360 с «‹ Все документы»):** метка «макет · тип», название,
  автор (Майя) с парой «чат · задача», дата, статус. Ниже путь файла, большая заглушка с «Открыть макет» (вся
  заглушка нажимается) и кнопка «Открыть макет».
- **Открытие:** просмотр файлов проекта, HTML в `iframe sandbox="allow-scripts"`, как Андрей открывал
  `turn-plan-feature-popup-1.html`. Чип фичи в шапке просмотра возвращает на вкладку, к тому же макету.
- **Нет в master:** заглушка приглушена, на ней «Появится после мержа», кнопка неактивна, рядом плашка «Ещё не влит
  в master. Макет лежит только в ветке `feat/…`. Макет появится после мержа; до этого его видно в чате Майи».
  У смерженной фичи тот же макет открывается.
- **Версии** (`-1`, `-2`, `-final`): показываем последнюю, остальные свёрнуты в «Прошлые версии · N»: имя
  файла, дата, «заменён», «Открыть» (старую версию тоже можно открыть).
- **Перекрёстные ссылки:** у плана и разреза под заголовком строка «Макеты в тексте» с чипами (миниатюра,
  название, статус). Чипы ищутся по путям `docs/mockups/…` в тексте документа, тап по чипу открывает карточку
  макета. У макета обратная строка «Упомянут в» с чипами документов.

## Откуда берётся макет (без новых хранилищ)

1. **Список макетов:** файлы `docs/mockups/*.html` из `linkedFiles` задач фичи (поле уже есть в карточке
   задачи, исполнитель кладёт туда итоговые файлы при `tasks_complete`). `.md`-записки и `-tokens.md` в группу не
   идут: это сопровождение, их видно в задаче.
2. **Название:** `<title>` макета, а если его нет, то имя файла.
3. **Тип:** `<meta name="mockup-kind" content="page|panel|popup|card">` в шапке макета. Эту строку я ставлю в новые
   макеты сама. У старых макетов её нет, и тогда чип типа не показывается: гадать по названию не будем.
4. **Версии:** общий корень имени без хвоста `-1`/`-2`/`-v2`/`-final`. Последняя версия: `-final`, иначе с
   наибольшим номером. «Заменён» вычисляется из этого же правила, отмечать его не нужно.
5. **В master или нет:** файл есть в `master` (`git cat-file -e master:<path>`). Корень проекта стоит на master,
   так что проверка наличия файла в корне даёт то же, если не заводить git-вызов.
6. **«Утверждён»:** явная отметка, варианты ниже.

### Как отмечать «утверждён»: варианты

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **А. Метка задачи `утверждён`** *(рекомендую)* | на задаче макета ставится метка (labels уже есть, ставится в карточке задачи в один клик или Софьей через `tasks_update`); относится к **последней** версии каждого макета этой задачи | ноль нового хранилища и формата, ставит человек в привычном месте, видно и в «Задачах» | если в одной задаче два разных макета с разным статусом, метка общая. Лечится правилом «один макет — одна задача макета» (так мы и работаем) |
| Б. Строка в первой строке `.md` рядом (`Статус: утверждён 20.10, Андрей`) | записка правится и коммитится | статус живёт в git рядом с файлом | нужен коммит ради отметки. Пока ветка не смержена, master его не видит. Разбор текста хрупкий |
| В. `<meta name="mockup-status">` в самом HTML | то же, но внутри макета | один файл | правка утверждённого файла ради отметки, тот же коммит |

Рекомендация — **А**: отметка ставится там, где Андрей и так принимает работу (задача), и без коммита.

## Проекция для бэка

`plans[]` в `GET features/{id}` расширяется до `documents[]`. Это только список, без текстов и файлов:

```ts
documents: {
  kind: 'plan' | 'cut' | 'consult' | 'mockup',
  taskId: string,
  title: string,          // у документа — название задачи, у макета — <title>
  path?: string,          // только mockup: docs/mockups/….html
  approved?: boolean,     // mockup: метка «утверждён» на задаче (вариант А)
  inMaster?: boolean,     // mockup: файл есть в master
  // как в plans[]: authorPersonaId, createdAt, completedAt, hasText (у документов)
}[]
```

Вычисляется на фронте и хранить их не надо: группировка версий, «заменён», тип (если бэк отдаёт `kind` из `<meta>`,
то это ещё одно необязательное поле `mockupKind?`), чипы «Макеты в тексте» (поиск путей по уже загруженному тексту
документа). Текст документа по-прежнему приходит по клику (`GET /api/tasks/{id}`), макет открывает просмотр файлов
по `path`.

## Для Киры (реализация)

- Список и строки: `PressableArea`, как у документов; группа — заголовок секции (`FS.xs`, капс, `C.textMuted`).
- Миниатюра: `span` 32×24 (`R.sm`, рамка `C.border`, фон `C.bgCard`, полосы `C.border`/`C.accentMuted`/`C.accent`);
  большая — 100 % × 160 (на 360 — 128), `R.lg`.
- Статус-чип: `R.sm`, `FS.xs` полужирный; цвета — в таблице состояний.
- «Открыть макет»: `ui/Button` primary `sm`; неактивная — `disabled` и подсказка. На 360 все кнопки и чипы ≥ 40
  (`.mkchip`, «Прошлые версии», «Открыть», «Все документы»).
- Просмотр: существующий просмотр файлов с HTML в песочнице, ничего нового; чип фичи — тот же, что у задачи.
- Новых токенов нет. Проверено в обеих темах, на 1280 и 360.
