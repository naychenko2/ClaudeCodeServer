# Разрез: фича не закрывается при мерже (FS-AC, 11.11.2026)

Решение Андрея 11.11: после мержа фича остаётся «смержена», пока человек сам не нажмёт «Закрыть».
Доработки после мержа считаются как раньше (`followUp*`, вне `Total`). Читано по `master` 90c4bd7c4.

## 1. Где фича «закрывается» при мерже — фактура

**Сервер эпик при мерже не закрывает.** В коде нет ни одной записи `Status = Done` эпику
(`role=feature`): присваивания Done в `TaskManager` есть только у плана (`:581`) и снятого хвоста
(`:1489`). Шаблон задачи мержа прямо пишет «Эпик не закрывать: фичу закрывает человек»
(`TasksController.cs:1910`). Состояние считает чистая функция:

- `FeatureProjector.TerminalState` (`FeatureProjector.cs:1868–1879`): `merged` — merge Done ∧
  (финал принят ∧ нет волны после мержа ∨ эпик Done); `closed` — эпик Done без мержа.
- `run.Closed` (`:559–560`) = эпик Done. `Bucket` (`:1953`), `FeatureBrief.KindOf` (`FeatureBrief.cs:372`)
  расщепляют `merged` по `run.Closed`: эпик открыт → `merged`, закрыт → `closed`.
- Индекс на бэке держит `merged` среди открытых (`:1385`, порядок `attention → running → merged → idle → closed`).

«Автозакрытие», которое видит человек, складывается из трёх мест вне проектора:

| # | Где | Что делает | Вывод |
|---|-----|-----------|-------|
| А | `frontend/src/lib/chatGroups.ts:762` — `FEATURE_LIST_SECTION_OF_KIND` | `merged: 'closed'`: смерженная фича с открытым эпиком уезжает в секцию «Закрытые» списка | **Регрессия FS-FL2a (e5c952ef0)** против решения 26.10 (`docs/mockups/feature-state-filter-1.md:38`: «в секцию «Закрытые» не попадает») |
| Б | Персона Марк, `MustDo[0]` | «Закрой эпик (`role=feature`) через `tasks_complete`» | Противоречит шаблону мержа. Из чата-исполнителя сервер отказывает (`FeatureTurnGate`), но правило толкает агента пробовать и докладывать «эпик не закрыт» |
| В | `FeatureTracker.cs:187–197` — вид `epic_open_after_merge` | Открытый эпик после мержа = «расхождение трекера», строкой в хвост хода ключевого чата; Софья по контракту несёт его Андрею | После решения 11.11 это штатное состояние, а не расхождение. Сигнал толкает закрыть |

Данные боя это подтверждают: у 10 из 15 последних смерженных фич эпик Done, обычно через 1–5 ч
после мержа (крайние случаи: за 5 минут до мержа и через сутки после). `ResultMarkdown` пуст,
в журнале голый `Todo → Done`. Закрывали руками (кнопкой или из обычного чата),
а не автоматически.

Прочее по п.1 постановки: `tasks_complete` у `role=merge` эпик не трогает. 409 `tail_decision_required`
(`:1712–1720`) и напоминание FS-XT2 (`FeatureVoiceReminderContributor.cs:89`, пропускает `merged`/`closed`)
от закрытия не зависят. Автозакрытия хвоста нет: снятие идёт только по выбору `withdraw` в диалоге.

## 2. Как человек закрывает фичу сегодня

Кнопка уже есть: «Закрыть» в шапке страницы фичи (`FeaturePageHeader.tsx:497`, `canCloseNow` = владелец ∧
эпик не Done, значит видна и у `merged`) → `PUT /api/tasks/{epic}` `{status:'done'}` (`doCloseFeature`, `:305`).
«Возобновить» есть только у `closed` без мержа (`:503`). **Новой ручки и кнопки не нужно.**

## 3. Что зависит от «закрыта при мерже»

| Потребитель | Сейчас | Если эпик открыт |
|---|---|---|
| `FeatureStepAccounting` (`:310, 428–433`) | `followUp` от момента **первого мержа**, а не закрытия | без изменений |
| `FeatureSummary` (`FeatureProjector.cs:573–600`) | строится при `terminal` (и при `merged`), длительность до `mergedAt` | без изменений, итоги видны у смерженной |
| `closedTail`, `withdrawnAtMerge` | решаются при мерже | без изменений |
| `FeatureFirstScreen.tsx:93` | итоги и у `merged`, и у `closed` | без изменений |
| `FeatureBriefModel.ts:239` | у `merged` пишет «Ничего — фича закрыта» | **ложь**: нужно «смержена, закройте, когда доработки не нужны» |
| `featureListSections` | `merged` → «Закрытые» | **ложь** (см. А) |
| `FeatureEstimateDrift.cs:57` (точность оценки) | только у `run.Closed` | точность появится лишь после ручного закрытия. Длительность меряется до `mergedAt`, поэтому число не поплывёт |
| `WaveAfterMerge` (`:1890`) | волна у открытого эпика снимает `merged` → `running`/`idle`; у закрытого не снимает | теперь это обычный путь: доработка после мержа возвращает фичу «в работу» |
| `LocalExecutorsContributor.cs:69`, `LocalIdleNudgeService.cs:103` | «открытая фича» = эпик не Done | смерженная открытая считается открытой: строка нагрузки в её ключевом чате. Безвредно |
| Повторный мерж кнопкой | `POST merge` при последнем merge Done → 409 «Фича смержена во время мержа» (`:1681`) | **старая дыра станет заметнее**: после доработки второй мерж кнопкой не пройдёт, только задачей `role=merge` от Софьи |

## 4. Инвариант и пути к нему

**Инвариант:** эпик фичи переводит в Done только человек. Предикат состояния один:
`TerminalState` / `Bucket` / `KindOf` на бэке, на фронте секцию решает только `kind` из индекса.

| Путь записи `Status=Done` эпику | Сейчас | Кто закрывает |
|---|---|---|
| REST `PUT /api/tasks/{id}` (кнопка «Закрыть», доска, перетаскивание в колонку Done) под JWT человека | разрешён | человек, остаётся |
| REST `PUT` под сервисным токеном из чата-исполнителя | отказ (`FeatureTurnGate`, `TasksController.cs:696`) | — |
| REST `PUT` под сервисным токеном из обычного чата (не исполнитель, не делегированный ход) | **разрешён** | Ш2 (по Q1) |
| MCP `tasks_update` / `tasks_complete` из чата-исполнителя или делегированного хода | отказ (`DenyFeatureClose`, `TasksToolset.cs:1309`) | — |
| MCP `tasks_update` / `tasks_complete` из обычного чата агента (оркестратор, любой чат) | **разрешён** | Ш2 (по Q1) |
| Задача `role=merge` / `POST features/{id}/merge` | эпик не трогает | — |
| Фоновые службы (`TaskManager`, сторожа, напоминания) | не пишут | — |

**не меняется**: второго предиката не заводим. Новых инлайновых `state === 'merged' || 'closed'` на фронте не добавлять:
их уже ~20 копий, это «работа закончена», и для смерженной это по-прежнему верно. Чистка копий — отдельный долг, сюда не входит.

## 6. Вопросы Андрею (с рекомендацией)

- **Q1.** Запретить агенту закрывать эпик совсем (Ш2)? Рекомендую **да**: правила персон мягкие, у Марка правило прямо
  противоположное. Цена: «закрой фичу» в чате агент не выполнит, кнопка остаётся.
- **Q2.** Доработка после мержа возвращает фичу из «смержена» в «в работе» (так работает `WaveAfterMerge` у открытого эпика).
  Рекомендую **оставить**: состояние отражает живую работу, строка «Доработки: N из M» (решение 11.11) не страдает.
- **Q3.** Показывать точность оценки уже у смерженной (Ш5)? Рекомендую **да**: длительность и так считается до `mergedAt`.
