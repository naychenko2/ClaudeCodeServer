## Сценарий

Андрей хочет прочитать, что решили при проектировании фичи: разрез Александра, план Егора, консультации. Сейчас
эти тексты лежат итогом в карточках задач (`resultMarkdown`), и чтобы их найти, надо знать, какая задача —
разрез, а какая — план. Вкладка собирает их в одном месте и даёт читать, не уходя со страницы фичи.

## Что на вкладке

- **Порядок вкладок:** «Хронология · Планы · Чаты · Задачи · События · Статистика». «Планы» стоят второй: после
  того как вы увидели, где фича сейчас, естественный следующий вопрос — что вообще задумано (см. вопрос 1).
- **1280:** слева список документов (240 px, прилипает при прокрутке), справа читалка.
  Строка списка: значок роли (разрез · план · консультация), заголовок до двух строк, автор и время, у документа
  без текста — пометка «без текста». Открытый документ подсвечен `C.accentLight`.
- **Читалка:** метка роли, заголовок (PT Serif 20), автор с парой «чат · задача» (как везде на странице:
  чат — в чат исполнителя, задача — в карточку задачи; страница скрывается и возвращается по плашке на эту же
  вкладку), время сдачи. Ниже — markdown: заголовки, абзацы, списки, таблицы (своя горизонтальная прокрутка,
  страница не едет вбок), блоки кода, Mermaid. Подвал: «Текст — итог задачи. Здесь только чтение; правка — в задаче».
- **Mermaid** в макете — заглушка «Диаграмма · flowchart · N строк» с кнопкой «Исходник». В продукте — тот же
  рендер markdown, что в ленте чата: он уже рисует таблицы, код и Mermaid, своего разбора заводить не нужно.
- **Длинный документ** (6 и больше разделов `##`): оглавление «Содержание · N» (на 1280 раскрыто, в две колонки;
  на 360 свёрнуто), переход по пункту докручивает раздел под липкие вкладки; каждый раздел сворачивается,
  «Свернуть все / Развернуть все». Короткий документ — сплошной текст без свёртки.
- **360:** список во всю ширину (строки 56), тап открывает документ отдельным экраном внутри вкладки,
  сверху «‹ Все документы» (44). Все кнопки на вкладке ≥ 40.

## Состояния

| Состояние | Что видно |
|---|---|
| есть документы | список и открытый документ (на 1280 по умолчанию — план, на 360 — список) |
| «Планов пока нет» | пустое состояние: «Разрез Александра, план Егора и консультации появятся здесь, как только их задачи будут созданы» + «Открыть ключевой чат». У не начатой фичи — с припиской «Фича ещё не начата» |
| загрузка текста | скелет абзацев и блока в читалке; список и заголовок документа уже видны (они из `plans[]`) |
| ошибка загрузки | «Не удалось загрузить текст. Задача не ответила…» + «Повторить» + «задача» (открыть текст там) |
| текста пока нет (`hasText = false`) | «Текста пока нет. {Автор} ещё работает: итог задачи не записан…» + «чат · задача» |
| длинный документ | оглавление и свёртка разделов |

## Данные

| Что | Откуда | Новое? |
|---|---|---|
| список документов | `GET features/{id}` → `plans[]` = `{taskId, role (plan · cut · consult), title, authorPersonaId, createdAt, completedAt, hasText}` | **да, аддитивное поле проекции**, без текста и без нового хранилища |
| текст | `GET /api/tasks/{id}` → `resultMarkdown`, по клику, кешируется на время жизни страницы | нет |
| автор → чат | `LinkedSessionId` задачи (как у остальных вкладок) | нет |
| счётчик на вкладке | `plans.length` | нет |

Сейчас в агрегате фичи есть только задачи с ролью `plan` (`run.Plan`); `cut` и `consult` в `plans[]` надо добавить.
