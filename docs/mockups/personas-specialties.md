# Экран «Специальности» в разделе «Персоны» — макет-спецификация

Перенос настройки специальностей из вкладки «Правила» диалога «Модели и расход»
(`SpecialRulesTab`, макет v4) в центральную зону `PersonasPage` как второй режим
раздела, плюс новый срез «Кто работает по этой роли». Реализация — за Кирой;
здесь композиция из существующих контролов и токенов, новых значений в шкалах нет.

Эталон переносимой механики — [model-settings-v4/special-rules-groups.html](model-settings-v4/special-rules-groups.html)
и код `frontend/src/features/modelsSpend/specialRules/`: карточки, слои,
`RoutePicker`, полосы «Картина по уровням», мастер добавления, строка «Сейчас
пойдёт» переезжают без изменения внутреннего устройства; этот документ задаёт
новую раму (раздел вместо модалки) и новые блоки.

## Сценарий и проблема

Человек завёл персон и хочет понять: кто из них за какую роль отвечает и по каким
моделям они ходят. Сегодня ответ разрезан пополам: роли с их правилами живут
глубоко в диалоге «Модели и расход» (вкладка «Правила»), а персоны — в своём
разделе, и связь «роль ↔ люди» нигде не видна. При этом вёрстка вкладки
рассчитана на модалку `MODAL_W.wide` = 720 и в ней тесно: три слоя настроек,
полосы, группы карточек — всё в прокрутке узкого окна.

Перенос в раздел «Персоны» решает обе части: настройка ролей встаёт рядом с
самими персонами (один раздел — один вопрос «кто и как у меня работает»), а
центральная зона страницы шире 720 — карточки дышат. Заодно каждая роль получает
срез «Кто работает по этой роли»: правила перестают быть абстракцией, под ними
видны живые персоны, которых эти правила коснутся.

## Рама: переключатель режима и точка входа

Центральная зона `PersonasPage` получает режим `personas | specialties`.
Переключатель — `PillSwitch` (тот же контрол, что «Глобальные / Все» в списке),
стоит в hero-заголовке центра на холсте — на месте, где в режиме хаба сейчас
заголовок раздела. Левая рельса со списком персон остаётся на месте: она
принадлежит разделу, а не режиму.

**Бейдж охвата «N из 14»** — на сегменте «Специальности» переключателя, это и
есть точка входа в режим. N — число ролей каталога, у которых задано хотя бы одно
правило в текущем слое (без записи «Не задана»; 14 — весь каталог). Форма —
моноширинный бейдж на `C.bgSelected` / `C.textSecondary`, радиус `R.max`
(та же форма, что у счётчиков в `FilterBar`): «9 из 14». Бейдж живёт и на
неактивном сегменте — это приглашение заглянуть, а не украшение активной
вкладки. У переключателя режима `persistKey` свой, скольжение пилюли — как у
соседних `PillSwitch`.

```
+------------------------------------------------------+
| ( Персоны ) ( Специальности [9 из 14] )              |
|                                                      |
| Роль задаёт, какие модели, доступы и инструкции      |
| получит персона по умолчанию.                        |
+------------------------------------------------------+
```

Подзаголовок — дословно: «Роль задаёт, какие модели, доступы и инструкции
получит персона по умолчанию.» `FS.sm`, `C.textSecondary`, line-height 1.5 —
заменяет прежний текст вкладки («Правила для специальностей; их наследуют поля
персоны этой специальности»): новый отвечает на вопрос «зачем мне роль», а не
«что такое правило».

## Десктоп: состав экрана

Контентная колонка — до `CHAT_MAX_W` (950), по центру холста: это список
карточек-строк, а не сетка (сетка раздела `CONTENT_MAX_W` здесь растянула бы
карточки в полосы). Рельса слева остаётся; компенсация перекоса зон — как у хаба
(`centerContentWidth`).

```
 центр PersonasPage, режим «Специальности»
+----------------------------------------------------------+
| ( Персоны ) ( Специальности [9 из 14] )                  |
| Роль задаёт, какие модели, доступы и инструкции получит  |
| персона по умолчанию.                                    |
|                                                          |
| ( Для всех ) ( Только для меня ) ( Пользователю… )       |
| Слой определяет, кого коснётся правило.                  |
|                                                          |
| +------------------------------------------------------+ |
| | ЛЮБАЯ СПЕЦИАЛЬНОСТЬ   персоны без своей специальности | |
| | Сильная  [ Сильный — основной                    ]   | |
| | Средняя  [ Средний — экономный                   ]   | |
| | Слабая   [ Слабый — быстрый                      ]   | |
| | Сейчас пойдёт: Sonnet 5 / Sonnet 5 / Haiku 4.5       | |
| +------------------------------------------------------+ |
|                                                          |
| Картина по уровням  [====полосы====]  (как во вкладке)   |
|                                                          |
| +------------------------------------------------------+ |
| | > Раскрытая роль: поля + «Кто работает по этой роли» | |
| +------------------------------------------------------+ |
| +------------------------------------------------------+ |
| | [Планировщик][Координатор]  Сильный — основной …  v  | |
| +------------------------------------------------------+ |
| +------------------------------------------------------+ |
| | Наставник   Правил нет — 3 персоны по общим …     v  | |
| +------------------------------------------------------+ |
|                       [+ Добавить правило]               |
+----------------------------------------------------------+
```

Переносится из вкладки «Правила» без переделки: переключатель слоёв («Для всех /
Только для меня / Пользователю…» — последний только админу), карточка «Любая
специальность» (всегда раскрыта, первая), «Картина по уровням» с подсветкой
карточек по клику на сегмент, группы одинаковых наборов с «выделить», отдельные
роли, мастер «Добавить правило» (одна панель из трёх шагов), строка «Сейчас
пойдёт», пустые слои («Общих правил пока нет» / «Особых правил пока нет»).
Вложенность по-прежнему ≤ 2 уровней: карточка → панель выбора `RoutePicker`.

Новое в раме — три вещи: ширина (была модалка 720, стала колонка до 950), блок
«Кто работает по этой роли» в каждой карточке и секция ролей без правил
(ниже). Правило слоя «пустой „Для всех" уводит на „Только для меня"» сохраняется.

## Раскрытая карточка роли: срез «Кто работает по этой роли»

Раскрытой по-прежнему может быть только одна карточка (внутри — несохранённый
черновик цепочки). Корпус карточки — как в v4: `C.bgWhite`, радиус `R.xl`,
раскрытая подсвечена кромкой `C.accentMuted`, тело — `C.bgCard` за пунктирной
`borderTop`. В теле после трёх полей уровней и строки «Сейчас пойдёт» — новый
блок, отделённый заголовком секции (`SectionTitle` из `specialRules/parts`):

```
+----------------------------------------------------------+
| Исполнитель (бэкенд)                                   v |
|----------------------------------------------------------|
| Сильная  [ Сильный — основной                       ]    |
| Средняя  [ · · · Как «Любая специальность» · · ·    ]    |
| Слабая   [ Слабый — быстрый                         ]    |
| Сейчас пойдёт: Opus 5 / Sonnet 5 / Haiku 4.5             |
|                                                          |
| КТО РАБОТАЕТ ПО ЭТОЙ РОЛИ                                |
|  (o) Денис — Sonnet 5, сильная · в чате                  |
|  (o) Глеб — Sonnet 5, сильная · свободен                 |
+----------------------------------------------------------+
```

**Строка персоны** (формат из постановки: «Денис — Sonnet 5, сильная · в чате»):

- аватар `PersonaAvatar` size 20, затем имя — `FS.base`, 600, `C.textHeading`;
- далее тире и модель — `FS.sm`, `C.textSecondary`: эффективная модель уровня
  персоны по серверному резолву (та же точка превью, что у строки «Сейчас
  пойдёт», — второй точки истины на фронте не заводим), затем уровень словом из
  `TIERS` («сильная / средняя / слабая»);
- статус после «·»: «в чате» — у персоны прямо сейчас идёт ход (точка
  `C.success` слева от слова); «свободен» — без точки, `C.textMuted`. Если
  живой статус занятости бэкендом не отдаётся — показываем только «имя —
  модель, уровень», без выдуманной активности (данные для статуса — задел для
  бэкенд-волны, макет допускает оба варианта);
- вся строка — кнопка: hover/tap — фон `C.bgSelected`, тап ведёт в студию
  персоны (`selectPersona` — режим «Персоны», выбранная карточка). Длинные
  имена режутся многоточием, полный текст — в `title`.

**Пустое состояние блока** — роль есть, персон по ней нет:

```
| КТО РАБОТАЕТ ПО ЭТОЙ РОЛИ                                |
|  По этой роли пока никто не работает. Роль назначается   |
|  в профиле персоны.                                      |
```

Текст `FS.sm`, `C.textMuted`, без кнопки: переход «куда назначать» вёл бы из
настройки в создание персоны и рвал бы контекст правки; подсказка-путь
достаточна. Кнопку не добавлять сознательно (согласовано рамкой v4: ничего
третьего уровня внутри карточек).

## Карточка роли без правил

В v4 роль без правил карточки не имела вовсе — теперь она несёт срез персон,
поэтому получает свёрнутую карточку в секции «Без своих правил» (под карточками
с правилами, перед мастером). Свёрнутая строка:

```
+----------------------------------------------------------+
| Наставник      Правил нет — 3 персоны работают по        |
|                общим настройкам                        v |
+----------------------------------------------------------+
```

- слева — подпись роли из каталога, `FS.base`, 600, `C.textHeading`;
- справа от неё — пояснение дословно: «Правил нет — N персоны работают по общим
  настройкам» (`FS.xs`, `C.textMuted`; N=1: «1 персона работает», N=0 — карточка
  не нужна вовсе: роль без правил и без персон не показываем — она никому не
  мешает и ничего не объясняет);
- «общие настройки» = «Любая специальность» того же слоя, а дальше вниз по
  наследованию — это уже видно в карточке «Любой специальности» выше, дублировать
  тройку в свёрнутой строке не надо;
- раскрытие — те же три поля уровня с пунктирными «Как «Любая специальность»»
  (видимое наследование из v4) плюс блок «Кто работает по этой роли». Первое же
  заданное поле переводит роль из этой секции в карточки с правилами.

## Групповая карточка

Группа одинаковых наборов — как в v4 (чипы ролей, общая тройка, предупреждение
«Изменение применится к N ролям», «выделить»). Дополнение — срез персон в
раскрытом теле: блок «Кто работает по этой роли» объединяет персон всех ролей
группы, у каждой строки справа от статуса — чип её роли (`FS.xs`, `C.bgSelected`,
`R.max`), чтобы «Денис» и «Кира» в одной группе не сливались в безымянный список:

```
+----------------------------------------------------------+
| [Исполнитель (бэкенд)] [Исполнитель (фронтенд)]        v |
|----------------------------------------------------------|
| Сильная  [ Сильный — основной                       ]    |
| ...                                                      |
| КТО РАБОТАЕТ ПО ЭТИМ РОЛЯМ                               |
|  (o) Денис — Sonnet 5, сильная · в чате   [бэкенд]       |
|  (o) Кира  — Sonnet 5, сильная · свободна [фронтенд]     |
+----------------------------------------------------------+
```

Заголовок блока во множественном: «Кто работает по этим ролям». Пустое
состояние — то же, что у одиночной роли.

## Карточка «Любой специальности»

Без изменений из v4: закреплена первой, аккордеона нет, три поля с плейсхолдером
«Как «Модели по умолчанию»» (в чужом слое — «Как у владельца»), подпись-хинт со
счётом персон без специальности («персоны без своей специальности — таких 2 из
14») сохраняется в слое владельца. Блок «Кто работает» здесь — это ровно
персоны без специальности, и хинт уже отвечает на вопрос их числом; список имён
под карточкой не дублируем: «Любая специальность» — не роль, а ответ на её
отсутствие, и её аудитория видна в секции «Без своих правил» суммарно.

## Мобила 360px

Экран — полноэкранный режим центра (как студия персоны на мобиле): список персон
уходит, вверху **явная кнопка «Назад»** — `IconButton` с `ChevronLeft` +
подпись «Персоны», tap-цель `TB.iconHitMobile` (40), слева в шапке режима.
Возвращает в режим «Персоны» (список). Переключатель режима на мобиле живёт в
шапке списка персон (над ним, той же строкой, что приглашение-познакомиться) —
поэтому «Назад» нужна именно как кнопка, а не как второй тап по переключателю:
выйти из режима должно быть можно одним жестом от края.

(многоточие по имени, статус не режется никогда). Полосы «Картины по уровням» и
переключатель слоёв ведут себя как во вкладке v4: слои переносятся на вторую

«Правил нет — …» уходит второй строкой под подпись роли, шеврон на месте.

## Темы

Обе темы бесплатны: вся композиция на семантических парах токенов
(`C.bgWhite`/`C.bgCard` карточек, `C.border`/`C.borderLight`, `C.accentMuted`
кромки раскрытой, `C.bgSelected` hover и чипов, `C.textHeading/Secondary/Muted`,
точка статуса `C.success`, бейдж охвата `C.bgSelected` + `C.textSecondary`) —
все значения уже объявлены в `theme.css` для светлой и тёмной, сырых hex нет.
Отдельных значений для dark не требуется; в тёмной теме раскрытая карточка
читается за счёт кромки `C.accentMuted` (контраст к фону холста проверен на
вкладке «Правила» — тот же корпус).

## Спецификация для реализации

Контролы (всё существующее, новых нет):

| Кусок | Контрол / паттерн |
|---|---|
| Переключатель режима | `PillSwitch` (`ui/PillSwitch`), `persistKey` новый; бейдж охвата — моноширинный счётчик по образцу `FilterBar` (`FONT.mono`, `FS.xs`, `C.bgSelected`, `R.max`) |
| Кнопка «Назад» (360px) | `IconButton` + `ChevronLeft` (`ICON_SIZE`/`ICON_STROKE`) + подпись; паттерн `onBack` студии персоны |
| Карточки, поля уровней, слои, мастер, «Сейчас пойдёт», полосы | перенос `specialRules/` (`cards.tsx`, `parts.tsx`, `LevelsPicture`, `AddRuleWizard`) — корпус не меняется |
| Заголовок «Кто работает по этой роли» | `SectionTitle` из `specialRules/parts` |
| Строка персоны | `PersonaAvatar` size 20 + текстовые стили выше; клик — `selectPersona` |
| Чип роли в групповой карточке | тот же стиль, что чипы ролей в шапке группы (`FS.xs`, `C.bgSelected`, `C.textSecondary`, `R.max`) |
| Пустое состояние блока | текстовая заглушка `FS.sm`/`C.textMuted` (без `EmptyState` — это фрагмент карточки, не экран) |

Токены: `C.bgWhite/bgCard/bgSelected/accentMuted/border/borderLight`,
`C.textHeading/textSecondary/textMuted`, `C.success`, `FS.xs/sm/base`, `R.xl/max`,
`SP.xxs…xl`, `FONT.mono` (бейдж), `CHAT_MAX_W` (колонка), `TB.iconHitMobile`
(«Назад»). Ни одного литерала цвета или размера.

Поведение и инварианты, которые перенос обязан сохранить: одна раскрытая
карточка; смена слоя сбрасывает раскрытие/выделение/мастера; правка полей
группы — одним PUT (класс 65d8df66); очистка последнего поля роли — серверный
сброс записи (иначе пустая запись-затенение); «Сейчас пойдёт» не рисуется в
чужом слое. Эффективная модель в строке персоны — только из серверного превью;
это новый вызов резолва «по персоне», и если бэкенд-волна его не даст — блок
деградирует до «имя · статус», без фронтового пересчёта цепочки.

## Что макет не решает

Затирание чужого слоя настроек (часть плана команды) — серверная история, на
вёрстку не влияет; живая занятость «в чате» и резолв модели по персоне — задел
для бэкенд-волны (выше показана деградация без них). Назначение роли персоне из
этого экрана не делаем: роль выбирается в профиле персоны, и ссылка туда —
разрыв контекста правки слоя. Панель «Инструкции для роли»
(`SpecialtyPromptSectionsPanel`) переезжает тем же переносом, её внутренности
здесь не пересматриваются.

## Итерации

- **v1 (24.08.2026)** — первый проход: рама режима с бейджем охвата на точке
  входа, срез «Кто работает по этой роли» во всех видах карточек, секция ролей
  без правил, мобильная раскладка 360px с явной «Назад». Открытые тексты (сверх
  постановки, согласовать): «По этой роли пока никто не работает. Роль
  назначается в профиле персоны.», «Правил нет — N персоны работают по общим
  настройкам» (из постановки, N и склонения уточнены), «Кто работает по этим
  ролям» (множественное в групповой карточке).
