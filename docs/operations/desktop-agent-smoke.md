# Сквозная проверка десктопного агента (вторая волна)

**Дата:** 2026-08-20
**Связанный ADR:** [ADR-008](../adr/ADR-008-desktop-agent.md) · клиент — [desktop-agent-client.md](../features/desktop-agent-client.md)
**Зачем:** критерий готовности второй волны — «код → сопряжение → тост → кадр в ход» —
доказан кодом, сборкой и тестами, но **не наблюдением**. Первая волна уже показала, чего
стоят зелёные тесты на стыке: контракт MCP↔бэкенд разошёлся, и любой вызов грани кончался
бы 400, пока это не нашли чтением кода. Поэтому проверка ручная и по шагам.

Занимает около десяти минут. Всё делается на одной машине.

## Подготовка

1. **Рабочее дерево.** Проверка идёт в `.claude/worktrees/desktop-smoke` (ветка
   `feature/desktop-agent`). Основное дерево не трогаем.

2. **Отладочный ключ.** В `backend/ClaudeHomeServer/appsettings.Local.json` этого дерева:

   ```json
   "Desktop": { "AllowSameHostPairing": true }
   ```

   Это осознанная дыра: она снимает отказ сопрягать устройство, чей отпечаток совпал с
   машиной бэкенда. Работает **только** в Development и только потому, что иначе сквозной
   путь на одной машине нечем проверить. На бою так нельзя — руки на машине сервера обходят
   изоляцию песочницы, ради которой грань и заведена.

3. **Фронт.** В новом worktree `node_modules` пустая:

   ```powershell
   cd frontend; npm ci; npm run build
   ```

   Стенд на :5000 раздаёт именно `frontend/dist` последней сборки — без этого шага увидишь
   старый бандл без грани.

4. **Бэкенд** — только так, иначе процесс уедет в Production и упрётся в занятый :80:

   ```powershell
   cd backend; dotnet run --project ClaudeHomeServer
   ```

## Негативные проверки — они важнее позитивных

1. **Закрыть окно клиента** во время сеанса → сеанс гаснет, инструменты отвечают отказом.
2. **Снять тумблер грани в проекте** при живом сеансе → сеанс гасится, вызовы отбиваются.
   Это тот случай, где легко получить «тумблер выключен, а руки работают».
3. **Отклонить тост** → модель получает текст отказа, а не молчание и не таймаут.

## Когда не работает

- **`409 { outcome, message }`** — это гейт (`DesktopAccessGate`), а не поломка: сообщение
  называет причину (нет сеанса, чужое устройство, устройство офлайн, снят тумблер).
- **`no_ack`** — команда доехала, клиент не подтвердил приём за 2 секунды. Смотреть, жив ли
  поток UI клиента: тосты идут только на нём.
- **Счётчики вызовов** — `GET /api/mcp/calls` (админ): видно, что именно звалось и что отказало.

## Что проверка НЕ покрывает

UIA-снапшот, клики и ввод, `desktop_run`, браузерное расширение — их в этой волне нет.
Управление allow-list для `desktop_open` тоже: записи правятся руками в
`%APPDATA%\AiHomeDesktop\settings.json`, ссылки `http`/`https` разрешены классом.
