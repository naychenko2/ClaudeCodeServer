# Персонализированные «Специальности» — сверка макета с дизайн-системой

> Дизайн-сверка `index.html` (кликабельный макет, десктоп + переключатель «360px») и
> `mobile.html` (тот же экран, зафиксированный вьюпорт 375px) с дизайн-системой проекта.
> Волна 1 из 5 плана «Персонализация специальностей»: макеты фиксируют состояния для
> следующих волн (бэкенд-слои, `/api/specialties`, фронт), а не дизайн с нуля — оба файла
> используют только токены `C.*`/`FS`/`SP`/`R` (в макете — `var(--c-*)`, значения из
> `frontend/src/lib/theme.css`) и повторяют существующие компоненты (`Button`, `PillSwitch`,
> `Badge`, `Toggle`, `Field`), см. `docs/design/specialties-ui-inventory.md`.

## Три экрана

Раздел «Персоны» → режим «Специальности» → строка роли → карточка роли → «Настроить».

### 1. Список специальностей (`viewList()` / `roleRow()`, index.html:719-813)

- Заголовок `h1.page` (serif, 28/500) + подзаголовок; переключатель слоёв (`layerSwitch()`);
  список ролей с правилами (`withRules`); отдельно, под заголовком «Без своих правил» —
  роли без правил, но с персонами, и (по тумблеру «Показать все роли каталога») роли совсем
  без персон.
- Каталог (`CATALOG`, index.html:507-522) — 14 именованных ролей продукта, взят из
  `SpecialtyCatalog.All` **без** записи `None` («Не задана») — сам код так и комментирует
  источник (`// Каталог ролей: … (без «Не задана»)`, index.html:506). Пункта
  «Любая специальность» (старая `AnySpecialtyCard` из `cards.tsx`, ключ `AnySpecialtyKey`)
  в новом каталоге нет вовсе — ни в списке ролей, ни где-либо ещё в макете (проверено
  текстовым поиском по обоим файлам).
- Бейдж источника имени роли (`srcBadge()`, index.html:665-669) — четыре состояния:
  - **«Из кода»** — `badge.code` (курсив, нейтральный тон), когда имя = дефолт каталога.
  - **«Общее»** — переопределение слоя «Для всех» (`LAYERS[0].badge`).
  - **«Пользователя»** — переопределение слоя «Пользователю …» (`LAYERS[1].badge`).
  - **«Ваше»** — переопределение слоя «Только для меня» (`LAYERS[2].badge`), единственный
    тон `accent` — это ЕДИНСТВЕННЫЙ бейдж с акцентным цветом, три остальных — нейтральные.
  Бейдж рисуется, только если источник ≠ `code` (`eff.src.name !== 'code' ? srcBadge(...) : ''`).

### 2. Визитка роли — read-only (`viewRole()`, index.html:818-887)

Раскладка — как `PersonaPreview`: hero (значок + имя + описание) + плоские секции с
разделителем сверху (`.flat`), а не набор отдельных карточек-островов.

- **Ни одного поля ввода и ни одного тумблера.** Значок роли и текст рисуются напрямую
  (`roleAvatar(eff, 80)`, index.html:838), без `<input>`/`<textarea>`. Пресеты рендерятся
  через `presetList(role.key, true)` (флаг `ro=true`) — то же для срав. `viewEdit()`
  (index.html:1185, без флага). Внутри `presetCard()` (index.html:935-973) `ro` убирает
  тумблер включения секции и кнопку «Задать свой текст», а `<textarea>` заменяется на
  `<div class="rotext">` — обычный читаемый текст, не притворяющийся полем ввода.
  Привязки (`bindCard()`, index.html:990-1040) в `ro`-режиме тоже без `textarea`/пилюли
  режима с кликом — только `rotext` и статичный `badge`.
- **Значок роли не кликается, без подсказки в этом экране.** `roleAvatar(eff, 80)` в
  визитке вызывается без обёртки — title="Значок роли задан продуктом и не настраивается"
  висит **только** на значке в форме настройки (см. §3), потому что там это единственное
  нередактируемое поле среди остальных, которые можно менять — подсказка нужна именно
  там, где могло бы возникнуть ожидание «а почему это не редактируется». В визитке весь
  экран read-only, отдельно объяснять нечего.
- **Счётчик символов пресета в этом экране не показывается вовсе.** В `presetCard()`
  span-счётчик `${len} / ${PRESET_TEXT_LIMIT}` рендерится только когда `!ro`
  (index.html:963) — пороги 80%/95% (см. §4) видны исключительно в форме настройки, не в
  визитке: там нечего лимитировать, текст уже сохранён.
- **Срез «Кто работает по этой роли»** (`sliceBlock()`, index.html:1055-1082) — слоевая
  развилка, см. §5.

### 3. Форма настройки (`viewEdit()`, index.html:1106-1196)

- Поля есть: `Название роли` (`.bigfield`, крупный serif-инпут как «Роль \*» у персоны) и
  `Чем занимается` (`.input`) — оба с бейджем источника, счётчиком символов и кнопкой
  «Вернуть типовое», когда есть что сбрасывать (`canReset()`, index.html:1119).
- **Значок роли — единственное нередактируемое поле формы**, и только на нём висит
  `title="Значок роли задан продуктом и не настраивается"` (index.html:1135). Ни выбора
  значка, ни выбора цвета нигде в макете нет — соответствует инварианту бэкенда:
  `SpecialtyCatalog.Entry.Icon`/`Color` — «дефолты кода, ТОЛЬКО для показа: персонализация
  их не переопределяет» (`backend/ClaudeHomeServer/Services/SpecialtyCatalog.cs:27-29`,
  этот же комментарий называет источником утверждённых значений именно этот макет).
  Значок рисуется по имени иконки lucide (`CATALOG[].icon`, те же ключи, что в
  `SpecialtyCatalog.All`, например `"chart"`, `"shield"`) — в продукте это будет
  `DynamicIcon` (см. `frontend/src/lib/projectGlyphs.tsx`), в макете — статичная SVG-заглушка
  из локального `ICONS`, содержимое эквивалентно.
- Пресеты и типовые умения — те же карточки, что в визитке, но с тумблерами/textarea
  (`ro` не передан → `presetList(role.key)`, `bindList(skills, 'form')`).

## 4. Счётчик потолка пресета — 1024 символа, пороги 80%/95%

`PRESET_TEXT_LIMIT = 1024` (index.html:565, комментарий: `SpecialtyPromptPresets.SectionTextLimit`).
Цвет счётчика в `presetCard()` (index.html:938-939):

```
len > 1024 * 0.95 (973)  → var(--c-danger)   — красный
len >= 1024 * 0.8 (819)  → var(--c-warning)  — жёлтый
иначе                     → var(--c-text-muted) — нейтральный
```

Счётчик виден только в форме настройки (см. §2/§3) — визитка его не показывает.

## 5. Слои: различия «Только для меня» vs «Для всех» / «Пользователю …»

Порядок наследования `code → all → user → me` (`CHAIN`, index.html:640). Два места макета
меняются по выбранному слою:

- **Срез в визитке роли** (`sliceBlock()`, index.html:1058-1066) — на `all`/`user` показывает
  только объясняющую строку («Список персон показан на слое «Только для меня» …», тот же
  принцип, что T8-объяснение в текущем проде — `PersonaSliceExplanation()` в
  `frontend/src/features/specialties/specialRules/cards.tsx`); на `me` — заголовок + бейдж
  числа (`<span class="badge xs">${people.length}</span>`) + список персон с их моделью и
  пометками («модель задана вручную», «умения настроены вручную»).
- **Строка роли в списке** (`roleRow()`, index.html:776-813) — стопка аватаров (`.stack`,
  до 3 персон), бейдж «N вручную» (только у персон с `manualModel`/несинхронными
  `manualSkills`) и число персон в подписи «Правил нет — N …» показываются **только на
  слое «Только для меня»**; на `all`/`user` — ничего этого, подпись «Правил нет» без числа.

  **Исправлено в этой сверке.** До правки `roleRow()` в обоих файлах строила `people`
  безусловно (`personasOf(role.key)`), поэтому стопка/бейдж/число показывались на любом
  слое — расхождение с постановкой и с тем же T8-принципом, что уже применён в срезе:
  на `all`/`user` персоны, работающие по роли, — это персоны другого владельца или всех
  сразу, а не «мои», и подмешивать сюда аватары своих персон было бы враньём. Правка —
  `people = S.layer === 'me' ? personasOf(role.key) : []` плюс подпись `unruled`-строки без
  числа вне слоя `me` (index.html:776-791, mobile.html:737-752). Проверено вне браузера:
  извлечена чистая JS-логика обоих файлов (без DOM-обвязки) и прогнана в Node для трёх
  слоёв на ролях `reviewer` (правила есть) и `backendExecutor` (два «вручную»: Денис —
  `manualModel`, Гефест — `manualSkills` без применения типовых) — на `all`/`user`
  `hasStack: false`, `hasManualBadge: false`, `sub: 'Правил нет'`; на `me` — стопка,
  `'2 вручную'` и подпись с числом персон, как в постановке.

## 6. Мобильная раскладка — точки перелома (`mobile.html`)

В CSS нет диапазонных `@media` — единственная точка перелома это булев класс `.phone`
на `.stage` (соответствует продуктовому `useIsMobile` — булев хук, не диапазон ширин,
`frontend/src/lib/breakpoints.ts`). `index.html` переключает его кнопкой «360px» поверх
десктопной демо-рамки; `mobile.html` держит его включённым всегда и меняет саму формулу
ширины сцены на «настоящий» телефонный вьюпорт: `width:calc(100% - 24px); max-width:420px`
вместо десктопных `min(1180px, calc(100% - 32px))` / фиксированных `360px` (mobile.html:93-97
vs index.html:89-95) — то есть мобильный файл проверяет целевую ширину 375 CSS px
(см. `docs/design/target-devices.md`), а не демо-масштаб внутри десктопа.

Что меняется правилами `.phone …` (одинаково в обоих файлах, `mobile.html` — те же правила
без селектора-префикса, так как `.phone` у него всегда на `.stage`):

| Элемент | Десктоп | `.phone` |
|---|---|---|
| Рельса со списком персон (`.rail`) | видна, 236px | `display:none` — на мобиле это отдельный полноэкранный список (§5.2 инвентаря), в «Специальности» попадаешь уже с открытым видом |
| Pill-переключатель (слои/режим) | по контенту | `width:100%`, сегменты растянуты `flex:1`, шрифт 13→12 |
| Хвостовые чипы строки роли (`.rolerow .tail .chips`) | видны (счётчик пресетов/умений, чипы уровней моделей) | `display:none` — дублируются в детальном экране, в строке списка только сжимали бы текст |
| Карточка `.card` | padding 16 | padding 12 |
| `.row3` (строка «уровень — пикер — источник») | 3 колонки `74px 1fr auto` | 2 колонки `64px 1fr`; `.src` переносится на отдельную строку на всю ширину (`grid-column:1/-1`) |
| `.hero` (визитка/форма) | ряд (значок слева, текст справа) | колонка, значок центрируется первым (`:first-child{align-self:center}`) — иначе значок 80px съедает половину узкой ширины |
| `.hero.preview .grow` (только визитка) | не центрируется | `text-align:center` — в форме то же самое НЕ делается: центрированные поля ввода читались бы как ошибка вёрстки |
| `.bigfield` («Название роли») | 24px | 21px |
| `h1.page` / `h2.role` | 28 / 22 | 24 / 20 |
| `.factgrid` (плитки «Модели по уровням») | `minmax(150px,1fr)` | `minmax(120px,1fr)` |
| Модалка подтверждения (`.overlay`/`.modal`) | центр экрана, `R.modal` со всех сторон | bottom-sheet: `align-items:flex-end`, скругление только сверху, `padding-bottom` с `env(safe-area-inset-bottom)` |

## Проверка

- Синтаксис обоих файлов (`<script>`) валиден: `node -e "new Function(...)"` на извлечённом
  теле скрипта — без ошибок для `index.html` и `mobile.html`.
- Слоевая логика `roleRow()` (после правки §5) прогнана без браузера: чистая JS-логика
  извлечена из обоих файлов (DOM-обвязка вырезана, `document` застаблен), вызвана для трёх
  слоёв на ролях `reviewer` и `backendExecutor` — поведение совпадает с постановкой
  (см. конкретные значения в §5) в обоих файлах.
- Текстовый поиск по обоим файлам подтвердил отсутствие «Любая специальность», `DynamicIcon`
  как реального импорта (ожидаемо — макет статичен) и единственное вхождение подсказки
  «Значок роли задан продуктом и не настраивается» — на значке формы настройки.
- Живой прогон в браузере (Playwright) для этой сверки не потребовался: логика проверена
  вне DOM, а визуальная целостность (обе темы, ширина 360/375, раскрытые пресеты/привязки)
  уже зафиксирована скриншотами предыдущего прохода в `.cc-attachments/spec-*.png`.
