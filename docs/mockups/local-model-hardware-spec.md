# Вкладка «Железо» — спецификация реализации

Макет: [local-model-hardware-v2.html](local-model-hardware-v2.html) (состояния, обе темы, 380/360/320).
Задача d0c83bea, история вариантов — [proposal](local-model-hardware-proposal.md). Эпика пока нет:
featureId и stepRef проставит Софья при нарезке. Шаги: **Б1** бэкенд (Денис), **Ф1** вкладка, **Ф2** строка-ссылка (Кира).

## Структура вкладки сверху вниз

Третья вкладка панели «Локальные модели»: `LLM · Медиа · Железо`, иконка `Cpu`. **Только админ.** Не-админу
вкладки нет и ручка отвечает 403. Ключ вкладки `'hardware'` в `Tab` и в `localStorage`. Если сохранена
`'hardware'`, а пользователь не админ, открывается `'text'`. Опрос раз в 2 с, только пока вкладка активна, как у LLM/Медиа.

1. **Баннер «Стенд не отвечает»** (`status='stale'`): `C.warningBg`/`C.warningText`, R.lg.
2. **Card «Стенд»**: справа плашка уровня, под заголовком строка-сводка, сетка плиток, строка вентиляторов.
3. **Card «Температуры»**: окна 1 мин · 5 мин · 15 мин · 1 ч (по умолчанию **15 мин**, своё состояние, не общее с LLM),
   чипы семейств, линейный график, легенда.
4. **Card «Видеокарты»** («Видеокарта», если она одна): подробные карточки, `grid auto-fit minmax(160px,1fr)`, gap SP.sm.

**Решение по старой карточке:** `GpuCard` уходит с LLM и Медиа целиком и живёт только на «Железе».
Физическая карта показывается один раз (склейка по `uuid`), подпись ролей — «текст», «медиа» или «текст · медиа».
Проп `kind` заменяется на `roles`. На LLM вместо карточек остаётся **строка-ссылка** «Видеокарты»: точка худшего уровня
карт, «память 68° · 81°», плашка «в лимите мощности» (`p-info`), «перегрев» (`p-danger`, если `thermal`), «Железо →».
Строка — Card с `role="button"`, касание переключает вкладку. На «Медиа» у админа та же строка, но только по картам
с ролью `media`. У не-админа строки нет (ADR-030). Подстрока «2 карты, TP=2» остаётся как есть.

**Точка на вкладке «Железо»** (`tabdot` 6 px, `C.warning`/`C.danger`) появляется при `level` warn/danger и видна с любой
вкладки. При `stale` её нет.

## Компоненты и состояния

| Компонент | Норма | warn / danger | Нет датчика | stale |
|---|---|---|---|---|
| `HwTile` | фон `C.bgWhite`, рамка `C.borderLight`, точка `C.success` | фон `C.warningBg`/`C.dangerBg`, рамка `C.warning`/`C.dangerBorder`, значение `C.warningText`/`C.dangerText` | «нет данных» / «датчика нет» курсивом `C.textMuted`, вместо графика подложка `C.bgInset` h 24 | значения `C.textMuted`, без окраски, точка `C.track`, график обрывается |
| `Sparkline` | линия `C.success` 1,5 px | `C.warning` / `C.danger` | подложка | `C.textMuted` |
| `GpuDetailCard` | крупно память 22 px + шкала 30…110 с меткой 95 | рамка/фон по уровню, плашка «Сбрасывает частоту от перегрева» | «нет данных», «датчик памяти не ответил» | как у плитки |
| `HwLinkRow` | точка по картам | цифры памяти по уровню | «нет данных» | приглушена |

**Плитка** (`HwTile`): R.lg, паддинг SP.sm, `position:relative; overflow:hidden`, сетка `auto-fit minmax(130px,1fr)`,
gap SP.sm (на 320 — две колонки). Сверху вниз: точка + имя (FS.xs, 600, `C.textSecondary`, многоточие), значение
(mono 20 px, 600), подпись датчика (10 px, `C.textSecondary`), мини-график (h 24, на всю ширину), деталь (FS.xs, числа
mono `C.textPrimary`). **Фоновая иконка**: lucide size 52, `strokeWidth 1.5`, цвет `C.textMuted`, `opacity: 0.12`,
`position:absolute; top:SP.xs; right:-6px`, `aria-hidden`, `pointerEvents:'none'`. Она идёт первой в DOM, контент
поверх. Контраст мелкого текста поверх штриха теряет не больше 10 % (худший случай — `warningText` на `warningBg`:
4,44 → 4,00, это свойство самих токенов). Цифры (20 px) не опускаются ниже 9:1. В `title` плитки пишется
«Предупреждение с N °C, опасность с M °C». Плитки не кликабельны, hover нет. Порядок плиток фиксирован, по тревоге
они не сортируются: место узла запоминается.

**Мини-график**: 15 мин, 90 точек (шаг 10 с), без осей и сетки, `viewBox` + `preserveAspectRatio="none"`,
`vector-effect: non-scaling-stroke`. Масштаб по Y — min…max ряда ±1 °C. Точка r 2,5 на последнем значении, `null` рвёт линию.

**Карточка карты**: шапка (точка, «RTX 3090 · роли»), подстрока «карта N из M · 24 ГБ». **Главное — температура
памяти** + шкала «запас до замедления N °C» (при ≥ 95 — «память замедляется»). Дальше плашки, строки Ядро, Горячая точка,
Вентилятор, Загрузка (bar 4 px `C.accent`), Видеопамять, Мощность. Внизу «Подробнее ▾»: частоты, шина памяти, режим
питания, PCIe, шина. **Вентилятор**: «0 %» нейтрально. Он окрашивается цветом уровня карты, только если `level`
карты warn/danger, а сам по себе 0 % при нагрузке тревогой не считается (водянка или внешнее управление).
Плашка **«Упирается в лимит мощности»** — `C.infoBg`/`C.info`, информационная.

**График «Температуры»**: семейства — Память карт `C.accent`, Ядро карт `C.info`, Горячая точка `C.plan`, Процессор
`C.success`, Чипсет `C.textSecondary`, Диски `C.warning`. По умолчанию выбрана память. Сразу не больше 3 семейств,
остальные чипы `disabled` с подсказкой. Карты различаются начертанием: первая сплошная, вторая пунктир `4 3`.
У одного выбранного семейства пунктиром `C.warning` рисуется его порог предупреждения (у дисков — порог диска кэша).
При `stale` правый хвост закрыт `C.bgInset` 60 % с подписью «нет связи». **Новых цветов нет, theme.css не меняется.**

**Мобила** (`useIsMobile`, лист снизу): переключатель вкладок строкой в теле (как сейчас), плитки в 2 колонки,
карточки карт в 1 колонку, строка-ссылка переносится, «Железо →» прижат вправо.

## Плитки

| Узел | Значение и мини-график | Иконка lucide | warn / danger, °C |
|---|---|---|---|
| Карта N | память GDDR6X (`memTempC`); нет — ядро | `Gpu` | 95 / 105. Уровень карты — худший из памяти, ядра (85/92) и горячей точки (—/100) |
| Процессор | Tctl, деталь — кристаллы | `Cpu` | 85 / 95 |
| Питание процессора | VRM | `Zap` | 90 / 105 |
| Чипсет платы | чипсет, деталь — вентилятор об/мин | `CircuitBoard` | 85 / 95 |
| Диск кэша | самый горячий датчик, деталь — «до предела N °C · занято» | `HardDrive` | предел − 10 / предел − 3 (84 → 74 / 81) |
| Системный диск | температура | `HardDrive` | то же. Предел неизвестен → 70 / 80 и подпись «предел не сообщает — пороги 70 / 80» |
| Оперативная память | «датчика нет», без графика, деталь — «занято N из M ГБ» | `MemoryStick` | — |
| Вентиляторы корпуса | строка под сеткой, иконка `Fan` 14 px `C.textMuted` | `Fan` | — |

AUXTIN1/2 и «процессор по датчику платы» не показываются. Пороги — константы бэкенда, фронт их не дублирует.

## Тексты

Вкладка «Железо». Карточки: «Стенд», «Температуры», «Видеокарты». Плашка стенда: «всё в норме» / «есть горячие узлы» /
«есть опасность». Сводка: «Горячее всех — {узел}: N °C» (норма); «Горячо — {узел}: N °C, опасно с M °C» (warn);
«Ближе всех к пределу — {узел}: N °C, опасно с M °C» (danger). Узел выбирается так: худший уровень, при равенстве —
меньший запас до порога опасности. Баннер: «**Стенд не отвечает** с ЧЧ:ММ:СС. Показаны последние данные — они могут
быть неверны.» Подсказка лимита: «Карта берёт максимум разрешённой мощности — поэтому быстрее не станет. Это не поломка.»
Пустой график: «Выберите, что показать». `aria-label` строки-ссылки: «Видеокарты — открыть вкладку „Железо“».

## Контракт бэкенда (Б1)

`GET /api/local-model/hardware?window=1m|5m|15m|1h` — `[Authorize]` + роль admin, иначе 403.

```ts
{ at: number; status: 'ok'|'stale'; staleSince?: number; level: Level;          // Level = 'ok'|'warn'|'danger'
  gpus: { index; uuid; name; roles: ('text'|'media')[]; utilPerc; memUsedMb; memTotalMb; memBusPerc;
    coreTempC; memTempC: number|null; hotspotTempC: number|null; fanPerc: number|null;
    clockMhz; clockMaxMhz; memClockMhz; powerW; powerLimitW; throttle: { powerCap: boolean; thermal: boolean };
    pstate; pcie: { gen; width }; busId; level: Level; levels: { mem; core; hotspot: Level|'none' } }[];
  nodes: { key: string; kind: 'gpu'|'cpu'|'vrm'|'chipset'|'disk'|'ram'; name: string;
    tempC: number|null; sensor: 'ok'|'none'|'nodata';        // none — датчика нет, nodata — не ответил
    level: Level|'none'; warnC: number|null; dangerC: number|null;
    detail: { ccdC?: number[]; fanRpm?: number; role?: 'system'|'kv'; temp2C?: number; critC?: number|null;
              usedGb?: number; totalGb?: number };
    spark15m: (number|null)[] }[];                            // 90 точек, шаг 10 с, max за шаг
  caseFans: { label: string; rpm: number }[];                 // только подключённые входы
  series: { key: string; family: 'mem'|'core'|'hotspot'|'cpu'|'chipset'|'disk'; gpuIndex?: number;
    label: string; points: (number|null)[] }[]; stepMs: number }
```

История живёт в кольцевом буфере на 1 ч в памяти, снимок раз в 2 с. Ряды `series` для окна: 1m → шаг 2 с (30 точек),
5m → 5 с (60), 15m → 10 с (90), 1h → 30 с (120); в бакете берётся **максимум** (пики важнее среднего).
`level` всех узлов и карт считает бэкенд; `nodes[].level` у диска — от `critC` (NVMe WCTEMP из SMART), без него 70/80.
Для строки-ссылки и точки на вкладке в ответы `stats` и `media` **только для админа** добавляется
`hardware?: { level: Level; gpus: { uuid; memTempC: number|null; level: Level; powerCap: boolean; thermal: boolean }[] }`,
отдельного опроса нет. Ответы датчиков (nvidia-smi, помощник root, hwmon, smartctl) недоверенные: исключение разбора
не выходит из `BackgroundService`, а узел получает `sensor:'nodata'`.

## Открытых вопросов нет

Принятые без Андрея решения: окно по умолчанию — 15 мин, чтобы совпадать с мини-графиками; порог VRM 90/105
(MOSFET держат 125); чипсет 85/95; системный диск без предела — 70/80; в бакете максимум, а не среднее.
Цена решения по диску кэша: в живом состоянии (82,8 из 84) плитка **постоянно красная** — это правда о диске,
а не ложная тревога.
