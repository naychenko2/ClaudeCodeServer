# ADR-030: история медиа-генераций и видимость для админа

- **Статус:** принято 2026-10-15 (решения Андрея), ветка `feat/local-media-history`. Разрез — Александр (задача `75d7c4a7`), макет — Майя ([local-model-stats-history.md](../mockups/local-model-stats-history.md), [html](../mockups/local-model-stats-history.html)). Журнал (шаг 2) влит в ветку коммитом `31dc5938e`; чтение и превью (шаг 3, Денис) и фронт (шаг 4, Кира) — в ветке.
- **Частично заменяет [ADR-029](ADR-029-local-model-stats.md):** «Общие решения», пункт «история — только окно ~1 ч в памяти» (для медиа-части), и «Решения: медиа-стенд» п.4 в части того, что админ видит по чужим генерациям. Живые блоки панели (LLM, «Сейчас считается», очередь) по-прежнему обезличены.
- **Расширяет [ADR-026](ADR-026-character-lora-training.md) §2 на чтение:** имя LoRA и фото обучения в админской истории видны админу так же, как владельцу (ADR-026, раздел «14. Видимость в админской истории»).
- **Связано:** [ADR-014](ADR-014-internal-subsystems.md) (границы вертикалей, отключаемость), [ADR-016](ADR-016-local-projects.md) (`ProjectCapabilities`, локальные проекты), [ADR-020](ADR-020-local-media-audio.md) (одна очередь GPU).
- **Для людей:** [local-model-stats.md](../features/local-model-stats.md), раздел «История генераций»; контракт — [api.md](../architecture/api.md), раздел «Статистика локальных моделей».

## Контекст

На вкладке «Медиа» панели «Локальные модели» был только «Последний час»: кольцо завершённых прогонов в памяти `ComfyPromptLedger`. После рестарта он пустой, промпта и параметров в нём нет, результат не посмотреть. Разбирать, что упало ночью и почему, было не по чему.

Андрей решил:
1. История медиа-генераций хранится **7 дней на диске** и переживает рестарты и выкатки.
2. Админ видит **промпты, параметры и результаты всех пользователей** плюс логин владельца. Название чужого чата и проекта и переход в чужой чат остаются скрытыми.
3. **LoRA — «показывать всё»:** имя LoRA и фото обучения админ видит так же, как владелец. Предложение разреза — пометка «LoRA персонажа» без имени — отклонено.
4. Блок «История · 7 дней» **заменяет** «Последний час» на вкладке «Медиа».

## Решения

### 1. Журнал — один писатель, события в файлах дня

- **Писатель один — `ComfyRunHistory`** (Images, `Services/LocalMedia/Stats/`), и зовёт его только реестр `ComfyPromptLedger`: `Register` → `enqueued`, `MarkStarted` → `started`, `Complete` → `finished`. Реестр и так единственная точка атрибуции (ADR-029, медиа п.1), поэтому в адаптерах и редакторах второй точки записи нет. Через реестр проходят все пути постановки: прямые `local_*`, три редактора, обучение LoRA и апскейл видео (у него раньше был `origin: null`, теперь метка есть).
- **Хранение:** `data/local-media-history/YYYY-MM-DD.jsonl` (день по UTC), только дозапись строк под `lock`. Строка — одно событие:

  ```
  { v: 1, t: "enqueued"|"started"|"finished", ts: <ISO-8601 UTC>, id: <prompt_id>,
    origin: LocalJobOrigin | null,
    model?, prompt?, params?,          // только у enqueued
    card?,                             // только у started: снимок /ccs/stats
    outcome?, runSeconds?, error? }    // только у finished
  ```

  Отсутствующее поле пишется как `null`. Формат версионирован полем `v`; читатель пропускает строки с незнакомой версией и битые строки, файл целиком не роняет.
- **Почему события, а не одна строка на финише:** прогон, оборванный рестартом бэкенда, иначе исчез бы бесследно. С событиями у него есть `enqueued` (и, может быть, `started`), но нет `finished` — читатель покажет его «прерванным».
- **Правило `interrupted` при чтении:** запись без `finished`, чьё последнее событие (`started` или `enqueued`) старше момента старта процесса, помечается `interrupted` (процесс умер до записи `finished`). Момент старта — параметр конструктора `MediaHistoryIndex` (по умолчанию `DateTimeOffset.UtcNow` в момент конструирования singleton). Живой ход (события после старта) остаётся `running`/`queued`.
- **Исходы:** `completed` | `cancelled` | `failed` (+ `error`) | `interrupted`. Первые три пишет реестр (`NormalizeOutcome`: неизвестное → `failed`). `interrupted` пишет монитор очереди: prompt_id ушёл из очереди, а `GET /history/{id}` вернул `null` подряд `MaxNullHistoryTicks` (20) тиков — прогон пропал из истории ComfyUI, то есть рестарт стенда ComfyUI или самого бэкенда, а не сбой графа (тот остаётся `failed` по `history.Error`). ComfyUI отдаёт отмену как ошибку `execution_interrupted`, поэтому отмену (`cancelled`) отличаем от ошибки по отмене с нашей стороны (флаг задачи стора, отмена редактора), а не по тексту ComfyUI.
- **Состав записи** — `LocalRunDetails(Model, Prompt, Params)`, его передаёт адаптер аргументом `Register`:
  - промпт обрезается до 4 КБ (`MaxPromptLength`);
  - `Params` — **белый список** `LocalRunParams`: `width`, `height`, `durationSec`, `frames`, `steps`, `seed`, `count`, `engine`, `fast`. Произвольный `JsonObject` запроса (у звука) целиком не пишем никогда;
  - `error` — недоверенный текст ComfyUI, обрезка до 500 символов.
- **Время.** Ожидание = `started − enqueued` по часам бэкенда; расчёт — `runSeconds` по меткам ComfyUI. Если рестарт пришёлся между событиями, ожидание неизвестно (`null`), а не выдумано.
- **Карта.** ComfyUI не сообщает, на каком устройстве шёл конкретный prompt. Узел однокарточный, поэтому в `started` пишется снимок `/ccs/stats` монитора на этот момент. Нет маршрута — `card: null`, в UI «не сообщает». Индекс карты не выдумываем.
- **Связь с источником — через `LocalJobOrigin`** (Core). Добавлены необязательные поля `ProjectId?`, `Source` (`local-media` | `image-editor` | `audio-editor` | `video-editor` | `lora`) и `SourceJobId?` (job_id `local_*` или id задачи редактора). Их заполняют движки редакторов из своей задачи, поэтому новых связей «вертикаль → вертикаль» нет. `versionId` в момент постановки ещё не существует, связь с результатом идёт по `SourceJobId`.
- **Обезличивание живых блоков не протекает:** новые поля `LocalJobOrigin` в `ComfyJobRow` и `ComfyOwnerSnapshot` не попадают (держит `LocalGpuQueueInfoContractTests`).
- **Сбой записи** (диск, права) — `Debug` в лог и дальше. Журнал — наблюдение, а не критичный путь; исключение не выходит ни из реестра, ни из `BackgroundService`.
- **Промпты в лог не пишем:** журнал — единственное место, где они хранятся.

### 2. Ротация и бэкап

- **Ротация — 7 дней по имени файла.** Её делает существующий `LocalMediaCleanup` (`RotateHistory`): файлы дня старше `HistoryRetentionDays` удаляются. Нового фонового сервиса нет. Срок совпадает с TTL рабочих папок редакторов и `LocalMediaJobStore.JobRetentionDays`, поэтому превью у записей почти всегда живое.
- **В бэкап не едет.** Это наблюдение с коротким сроком и промптами всех пользователей; рабочие папки редакторов, на которые ссылается история, из архива тоже исключены. Исключение — одна строка в `BackupPaths.ShouldInclude` для корня `local-media-history` (вместе с `thumbs/`) и тест `BackupPathsTests`. Файл в архив не попадает, поэтому `BackupSchema.Version` не трогаем; у журнала своё поле `v`.

### 3. Превью — шов `IMediaHistoryResultSource`, только по id записи

- **Шов Core** `IMediaHistoryResultSource` (`Core/Services/Media/`): ключ `Source` и `ResolveAsync(ownerId, sourceJobId, projectId?, n, ct)` → файл (`HostPath`, `ContentType`) или причина, почему его нет. Реализаций пять, каждая в своей вертикали, и регистрируется только при включённой подсистеме:

  | `Source` | Где лежит результат |
  |---|---|
  | `image-editor` | рабочая папка `ImageEditWorkspace`: `data/image-editor/{owner}/{jobId}/…` |
  | `audio-editor` | `AudioEditWorkspace`: `data/audio-editor/{owner}/{job}/…`, роль `main` |
  | `video-editor` | `VideoEditWorkspace`: `data/video-editor/{owner}/{job}/{variant}/clip.mp4` |
  | `local-media` | `LocalMediaJob.Outputs[n].Path` (относительный путь в проекте) + `RootPath` проекта через **`SafePath.Join`**; задача берётся из стора по владельцу записи |
  | `lora` | фото обучения персонажа: `data/lora-training/<ownerKey>/<projectKey>/<slug>/` (ADR-026 §5), путь — `SafePath.Join` от корня `data` |

- **Шов необязательный:** контроллер берёт `IEnumerable<IMediaHistoryResultSource>`. У выключенной подсистемы реализации нет, и превью такой записи даёт `410 source_disabled`, а не `500` (правило отключаемости ADR-014).
- **С клиента приходит только id записи и номер варианта `n`.** Путь, владельца и `SourceJobId` сервер берёт из своей записи; `n` ограничен числом вариантов записи. `recordId` с `..`, чужой или неверный `n` — `404`. Это единственный способ отдать админу файл чужого проекта, не открыв произвольное чтение диска.
- **Отдача:** `PhysicalFile` с поддержкой Range (звук и видео), `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`. `Content-Type` определяется по сигнатуре файла (`ImageFormatSniffer` и аналоги), а не по расширению. SVG и HTML не отдаём никогда. `size=full` — оригинал, стримится через Range без жёсткого потолка по размеру (файл целиком в память не грузится).
- **Перемещённые файлы не ищем.** Поиск по проекту — та же эвристика, которую ADR-029 запретил для атрибуции. Копию, сохранённую человеком в проект (`hero.v2.png`), история не отслеживает: её ссылка ведёт на рабочую копию.
- **Локальные проекты (ADR-016).** Сейчас медиа на устройство не попадает (отказ `local-media` при `!FilesOnServer`, отказ движков звука и видео, `FileBound` у картинок). Но проект мог переехать на устройство после генерации, поэтому шов **на каждом вызове** проверяет `ProjectCapabilities.FilesOnServer` и при `false` отвечает `local_project`, не касаясь диска (дух сторожа G10). Ретранслятор чтения устройства для истории не используется. Инлайновых `IsLocal` не заводим.

### 4. Причины `410`

`410 { reason }` — запись есть, результата больше нет. Фронт показывает «Результат больше не доступен» и подпись по причине; промпт, параметры и время остаются.

| `reason` | Когда |
|---|---|
| `expired` | истёк срок рабочей папки редактора или задачи стора |
| `missing` | файла нет на месте (удалили) |
| `project_gone` | проект удалён |
| `local_project` | проект переехал на устройство, его файлы не на сервере |
| `source_disabled` | подсистема источника выключена, реализации шва нет |
| `no_result` | исход не `completed` (ошибка, отмена, прерывание): результата и не было |

Список открытый: фронт показывает незнакомую причину как «Файл недоступен».

### 5. Миниатюры

- **Генерируем, оригиналы в список не грузим.** Картинка 1328² PNG весит 2–3 МБ, страница из 50 записей с оригиналами — около 150 МБ.
- **Лениво, при первом запросе `size=thumb`:** `ffmpeg` (уже стоит, его использует `FfmpegVideoDsp`) → webp 256 px. Видео — кадр из середины. Звук миниатюры не имеет: фронт его не запрашивает, рисует плитку вида, плеер — по `size=full`.
- **Кэш** — `data/local-media-history/thumbs/{recordId}-{n}.webp`. Удаляется ротацией вместе с днём, в бэкап не едет (тот же корень).
- **Нагрузка ограничена:** семафор на 2 процесса ffmpeg, таймаут 10 с. Отказ — `410`/ошибка без `500`, фронт рисует плитку и не ретраит.
- **Атомарная запись:** ffmpeg пишет в `.tmp`, при успехе — `File.Move` на целевой путь; при таймауте/сбое `.tmp` удаляется. Целевой файл не бывает «наполовину».
- **Сразу при завершении не строим:** у адаптера редактора в этот момент байты в памяти, а файл на диске появляется только после `Poll` в редакторе.
- **ImageSharp не тянем:** его в проекте нет, а ffmpeg уже есть.
- **Отклонение от `ccs-agents.slice`:** миниатюры генерируются напрямую через `ffmpeg` (не через агент-прокси), потому что результат — маленький webp 256 px, а не стрим медиа. Семафор на 2 процесса ограничивает параллелизм.
- **Аудио/видео: запись показывает все варианты.** Сейчас `n` в `GET /history/{id}/file?n=` выбирает вариант из полного списка; запись в истории не привязана к конкретному варианту. Для N-вариантной задачи все N записей показывают все N вариантов. Дешёвая правка (привязка `n` к записи) отложена; если понадобится — добавить поле `variantIndex` в `LocalJobOrigin`.

### 6. Доступ: роль admin и серверный гейт флага

- Обе ручки (`GET /api/local-model/history` и `GET /api/local-model/history/{id}/file`) — `[Authorize(Roles = "admin")]`: не-админ получает `403`.
- **Плюс серверная проверка флага `local-model-stats`** у текущего пользователя через `FeatureFlagService`: без флага — `404`. Остальные ручки фичи флаг на сервере не проверяют (его проверяет фронт), но здесь наружу впервые идут чужие промпты и файлы, и UI-гейта мало.
- **Обычному пользователю ничего не меняется:** `ComfyOwnerSnapshot`, карточки редакторов и инвариант «чужая задача неотличима от несуществующей» не трогаем.

### 7. Нагрузка и чтение

- **Объём:** очередь GPU одна, прогон длится от ~15 с до 15 мин. Реально — сотни прогонов в сутки, потолок — около 4 тыс. в сутки на одних быстрых картинках. За 7 дней — до ~30 тыс. записей по 1–2 КБ, то есть до ~50 МБ в худшем случае, по факту единицы мегабайт.
- **Индекс в памяти:** при старте читаются 7 файлов, дальше подхватываются новые события. Фильтры — в памяти: вид, модель, исход, владелец (логин), период.
- **Курсорная пагинация** по `(время desc, prompt_id)`, страница 50. Своего поллинга у истории нет: вкладка берёт первую страницу при открытии, по кнопке «Обновить» и когда живой `/stats/media` показывает новое завершение.

### 8. Приватность: что видит админ и чем это отличается от прежнего правила

| | ADR-029 (было) | ADR-030 (стало, только история) |
|---|---|---|
| Чужой владелец | не виден | **логин** (без него не работает фильтр по пользователю) |
| Промпт, параметры, seed | не видны | **видны** |
| Результат (картинка, звук, видео) | не виден | **виден** (превью и оригинал) |
| Имя LoRA, фото обучения (ADR-026) | не видны | **видны** так же, как владельцу |
| Название чата и проекта, переход в чат | скрыты | **скрыты**, как и раньше |
| Живые блоки «Сейчас считается», очередь, вкладка LLM | «Чат другого пользователя» | без изменений |
| Обычный пользователь | только агрегаты | без изменений |

- Название чата и проекта для цели фичи не нужны, поэтому это минимальное расширение, а не отмена анонимизации. Свои записи тоже показываются без названия чата и проекта — строка и карточка одинаковы для всех, без условных веток.
- **Пометка на виду (макет, раздел 6):** под заголовком блока всегда видна строка «Видны генерации всех пользователей AI Home — промпты и результаты. Этот раздел доступен только администраторам.»; чужая запись подписана логином, в её карточке — плашка «Генерация пользователя …». Админ не должен случайно показать чужую работу, не поняв, что это чужая работа.
- **LoRA.** `LoraNamespace.VisibleTo` остаётся единственным правилом видимости LoRA везде, кроме админской истории. В истории имя LoRA и фото обучения админу видны **только на чтение**: подключить чужую LoRA, вписать её в персонажа, запустить с ней генерацию или изменить её админ по-прежнему не может — все три точки `VisibleTo` (ADR-026 §2) не меняются. Подробности — ADR-026, раздел 14.

### 9. Изменение правила приватности (2026-10-18): медиа-панель для обычных пользователей

Раньше (ADR-029 и §6–8 выше) панель «Локальные модели» целиком была админской: не-админ получал `403` на все ручки. Андрей решил открыть **вкладку «Медиа» и историю** обычным пользователям — но **только с их собственными генерациями**. Это сужает, а не расширяет, то, что не-админ видит: правило «не-админ не видит ничего» (ADR-029) сменяется на «не-админ видит только своё».

**Что видит не-админ:**
- **`/stats/media`** — `scope: "self"`: `running`/`queue`/`lastHour` — только строки, где `OwnerId == sub` и не Foreign (чужие и Foreign — другие инстансы/транскрипция/external — не попадают вовсе); `gpus: null` (видеокарты скрыты); `queueAhead` — счётчик «перед вами N» (сколько задач в **полной** очереди стоит перед первой своей поставленной в очередь задачей; нет своих — `null`). `slots`, `loadedModels`, `comfy`, `configured` — как есть.
- **`/history`** — `scope: "self"`: индекс запрашивается с **обязательным фильтром `OwnerId == sub` на уровне запроса** (не пост-фильтр, не фильтр в UI); параметр `login` игнорируется; поле логина владельца в DTO не заполняется (свои записи, логин не раскрываем).
- **`/history/{id}/file` и превью** — запись должна принадлежать не-админу, иначе **`404`**.

**Админ не меняется ни в чём:** `scope: "all"`, все строки, `gpus` на месте, логин владельца раскрывается, флаг `local-model-stats` проверяется как раньше.

**Почему `404`, а не `403`:** чужая запись не должна подтверждать своё существование не-админу — `403` сказал бы «запись есть, но тебе нельзя», а `404` — «записи нет» (тот же приём, что у ADR-030 §3 для `recordId`/`n`).

**Рубильник `LocalModelStats:MediaForUsers`** (по умолчанию `true`): `false` → не-админ получает `404` на медиа и историю, как будто функции нет (админ не зависит от него). Читается одной точкой (связывание секции `LocalModelStats` в `Program.cs`), не инлайн `config.GetValue` в контроллерах. Фич-флаг `local-model-stats` для не-админа **не требуется** (для админа — как раньше).

**Отвергнуто:**
- **Показывать не-админу чужие строки очереди** (как живые обезличенные блоки ADR-029) — мутит правило «только свои» и раскрывает, что ещё считается на стенде; оставлен только счётчик `queueAhead`.
- **Фильтровать «только свои» на фронте** — фронту не доверяем: чужая строка, просочившись в ответ, уже раскрыта; резка — на сервере в каждой ручке.
- **Отдельный endpoint для не-админа** — дублировал бы всю логику; достаточно роли + `scope`.

## Цена

- В `data/` появляется журнал с промптами всех пользователей — до ~50 МБ и 7 дней. Его утечка раскрывает чужую работу; защищён он тем же, чем остальное содержимое `data/`.
- Админ получает доступ к чужому творчеству и биометрии (фото обучения LoRA). Это осознанное решение Андрея; на стороне продукта его ограничивают только роль admin, серверный флаг и пометка в UI.
- Пять реализаций шва в пяти вертикалях. Новый источник генераций без своей реализации даст `410 source_disabled` у всех своих записей — это видно сразу, но молча не чинится.
- Ленивая миниатюра — запуск `ffmpeg` на первом просмотре страницы; потолок — семафор на 2 процесса.
- Различение отмены и ошибки требует знания с нашей стороны: по тексту ComfyUI его не сделать.

## Отвергнуто

- **Дописать ADR-029 вместо нового ADR.** Смена правила приватности — отдельное решение со своей датой, причиной и ценой; в истории решений должно быть видно, что раньше было иначе. ADR-029 получает только пометку в шапке.
- **Писать запись в адаптерах или редакторах.** Вторая точка записи рядом с реестром — вторая точка правды об атрибуции; апскейл и LoRA легко потерялись бы.
- **Одна строка на финише.** Прерванные рестартом прогоны пропадали бы бесследно.
- **Хранить в памяти, как «Последний час».** Неделя не переживёт ни рестарта, ни выкатки.
- **Включить журнал в бэкап.** Промпты всех пользователей уехали бы в облачный архив ради данных с жизнью в 7 дней, на файлы которых всё равно нет ссылок в архиве.
- **Путь к файлу с клиента / поиск перемещённого файла по проекту.** Первое — произвольное чтение диска админом через веб-морду, второе — эвристика, которую ADR-029 уже запретил.
- **Отдавать оригиналы в список.** ~150 МБ на страницу.
- **Строить миниатюру при завершении.** Файла на диске в этот момент ещё нет; плюс работа ради записей, которые никто не откроет.
- **ImageSharp для миниатюр.** Новая зависимость там, где уже есть `ffmpeg`.
- **«LoRA персонажа» без имени и без превью фото обучения** (предложение разреза). Андрей решил показывать всё; оформлено как явное расширение ADR-026 на чтение, а не тихое исключение.
- **Показывать админу название чужого чата и проекта, переход в чат.** Для разбора генерации не нужно, а прецедента такого доступа в продукте нет.
- **Живые блоки вкладки тоже деанонимизировать.** Решение касается только истории; живые блоки остаются по ADR-029.

## Инварианты и сторожа

1. **Границы ADR-014:** Images не знает редакторов, редакторы не знают Images; связь — только `LocalJobOrigin` и `IMediaHistoryResultSource` в Core. Новые реализации — под `SubsystemBoundaryTests`.
2. **Обезличивание живых блоков:** новые поля `LocalJobOrigin` не попадают в `ComfyJobRow`/`ComfyOwnerSnapshot` — `LocalGpuQueueInfoContractTests`.
3. **Бэкап:** `ShouldInclude("local-media-history/…") == false`, включая `thumbs/` — `BackupPathsTests`.
4. **`SafePath.Join`** для `local-media` и `lora`; у рабочих папок путь собирается только из id и владельца записи. Тест: `recordId` с `..` или чужой `n` → `404`.
5. **`ProjectCapabilities.FilesOnServer`** проверяется в шве на каждом вызове.
6. **Недоверенные ответы ComfyUI:** `error` обрезан до 500 символов, разбор только через `TryGetValue`, исключение не выходит из `BackgroundService`.
7. **Флаг на сервере:** без `local-model-stats` ручки `/history*` отвечают `404`, не-админ — `403`.
8. **LoRA:** три точки `VisibleTo` из ADR-026 §2 не меняются; админская история только читает.
