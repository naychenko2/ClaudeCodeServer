# Дизайн-спецификация: Каталог секций промптов («Инструкции для роли»)

> Автор: Майя (UI/UX). Этап 1 плана `.omc/plans/specialty-prompt-sections.md` (шлюз дизайн-макетов).
> Назначение: чертёж кликабельного HTML-прототипа `docs/mockups/specialty-prompt-sections.html`.

## Контекст

В настройках специальностей (вкладка «Правила» диалога «Модели и расход», `SpecialRulesTab`) появляется каталог секций промптов — готовых инструкций, которые вклеиваются в системный промпт персон этой специальности.

Секции (первая волна): «История решений» (включена у 9 из 14 ролей), «Стиль ответов» (каркас), «Процессы» (каркас).
Слои наследования: «Для всех» (global, админ) → «Пользователю…» (user, админ) → «Только для меня» (owner). Значение — из верхнего слоя, где задано; явный off владельца перекрывает on админа.

## 1. Структура экрана

- Точка входа: внутри вкладки «Правила» (`SpecialRulesTab`), новый блок **после** карточек специальностей, перед подвальной подсказкой.
- Заголовок-разделитель: «Инструкции для роли» — `FS.md`, 700, `C.textHeading`, снизу `1px solid C.divider`.
- Подзаголовок: «Текст инструкций добавляется в системный промпт всех персон этой специальности. Значения наследуются: владельцы видят и могут переопределить настройки администратора.» — `FS.xs`, `C.textSecondary`.
- Кликатбельность прототипа: тумблер вкл/выкл; селект пресета; текстовое поле (автосохранение в реальном UI); «Вернуть типовой»; бейдж источника (инфо); счётчик символов (инфо).

## 2. Карточка секции

Корпус: `C.bgWhite`, `1px solid C.border`, `R.xl`, `marginBottom: SP.sm`.

Шапка: `[Тумблер] [Название FS.base/700] ... [Бейдж источника] [ChevronDown]`, под ней описание `FS.sm`/`C.textSecondary` (одной строкой, ellipsis).

Бейдж источника: `FS.xs`, 600, паддинг `2px 8px`, `R.max`, фон `C.bgSelected`; цвета: global → `C.textMuted` «Общее»; user → `C.textSecondary` «Пользователя»; owner → `C.accent` «Ваше»; default → `C.textMuted` курсив «Из кода».

Тело (раскрытое; видно когда включена ИЛИ есть override): `C.bgCard`, `borderTop: 1px dashed C.border`, паддинг `4px 14px SP.md`. Компоновка:
```
[Пресет ▼] [Вернуть типовой]              [142 / 1024]
[ textarea: текст секции, minHeight 80px, maxHeight 200px ]
«Сейчас пойдёт: текст из …»
```

- Селект пресета: нативный select, `FS.sm`, `R.md`, `1px solid C.border`, плейсхолдер «Типовой текст…»; выбор замещает текст редактора.
- «Вернуть типовой»: ghost-кнопка `FS.xs`, `C.accent`, underline; видна только при override в текущем слое; удаляет запись слоя (значение падает вниз, бейдж обновляется).
- Счётчик: `FS.xs`, `FONT.mono`, справа; 0–80% → `C.textMuted`; 80–95% → `C.warning`; >95% → `C.danger`. Формат «142 / 1024».
- Textarea: `FS.sm`, `C.textHeading`, `C.bgWhite`, `R.xl`, паддинг `8px 10px`, `resize: vertical`; фокус — рамка `C.accent`. Если эффективное значение из нижнего слоя (global/user) — disabled: фон `C.bgSelected`, текст `C.textSecondary`.
- Подпись: «Сейчас пойдёт: текст из общего слоя (настройки администратора)» / «…из слоя пользователя (выбранного администратором)» / «ваш текст» / «текста из кода (дефолт)» — `FS.xs`, `C.textMuted`.

Состояния карточки: включена+override (раскрыта, бейдж «Ваше»); включена+наследование (раскрыта, бейдж «Общее»/«Пользователя»); выключена владельцем (схлопнута, бейдж «Ваше»); выключена наследование (схлопнута, бейдж источника); все выключены → empty-state.

## 3. Тексты секций и empty-state

- «История решений» — «Сценарные правила: когда и как использовать историю решений (досье).»
- «Стиль ответов» — «Каркас: пресеты пока не наполнены.»
- «Процессы» — «Каркас: пресеты пока не наполнены.»

Empty-state (все выключены, паттерн EmptyBox): рамка `1px dashed C.dashed`, `R.xl`, паддинг `22px 18px`, центр; заголовок «Секции пока не настроены» (`FS.md`, 700); подпись «Включите секции и задайте текст — инструкции добавятся в промпт персон этой специальности.»
Ошибка загрузки: «Не удалось загрузить секции» / «Проверьте соединение и попробуйте обновить страницу.»

## 4. Мобильная раскладка (<768px)

- Шапка: тумблер+название+стрелка на первой строке; описание и бейдж — на второй.
- Панель пресета: пресет `flex: 1`, кнопка и счётчик переносятся.
- Отступы тела `4px 10px SP.sm`; описание `FS.xs`; карточки `marginBottom: SP.xs`; textarea `minHeight: 60px`; тач-цели ≥40px.

## 5. Решённые развилки

1. Живёт ВНУТРИ вкладки «Правила» (не отдельная вкладка) — если секций станет >5, вынести.
2. Выключенная секция видна схлопнутой (не скрывается); EmptyBox — только когда выключены все.
3. Название раздела — «Инструкции для роли» (не «Секции промпта»): польза, не реализация.
4. Автосохранение с debounce 300–500 мс и индикатором «Сохранение…» (паттерн SpecialRulesTab), без кнопки «Сохранить».
5. Жёсткий лимит текста 1024 символа (`maxLength`) + цветовой счётчик.

## 6. Контрольный список прототипа

- Только токены `C.*`/`FS`/`SP`/`R` (в прототипе — их фактические значения из `theme.css`/`design.ts`, обе темы).
- Карточки в паттерне RuleSpecCard; тёмная тема читаема; мобильная ширина; тумблер/селект/счётчик живые; empty-state демонстрируемый.

# v6: типовые умения роли (ред. 2 — единый язык со вкладкой «Умения» персоны)

В раскрытой панели роли (под «Пресеты для роли») — блок **«Типовые умения»**: профиль умений, который при создании персоны роли материализуется в её личные умения. Модель — копия при создании; смена дефолта роли не трогает существующих персон; им — кнопка «Применить типовые».

**Единый язык с настройками персоны (требование пользователя):** блок выглядит и редактируется как вкладка «Умения» персоны (`PersonaBindingsPanel`), переиспользует её словарь и компоненты — `BINDING_TYPE_META` (имена/подсказки/цвета), `BindingTypeIcon`, `BindingModeBadge`, степпер ①②③. Отличие ровно одно: у типового умения цель не выбирается — её при создании персоны подберёт AI (кроме типа «Навык» — там выбор из каталога).

Карточка типового умения (как карточка умения персоны):
- цветной бейдж типа по `BINDING_TYPE_META`: «Проект» (accent), «Папка или файл», «Знания проекта» (info), «Заметки» (success), «Инструмент» (plan), «Навык» (warning), «Команда проекта»/«Задачи проекта» (danger) + подсказка типа (`hint`);
- цель: «AI подберёт при создании» (`C.textMuted`) — для «Навыка»: имя выбранного скилла из каталога;
- правило «когда пользоваться» — текст-условие как у персоны (примеры: «когда спрашивают про релизы», «когда просят статус задач»);
- бейдж режима «Авто / Всегда / Выкл» (`BindingModeBadge`);
- тумблер вкл/выкл записи.

Добавление — степпер как у персоны: **① Тип → ② Цель → ③ Правило**; в шаге ② для не-навыков показывается «AI подберёт при создании» с пояснением, для «Навыка» — поиск по каталогу скиллов (в макете — список-заглушка).

**Скиллы НЕ отдельный подраздел** (ред. 2): скилл — тип «Навык» («Готовый приём работы») в общем списке типовых умений. Выбранные навыки привяжутся к новой персоне; отсутствующие в каталоге пропускаются молча.

Подпись блока: «При создании персоны этой роли умения добавляются автоматически. Существующим персонам — по кнопке „Применить типовые“.»
Empty-state: «Типовых умений нет — персона этой роли создаётся с пустыми умениями.»

Типовые дефолты по ролям (из плана): библиотекарь/консультант — Knowledge+Notes; секретарь — Notes+ProjectTasks; координатор — ProjectTasks+ProjectPersonas; планировщик — ProjectTasks+Project; исполнители/ревьюер/тестер — Project+ProjectPath; наставник/дизайнер/аналитик — Project+Notes. В прототипе показать 2 записи для выбранной роли по этой таблице.

# v5: согласованный состав каталога (пользователь, 2026-08-23)

Первая волна — 4 секции (упоминания «Стиль ответов»/«Процессы» в ранних разделах — исторические, до согласования):

1. **История решений** — сценарии «когда и как использовать досье» (`dossier_lookup`/`dossier_get`). Вкл у 9 ролей: analyst, planner, reviewer, tester, executor, backendExecutor, frontendExecutor, devopsExecutor, consultant.
2. **Граф кода** — сценарии codegraph per-role: find «где объявлен X», neighbors «что сломается, если правлю X», hubs «с чего начать в незнакомом». Вкл у 6: три executor, reviewer, tester, planner.
3. **Процессы роли (DoD)** — что сделать перед сдачей результата (сборка/тесты/lint:design) и куда складывать результат (задачи/заметки/docs). Вкл у 9: executor×3, tester, planner, reviewer, secretary, librarian.
4. **Правила роли** — специализированные инструкции, характерные для специальности, НЕ привязанные к инструментам: профессиональные рамки роли (ревьюер — «спорь с решением, а не с оформлением»; наставник — педагогические ограничители; библиотекарь — принципы атрибуции источников). Вкл у всех 14.

«Стиль ответов» в состав не входит: перекрывается контрактом персоны (слой персоны клеится после секций). У каждой секции — типовой пресет под каждую роль; лимит ~1 КБ на секцию; вклеиваются только включённые.

# v4: раскрытие пресетов под карточкой специальности (master-detail отменён)

Пользователь работает в основном на планшете — двухпанельный master-detail (v3) не помещается. Решение пользователя: **раскрытие на месте** — клик по карточке специальности раскрывает её пресеты прямо под карточкой. Раздел v3.1–v3.2 ОТМЕНЁН; read-only дефолты, карточки, тексты, тост — по-прежнему из v2.

## v4.1. Поведение

- Карточки специальностей во вкладке «Правила» (как в v1) — кликабельные, в правом углу ChevronDown (поворот 180° при раскрытии).
- Клик → под карточкой раскрывается панель пресетов ЭТОЙ специальности, в пределах ширины списка карточек. Повторный клик — схлопнуть. Раскрыта **одна специальность за раз** (раскрытие другой закрывает предыдущую — меньше скролла на планшете).
- Панель пресетов: фон `C.bgCard`, `borderTop`/рамка в тоне карточки, паддинг `SP.sm–md`; сверху строка с индикатором слоя «Редактируется слой: …» (read-only бейдж из v2) и подзаголовок «Пресеты для роли» (`FS.base`/700, `1px solid C.divider`); ниже — карточки пресетов (§2 без изменений).
- Закрыто — пресеты не занимают ни пикселя; заголовок-разделитель «Инструкции для роли» над карточками специальностей остаётся (вход в механику).

# v2: иерархическая навигация (по итогам осмотра первого макета пользователем)

Первый макет (плоский блок во вкладке «Правила») пользователь не понял. Его ментальная модель — требование:

**настройки → список специальностей → вход в специальность → список её ПРЕСЕТОВ** (вкл/выкл, правка; дефолтные значения видны read-only, не редактируются).

## v2.1. Навигация

- Карточки специальностей во вкладке «Правила» становятся КЛИКАБЕЛЬНЫМИ: клик → детальный вид специальности.
- Детальный вид — **дровер справа** (рекомендация Майи из трёх вариантов: дровер / drill-down-страница / аккордеон): сохраняет контекст списка, на мобиле — во всю ширину; закрытие по «← Правила» в шапке и по клику вне.
- Шапка детального вида: «← Правила» (ghost, `FS.sm`), название специальности `FS.h2`/700/`C.textHeading`, описание из каталога `FS.sm`/`C.textSecondary`.
- Под шапкой — индикатор активного слоя (read-only бейдж, НЕ второй переключатель): «Редактируется слой: Для всех» — `FS.xs`, `C.bgSelected`, `R.max`. Переключатель слоёв остаётся один, на вкладке «Правила» (решение по развилке 2 Майи + уточнение продакта).
- Подзаголовок списка: «Пресеты для роли» — `FS.base`/700, снизу `1px solid C.divider`.

## v2.2. Пресеты в детальном виде

Карточки секций из §2 старой спеки сохраняются полностью (тумблер, бейдж источника, селект типового текста, textarea, счётчик 1024, «Вернуть типовой», подпись «Сейчас пойдёт: …»). Отличия v2:

- Словарь пользователя: в UI — «пресет» (не «секция»).
- **Read-only дефолты (ключевое требование):** если значение наследуется из кода/нижнего слоя — текст дефолта ПОКАЗЫВАЕТСЯ (не прячется): textarea disabled, фон `C.bgSelected`, текст `C.textSecondary`, бейдж «Из кода» курсивом / «Общее» / «Пользователя». Тумблер при этом доступен: включение пресета в текущем слое создаёт переопределение, после чего textarea редактируется, бейдж → «Ваше»/«Общее» по контексту.
- Тост при попытке правки disabled-текста: «Чтобы задать свой текст, включите пресет» (`FS.xs`, тёмная плашка снизу, авто-скрытие ~2 с).
- «Вернуть типовой» удаляет переопределение — значение снова падает в read-only дефолт, текст дефолта снова виден.
