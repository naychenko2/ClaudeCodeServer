# «Подставить персонажа» · два лица одним запросом (этап 3)

Макет: [character-face-swap-v2.html](character-face-swap-v2.html). В шапке переключаются тема (светлая / тёмная / обе), ширина (десктоп / 320 CSS px / обе), состояния редактора 1–11 и ленты Л1–Л6, «Все состояния» сеткой и «Зоны касания». Адрес тоже задаёт вид: `?theme=both&w=both&s=all`, `s=e5`, `s=f4`, `&hit=1`.
Основа — вариант A этапа 2 ([v1](character-face-swap-v1.html), [proposal](character-face-swap-proposal.md)). Разрез — карточка Александра bfde7fef, §4.

## Сценарий и проблема

На картинке три человека; Мария нужна слева, Иван в центре. На этапе 2 это два отдельных запуска и промежуточная версия, которая никому не нужна. Теперь: нажать лицо → выбрать Марию → нажать второе лицо → выбрать Ивана → «Подставить (2)». Получается одна версия, видеокарта делает два прохода.

## Решение коротко

- Одиночный выбор лица превращается в **назначения**: выбранный персонаж сразу закрепляется за лицом, на рамке появляется ярлык с аватаром и именем.
- В боковой части (на мобиле — под холстом) — список «Назначения · N из 2»: строка на каждое лицо, ✕ снимает назначение, тап по строке переназначает.
- Выбор персонажа «Кто будет на лице N?» виден, только пока лицо активно, и стоит выше списка назначений.
- Персонаж, назначенный на другое лицо, в выборе серый и подписан «Уже на лице 1».
- Подвал: чип котировки и «Подставить» / «Подставить (2)».
- Лента: одна карточка запуска со стадией «Проход k из 2», одна версия, строка ✓/✗ на каждое лицо.

## Тексты интерфейса

Новые — на согласование Софье. Тексты из v1, которые уже живут в `FS_TEXT`, остаются дословно.

**Плашка режима (над холстом):**
- нет назначений — `Нажмите на лицо, на которое нужно подставить персонажа` (как в v1);
- лицо активно, не назначено — `Выберите персонажа для лица {n}`;
- лицо активно, назначено — `Выберите другого персонажа для лица {n} — или снимите назначение`;
- одно назначение — `Можно назначить ещё одно лицо — или подставить сразу`;
- два назначения — `Два лица назначены — можно подставлять`.

**Боковая часть:**
- заголовок секции — `Назначения`, счётчик — `{k} из 2`;
- empty state — `Пока никого не назначили. Нажмите на лицо на картинке`;
- слот после первого назначения — `Нажмите на другое лицо, чтобы назначить второго персонажа`;
- строка активного неназначенного лица — `Лицо {n}` + `выберите персонажа`;
- `aria-label` у ✕ — `Снять назначение с лица {n}`;
- заголовок выбора — `Кто будет на лице {n}?`; подсказка под ним — как в v1 (`Персонаж из строки контекста сам не подставляется…`);
- занятый персонаж: строка — `Уже на лице {n}`, плитка — `на лице {n}`, `title` — `Уже на лице {n}`;
- `aria-label` рамки: `Лицо {n}: назначить персонажа` / `Лицо {n}: {Имя}. Переназначить` / `Лицо {n}: слишком мелкое`.

**Плашки и отказы:**
- лимит (warning) — `Не больше 2 лиц за раз. Снимите одно назначение, чтобы выбрать это лицо`;
- близко (danger) — `Лицо {n} стоит слишком близко к соседнему — его не подставить`; кнопка `Снять назначение с лица {n}`; причина в строке — `слишком близко к соседнему`;
- вне кадра (danger) — `Лицо {n} выходит за край картинки — его не подставить`; кнопка та же; причина — `выходит за край картинки`;
- мелкое — как в v1 (`FS_TEXT.small` + «Закрасить кистью»);
- изменилась картинка (info) — `Картинка изменилась — лица найдены заново. Назначьте персонажей ещё раз`.

**Подвал:**
- чип: одно назначение — `бесплатно · ~1 мин` (как в v1), два — `2 прохода · бесплатно · ~2 мин` (ETA = N × ETA одной правки, из котировки);
- кнопка: `Подставить` / `Подставить (2)`.

**Лента:**
- строка запуска — `Правка версии {v} · {Сцена} · Мария → лицо 1, Иван → лицо 2 · локальные модели · ~2 мин`;
- стадия — `Проход {k} из 2 · лицо {n}`; между проходами, пока ждём видеокарту, — `Проход 2 из 2 · ждём видеокарту`;
- подсказка во втором проходе — `Если отменить сейчас, версия сохранится с лицом 1`;
- строки результата: `Мария → лицо 1` + `сходство 0,81` | `не удалось` | `отменено`;
- плашка частичного результата (ошибка) — `Лицо 2 не подставилось — версия сохранена с лицом 1. Можно повторить только лицо 2: лицо 1 останется как есть.`;
- плашка частичного результата (отмена) — `Запуск отменён после лица 1 — версия сохранена с ним. Можно повторить только лицо 2: лицо 1 останется как есть.`;
- кнопка — `Повторить для лица 2`;
- ни одного лица: ошибка — `Не удалось подставить лица — версия не создана. Назначения можно повторить из редактора.`; отмена — `Отменено — версия не создана`;
- мета под строками: `2 прохода · от версии 2 · локальные модели` / `1 проход из 2 · …`.

**«Что нового»:**
> Теперь в AI Home можно поставить двух персонажей на разные лица за один раз: нажмите на лицо, выберите, кто там будет, повторите для второго — и получите одну готовую картинку. Если одно лицо не получится, картинка сохранится со вторым, а неудавшееся лицо можно повторить одной кнопкой.

## Спецификация для Киры

Всё, чего здесь нет, — как в спецификации v1 (рамки, бейджи-номера, плитки, подвал, мобила). Цвета — только `C.*`, размеры — `FS`/`SP`/`R`/`SHADOW`.

**Рамка лица — пять видов** (`FaceOverlay`):

| Вид | Рамка | Номер |
|---|---|---|
| свободная | 2px `C.onDark` + ореол `C.mediaScrim` (как v1) | `C.mediaScrim` / `C.onDark` |
| выбрана сейчас (`active`) | 3px `C.accent` + кольцо `0 0 0 4px C.accentMuted` (как v1 `sel`) | залит `C.accent`, цифра `C.onAccent` |
| назначена | 3px `C.accent`, без кольца | залит `C.accent` |
| приглушена (пока другое лицо активно, только свободные) | opacity .65, нажимается | — |
| лимит (миг после тапа по третьему) | `C.warning` | `C.warning` |
| отказ | `C.danger` | `C.danger` |

Мелкая рамка — как в v1 (пунктир, не назначается).

**Ярлык назначения** — внутри кнопки рамки: тап по нему = тап по рамке; `pointer-events: none` у самого ярлыка.
- Положение: `top: calc(100% + SP.xs)`, по центру рамки (`left: 50%`, `translateX(-50%)`). Если центр рамки правее 84 % ширины картинки — прижат к правому краю рамки (`right: -3px`), чтобы не вылезать за картинку. Лица у нижнего края в первом срезе не обрабатываем (вопрос В3).
- Форма: высота 22 (мобила 24), `R.max`, фон `C.accent`, текст `C.onAccent`, `FS.xs` 700, ореол `0 0 0 1px C.mediaScrim`, `max-width: 120px`, имя обрезается многоточием.
- Внутри: аватар 18 (обводка `C.onAccent`) + имя; у рамки с отказом — фон `C.danger`, текст `C.onDark`, вместо аватара `AlertTriangle` 12.

**Список назначений** — `role="list"`, строки `role="listitem"`:
- строка: min-height 44 (мобила 48), фон `C.bgCard`, рамка 1px `C.border`, `R.md`; слева `Badge` «Лицо n» (`accent`; у строки с отказом — `neutral`), аватар 24, имя `FS.base` 600; справа `IconButton` ✕ 40×40 (мобила 44×44);
- активная строка — фон `C.accentLight`, рамка `C.accent`;
- строка с отказом — фон `C.dangerBg`, рамка `C.dangerBorder`, под именем причина `FS.xs` `C.dangerText`;
- строка активного неназначенного лица — бейдж `accent`, вместо имени «выберите персонажа» `C.textSecondary`, ✕ нет;
- пунктирный слот — 1px dashed `C.dashed`, без фона, `FS.sm` `C.textMuted`, не нажимается;
- порядок строк — по номеру лица; тап по строке = тап по рамке; hover (десктоп) — `C.bgSelected`; focus-visible — `SHADOW.focus`.

**Выбор персонажа:**
- рендерится, только пока есть активное лицо, и стоит **выше** списка назначений (на мобиле иначе уходит под подвал);
- отмечен персонаж, уже назначенный на активное лицо;
- занятый на другом лице: opacity .5, `aria-disabled="true"`, `cursor: not-allowed`, hover выключен, `title` «Уже на лице n»; строка — вторая строка под именем `FS.xs` `C.textMuted`, плитка — вместо «в контексте»; тап ничего не делает;
- выбор свободного персонажа: назначение создаётся или заменяется, активное лицо сбрасывается, к следующему лицу сами не переходим (Р1).

**Логика (чистая, в `faceSwapView.ts`, с тестами):**
- `assignments: Map<faceN, slug>` — максимум 2; `active: faceN | null`;
- тап по свободной рамке при 2 назначениях → `limit = n`, `active` не меняется, плашка лимита; плашку снимает любое изменение назначений или тап по назначенной рамке;
- тап по мелкой → как v1;
- тап по активной рамке ещё раз → `active = null`;
- `canSubmit = assignments.size ≥ 1 && нет отказа по текущему набору && исполнитель local`;
- отказ сервера (`faces_too_close`, `face_out_of_frame` с номером лица) хранится до любого изменения назначений; кнопка в плашке = снять назначение этого лица;
- 409 `faces_changed` → назначения и `active` сбрасываются;
- «Подставить» при 1 назначении — тот же контракт, `faces` из одного элемента.

**Подвал** (десктоп и мобила): `flex-wrap: wrap`, `justify-content: flex-end`, кнопка `flex: 1 1 140px`. При одном назначении чип и кнопка стоят в одну строку. При двух чип на 320 (и в боковой части 310) не помещается — переносится строкой выше, кнопка идёт на всю ширину. Проверено: на 320 без горизонтального переполнения.

**Карточки в ленте:**
- стадия: спиннер + «Проход k из 2 · лицо n» + `Button ghost xs` «Отменить»; под ними полоска из N отрезков высотой 4, `R.max`, зазор `SP.xs`: готовый — `C.success`, текущий — `C.accent`, впереди — `C.progressTrack`; `role="progressbar"`;
- строка результата: кружок 18 (`C.successBg`/`C.successText` с ✓ или `C.dangerBg`/`C.dangerText` с ✕), пара `FS.sm` 600, результат `FS.xs` `C.textMuted` (у ✗ — `C.dangerText`); строки переносятся;
- метки на картинке карточки (некликабельные, `aria-hidden`): «n ✓» / «n ✕» на левом верхнем углу bbox лица, высота 18, фон `C.mediaScrim`, обводка `C.onDark`; у ✗ — фон и обводка `C.danger`. Смысл несут строки результата, метки только показывают, где «лицо 2»;
- частичный результат: `Notice warning` + `Button ghostAccent sm` «Повторить для лица 2» (иконка `RotateCcw`) — открывает редактор ЭТОЙ версии в режиме «Подставить» с назначением «лицо 2 → Иван» (как его сопоставить — вопрос В2). Шапку карточки не трогаем;
- ни одного лица: обычный вид ошибки или отмены запуска, без новых элементов.

**Мобила:** раскладка как в v1 (холст сверху, ниже прокрутка, подвал прилипает). Зоны касания ≥ 44: рамки и номера (псевдоэлемент), ✕ назначения 44×44, плитки 72×84, кнопки в плашках и подвале, «Отменить» в карточке. Макет проверен скриптом: на 320 ни одной кнопки меньше 44 по стороне. Кнопки самой карточки и шапки редактора в макете тоже подняты до 44, но это общая правка компонентов, не этой задачи.
**Тёмная тема** — только токены; рамки, ярлыки и метки на фото одинаковы в обеих темах.

## Развилка для Андрея

**Р1. Что происходит после выбора персонажа для лица 1.**
- (а) **Остаёмся на месте** (в макете, рекомендую): лицо 1 назначено, активного лица нет, плашка «Можно назначить ещё одно лицо — или подставить сразу». Ничего не прыгает, одно лицо подставляется так же быстро, как на этапе 2.
- (б) Сразу активируем следующее свободное лицо: на один тап меньше в сценарии «двое», но на картинке с тремя людьми выбор лица программой почти всегда не тот, и одиночный сценарий получает лишнюю отмену.

## Открытые вопросы (Александру и Софье, не Андрею)

- **В1. Кисть при назначениях.** «Закрасить кистью» (лиц нет / мелкое лицо) — одиночный путь этапа 2. Предлагаю так: при нажатии с существующими назначениями показывать подтверждение «Кисть работает с одним лицом — назначения сбросятся», в первом срезе кисть и назначения не смешивать.
- **В2. «Повторить для лица 2».** Новая версия совпадает с базовой вне лица 1, но детекция пойдёт заново: номер лица может смениться. Предлагаю сопоставлять по bbox (как в вопросе 6 этапа 2); не сопоставилось — открыть режим с Иваном, выбранным заранее, без лица.
- **В3. Ярлык у нижнего края.** Лицо у нижнего края картинки — ярлык над рамкой? В первом срезе предлагаю не обрабатывать (лица у низа кадра редки), вернуться по живой проверке Веры.
- **В4. `count > 1` в строке контекста.** При двух лицах вариант один. Нужен ли `Badge neutral` «1 вариант» в подвале или достаточно тихо игнорировать? Предлагаю бейдж, только когда в контексте выбрано больше одного.

## Расхождения с v1

1. Одиночный выбор лица → назначения (выбор персонажа сразу закрепляется, активное лицо сбрасывается).
2. Выбор персонажа не показывается неактивным заранее, а появляется, только пока лицо активно, и стоит выше списка (в v1 — всегда виден, до выбора лица `opacity .5`).
3. Новые элементы: ярлык на рамке, список «Назначения», вид рамки «назначена», вид «лимит», серый занятый персонаж.
4. Отказ «близко» ведёт не к кисти, а к «Снять назначение с лица n»: кисть в мультирежиме — В1. Тексты отказов называют номер лица.
5. 409 `faces_changed` сбрасывает все назначения (в v1 сбрасывался выбор лица, персонаж оставался).
6. Подвал переносит чип строкой выше; кнопка тянется на всю ширину и на десктопе.
7. Зоны касания на мобиле подняты с 40 до 44 у новых кнопок (✕ назначения, кнопки плашек, кнопка запуска).
8. Подпись карточки — строка на каждое лицо с ✓/✗ и сходством вместо одной строки `{Имя} → лицо {n} · сходство`; стадия «Проход k из N» с полоской.
9. Варианты B и C v1 не рассматриваются: выбран A.
