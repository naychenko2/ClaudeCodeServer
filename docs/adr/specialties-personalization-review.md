# ADR: раздел «Специальности» — только настройки роли

**Статус:** принято 25.08.2026, применилось в волне 4 плана
«Персонализированные специальности». Согласовано с владельцем.
**Что заменяет:** черновик приёмки макета и продуктовая постановка к нему — оба
документа не вошли в репозиторий: первый был read-only черновиком, вторая —
продуктовой запиской, оба потеряли актуальность после отмены части требований.

## Контекст

В архитектурной приёмке макета раздела «Специальности» и продуктовой постановке к
нему планировался ряд расширений: словарь слоя для владельческих подписей роли,
эффективные подписи рядом с системными в ответе каталога, серверная валидация
длины пользовательского текста, отдельный фич-флаг под всё перечисленное.

## Решение

Отменяем персонализацию подписей роли: название и описание берутся из каталога
ровно в одном виде и не подменяются ни на каком слое. Персонализируются только
настройки роли:

- модели по уровням (сильная / средняя / слабая);
- пресеты секций промпта;
- типовые умения (правила привязок).

Состав каталога ролей тоже не настраивается: ровно 14 ролей, добавить или удалить
нельзя — на ключах ролей стоит оркестрация.

## Что НЕ делается

- Словарь слоя, в котором хранились бы владельческие подписи роли.
- Эффективные подписи рядом с системной в ответе `/api/specialties`.
- Серверная валидация длины пользовательского текста роли.
- Отдельный фич-флаг под это.

## Почему

Подпись роли — машинный контракт: на ключах стоит оркестрация (роутинг подзадач,
write-набор субагента, планирование команды, выбор по семейству исполнителя).
Владельческое имя добавляло бы расхождение между машинной подписью и
пользовательской без пользы для маршрутизации и становилось бы лишней точкой
инъекции в коде, который формирует промпты планировщика.

## Где живёт

- Поведение раздела для пользователя: `docs/architecture/features.md`, §Специальности.
- Каталог ролей: `SpecialtyCatalog.cs`.
- Слой настроек: `SpecialtySettingsLayer` и `SpecialtySettingsStore.cs`.
- API ролей: `SpecialtiesController.cs`.
- Фронтовый раздел: `frontend/src/features/personas/`.
- Промпт планировщика команды: `TeamPlanningService.cs` (машинный контракт — ключи).
- Срез «Кто работает по этой роли»: `frontend/src/features/specialties/specialRules/model.ts`.
