# Модель без поставщика: тексты ошибок и подсказка — продуктовая спека

**Статус:** тексты утверждены, берутся в код дословно.
**Смежные документы:** раздел целиком — [model-providers-rework.md](model-providers-rework.md)
(первая итерация) и [model-presets-and-tiers.md](model-presets-and-tiers.md) (вторая,
там же общее «Правило языка» интерфейса).
**Где применяется:** «Поставщики моделей» → выбор модели для места, слота, пресета.

---

## Что случилось и почему нужны тексты

На проде у одного из мест записалось значение `MiniMax-M3` — название модели без
пометки о том, каким способом её вызывать (у моделей прямого вызова она обязательна:
`direct:MiniMax-M3`). Продукт честно попытался вызвать модель обычным путём, тот её не
знал, и место всё время работало моделью по умолчанию. Настройка выглядела заданной и
при этом ничего не значила — тот же класс дефекта, из-за которого этот раздел уже
переделывали дважды: **настройка, не связанная с поведением**.

Проверка формата закрывает дыру технически. Задача текстов — чтобы человек, наткнувшись
на неё, за одну секунду понял: **что не так** (у модели не указан поставщик) и **что
делать** (выбрать её в списке, а не вписывать название).

**Правило языка соблюдено:** ни в одном тексте нет слов «маршрут», «префикс», `direct:`,
«валидация», «каталог». Человек видит: **модель**, **поставщик**, **список**.

---

## Что видит человек

Три ситуации, три текста.

1. **Пытается сохранить модель без поставщика** (значение пришло не из списка: старая
   настройка, перенос данных, правка через API) → ошибка в форме, настройка не
   сохраняется.
2. **Тот же случай, но ответ приходит из API** (внешний вызов, интеграция, лог) →
   сообщение в поле `error`, самодостаточное и без контекста экрана.
3. **Просто смотрит на поле выбора** → короткая подсказка, объясняющая, почему модель
   выбирается из списка.

Плюс четвёртый текст — на уже сохранённое негодное значение: пока его не переставили,
место должно **само сказать**, что оно не работает, а не изображать рабочую настройку.

## Тексты (дословно)

| Ключ | Место | Текст |
|---|---|---|
| `route.noProvider.form` | Форма выбора модели в «Поставщиках моделей», строка под полем после неудачного сохранения | «У этой модели не указан поставщик — непонятно, через кого её вызывать. Выберите модель в списке: поставщик подставится сам.» |
| `route.noProvider.api` | Ответ API, поле `error` (400) | «Модель «{model}» указана без поставщика — по одному названию непонятно, через кого её вызывать. Выберите её в списке раздела «Поставщики моделей».» |
| `route.pickerHint` | Постоянная подсказка под полем выбора модели | «Модель берётся из списка — вместе с названием запоминается поставщик, через которого она вызывается.» |
| `route.brokenValue` | Уже сохранённое значение без поставщика, в самом месте выбора | «{model} — сохранено без поставщика и не работает: пока идёт модель по умолчанию. Выберите модель заново.» |
| `route.unknownModel` | Ответ API (400) и форма, когда такой модели нет вовсе | «Модель «{model}» не найдена среди доступных. Выберите её в списке раздела «Поставщики моделей».» |

**Подстановка.** `{model}` — значение ровно в том виде, в каком его прислали, в
кавычках-ёлочках внутри текста API (`«MiniMax-M3»`) и без кавычек в `route.brokenValue`
(там оно и так стоит отдельным значением). Ничего не обрезаем и не «чиним» в тексте:
человек должен узнать в сообщении то, что у него записано.

**Разделение `noProvider` и `unknownModel`.** Первое — когда модель с таким названием
существует, но записана без поставщика (случай с прода). Второе — когда такой модели нет
совсем (опечатка). Один общий текст здесь не годится: в первом случае человек уверен, что
модель есть, — и сообщение «не найдена» выглядит враньём, после которого он идёт искать
проблему не там. `route.unknownModel` заменяет прежнее «Модель «…» отсутствует в
каталоге»: слово «каталог» человеку ничего не говорит.

---

## Наблюдаемое поведение

- Ни одна модель не сохраняется без поставщика: попытка заканчивается текстом
  `route.noProvider.form`, а прежнее значение места остаётся нетронутым.
- Выбор модели из списка не может привести к этой ошибке вовсе — поставщик подставляется
  вместе с названием.
- Уже сохранённое негодное значение видно как негодное (`route.brokenValue`), а не как
  обычная настройка; место при этом продолжает работать моделью по умолчанию — ни один
  фоновый вызов из-за этого не падает.
- Тексты одинаковы в форме и в ответе API по смыслу и по совету: «выберите в списке».
  Человек не должен получать два разных объяснения одной причины.

---

## Что проверяет приёмка

1. Сохранение названия модели без поставщика → отказ с текстом `route.noProvider.form`,
   значение места не изменилось.
2. Тот же вызов через API → в `error` лежит `route.noProvider.api` с подставленным
   названием.
3. Несуществующая модель → `route.unknownModel`, а не текст про поставщика.
4. Место с уже сохранённым негодным значением показывает `route.brokenValue` и продолжает
   работать моделью по умолчанию.
5. В текстах на экране нет слов «маршрут», «префикс», `direct:`, «каталог».

---

## В «Что нового» не идёт

Это починка дефекта, а не новая возможность: пользователь не получает ничего, о чём стоит
объявлять, — он получает обратно то, что и так считал работающим. Публиковать такое в
ленте значит рассказать людям, что настройка молча не работала, и ничего им не дать
взамен. Тем, у кого значение реально было испорчено, его чинят при выкатке (отдельная
часть плана), и место после этого просто работает.
