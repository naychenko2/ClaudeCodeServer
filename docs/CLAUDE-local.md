# ClaudeHomeServer — краткая карта для локальной модели

**Отвечай по-русски.** Весь текст, который видит человек — рассуждения по ходу
работы, отчёты, сообщения коммитов — на русском. Английский только внутри кода:
имена, ключевые слова, вывод команд. Чем дальше ход, тем больше английского
вокруг тебя: код, логи сборки, вывод команд. Соскользнуть вслед за ними легко —
следи за собой до последнего ответа.

Полная карта проекта — корневой `CLAUDE.md` и `docs/architecture/`,
`docs/features/`, `docs/adr/`.

## Чем ты работаешь

**Есть:** `Bash`, `Read`, `Edit`, `Write`, `Glob`, `Grep`, `Task` (только субагент `scout`, см. ниже).
**Нет:** `PowerShell`, `TodoWrite`, `WebSearch`, `WebFetch`.

`Edit` работает ТОЛЬКО после `Read` этого же файла в этом ходе, `old_string` должен
совпадать посимвольно с отступами. Офисные файлы и PDF → markdown: `markitdown файл > файл.md`.

**Рабочий каталог — корень проекта чата.** Файл за его пределами открывай по
полному абсолютному пути, не по относительному.

**Сначала ищи, потом читай.** Веерное чтение — двадцать `Read` подряд «чтобы
разобраться» — съедает окно и вытесняет из него саму задачу. Порядок:
`Grep`/`codegraph` находит места → `Read` открывает найденное точечно.
Поиск по коду: `codegraph_find` (где объявлен тип), `codegraph_neighbors`
(кто зависит), `codegraph_hubs` (с чего начать). Текст и конфиги — `Grep`.

**Картинки — максимум 3 за чат.** `Read` картинки остаётся в разговоре навсегда и
едет в каждом ходе; четвёртая обрывает чат намертво, без починки изнутри.
Открывай только когда без неё не ответить, не повторно.

**Независимое — одним шагом.** Независимые поиски/чтения — в ОДНОМ ответе
несколькими вызовами: лишний шаг — отдельный круг модели. Место файла читай
с запасом (100–200 строк), не кусками по 20–30.

**Разведку по коду отдавай субагенту `scout`** (`Task`, `subagent_type: "scout"`):
ищет по репозиторию, возвращает `файл:строка` с пояснениями. Его чтение НЕ попадает
в твоё окно, а окно решает скорость: после 100 тыс. токенов она падает на треть. Правила:
- «Где объявлен X», «кто зовёт Y» — в `scout`, а не двадцать `Read`. Можно ДВУХ
  за раз на независимые вопросы; больше двух — нельзя, делят одну видеокарту.
- Вопрос формулируй самодостаточно: разведчик не видит твою задачу и переписку.
- Ответ разведчика — НЕ доказательство. Прежде чем опереться на него в правке или написать
  утверждение в код, открой названные строки `Read`-ом сам. Строка без ссылки `файл:строка`
  не принимается вовсе.
- Правки, команды и решения — только твои: у разведчика нет `Edit`, `Write` и `Bash`.
- **Своя работа кончилась, а ответа разведчика нет — не жди Bash-циклом** (`sleep`,
  повторное чтение лога). Заверши ход: ответ вернётся сам отдельным сообщением, опрос
  его не ускоряет, а жжёт ход впустую (было — 15 минут в таком цикле на живой задаче).

**Риск потери чужой работы — не решай сам, спроси.** Untracked-файл или чужие правки
на пути удаления/перезаписи — останови и опиши риск: не твоё решение.

**Фича «закрепить/сохранить/пометить» — по умолчанию персистентна**, переживает
рестарт процесса, если не сказано иначе явно.

Если инструмента нет и обходного пути тоже — скажи прямо, не имитируй результат.

## Команды

```bash
dotnet build backend/ClaudeHomeServer -m:4
dotnet test backend/ClaudeHomeServer.Tests -m:4 --filter "FullyQualifiedName~ИмяНабора" > /tmp/t.log 2>&1; echo "exit=$?"; grep -E "Пройден!|Не пройден!|error" /tmp/t.log | tail -5
cd frontend && npx tsc -b && npx vitest run src/путь/к/файлу.test.ts
```

**`dotnet test` — всегда с путём к ОДНОМУ тестовому проекту** (`backend/<Проект>.Tests`).
Без пути, из `backend/`, он собирает и гоняет ВСЕ тестовые проекты решения:
фильтр тут не спасает, прогон растягивается на 10–20 минут и может упасть
сбоем CLR. Имя тестового проекта выводится из имени вертикали:
`ClaudeHomeServer.X` → `ClaudeHomeServer.X.Tests`. Список вертикалей —
`ls -d backend/ClaudeHomeServer.*`, а не по памяти.

**Не прячь код возврата.** `команда | tail` возвращает код `tail`, то есть 0, —
упавший прогон выглядит успешным. Пиши вывод в файл, печатай `exit=$?`, потом
`grep`/`tail` по файлу.

**Собирай один раз, тесты — от готовой сборки.** `dotnet test` без `--no-build`
пересобирает перед каждым прогоном (минуты на холодном дереве). Порядок: одна
`dotnet build <проект> -m:4` → все `dotnet test … --no-build --filter …` от неё.

**Перед сдачей — одна связка, не только точечные фильтры.** Точечный фильтр
экономит время по ходу, но прячет дефекты совместного прогона (общее состояние,
гонки). Финал — один прогон со ВСЕМИ затронутыми наборами. Упало в связке, по
одному зелено — находка, не помеха: ищи общее состояние, не перезапускай до зелёного.
Связка — ЗАТРОНУТЫЕ наборы, не весь проект: прогон «заодно всего» жжёт окно и время.

**Жди прогон, а не опрашивай.** Сборку и тесты запускай обычной командой, не в
фоне: она сама вернётся с результатом. Циклы `sleep N; tail файл` тратят минуты впустую.

CI гоняет тесты на Linux (`ubuntu-latest`), разработка на Windows — тесты
обязаны быть платформонезависимыми: пути через `Path.GetTempPath()` +
`Path.Combine`, тайминги через `TaskCompletionSource` + `Task.WhenAny`,
а не `Task.Delay`.

## Архитектура

Браузер (React 18 + TypeScript) → SignalR WebSocket → ASP.NET Core 10
(:5000). Слои бэкенда: `Controllers/`, `Hubs/SessionHub`, `Services/`
(в т.ч. `Llm/`), `Protocol/ServerMessage`. Фронт: `pages/`,
`components/`, `hooks/`, `lib/` (`api.ts`, `signalr.ts`, `design.ts`),
`types/`. Хранилище: `data/projects.json`, `data/sessions.json`,
`data/sessions/{claudeSessionId}/history.json`; resume через `--resume`.

Подсистемы (`IAppSubsystem`, `Core`) изолируют вертикали; границы держит
`SubsystemBoundaryTests` (рефлексия по сборке, default-deny + allow-list
в `Boundaries`) и `SubsystemBoundaryCoverageTests` (каждая реализация
должна быть в таблице). Вертикаль зависит только от спины
(`Microsoft.*`, `Models`, `Services.Http`/`Composition`/`Mcp`) и явных
швов — не от другой вертикали напрямую.

## Инварианты

- `FileService.SafeJoin` — все пути через неё, иначе pathtraversal.
- Per-owner: токен подписки доставляется в песочницу per-exec, а не
  запекается при создании контейнера; OAuth-логин CLI живёт в профилях
  `data/claude-profiles/{key}`; env хода вычищается от `ANTHROPIC_*`,
  `CLAUDE_CONFIG_DIR` (`ProviderEnvKeys` → `ClearEnv`).
- Состав `tools/list` НЕ зависит от хода (входит в сигнатуру запуска CLI),
  МОЖЕТ зависеть от свойств сессии. Сторож: `McpToolsetStabilityTests`.
- `UpdatedAt` не двигают ни настройки чата, ни архивация (признак архива
  производный: `IsArchived = ArchivedAt != null && UpdatedAt <= ArchivedAt`).
- Новое хранилище → сверься с бэкапом: всё в `data/` попадает в архив по
  умолчанию; критичный стор — в `BackupValidation.Validate`; ломающее
  изменение формата = инкремент `BackupSchema.Version`.
- Дизайн-система — токены `C.*` из `lib/design.ts`; сырой hex в `.tsx` —
  дефект; гейт перед коммитом `cd frontend; npm run lint:design`.
- Остальные инварианты — в корневом `CLAUDE.md`. Задача про слой LLM-провайдеров
  (`ClaudeHomeServer.Llm`: сессия CLI, фолбэк, слоты моделей) — сначала прочитай
  `docs/architecture/llm-providers.md`; про песочницу — `docs/architecture/sandbox.md`.

## Соглашения

- **Русский язык** во всём, что видит человек, включая комментарии в коде.
- Conventional Commits по-русски: `тип(область): описание`, повелительное
  наклонение, с маленькой буквы, без точки. Один коммит — одно изменение.
- Трейлер `Co-Authored-By: <модель> <noreply@…>` обязателен; домен
  по вендору (anthropic → `@anthropic.com`, z.ai → `@z.ai`).
- **Потолок: одна Bash-команда ≤ 5 000 символов.** Длинная команда приходит
  в bash обрезанной и падает с `unexpected EOF` — ошибка выглядит
  синтаксической, но дело в длине.

## Как вести изменение

**1. Трасса данных — обычным текстом, до правки.** Скрытые размышления коротко
обрезаются — длинная мысль там не поместится. Перед правкой, которая пишет
данные/меняет поведение, выпиши В ОТВЕТЕ трассу: вход → где копится → в каком
ПОРЯДКЕ сливается в хранилище → как читается обратно. Каждое звено —
`файл:строка`. Не нашёл — ищи дальше, не додумывай.

**2. Чек-лист перед коммитом** — пройди по пунктам, отметь каждый в ответе:
- перечитал свой `git diff` целиком;
- каждая новая запись в коллекцию/файл: где окажется ПОСЛЕ всего цикла — рядом
  с чем и в каком порядке;
- каждое утверждение в комментарии («только», «единственный», «никогда»,
  «всегда») подтверждено `файл:строка`, иначе удалено;
- тест проверяет конечное состояние после полного цикла, а не сразу после вызова;
- сборка и тесты реально прогнаны, цифры в итоге — из их вывода.

**3. Критерий выполнен и проверен — останавливайся.** Соседние улучшения, чужие
вертикали, документация «заодно» — вне задачи: жгут окно и лезут в чужую работу.
Заметил рядом дефект — назови в отчёте, не чини.

**4. Отчёт — доказательства, а не пересказ.** Каждый диагноз и каждое «почему»
в итоге задачи — со ссылкой на `файл:строка` или вывод команды. Не проверил —
так и напиши.

**5. Прошлое решение — чужой код.** Нашёл через память или git прошлое решение
этой же задачи — не переноси его, а проверь по чек-листу, как код, написанный
другим: в нём могут быть дефекты.

Нет проверки = не готово.
