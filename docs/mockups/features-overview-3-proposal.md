## Сценарий и проблема

Андрей открывает страницу фичи в двух случаях: **«что там и нужен ли я»** (каждый день, по плашке со статусом
«ждёт вас») и **«чем кончилось и во что обошлось»** (после мержа). Сейчас на странице после быстрого трека
остался один конвейер. Из волны 2 ждут возврата тревога, шаги и витки, чаты, задачи, лента и `⋯`, а идеи
волны 3 добавляют остановку и запуск, очередь, роль исполнителя, чип модели, состояние «мерж ждёт согласия» и
метрики. Если всё это вывалить списком, страница превратится в свалку. Варианты ниже отличаются тем, **что
видно первым** и **где живут действия**.

Оболочка у всех трёх одна, как сейчас в коде: страница открывается как файл (`CenterViewShell`, шапка `Toolbar`,
фон `C.bgCard`, «Закрыть» слева, остров на десктопе, `BackButton` «К списку» на 360, `Esc` закрывает).
Различается только тело.

## Варианты

### А · Паспорт (документ)
Одна колонка шириной до 760, читается сверху вниз как документ:
мета-строка (ветка, возраст, задачи, место в очереди) → полоса метрик («идёт 1 дн 6 ч · работа 3 ч 20 мин · токенов
2,1М · ждёт вас 40 мин · ошибок 2 · возвратов 3») → блок тревоги с действием → **липкая навигация по разделам**
(Конвейер · Очередь · Шаги · Чаты · Задачи · События · Метрики, подсветка при прокрутке) → разделы по порядку.
Главное действие и «Остановить» стоят в шапке, остальное в `⋯`. «Итоги фичи» после мержа встают над тревогой.
- **Плюсы:** одна раскладка на 1280 и 360 (на 360 полоса метрик сжимается до сетки 2×2); ближе всех к
  «странице как файлу»; меньше всего кода для Киры: те же блоки, что в волне 2, плюс навигация.
- **Минусы:** страница длинная. До метрик и событий доходят прокруткой или через навигацию.

### Б · Пульт (панель управления)
Две колонки. Слева вкладки «Обзор / Чаты N / Задачи N / События / Метрики». Обзор: тревога, горизонтальный
конвейер с ролями, шаги, последние события. Справа колонка 280: **«Управление»** (статус и все действия
кнопками во всю ширину), **«Метрики»** 2×2 с «Дороже всего», **«Очередь»** с перестановкой, **«Команда»**
(персоны с ролями). На 360 «Управление» и «Метрики» встают над вкладками, очередь уходит вниз «Обзора».
- **Плюсы:** действия и цифры видны всегда, при любой вкладке; очередь под рукой. Удобно, если на странице
  в основном управляют.
- **Минусы:** две раскладки, десктопная и мобильная, это двойная работа и двойная приёмка. Колонка 280 сжимает
  основную часть до ~580 px. Вкладки прячут чаты и задачи на клик глубже. В шапке действий нет (они справа),
  и это расходится с файлом.

### В · Хронология
Сверху **лента этапов**: ширина сегмента равна времени этапа, текущий сегмент выделен тоном статуса, клик ведёт
к этапу. Ниже вертикальная хронология, этап за этапом. **Внутри каждого этапа его шаги и витки, его чаты
карточками (с чипом модели) и его события.** Тревога стоит в том этапе, где случилась («Производство: Кира
ждёт ответа»). Метрики в конце, задачи и полный список чатов под хронологией.
- **Плюсы:** лучше всех отвечает на вопрос «где застряли и сколько это длилось». Лента этапов сама по себе
  уже метрика «время по этапам». События привязаны к контексту.
- **Минусы:** нужен **журнал событий**, иначе ширины этапов и привязка событий к этапам приблизительны (лента
  волны 2 видит только последнюю пару старт/стоп). Чаты и задачи раскиданы по этапам, общий список дублирует их.
  На 360 короткие этапы ленты сжимаются до буквы.

## Рекомендация Майи

**Вариант А за основу, из В взять ленту «время по этапам» внутрь раздела «Метрики»** (так в макете уже сделано).
Почему:
1. Страница по решению Андрея открывается **как файл**, а файл читают сверху вниз. Документ из одной колонки здесь
   естественнее пульта с боковой колонкой.
2. **Одна раскладка** на десктоп и 360. Кира работает с узким окном, а Вера проверяет один путь, а не два.
3. Действия там же, где у файла: главное в шапке, редкое в `⋯`, контекстное в блоке тревоги. Отдельная колонка
   «Управление» нужна, только если на странице правда часто управляют, а по сценарию её чаще читают.
4. В можно сделать позже, когда появится журнал. Сегодня его ширины были бы неправдой.

Если Андрей хочет, чтобы цифры не уезжали при прокрутке, есть компромисс: в А сделать полосу метрик липкой вместе с
навигацией (плюс 40 px высоты, бэк не нужен).

## Поведение окна (запрос Андрея №2)

В макете слева рельса (Чаты, Файлы, Задачи, Заметки) и панель «Чаты» с плашкой фичи. Что можно нажать:
- **клик по чату** в панели, в разделе «Чаты фичи» или по «Ответить Кире»: страница **скрывается**, в центре
  открывается чат, выделение уходит с плашки на чат;
- **кнопка другого окна на рельсе** («Задачи», «Заметки», «Файлы» → файл) открывает это окно, страница скрывается;
- **клик по плашке** или по чипу фичи в шапке чата возвращает страницу с тем же состоянием (раскрытые шаги,
  прокрутка, вкладка в Б). Страница скрыта, а не закрыта;
- **«Закрыть» / Esc** закрывает страницу: на десктопе в центре «Выберите чат», на 360 возврат к списку.

На 360 страница занимает весь экран: «К списку» ведёт в список, из списка открываются чат или плашка.
Это поведение Кира делает в коде отдельно, макет служит ей ориентиром.

## Цена: что нужно от бэка

Метки в макете: **проекция** (синяя, дёшево: новое поле в `GET features/{id}` из уже лежащих данных),
**API** (жёлтая: новая ручка-действие без нового хранения), **хранилище** (красная: новое persistent-поле или
журнал, **только по «да» Андрея**).

| Элемент | Проекция | API | Хранилище | Комментарий |
|---|:-:|:-:|:-:|---|
| «Мерж ждёт согласия» (состояние, тег, этап) | ✓ | | | вывод в `FeatureProjector`, фронт не пересчитывает |
| Роль исполнителя везде | ✓ | | | `role`/`lane` задачи и специальность персоны |
| Чип модели на фото | ✓ | | | модель сессии в `FeatureChat`; карта «модель → короткая подпись» |
| Архивные чаты фичи | ✓ | | | техдолг п. 17, 18, 28 |
| Метрики времени, возвратов, ошибок (приближённо) | ✓ | | | из полей задач и классификатора ошибок; только по последнему состоянию |
| Перезапустить шаг со страницы | | ✓ | | обёртка над запуском исполнителя |
| Закрыть без мержа / Вернуть в работу | | ✓ | | вторая очередь волны 2 |
| Остановить / Запустить, «на паузе» | | ✓ | ✓ | флаг паузы у фичи и задач, след в ленте, fail-closed, только владелец |
| Очередь фич: позиция, порядок, автозапуск | | ✓ | ✓ | хранимый порядок; уведомление «запущена из очереди» |
| Уступка очереди при ожидании мержа | | | ✓ | часть очереди |
| Токены по фиче, «Сейчас дороже всего» | | | ✓ | ключ `featureId` в учёте хода |
| Точные ожидание и простой, «время по этапам», события остановок | | | ✓ | журнал событий (append-only) |

**Что сделать без «да» Андрея:** все строки с одной проекцией: «мерж ждёт согласия», роли, чип модели, архив,

пока остаются в макете за меткой.

## Вопросы к Андрею

1. **Какой вариант?** Я рекомендую А с лентой этапов из В внутри «Метрик». Б выбирать, если на странице
   чаще управляют, чем читают.
2. **Остановка по умолчанию:** «дождаться конца хода» (так в макете) или «прервать сразу»? И трогать ли чаты, где
   пишете вы сами (сейчас не трогаем)?
3. **Очередь:** одна на проект или на владельца? Сколько фич можно вести параллельно (в макете одна, «Запустить
   сейчас» явно идёт параллельно)? Блокирует ли очередь фича, которая ждёт вас по вопросу, а не по мержу?
4. **Метрики:** что нужно первым, время и ожидание (дёшево, проекция) или токены (нужна привязка расхода к фиче,
   это хранилище)? Показывать только токены или ещё деньги?
5. **Чип модели при «Авто»:** писать «Авто» (так в макете, полная модель в подсказке) или реальную модель хода?
6. **Журнал событий:** заводим (тогда В и точные простои становятся честными) или пока живём на проекции?

## Что не вошло

Плашка в списке и рельса в плане хода в макете показаны только для сценария окна. Их правки под «ждёт согласия
на мерж» описаны в таблице токенов (раздел 7) и делаются тем же шагом, что и состояние в проекторе.
Перестановку очереди на 360 даю кнопками ↑/↓ (40×40), без перетаскивания: на таче его легко спутать с прокруткой.
