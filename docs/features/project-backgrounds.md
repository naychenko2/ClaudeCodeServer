# Свой фон у каждого проекта — тексты интерфейса, «Что нового», критерии снятия флага

**Статус:** согласовано владельцем 2026-08-11, реализация идёт волнами.
**Источник правды:** продуктовая постановка «Свой фон у каждого проекта — генерация по
смыслу проекта» (задача трекера `515b8bba-c803-4ec3-989e-797a4bd50b50`). Все тексты ниже
перенесены из неё **дословно**.
**Фич-флаг:** `project-backgrounds`, по умолчанию выключен.

**Как пользоваться этой страницей.** Это единственный источник правды по формулировкам
для фронтенда, бэкенда и QA: строки в UI, тексты уведомлений и ожидаемые значения в
тестах берутся отсюда, а не сочиняются на месте. Правка любой формулировки = правка
продуктовой постановки, а не этого файла в одиночку.

**Польза одной фразой** (из постановки):

> фон подсказывает, в каком проекте ты находишься, раньше, чем ты прочитаешь название, —
> и продукт перестаёт выглядеть айтишным инструментом для тех, кто в нём не про код.

## 1. Тексты интерфейса

### 1.1. Настройки проекта, раздел «Оформление»

Дословно из постановки:

- Заголовок: **Фон рабочего пространства**
- Пояснение: «Рисунок и цвет подобраны по смыслу проекта. Фон еле заметен и не мешает работе».
- Действия: `Сгенерировать заново` · `Вернуть стандартный`
- Состояние генерации: «Рисуем фон под этот проект — обычно занимает несколько секунд».
- Если генерация не удалась: «Не получилось нарисовать фон — оставили стандартный. Можно попробовать ещё раз».
- Если цвет проекта был выбран руками, а генерация предлагает другой: цвет иконки не перезаписываем молча — предупредить в диалоге: «Цвет проекта изменится на \<название\>. Оставить прежний?»

### 1.2. Сводка строк для реализации

| Где | Что показываем | Точный текст |
|---|---|---|
| Заголовок раздела | всегда | Фон рабочего пространства |
| Пояснение под заголовком | всегда | Рисунок и цвет подобраны по смыслу проекта. Фон еле заметен и не мешает работе. |
| Кнопка | всегда | Сгенерировать заново |
| Кнопка | всегда | Вернуть стандартный |
| Состояние | идёт генерация | Рисуем фон под этот проект — обычно занимает несколько секунд. |
| Ошибка | генерация не удалась | Не получилось нарисовать фон — оставили стандартный. Можно попробовать ещё раз. |
| Диалог | генерация предлагает цвет, отличный от выбранного руками | Цвет проекта изменится на \<название\>. Оставить прежний? |

Две пометки к таблице — это **уточнения продакта, а не цитаты**:

- В постановке пояснение, состояние генерации и текст ошибки заключены в кавычки-«ёлочки»,
  а точка стоит за закрывающей кавычкой. В интерфейсе эти три строки показываем **с точкой
  в конце** — это законченные предложения. Сомнение снимается здесь, чтобы фронтенд и QA
  не разошлись на пустом месте.
- `<название>` в тексте предупреждения — подстановка названия цвета из палитры
  `AGENT_COLORS`, а не литерал.

### 1.3. Подпись строки каталога моделей

Дословно из постановки (раздел «Решённые развилки»):

> **Чем генерируем:** отдельная строка в `LocalActionCatalog` («Фон проекта»), исполнителя
> выбирает админ в диалоге «Поставщики моделей». Дефолт — **сильный слот**: рисование SVG
> не текстовая задача, дешёвая модель даёт кашу из линий.

Подпись строки в диалоге «Поставщики моделей», уровень 3 «Кто что выполняет»: **Фон проекта**.

## 2. «Что нового»

Пункт целиком, дословно:

> **У каждого проекта теперь свой фон.** Рисунок и цвет подбираются по смыслу самого
> проекта: финансы, поездки, учёба и код больше не выглядят одинаково, а фон совпадает по
> цвету с иконкой проекта. Не понравился — «Сгенерировать заново» или «Вернуть
> стандартный» в настройках проекта.

---

## 3. Фич-флаг и критерии снятия

Дословно из постановки:

> `project-backgrounds`, по умолчанию выключен. Снимаем, когда:
> - фоны сгенерированы для всех существующих проектов владельца и ни один не выглядит браком;
> - отработали обе кнопки — «Сгенерировать заново» и «Вернуть стандартный»;
> - проверена тёмная тема (цвет проекта на тёмном не тяжелит экран);
> - фон в чате проверен на длинной переписке — не мешает читать;
> - цвет, выбранный пользователем руками, не перезаписан без предупреждения;
> - участник проекта, не являющийся владельцем, фон менять не может.

Последние два пункта — одновременно и требования к поведению, не только к проверке:
молчаливая перезапись выбранного руками цвета и доступ к смене фона у не-владельца
считаются дефектами, а не недоделками приёмки.

## 4. Что ещё зафиксировано постановкой (кратко, без пересказа решений)

Эти пункты нужны, чтобы тексты выше читались в контексте; полные формулировки —
в постановке.

- Фон виден **везде внутри проекта**, включая рабочее пространство чата.
- Генерация — **один раз при создании проекта**, в фоне; пока не готово — стандартный фон.
  Результат сохраняется в проекте.
- «Сгенерировать заново» и «Вернуть стандартный» доступны **владельцу проекта**.
- Существующим проектам фоны генерируются разом при включении флага.
- Цвет из генерации принимается **только как ключ палитры** `AGENT_COLORS`
  (yellow/orange/blue/green/purple/red/brown/cyan/pink), не как произвольный hex.
- Открытый вопрос к архитектору из постановки: SVG уезжает в CSS `mask-image` через
  `data:`, принимать только белый список тегов и атрибутов.
