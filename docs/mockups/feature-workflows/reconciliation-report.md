Бэкенд не открывался: для сверки UI он не нужен, подтверждено только существование `backend/ClaudeHomeServer.Tasks/StageScreenService.cs`; поля ответа брал из `frontend/src/types/featureRun.ts` и `featureStage.ts`.

Принятые правила классификации:
- **Ф** — нет механики, экрана, состояния или перехода, либо ведёт себя иначе; сюда же отнесено, если элемент несёт данные или состояние, которых нигде на экране нет.
- **В** — компоновка, порядок, текст, размеры, пустое состояние; данные при этом где-то показаны.
- «—» — расхождения нет. Поле `Есть?`: да / частично / НЕТ.
- Макет — прототип с пультом (тема, ширина, вариант A/B, состояние); пульт в продукт не входит и в сверку не берётся. Тёмную тему и токены не сверял (цвета в коде идут через `C.*`, это конвенция проекта).

Сокращения путей: `FPage` = `FeaturePage.tsx`, `FHeader` = `FeaturePageHeader.tsx`, `FGraph` = `FeatureProcessGraph.tsx`, `FArea` = `FeatureStageArea.tsx`, `FScreen` = `FeatureStageScreen.tsx`, `FConfirm` = `FeatureWorkflowConfirm.tsx`, `FFirst` = `FeatureFirstScreen.tsx` (все в `frontend/src/components/feature/`).
