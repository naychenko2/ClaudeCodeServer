# «Фото персонажа» в карточке результата — спецификация для реализации

Макет: [character-smart-photos.html](character-smart-photos.html) (переключатели темы, ширины 320 px, пяти видов блока и трёх состояний окна).
Контракт: [ADR-027](../adr/ADR-027-character-smart-photos.md) §7–8. Тексты: заметка «Умный подбор фото — тексты».
Метки у фото в форме персонажа здесь не рисуются: они в `character-panel-final-spec.md` §8.1.2 (ветка `design/character-panel`).

## Проблема → решение

Человек попросил «Андрей смеётся у окна, в профиль», получил картинку и не понимает, почему лицо не похоже: какие фото персонажа ушли модели, не видно. Решение: под картинкой в карточке версии стоит тихий блок «Фото персонажа». В нём миниатюры взятых фото, пометка, как они выбраны, и кнопка «Заменить». Она открывает окно выбора, и новый запуск идёт с явным списком. Исходная версия остаётся.

## 1. Где и когда показывать

- Файл: `frontend/src/features/imageEditor/thread/VersionCards.tsx`, компонент `VersionCard`.
- Место: **между строкой подписи (`meta`) и рядом кнопок** («Открыть», «Сохранить в проект»…).
- Блок есть, только если выполнены **все** условия:
  1. флаг `character-smart-photos` включён (`useFeature(FLAGS.characterSmartPhotos)`);
  2. у запуска версии есть персонаж: `launchOf(thread, version.jobId)?.character` не `null`;
  3. это не обрезка без ИИ (`cropNote == null`) и не исходник (`version.id !== ORIGIN`).
- Иначе блока нет вовсе: пустую плашку не рисуем. Старые нити с `character = null` выглядят как сейчас.
- Пока запуск рисуется (карточка «Рисуем…»), блока нет: он появляется вместе с версией.
- У каждого варианта одного запуска блок одинаковый, потому что фото общие на запуск. Рисуем его в каждой карточке: карточки сворачиваются по одной.

## 2. Данные

Тип для `threadsApi.ts` (зеркало ADR-027 §8):

```ts
export interface ImageThreadCharacter {
  slug: string;
  photos: string[];          // имена файлов манифеста в порядке отправки, до 3
  pick: 'auto' | 'manual' | 'fallback';
  scene: { angle: string | null; pitch: string | null; emotion: string | null } | null;
}
// ImageThreadLaunch: + character?: ImageThreadCharacter | null
```

Миниатюры и метки берутся из карточки персонажа (`slug`): там есть имя, список фото с URL и метками. Окно сначала читает её свежей: человек мог удалить фото после запуска.

## 3. Компонент `CharacterPhotosStrip` (новый, рядом с `VersionCards.tsx`)

Props: `{ projectId, sessionId, thread, version, character: ImageThreadCharacter }`.

### 3.1 Пометка

| `pick` | Badge | Иконка lucide | Текст | `title` |
|---|---|---|---|---|
| `auto` | `tone="info"` | `Sparkles` | Подобраны под сюжет | — |
| `manual` | `tone="neutral"` | `Hand` | Выбраны вами | — |
| `fallback` | `tone="neutral"` | `ListOrdered` | Обычный порядок | Подходящих под сюжет фото не нашлось — взяты по порядку, главное первым |

Оранжевый тон (`accent`) здесь **не брать**: в шапке карточки он уже занят бейджем «В работе».

**Строка сюжета** — «Под сюжет: {признаки}». Признаки через запятую в порядке «ракурс, наклон, эмоция», пропуская `null`. Словарь (строчными):

| поле | значение → текст |
|---|---|
| angle | `front` → анфас, `three-quarter` → вполоборота, `profile` → в профиль |
| pitch | `up` → сверху, `down` → снизу, `level` → **не выводим** (ничего не говорит человеку) |
| emotion | `neutral` → спокойное, `smile` → улыбка, `laugh` → смех, `serious` → серьёзное, `sad` → грустное, `surprised` → удивление |

Пример: `{profile, level, laugh}` → «Под сюжет: в профиль, смех». Если после пропусков признаков не осталось, строки нет.

### 3.2 Миниатюра

- `span` (не кнопка, **не нажимается**): `width/height: 40` (константа `THUMB = 40` в файле, как `PREVIEW_RATIO`), `flexShrink: 0`, `borderRadius: R.md`, `border: 1px solid C.borderLight`, `background: C.bgCard`, `overflow: hidden`.
- `img`: `objectFit: 'cover'`, `alt=""`, `title` — подпись меток фото («В профиль · смех», та же функция `labels.caption`, что в панели персонажа). Меток нет — `title` = «Фото N».
- **Фото больше нет у персонажа** (имени нет в манифесте или `onError` у картинки): вместо `img` — иконка `ImageOff` `ICON_SIZE.sm` цвета `C.textMuted` по центру, `title` = «Этого фото больше нет у персонажа». Остальной блок не меняется.
- Загрузка карточки персонажа ещё идёт: миниатюры — заглушки `className="cc-skel"` того же размера.
- Карточку персонажа не удалось загрузить или персонаж удалён: миниатюр нет, вместо строки 3 — `FS.xs` `C.textMuted` «Персонажа больше нет в проекте»; «Заменить» нет.

### 3.3 «Заменить»

- Есть, если у персонажа **2 фото и больше** (по свежей карточке).
- Нажатие открывает `CharacterPhotosPicker` (§4). `disabled`, пока открыт сам пикер или идёт запуск из него.
- Клик по кнопке не должен выбирать карточку: это уже так, у `Shell` есть `isCardPick`.

### 3.4 Empty-state: у персонажа одно фото

- Пометки нет: при одном фото она ничего не говорит. «Заменить» нет. Миниатюра одна.
- Строка 4: flex, `gap: SP.xs`, `alignItems: 'flex-start'`; иконка `ImagePlus` `ICON_SIZE.xs` `C.textMuted` (`marginTop: 1`); текст `FS.xs` `C.textMuted` `lineHeight: 1.4`:
  **«Добавьте фото в разных ракурсах — AI Home будет подбирать подходящее под сюжет.»**

## 4. Окно `CharacterPhotosPicker` (новый)

`Modal width={MODAL_W.form}` (440). На мобиле сам `Modal` превращается в шторку снизу, и ничего дополнительно делать не надо.

- `title` — **«Какие фото взять»**.
- `subtitle` — **«Первое фото важнее остальных. Локальная модель берёт только одно.»**
- `footer` — `ModalActions`: `cancelLabel="Отмена"`, `confirmLabel="Перерисовать"`, `confirmDisabled={order.length === 0}`, `loading` во время запуска.

### 4.1 Тело (колонка, `gap: SP.sm`)

1. *(только при ошибке)* `Notice tone="danger" icon={AlertTriangle}` (§4.4).
2. **Счётчик** — flex, `alignItems: center`, `minHeight: 24`: «Выбрано {n} из 3» `FS.sm` `C.textSecondary`; справа (`marginLeft: auto`) `Button variant="ghost" size="xs"` «Сбросить выбор» — только при `n > 0`.
3. **Сетка** — `display: grid; gridTemplateColumns: 'repeat(auto-fill, minmax(72px, 1fr))'; gap: SP.sm`. Это та же сетка, что в шторке «Фото» панели персонажа. На 320 px — 3 колонки, в 440 — 5.
4. **Строка цены** — `FS.xs` `C.textMuted`: «Новый запуск: {цена} · исходная версия останется». Цена — та же `estimateText`, что в карточке запуска (§6, вопрос 1).

### 4.2 Ячейка фото

`<button type="button" aria-pressed={selected}>` — колонка, `gap: SP.xs`, без фона и рамки, `textAlign: left`, `minWidth: 0`.

- **Фото**: `aspectRatio: 1`, `borderRadius: R.lg`, `border: 1px solid C.border`, `background: C.bgInset`, `overflow: hidden`, `position: relative`; `img` `objectFit: cover`.
- **Подпись** под фото — `PhotoLabelChips` в режиме подписи (панель, §8.1.2). Своей подписи не делаем: `FS.xs`, `lineHeight: 1.3`, 2 строки, цвета по источнику: auto — `C.textSecondary`, human — `C.textPrimary`, «Размечаем…» — `C.textMuted` курсив, «Без меток» — `C.textMuted`.
- **Главное фото** (первое в манифесте): `Badge size="xs" tone="neutral"` «Основное» в левом нижнем углу фото (`position: absolute; left: SP.xs; bottom: SP.xs`).

| Состояние | Вид |
|---|---|
| обычное | рамка `C.border` |
| hover (только pointer) | рамка `C.accentSoft` |
| focus-visible | рамка `C.accent` + `boxShadow: SHADOW.focus` |
| **выбрано** | `border: 2px solid C.accent` + `SHADOW.focus`; в левом верхнем углу (`top/left: SP.xs`) — номер по порядку (плашка ниже) |
| выбрано 3 из 3, ячейка не выбрана | `aria-disabled="true"`, фото `opacity: 0.45`, `cursor: not-allowed`, `title` = «Можно взять не больше 3 фото»; нажатие ничего не делает |
| tap (touch) | то же, что выбрано/снято, без hover; `:active` без сдвига |

Номер-плашка — `Badge size="xs"` с `style={{ background: C.accent, color: C.onAccent, minWidth: 18, justifyContent: 'center' }}` (проп `style` у `Badge` есть). Свою плашку из `span` не делать.

### 4.3 Поведение

- **Начальный выбор** — `character.photos` этого запуска в их порядке. Имена, которых уже нет в манифесте, отбрасываются.
- Нажатие по невыбранной ячейке добавляет фото **в конец** порядка. Нажатие по выбранной снимает его, и номера остальных сдвигаются. Порядок = порядок нажатий. Перетаскивания нет: чтобы сделать фото первым, человек сбрасывает выбор и нажимает заново.
- Лимит — 3 (`PhotosPerRequest`, бэкенд `CharacterStore`). Константу не дублировать: взять из ответа карточки персонажа или из общего места фронта (§6, вопрос 2).
- Клавиатура: `Tab` по ячейкам, `Enter`/`Space` — выбрать или снять, `Escape` закрывает окно (умеет `Modal`). Фокус при открытии — на первую ячейку.
- `aria-label` ячейки: «Фото {N}: {подпись}» + «, {k}-е по порядку», если выбрано.
- **«Перерисовать»**: новый запуск в ту же нить с **тем же промптом и той же базой**, что у запуска версии, плюс `characterPhotos: order` (имена файлов). Кнопка в это время — `loading`. Если запуск принят, окно закрывается, а ниже в ленте появляется обычная карточка «Рисуем…». Новая версия придёт с пометкой «Выбраны вами». Исходная версия не меняется и остаётся «В работе» по общим правилам.
- **«Отмена»**, крестик, `Escape`, клик по фону — закрыть без запуска. Выбор не запоминается.

### 4.4 Состояния окна

| Состояние | Вид |
|---|---|
| загрузка карточки персонажа | счётчик «Загружаем фото…», 6 заглушек `cc-skel` (`aspectRatio: 1`, `R.lg`) в той же сетке; «Перерисовать» `disabled` |
| ничего не выбрано | «Перерисовать» `disabled`, `title` = «Выберите хотя бы одно фото» |
| 400 `character_photos_invalid` | `Notice tone="danger" icon={AlertTriangle}`: «Части фото больше нет у персонажа. Выберите заново.» Карточка персонажа перечитывается, пропавшие фото снимаются из выбора, окно остаётся открытым |
| прочий отказ запуска | окно остаётся открытым, причина уходит тостом, как у любого `launchThread` (он сам показывает тост) |
| у персонажа стало одно фото | окно не открывается: блок уже в empty-state |

## 5. Мобила и тёмная тема

- **320 px**: шапка блока переносится (`flexWrap`), имя режется многоточием первым. Миниатюры 40 + «Заменить» `size="sm"` (32 по высоте) помещаются в одну строку: 3×40 + 2×4 + кнопка ≈ 230 из ~286 px содержимого. Окно — шторка, сетка в 3 колонки, `ModalActions` в один ряд.
- **Тёмная тема** ничего своего не требует: все цвета — токены. Проверено в макете: `C.bgInset` в тёмной теме темнее карточки, блок читается как утопленный, бейдж `info` контрастный.
- Миниатюры и фото в окне — настоящие картинки, их цвет от темы не зависит.

## 6. Открытые вопросы

1. **Цена в окне.** Нужна котировка нового запуска до нажатия. Если ручки «посчитать без запуска» на фронте нет, строку цены не показываем: запуск и так покажет цену в карточке «Рисуем…». Решает Денис.
2. **Лимит 3 на фронте**: пусть карточка персонажа отдаёт `photosPerRequest`. Иначе это вторая точка правды.
3. **Повтор с тем же промптом и базой**: `launchThread` сейчас собирает запуск из настроек полосы. Для «Перерисовать» нужен путь «повторить запуск {jobId} с `characterPhotos`». Если промпта у запуска нет (`launch.prompt == null`), «Заменить» прячем.
4. Тексты не из заметки, добавлены мной: «Сбросить выбор», «Выбрано {n} из 3», «Можно взять не больше 3 фото», «Выберите хотя бы одно фото», «Этого фото больше нет у персонажа», «Персонажа больше нет в проекте», «Части фото больше нет у персонажа. Выберите заново.», «Новый запуск: … · исходная версия останется», `title` у «Обычный порядок». Их нужно согласовать с Софьей и внести в заметку.
5. Словарь наклона: в заметке «Сверху/Снизу», а в спеке панели (§8.1.2) «Вверх/Вниз». Здесь взято по заметке. Одно из двух нужно привести к другому.
