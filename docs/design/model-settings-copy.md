# Лист текстов: настройка моделей v4

Единый источник видимых формулировок для переработки настройки моделей. Меняются **только видимые тексты** — ключи API, данных и лексика `tier:`/`preset:` в коде остаются как есть (допущение 6 постановки).

**Итерация 2 (14.08.2026):** модель настройки упрощена по решению человека. У персоны убраны «Уровень модели» и «Всегда работает моделью» (0 из 175 на проде) — остались три поля «Сильная / Средняя / Слабая» с видимым наследованием. У специальности убран «Уровень по умолчанию» (0 из 14) — остались три строки моделей. Место «Исполнитель задач» имеет собственный дефолт — **сильную** модель. Убранные настройки в текстах не упоминаются.

**Итерация 3 (14.08.2026):** у цепочки жёсткий потолок — **пять моделей** (`FallbackSettingsStore.HardMaxSubstitutions`), кнопка добавления на пятом шаге гаснет с подписью. Предупреждение о бюджете подмен остаётся условным и теперь показывается на вручную опущенном бюджете. «Особые правила» уходят от матрицы «специальность × уровень» (горизонтальный скролл) к **списку правил**; альтернатива «карточки специальностей» — в [../mockups/model-settings-v4/special-rules-variants.html](../mockups/model-settings-v4/special-rules-variants.html), выбор за человеком. Из списков «Используется в N местах» убрано место «модель чата» — выбор цепочки в чате в эту итерацию не входит (B4).

**Итерация 4 (14.08.2026):** «Особые правила» перерисованы на реальном объёме прода — 14 специальностей × 3 уровня = 42 правила (+3 поля «Любой специальности»), все в слое «Только для меня» ([../mockups/model-settings-v4/special-rules-groups.html](../mockups/model-settings-v4/special-rules-groups.html)). Гипотеза «4–5 профилей» подтвердилась частично: различных наборов 9, повторяемость поуровневая — поэтому сверху **картина по уровням** (три полосы), ниже **группы одинаковых наборов** и **отдельные роли**. Раскладки A/B на пяти фантазийных правилах отменены этой итерацией.

Прототипы, на которых эти тексты живут: [../mockups/model-settings-v4/index.html](../mockups/model-settings-v4/index.html) (раздел целиком), [persona.html](../mockups/model-settings-v4/persona.html), [task.html](../mockups/model-settings-v4/task.html), [chat.html](../mockups/model-settings-v4/chat.html), [special-rules-variants.html](../mockups/model-settings-v4/special-rules-variants.html) (два варианта «Особых правил» на выбор).

Убранные настройки **не упоминаются нигде** — ни как «бывшие», ни в миграционных подсказках:
«Уровень модели» у персоны, «Всегда работает моделью» у персоны, «Уровень по умолчанию» у специальности. Пользователь не должен узнать из интерфейса, что они были, — он видит только три поля и наследование.

## Вкладка «Цепочки» (B1–B3, C2, C4)

| Контекст | Текст |
|---|---|
| Заголовок вкладки | Цепочки |
| Подзаголовок | Запасной путь хода: если модель не ответила, ход продолжит следующая |
| Строка бюджета (B3) | Подмен за один ход: {N} · первый шаг — не подмена: цепочка из {N+1} шагов отработает целиком |
| Потолок цепочки | В цепочке не больше пяти моделей (подпись у погашенной кнопки «Добавить шаг» на пятом шаге; сервер отвечает 400 на шестой) |
| Кнопка создания | Новая цепочка |

| Поле имени, placeholder | Например: «Экономная, но живая» |
| Поле слоя | Для всех / Только для меня |
| Шаги | Шаг {N} |
| Кнопка | Создать цепочку |
| Диалог удаления, заголовок | Удалить цепочку «{имя}»? |
| Диалог удаления, тело | Она используется в {N} местах: {список}. Эти места вернутся к наследованию — ход пойдёт по «Моделям по умолчанию». |
| Кнопки | Отмена · Удалить |
| Приглушённый шаг (C4, условно) | Шаг {N} не успеет сработать — подмен за ход: {B}, сработают шаги 1–{B+1}. Уберите лишний шаг или поднимите бюджет. |
| Пустой список | Цепочек пока нет. Соберите первую — она подстрахует ход, если основная модель не ответит. |

**Правило бюджета (ADR-007 §9.3):** дефолт — 4 подмены за ход; первый шаг цепочки подменой не считается, бюджет тратит только смена поставщика. Значит, цепочка из 5 шагов при дефолте отрабатывает целиком. Предупреждение о мёртвом шаге показывается **условно** — только когда (шагов − 1) > эффективного бюджета; постоянной надписи быть не должно — она врала бы. Длина цепочки ограничена пятью моделями — потолок серверный, интерфейс не даёт его перейти (кнопка добавления гаснет с подписью).

Уровень у задачи остаётся, но сегмент получает явный вариант «По умолчанию» — собственный дефолт места «Исполнитель задач»: **сильная** модель. Задача без выбранного уровня не дешевеет молча; уровень, выбранный в задаче, сильнее всего.

## Согласуемые пункты

1. **D5**: имя раздела в текстах ошибок валидации маршрута («Поставщики моделей» → «Модели и расход») — требует правки `docs/features/model-providers.md` и сообщений об ошибках; отмечено к согласованию с человеком.
2. **«Применение моделей»**: имя третьей вкладки (каталог мест) оставлено прежним — вне реестра проблем, но подлежит подтверждению вместе с макетами.
3. Термин **«маршрут»** используется в макетах как внутреннее имя панели выбора (`routepick`); в видимых текстах не появляется — везде «модель или цепочка».
4. **Итерация 2 (14.08)**: убранные настройки («Уровень модели», «Всегда работает моделью» у персоны, «Уровень по умолчанию» у специальности) не упоминаются в текстах вовсе — миграционных подсказок «было так» не делаем. Дефолт места «Исполнитель задач» — сильная модель — назван явно в сегменте задачи и на вкладке «Применение моделей».
5. **Итерация 4 (14.08)**: бейдж-счётчик на вкладке «Особые правила» показывает число заданных полей (на проде это 45). При полном покрытии всех 14 специальностей этот счётчик теряет сигнал «что-то изменилось» — альтернатива: считать не поля, а специальности с правилами («14 из 14»). Требует решения человека.
6. **Итерация 4 (14.08)**: слой «Для всех» на проде пуст — все 45 полей живут в «Только для меня». Открывать вкладку сразу на личном слое (как в макете) или на общем с плашкой «Общих правил пока нет» — вопрос к человеку; макет демонстрирует оба.
