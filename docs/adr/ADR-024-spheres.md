# ADR-024: Сферы — зона персоны и полка памяти над проектами

- **Статус:** реализовано в ветке `feature/spheres`, за флагом `spheres` (dark launch, выключен по умолчанию). Разрез принят 2026-10-06 (Александр, решения Андрея по имени, срезу MVP и двум полкам памяти); финальное ревью — «не готово» с четырьмя блокерами, закрыты отдельной задачей.
- **Основа:** продуктовая проработка «Сферы» (Софья, решения Андрея 2026-10-06), макеты Майи (`docs/mockups/spheres-v1.html`), [ADR-014](ADR-014-internal-subsystems.md) (подсистемы и сторожа границ), [ADR-016](ADR-016-local-projects.md) (локальные проекты, `ProjectCapabilities`), [ADR-013](ADR-013-turn-event-bus.md) (вкладчики промпта).
- **Флаг:** `spheres` (`FeatureFlagCatalog`, `Default: false`). Выключен — «сферы» остаются группами проектов как были.
- **Описание для людей и персон:** [docs/features/spheres.md](../features/spheres.md).

## Контекст

«Группа проектов» была именем, цветом и порядком на вкладке «Проекты» — без команды, памяти и прав. Персона бывала глобальной (видит всё) или проектной (один проект); командная память, заметки, знания и задачи ключуются по проекту. Слоя «долгоживущая область с собственной командой агентов и накапливаемой памятью» нет, хотя проекты рождаются и умирают, а знания темы должны жить дольше любого из них.

## Решения

1. **Одна сущность, без миграции стора.** Сфера — это группа на месте: тот же `groups.json`, тот же `Project.GroupId`. Добавлены `Icon` (белый список `LucideGlyphs`) и `Charter` (устав, до `Sphere.CharterMaxLength`). Имя в интерфейсе — «Сфера», в коде — `Sphere`.
2. **Зона персоны — только через `PersonaZone` + `ISphereDirectory` (Core).** Три зоны: `Global` / `Project` / `Sphere`. Членство «проект ∈ сфера» считается живьём из справочника, **без кэша**: проект вошёл в сферу — персона его видит, вышел — со следующего вызова нет. **Fail-closed:** флаг выключен, сфера удалена, `SphereId` пуст — зона пуста, а не «как у Global».
3. **Синтетические скоупы, привязки не пишутся.** Доступ персоны сферы к файлам, задачам, заметкам и знаниям проекта выводится из зоны на лету (`BuildExternalTaskScopes`, `BuildWorkspacePlan`). Пустая зона даёт заглушку `__no-projects__`, а не `null` (иначе `null` читался бы как «без ограничений»).
4. **Членство и зону персоны сферы меняет только человек.** REST — да, MCP — нет: `projects_create`/`projects_update` с `groupId` при включённом флаге отказывают, `personas_create`/`personas_update` отказывают на неизвестный `scope` и на любую смену зоны с `sphere` или на `sphere`. Иначе модель самовыдаёт права (персона расширяет себе зону до глобальной).
5. **Ход вне зоны не стартует.** Проект чата вышел из сферы персоны — отказ `RefuseTurnAsync` с машинным признаком `action: "change-companion"` в `ErrorMessage`/истории; текст «{Имя} работает только в проектах сферы «…». Смените собеседника.». Персону молча не подменяем; исполнитель задачи вне зоны отклоняется тем же правилом (`OutOfZoneRefusal`).
6. **Две полки памяти над общим `MemoryShelf`.** Память проекта и память сферы — отдельные полки; ключ полок — **проект сессии**. В проекте сферы recall складывает обе (глобальные персоны сферную полку читают). Писать в полку сферы — персоны этой сферы и глобальные; перенос проект → сфера — явный (`sphere_memory_adopt` / кнопка «Перенести в сферу»), `adopt` = **перемещение**, не копия. Autolearn в сферу не пишет.
7. **MCP `sphere_memory_*` — по флагу владельца.** Состав `tools/list` зависит только от флага владельца (бит `:s1` в сигнатуре запуска CLI), не от хода, иначе рестарт CLI («Stream closed»).
8. **Устав — стабильная секция промпта** `sphere-charter` (`SphereCharterContributor`, Turn): стабильна на чат, не обнуляет prefix cache.
9. **Удаление сферы:** 409 только при наличии персон сферы (их нельзя молча расширить до глобальных); память сферы (стор + Dify-датасет) **удаляется вместе со сферой** — решение Андрея, одно подтверждение «Удалить сферу и N записей памяти».
10. **Подсистемы.** `Services.Spheres` — в спине обоих сторожей границ; Memory и Turn ходят к сферам только через Core-шов `ISphereDirectory`. Связей вертикаль → вертикаль нет. Полка сферы зарегистрирована как `IKnowledgeSyncParticipant` (каскад удаления пользователя, реконсайлер).

## Отвергнутые варианты

- **Отдельная сущность «сфера» рядом с группой** — миграция `groups.json`/`GroupId`, два источника правды о принадлежности проекта.
- **Зона через привязки персоны** (записывать проекты сферы в `Bindings`) — устаревает при смене состава сферы, а чужая правка привязок расширяла бы зону; синтетические скоупы всегда актуальны.
- **Кэш членства** — дал бы окно, в котором вышедший проект ещё виден персоне.
- **Одна слитая память** (проект + сфера в одном сторе) — нельзя курировать, шум растёт; выбраны две полки с явным переносом.
- **Копия при `adopt`** — запись жила бы на обеих полках и расходилась.
- **Тихая подмена собеседника при выходе проекта** — отвергнута: отказ с кнопкой «Сменить собеседника».
- **Блок удаления сферы с памятью** — отменён решением Андрея: память удаляется, блок остаётся только по персонам.

## Цена

- `BackupSchema` → **10**: инкремент из-за `PersonaScope.Sphere` (откат кода не прочтёт такие персоны). `Icon`/`Charter`/`SphereId`/`PromotedFrom`/`StoredErrorMessage.Action` аддитивны; `sphere-memory*.json` лежат в `data/` и попадают в архив по умолчанию, секретов в них нет.
- **Перезапуск CLI** при правке устава, состава команды сферы и переключении флага: всё это входит в сигнатуру запуска.
- **Заметки и самостоятельные базы знаний в MVP по зоне не сужаются** — названо прямо: персона сферы видит их так же, как раньше. Сужаются файлы, задачи и знания проектов.
- **Агент-файлы персон сферы остаются в `.claude/agents`** проектов при выключении флага — пересинка по смене флага нет. Известное ограничение: данные не утекают (субагент работает инструментами родительского хода), но персона формально «есть».
- **`adopt` не атомарен между полками:** сначала запись в сферу, потом удаление из проекта; падение между шагами оставит запись на обеих полках. Приемлемо.
- Не покрыто тестом: отмена отложенного Dify-синка при удалении сферы (код `MemoryShelf.DeleteScopeAsync` прочитан ревьюером, корректен).
- У страницы сферы нет собственного URL.
- **Поведение MCP `personas_update` изменилось:** пустой `scope: ""` теперь отказ «Неизвестный scope» (раньше молча давал Global). Пункт «Что нового» появится после мержа в master: changelog читает `HEAD`.

## Инварианты и сторожа

| Инвариант | Кто держит |
|---|---|
| Видимость проекта персоной — только `PersonaZone`; прямых проверок `Scope == Project` вне него нет (включая property-pattern) | `PersonaZoneGuardTests` |
| Fail-closed: флаг выключен / сфера удалена / пустой `SphereId` — зона пуста | `PersonaZoneTests` |
| Нет связей вертикаль → вертикаль; `Services.Spheres` — в спине | `SubsystemBoundaryTests`, `SubsystemBoundaryCoverageTests`, `IlBoundaryRegressionTests` |
| `tools/list` не зависит от хода; `SphereOf` не участвует в решении о составе | `McpToolsetStabilityTests` |
| Устав — стабильная секция, порядок вкладчиков | `ClaudeSessionPromptSectionsOrderTests`, `SphereCharterPromptTests`, `PromptSectionContributorsDiTests` |
| Датасеты `sphere:` классифицируются как служебные | `SphereMemoryServiceTests` (в т.ч. классификация датасетов `sphere:`) |
| Полка сферы в составе `IKnowledgeSyncParticipant` | тест состава `IEnumerable<IKnowledgeSyncParticipant>` из DI (блокер Б2 ревью) |
| MCP не меняет зону персоны сферы и состав сфер | тесты `PersonasToolset` / `projects_*` с `groupId` |

## Связь с другими ADR

- **ADR-014:** сфера — ещё одна вертикаль со швом `ISphereDirectory` в Core; правило «вертикаль не зависит от вертикали» не нарушено.
- **ADR-016:** доступ к файлам и знаниям проекта идёт через `ProjectCapabilities` по целевому проекту; инлайновых `IsDeviceBound` в коде сфер нет, `PersonaAgentFileSync` пишет только в проекты с файлами на сервере. Живая проверка с устройством не делалась — по первой возможности.

## Следующая волна

Чат сферы (вне проекта, зона — все проекты сферы); «наследие проекта» (итог при архивации проекта выжимается в память сферы); сужение заметок и знаний по зоне; собственный URL страницы сферы; наследование настроек проектом (устав как фрагмент промпта уже есть, остальное — нет); дайджест сферы.
