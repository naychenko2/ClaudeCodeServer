# ADR-035: LLM-wiki — производный слой заметок с одним писателем

- **Статус:** предложено 2026-10-20 (Александр, разрез Ф0–Ф1 эпика 9cbc09e5, задача разреза 6b8c33ca). Принимает Андрей. Номер 034 в постановке занят черновиком «обвязка персон» (`ADR-034-persona-harness-versions.md`), поэтому здесь 035.
- **Вход:** заметки `notes/Целевое видение — LLM-wiki в AI Home (драфт).md` и `notes/Исследование — LLM Wiki Карпати и смежные подходы (2026-10).md` (раздел 8 «Уроки»). Полный разрез со слоями, файлами и нарезкой шагов лежит в `resultMarkdown` задачи 6b8c33ca.
- **Связано:** [ADR-004](ADR-004-change-dossiers.md) (`SecretRedactor`, досье как источник в Ф3), [ADR-005](ADR-005-link-reader-server.md) (ридер ссылок для источников `url`), [ADR-007](ADR-007-model-preset-chains.md) (места маршрута и слоты), [ADR-012](ADR-012-mcp-over-http-transport.md) (тулсет `notes`, постоянный состав `tools/list`), [ADR-014](ADR-014-internal-subsystems.md) (границы подсистем), [ADR-016](ADR-016-local-projects.md) (локальные проекты, `ProjectCapabilities`), [ADR-032](ADR-032-executor-experience-and-memory-versions.md) (журнал изменений вместо перезаписи). Подробности подсистемы — [knowledge.md](../architecture/knowledge.md), раздел «LLM-wiki (proposed)».

## Контекст

Андрей хочет, чтобы заметки стали базой, которую ведёт ИИ, по паттерну LLM Wiki Карпати. Источники неизменяемы, производная вики лежит в папке `Вики/` каждой базы. Операций шесть, на каждом утверждении есть цитата, её проверяет код. Устаревшее замещается, а не удаляется. Правки ИИ проходят через пакеты изменений с ревью человека, а в вики пишет один писатель — служба «Хранитель базы».

Что мешает сделать это без архитектурных решений (сверено по коду 2026-10-20):

- **Гейта по пути записи нет нигде.** `NotesService` (Create, Update, Move, Delete) пишет в любое место источника. `FileService` проверяет только `SafePath.Join`. `FilesController` в Upload и SaveFromUrl пишет `FileStream` мимо `FileService`. Исполнитель задачи получает в `ClaudeSession.DecidePermissionAsync` разрешение на всё, хотя deny-правила проекта проверяются раньше этой ветки.
- **Побочные записи.** `NotesService.Update` при переименовании переписывает `[[…]]` во **всех** заметках (`RewriteLinks`). Есть ещё `RemoveWikilinksTo` (истечение заметки), `Annotate` (вписывает `^id`) и `NoteTaskSyncService` (чекбоксы).
- **Парсер ссылок и тегов не пропускает код** (дефект 7928ce94). Гейт «битая ссылка» на нём даст ложные срабатывания.
- **Журнала событий у личной базы нет.** `ProjectEventLogService` (SQLite) ключуется по `project_id`, `NoteChanged` пишется только у проектов и с actor `"user"` даже из MCP.
- **Запретить Bash агента, Obsidian и git невозможно.** Они пишут в файлы мимо сервера.

## Решения

### 1. Физическое разделение слоёв, признак вики — `_schema.md`

- Вики — папка `Вики/` в базе: `notes/Вики/` проекта и `data/notes/{userId}/Вики/`. Имя — одна константа `WikiPaths.FolderName` в Core. Сравнение пути без учёта регистра и с нормализацией Unicode NFC: Obsidian на macOS пишет «Вики» в NFD.
- Вики **заведена**, если есть `Вики/_schema.md`. Гейт привязан к этому признаку, а не к фич-флагу. Флаг `llm-wiki` прячет UI и инструменты, но гейт у заведённой вики работает всегда (fail-closed).
- Заметки человека вне `Вики/` остаются источниками, Хранитель их не меняет никогда.

### 2. Один писатель: отказ на серверных путях плюс обнаружение дрейфа

Запретом правило «пишет только Хранитель» не обеспечить, поэтому его держат два механизма. Без второго первый — самообман.

- **Жёсткий отказ на всех серверных путях.** Предикат `WikiPaths.IsWikiPath(root, rel)` — чистая функция в Core, рядом с `SafePath`: его зовёт и вертикаль Files, а ссылка Files → Notes запрещена (ADR-014). Проверка стоит:
  - внутри мутирующих методов `NotesService` (а не в тулсете), чтобы одна проверка закрывала REST, MCP и `INoteAccessor`; у Move проверяются обе стороны;
  - во внутренних точках `FileService` (закрывает `files_*`, WebDAV, Docs) и отдельно в Upload и SaveFromUrl `FilesController`;
  - во встроенном deny-правиле `DecidePermissionAsync` **до** ветки исполнителя (Edit, Write, NotebookEdit по `**/notes/Вики/**` и личному vault) и в статическом deny настроек запуска CLI.

  Отказ: MCP — `wiki_readonly` с подсказкой, какую операцию звать; REST — 409 `wiki_readonly`; FileService — `UnauthorizedAccessException`.
- **Обнаружение дрейфа.** У Хранителя есть манифест `{страница → sha256 после последнего применения}`. При каждом lint и перед каждым применением пакета хэш на диске сверяется с манифестом. Расхождение даёт статус `drift`, строку в `_health.md` и блок пакетов, которые задевают эту страницу. Человек выбирает «Принять как есть» (`adopt`) или «Вернуть» из прообразов. **Молча Хранитель не откатывает никогда:** git — законный путь отката для заметок проекта.
- Ни один публичный путь записи не умеет писать в `Вики/`, поэтому «пропуска для Хранителя» нет. Он пишет своим внутренним `WikiFileWriter` внутри сборки Notes.
- Побочные записи `NotesService` пропускают файлы `Вики/` и вместо правки вызывают внутренний `IWikiRelink` (системная операция `relink`, решение 6). `Annotate` на странице вики якорится только по цитате и заголовку, без `^id`. Чекбоксы задач в вики запрещены формой страницы.

### 3. Контракт цитаты; `status` и `sources` считает код

- Шапку страницы разбирает **строгий** парсер (плоские ключи, скаляр или `[a, b]`); нынешний терпимый `ParseFrontmatter` для гейта не годится. Поля модели: `type` (одно из шести значений), `kind`, `summary`, `aliases`, `owns`; `aliases` и `owns` уникальны по базе. Поля кода: `sources`, `updated`, `status` (`active` | `disputed` | `stale` | `drift`). `expires`, `annotates`, `file` на страницах вики запрещены.
- Алиасы страниц вики пополняют индекс резолва `ByName` в `NotesService.Build`; при коллизии побеждает заголовок.
- Утверждение — абзац или пункт «Сводки» и «Противоречий». Каждое заканчивается сноской Obsidian/GFM: `[^sN]: [[Карточка источника]] — «цитата»`, цитата 8–300 символов (те же пороги, что у комментариев). Номера сносок перенумеровывает Хранитель.
- Дословность цитаты против источника проверяет `QuoteMatcher`. Его выносим из `NotesService.Annotations` (`NormalizeForMatch`/`FoldQuotes`), второй копии не заводим.
- Секции страницы фиксированы и идут в порядке `Сводка` → `Хронология` → `Противоречия` → `История`. Блок «Источники» рендерит UI из сносок: второй точки правды нет. Замещение переносит утверждение в «Историю» дословно со сноской и датами «с — по» (`captured` старого и нового источников). Удаления нет.
- Карточка источника (`type: source`, `Вики/Источники/`) несёт `origin`, `ref`, `hash`, `captured`. Текст заметок и файлов не копируется, сохраняется хэш версии. Выдержку чата сервер режет сам по `sessionId` и диапазону сообщений, без вызовов инструментов, через `SecretRedactor`, не больше 8 КБ.

### 4. Пакет — намерения, а не файлы; применяется транзакцией

- Хранилище — `data/wiki/{baseId}/`: `packages/`, `manifest.json`, `log.jsonl`, `preimages/` (90 дней), `metrics.jsonl`. Всё под `data/`, значит попадает в бэкап по умолчанию; хранилище аддитивное, `BackupSchema.Version` не трогаем. Вики проекта страхует git проекта, коммитит человек, не Хранитель.
- Операций пять: `create`, `append`, `supersede`, `conflict`, `link`. Удаления нет. Пакет хранит намерения, файлы рендерит код при применении, поэтому пакет переживает чужие `append` на той же странице. Риск выставляет код.
- Статусы: `checking` → `proposed` | `rejected_by_checks` → `accepted` | `partially_accepted` | `rejected` → `applying` → `applied` | `apply_failed` | `stale`.
- Применение под блокировкой базы:
  1. модель строится мимо кэша графа (`BuildFresh`);
  2. диск сверяется с манифестом и `baseHashes`;
  3. на итоговом состоянии в памяти гоняется весь гейт;
  4. пишутся прообразы, статус ставится `applying`;
  5. каждый файл пишется через temp + `File.Move`;
  6. перегенерируются проекции, обновляются журнал и манифест, кэш графа инвалидируется у всех владельцев, чьи источники смотрят в этот путь.

  Исключение откатывает файлы по прообразам. Пакет, застрявший в `applying` после падения процесса, откатывает сторож старта.
- **`stale` без авто-rebase.** Если заменяемого утверждения больше нет, пакет требует повторного разбора.

### 5. Нет MCP-инструмента принятия пакета

Пакет базы проекта принимает только владелец проекта-человек и только через REST (`[Authorize]` и проверка владения базой). Ни у агента, ни у персоны, ни у исполнителя нет инструмента «принять пакет», иначе ревью превращается в фикцию. Сторож — тест на состав `tools/list`.

### 6. Системные операции без ревью

`relink` (переименована или истекла заметка, на которую ссылается вики), регенерация `_index`/`_log`/`_health`, `adopt` (только кнопкой человека) и `schema` (правка `_schema.md` человеком через Хранителя) идут **без ревью и в обход очереди**, но под той же блокировкой и с записью в журнал. Смысловых правок у них нет, и это проверяет код: `relink` меняет только цель `[[…]]`. Без этого переименование обычной заметки ломает ссылки вики и висит в очереди.

### 7. Модель без инструментов, ссылка вместо текста

- Модель в ingest — one-shot **без инструментов** (`ICheapTextRunner`), её вызывает Хранитель. Два прохода: A — утверждения с цитатами, B — план операций в JSON по схеме. Весь остальной путь — код: проверки до показа, лимиты, гейт, применение. На ремонт модели даётся одна попытка с перечнем нарушений.
- Чат-агент инструментами `wiki_ingest` и `wiki_add_fact` только ставит заявку и передаёт **ссылку** на источник (noteId, путь, `session:{id}#m{a}-{b}`, url). Текст источника и готовый план агент не присылает.
- Порядок защит от промпт-инъекций: нет инструментов → выход только JSON по схеме, его применяет код (пути только `Вики/`, `_schema` недоступна) → цитата дословно из источника → человек ревьюит. Разделитель с nonce — слабая мера, не основная.
- Имя `wiki_update` из видения как инструмент не берём: рядом `notes_update`, а однокоренные имена с пересекающимся смыслом запрещены (CLAUDE.md, раздел MCP). Инструмент называется `wiki_add_fact`.
- Места маршрута — `wiki-ingest` (умолчание — слот medium) и `wiki-fact` (weak) в `LocalActionRouter`. Модель из слота разворачивает только `UserModelTierResolver.ModelFor`. Промпт Хранителя — свой, в `ClaudeHomeServer.Prompts`; от пресета Библиотекаря берётся только тон.

### 8. Dify и recall без второй секции

- `Вики/_*` (`_index`, `_log`, `_health`, `_schema`) в Dify не индексируются, фильтр — одним предикатом `WikiPaths` в `NotesKnowledgeService`. Страницы и карточки источников индексируются.
- `wiki_query` — детерминированная сборка контекста без модели: строки `_index`, до трёх страниц и подсказка «полнотекст по сырью — `notes_search`». `_index` в каждый ход не подмешивается.
- `NotesRecallContributor` остаётся одной секцией. Единственная правка: если в выдаче есть и страница вики, и заметка, которую она цитирует, остаётся страница. Отдельной секции recall для вики нет.

### 9. Приватность личной базы и запрет кросс-проектных выдержек

- Личная база в Ф0–Ф1 только читается lint'ом. Операции с моделью для неё **закрыты до Ф2** (fail-closed): облако — только с явным согласием владельца.
- Выдержка чата в базу проекта допустима только из сессии **того же проекта и владельца**. Иначе личный чат утечёт в `notes/` проекта, а она лежит в git.
- Вики не поддерживается у локальных проектов (ADR-016): у Хранителя нет канала записи на устройство. Отказ идёт через `ProjectCapabilities`, инлайновых `if (IsLocal)` не заводим.

### 10. Блокировка и манифест — по каноническому пути

`SemaphoreSlim` и манифест ключуются по каноническому пути папки `Вики/`, а не по владельцу или проекту: у разных владельцев общая папка проекта допустима. Иначе на одних файлах окажутся два Хранителя. `baseId` (`personal-{userId}` | `project-{projectId}`) — только имя каталога хранилища.

### 11. Границы подсистем

Хранитель, гейт, lint, пакеты и REST живут внутри вертикали Notes (`ClaudeHomeServer.Notes/Services/Wiki/`). Отдельный `.csproj` и новая `IAppSubsystem` не нужны: Хранителю нужны внутренности `NotesService` (модель графа, призраки, обратные ссылки, нормализатор цитат), и вынос раздул бы шов `INoteAccessor` до половины сервиса. Наружу выходит только `WikiPaths` в Core. Тумблер `Subsystems:Notes` выключает вики целиком.

## Поправки к решениям по умолчанию видения (раздел 12)

| Решение видения | Вердикт | Поправка |
|---|---|---|
| 1. Ревью всегда | принять с поправкой | Механические системные операции (`relink`, проекции, `adopt`, `schema`) идут без ревью и в обход очереди (решение 6). |
| 2. Вики у каждой базы | принять с поправкой | Блокировка и манифест — по каноническому пути, а не по владельцу (решение 10). Личная база в Ф0–Ф1 только под lint, операции с моделью закрыты до Ф2 (решение 9). Локальные проекты не поддерживаются. |
| 3. Писатель — служба, не персона | принять с уточнением | Служба — единственный писатель **файлов** `Вики/`, а модель в ingest — one-shot без инструментов. Чат-агент только ставит заявку по ссылке (решение 7). Промпт свой, а не пресет Библиотекаря. |

## Ответы на открытые вопросы видения

- **git для личной базы** — в Ф0–Ф1 не нужен: хватает прообразов, журнала `log.jsonl` и бэкапа `data`.
- **Автоматический разбор журнала** — только по кнопке до Ф3.
- **Показывать ли пакеты базы проекта участникам** — вопрос снят: людей-участников проекта в модели нет, принимает только владелец (решение 5).

## Отклонено

- **Запрет записи в `Вики/` как единственная защита.** Bash агента, Obsidian и git его обходят; дрейф обязателен.
- **Гейт на фич-флаге.** Выключенный флаг открыл бы заведённую вики для записи мимо Хранителя.
- **Хранитель отдельной вертикалью.** Шов `INoteAccessor` пришлось бы расширить до половины `NotesService`.
- **Пакет как готовые файлы.** Конфликтовал бы с любой соседней правкой той же страницы.
- **Авто-rebase пакета `stale`.** Смысл замещения не переносится механически.
- **Отдельная секция recall для вики и `_index` в каждом ходе.** Вторая точка recall и двойной расход хвоста хода.
- **Расширение `ProjectEventLogService` на личную базу.** Журнал Хранителя одинаков для обеих баз, второй поток событий не нужен; для проекта дополнительно пишется `WikiChanged`.
- **`wiki_update` как имя инструмента.** Путается с `notes_update`.

## Последствия

- **Зависимость 0 — дефект 7928ce94.** Маска «вне кода» через `MarkdownFence` во всех потребителях: `ParseLinks`, `InlineTag`, `RewriteLinks`, `FindWord`, `RemoveWikilinksTo` и парсер сносок. Без неё гейт ложно срабатывает, а переименование переписывает код.
- **Новые сторожа:**
  - тест-перебор мутирующих методов `NotesService`, `FileService`, `files_*` и MCP `notes_*` на пути в `Вики/`; список методов собирается рефлексией, новый метод без проверки краснит тест;
  - внешняя правка между построением модели и записью даёт `apply_failed`;
  - `tools/list` без инструмента принятия; `McpToolsetStabilityTests`;
  - одна блокировка у двух владельцев на одной папке;
  - отказ в выдержке из чужой или кросс-проектной сессии;
  - golden-тест секций хода: одна `recall-notes`;
  - откат пакета из `applying` при старте;
  - фильтр `Вики/_*` в синке Dify;
  - битая шапка не роняет `BackgroundService` lint;
  - флаг выключен, `_schema.md` есть → запись отказана.
- **Не измерено и проверяется на живом:** работает ли deny CLI в `acceptEdits` и bypass. Если нет — остаётся только дрейф, и решение 2 это допускает. Не измерены и бюджет с качеством прохода B на слоте medium (≈ 35k вход и ≈ 7k выход на источник по оценке): первые 5 разборов пилота — замер, а не приёмка.
- **Базовая линия метрик** снимается кодом lint после фикса 7928ce94 и до первой записи в `Вики/`, с двумя цифрами «до фикса парсера» и «после фикса». Ручной замер видения от 2026-10-19 как база не используется. Карточка 15 вопросов по проекту — в `docs/research/llm-wiki-baseline-2026-10.md`, по личной базе — в личной заметке.
- Фронт: вкладка «Вики», «Входящие базы» с диффом (`DiffView`), «Здоровье» — по макету Майи, Кира начинает после макета.

## План шагов

Порядок: **0 → (1 ‖ макет) → 2 → 3 → 4 → 5 ‖ 6 → 7 → 8**. Код не пишется, пока ADR не принят.

- **Ф0:** 0 — дефект 7928ce94; 0б — базовая линия; 1 — `WikiPaths` и гейт на всех путях, deny CLI, `relink`; 2 — Хранитель без модели (`_schema`, шапка, `WikiGate`, проекции, манифест, дрейф, `adopt`, фильтр Dify); 3 — `WikiLint` и `_health`; 5 — фронт Ф0.
- **Ф1:** 4 — пакеты и транзакция; 6 — ingest, выдержки, MCP, recall; 7 — «Входящие» и пакет на фронте; 8 — пилот: 20 разборов и повтор карточки 15 вопросов.

Критерии готовности каждого шага — в разрезе 6b8c33ca, раздел 11.
