# Критерии приёмки и свидетельства у задачи

**Статус:** реализовано в ветке `feat/local-models-frontend`. Контракт для планировщика, ревьюера и исполнителей —
заметка «Контракт критериев приёмки: Егор, Глеб, исполнители»; происхождение и метрика —
[срез](../research/local-models-frontend-tasks-cut-2026-10.md) и
[план](../research/local-models-frontend-tasks-plan-2026-10.md).

> **Гейт держит дисциплину добросовестной модели, а не границу безопасности: он проверяет наличие свидетельства, а не его истинность, и исполнитель с сервисным токеном на хосте при желании может обойти признак «исполнитель» — на гейте нельзя строить доверие.**

## Поля задачи

- `Acceptance` — список критериев `{ id, text }`. Пустой `id` получает `c1`, `c2`…; повтор `id` и пустой `text` — отказ.
- `Evidence` — свидетельства `{ criterionId, how, result }`: чем проверено и что получилось. Пустые `how`/`result` и ссылка на неизвестный критерий — отказ.
- Повторное свидетельство по тому же `criterionId` **заменяет** прежнее.
- Смена `text` при том же `id` **сбрасывает** свидетельство этого критерия: старая проверка не закрывает новый смысл.

## Гейт закрытия

Одна точка: `AcceptanceRules.EnsureClosable` ([AcceptanceRules.cs](../../backend/ClaudeHomeServer.Tasks/AcceptanceRules.cs)),
её зовёт только `TaskManager` — в `Create` и в `Update` на переходе в `Done`. Все двери (REST, MCP `tasks_*`,
stdio через REST, мост заметок, волны штаба) проходят через `TaskManager`, поэтому отдельной проверки в
контроллерах и тулсете нет — они берут текст отказа из исключения. Нет свидетельства по критерию — задача
не закрывается, в отказе перечислены открытые критерии.

## Кто меняет критерии

Постановщик и человек — да. Исполнитель своей задачи — нет (допустим только совпадающий список: клиенты шлют поля целиком;
сравнение по множеству пар `id`+`text`, порядок не важен). Признак «исполнитель» — claim `typ=svc` и сессия, привязанная к задаче.
Свидетельства исполнитель добавляет сам.

## Причина возврата

В вердикте ревью при `returned` — структурированная причина `ReturnReason` из `TaskReturnReasons`:
`size | side-effect | contract | robustness | quality | other`. При других вердиктах не заполняется; пусто = «причина не указана».
По ней считается доля возвратов для замера «до/после».

## Совместимость

Задача без `acceptance` закрывается как раньше (гейт — no-op). Поля аддитивные и nullable, старые данные читаются как есть;
`BackupSchema.Version` не менялся.
