# Вкладка LLM: скорость ответа в определении облачных моделей

Родительская задача: 5987bf81.

## Зачем

Скорость локальной модели на панели должна быть в тех же единицах, что публикуют
для облачных, чтобы их можно было сравнивать.

- **Artificial Analysis** (методика 3.0.0 от 03.11.2026): «Output Speed» — выходные
  токены (вместе с токенами размышлений) ÷ ПОЛНОЕ время запроса, от отправки до
  последнего токена; время до первого токена входит. Отдельно «Time to First Token».
- **OpenRouter**: «throughput (TPS)» — тоже сквозное: выходные токены ÷ время от
  отправки запроса поставщику до конца ответа. Отдельно TTFT.

Главное число у обоих — сквозное. «Скорость, пока пишет» — второе, справочное.

## Что показываем (вкладка LLM панели «Локальные модели»)

1. **«Скорость ответа» — заглавное число**, сквозное определение, по всему стенду:
   Σ выходных токенов ÷ Σ полного времени запросов, завершённых в окне.
   Окна: **5 минут** (как у OpenRouter) и **1 час**. Рядом — медиана по запросам.
2. **Время до первого токена**: медиана и p90 за то же окно.
3. Нынешнюю «на поток» оставляем, но называем однозначно — **«скорость генерации
   (пока пишет)»**. В подсказках пишем, что с цифрами Artificial Analysis и OpenRouter
   сравнивается «Скорость ответа».
4. В блоке «Кто сейчас на модели» формулу не меняем; добавляем подсказку, что это
   сквозная скорость с ожиданием слота и чтением промпта.

## Источник данных

Сквозную скорость берём из **собственного учёта CCS по запросам**, а не из адаптера
метрик `strata-metrics.py` (на ai 20.11 11:01 адаптер со сверкой недосчитывал 12–21 %
токенов).

Учёт ведёт шлюз LLM: он видит каждый запрос к локальному движку и знает

- момент отправки запроса вверх (перед `SendAsync`),
- момент первой `content_block_delta`,
- момент завершения потока,
- выходные токены из `usage` ответа (вместе с токенами размышлений).

Из этого: полное время запроса = конец − старт, TTFT = первый токен − старт.

**Что НЕ попадает в учёт** (и это надо честно сказать в отчёте): прямые вызовы локальной
модели в обход шлюза — фоновые one-shot действия (теги, сводки, память, changelog) и
звонки «мест» сервера к именованному движку (`CheapTextRunner`). Их объём мал относительно
хода, но при сверке с журналом движка (`grep "done:" prod/serve.log`) это объясняет
недобор.

## Контракт REST (заморожен)

В `LocalModelStatsResponse` (backend/ClaudeHomeServer/Controllers/LocalModelStatsController.cs)
новый блок `answerSpeed`:

```json
"answerSpeed": {
  "windows": [
    { "window": "5m", "endToEndTps": 42.1, "medianTps": 46.0,
      "medianTtftSec": 6.4, "p90TtftSec": 14.2, "requests": 402 },
    { "window": "1h", "endToEndTps": 41.3, "medianTps": 45.1,
      "medianTtftSec": 6.2, "p90TtftSec": 13.8, "requests": 4804 }
  ],
  "minTokensForMedian": 32
}
```

- `endToEndTps` — сквозная скорость, ток/с: Σ токенов ÷ Σ полного времени запросов.
- `medianTps` — медиана скорости по запросам (ток/с); в медиану входят только запросы
  с выходными токенами ≥ `minTokensForMedian` (короткие ответы сильно занижают оценку).
- `medianTtftSec`, `p90TtftSec` — время до первого токена, с.
- `requests` — число запросов, завершённых в окне.
- Нет данных — `null`, не `0`.

Тип на фронте (frontend/src/features/localModel/types.ts):

```ts
answerSpeed?: {
  windows: {
    window: string;
    endToEndTps?: number | null;
    medianTps?: number | null;
    medianTtftSec?: number | null;
    p90TtftSec?: number | null;
    requests?: number;
  }[];
  minTokensForMedian?: number;
} | null;
```
