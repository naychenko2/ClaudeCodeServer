# ADR-008: Фон проекта — контракт генерации без разметки, серверная сборка тайла и форма хранения

**Статус:** Принято (к реализации, волны 2–6 фичи «Свой фон у каждого проекта»)
**Дата:** 2026-08-11
**Принимающий решение:** Андрей (владелец продукта)
**Автор:** Александр (тимлид/архитектор)
**Реализация:** backend — Денис, frontend — Кира, приёмка — Вера
**Связанные:** [docs/features/project-backgrounds.md](../features/project-backgrounds.md) —
источник правды по текстам интерфейса и критериям снятия флага (настоящий ADR текстов
не задаёт и не переопределяет); [ADR-005](ADR-005-link-reader-server.md) §2 — образец
принципа fail-closed на чужом контенте.

## Контекст

`CanvasBackdrop.tsx` рисует один статический SVG-тайл 260×260 (терминал, скобки, git-граф,
файлы) через `mask-image`; цвет линий задаётся снаружи одним `background-color`, поэтому
темизация бесплатна. Продуктовое решение (задача `515b8bba`, согласовано владельцем
2026-08-11): тайл и цвет проекта **генерирует модель по смыслу проекта**, фон виден везде
внутри проекта, всё за флагом `project-backgrounds`, существующим 39 проектам фоны
генерируются разом при включении флага.

Открытый вопрос, ради которого написан этот ADR, поставлен прямо в постановке:

> SVG уезжает в CSS `mask-image` через `data:` — принимать только белый список тегов
> и атрибутов. Модель генерирует разметку, которая попадает в страницу, — это вопрос
> к архитектору.

Ответ ниже — не «какой белый список», а «разметки от модели не будет вообще».

Что уже есть и на что контракт опирается:

- `LocalActionCatalog` + `CheapTextRunner.RunAsync(actionKey, prompt, ownerId: …)` —
  каталог мест применения модели, исполнителя выбирает админ, слот резолвится по владельцу.
- `ProjectManager.IconsDir` (`data/project-icons/{id}/`), `SetIconImage` / `DeleteAsset`,
  каскад удаления папки ассетов при удалении проекта — готовый образец «поля записи + файл».
- `ProjectIcon.Color` — ключ палитры `AGENT_COLORS` (yellow/orange/blue/green/purple/red/
  brown/cyan/pink); `null` = цвет считается из хеша id.
- `BackupPaths.ShouldInclude` — «в архив едет всё в `data/`, кроме перечисленных исключений».
- `FeatureFlagCatalog.All` + `lib/featureFlags.ts` + `useFeature` — трёхшаговая процедура флага.
- Практика разбора ответов фоновых мест — `ExtractJsonObject` в `DocumentAiService`.

## Решение

### 1. Модель не отдаёт разметку. Ни байта

**Модель возвращает данные (числа и строки путей), разметку собирает сервер из
константного шаблона.**

Почему не белый список тегов и атрибутов над сырым SVG модели:

- Санитайзер чужой разметки **fail-open по природе**: он пропускает всё, о чём не знает.
  Поверхность на одном только SVG — `<script>`, `<foreignObject>` (внутри — любой HTML),
  `<use href="…">`, `<image href="…">` (внешний запрос = маячок на чужой хост из страницы
  пользователя), `<style>` с `@import`, обработчики `on*`, XML-сущности. Каждая новая
  версия браузера — потенциально новый вектор, а наш список не обновляется.
- Даже безопасная разметка может быть синтаксически битой: незакрытый тег ломает всю маску,
  и вместо фона пользователь получает пустой экран без диагностики.
- Обратное направление — «модель отдаёт только данные» — **fail-closed**: то, чего нет
  в схеме, физически не попадает в страницу. Валидатор при этом отвечает не за
  безопасность, а за косметику (границы тайла, разумность чисел).

Инвариант формулируется одной строкой и проверяется тестом:

> В `data/project-backgrounds/**` и в ответе `GET …/background/tile.svg` не существует
> ни одного символа, пришедшего от модели, кроме цифр, точки, минуса, пробела, запятой
> и букв команд пути из §3.

### 2. Контракт JSON-ответа модели

#### 2.1. Что уходит в модель

Только `Project.Name` и `Project.SystemPrompt` (первые 800 символов, если задан). Ни
содержимое файлов проекта, ни истории чатов, ни путей на диске — фон не стоит того, чтобы
расширять поверхность утечки: место работает под учёткой владельца, но модель может быть
сторонним провайдером.

#### 2.2. Схема ответа

Ответ — один JSON-объект, без markdown-обвязки. Разбор устойчивый: срезаем ```-заборы,
берём подстроку от первой `{` до последней `}` (как `DocumentAiService.ExtractJsonObject`).

```json
{
  "colorKey": "green",
  "shapes": [
    {
      "x": 18, "y": 20, "rotate": -7,
      "paths": ["M0 0h34v25H0z", "M7 9l4.5 4-4.5 4M17 17h10"],
      "circles": [{ "cx": 5, "cy": 5, "r": 4 }]
    }
  ]
}
```

| Поле | Тип | Ограничение | Нарушение |
|---|---|---|---|
| `colorKey` | строка | ровно один из девяти ключей `AGENT_COLORS` в нижнем регистре | поле игнорируется, тайл принимается |
| `shapes` | массив | 8–14 элементов; хвост сверх 14 отбрасывается | < 8 годных после §3 → отказ генерации |
| `shapes[].x`, `.y` | число | 0 ≤ v ≤ 250, ≤ 1 знак после запятой | фигура отбрасывается |
| `shapes[].rotate` | число | −12 ≤ v ≤ 12; отсутствует = 0 | фигура отбрасывается |
| `shapes[].paths` | массив строк | 0–4 строк, каждая ≤ 512 символов | фигура отбрасывается |
| `shapes[].circles` | массив | 0–4; `r` ∈ [1, 30], `cx`/`cy` ∈ [−2, 46] | фигура отбрасывается |
| — | — | у фигуры суммарно ≥ 1 элемент (`paths` + `circles`) | фигура отбрасывается |
| — | — | суммарная длина всех `d` ≤ 4096 символов | хвостовые фигуры отбрасываются |

Два примитива, а не один: круг дугой `A` модели даются плохо (путаются флаги `large-arc`
и `sweep`, получается клякса), а круг — половина словаря дудлов (git-граф, чекбокс, солнце,
пузырь). Цена — одна ветка в шаблоне сборки и три числа в валидаторе. `rect`/`ellipse` не
заводим: прямоугольник — это `M…h…v…h…z`, эллипс в дудлах не встречается.

Позиционирование фигуры — только `translate(x,y) rotate(rotate)`. Никаких `scale`, `matrix`,
`skew`: масштаб задаётся `stroke-width` шаблона, а произвольная матрица снова открывает
вопрос про габариты.

#### 2.3. Что модели запрещено (в промпте — явно)

Ни `fill`, ни `opacity`, ни `style`, ни `stroke`-атрибуты, ни `<text>`, ни градиенты, ни
любая SVG-разметка в ответе. Маска работает по альфе; цвет и плотность задаёт CSS снаружи,
поэтому любая заливка от модели либо бессмысленна, либо ломает бесплатную темизацию. Схема
их и не принимает — запрет в промпте нужен, чтобы модель не тратила бюджет вывода.

### 3. Валидация путей: алфавит команд и границы чисел

Строка `d` проходит четыре проверки; провал любой = фигура отбрасывается (не весь тайл).

**(1) Алфавит.** Допустимы ровно: `M m L l H h V v C c S s Q q T t A a Z z`, цифры `0–9`,
`.`, `-`, `+`, пробел, запятая, `\t`, `\r`, `\n`. Всё остальное — отказ. Экспоненциальная
запись (`e`/`E`) **запрещена**: она — единственный дешёвый способ получить координату
в миллион символом-другим, а дудлам не нужна.

**(2) Форма чисел.** Регулярка числа — `[+-]?\d{1,3}(\.\d{1,3})?`. Ограничение мантиссы
тремя знаками убивает и «длинные хвосты» вида `1.0000000001`, и раздувание строки.

**(3) Синтаксис.** Первый непробельный символ — `M` или `m`. Число аргументов каждой
команды кратно её арности: `M/L/T` — 2, `H/V` — 1, `C` — 6, `S/Q` — 4, `A` — 7, `Z` — 0.
Команд в одной строке — не больше 40. Это не безопасность, а отсев мусора, который иначе
даст рваный рисунок.

**(4) Габарит.** `maxLocal` фигуры = максимум модуля всех чисел в её `d` плюс, для
окружностей, `|cx| + r` и `|cy| + r`. Требование: `x + maxLocal ≤ 250` и `y + maxLocal ≤ 250`.
Оценка грубая (сверху), точный bbox требовал бы прогона траектории — и не нужен: смысл
проверки в том, чтобы фигура не выехала за тайл. Выехавшая фигура в `repeat`-паттерне
**рвётся**: соседний тайл её не продолжает, видно шов.

Порог годности тайла — **8 фигур**. Меньше — генерация считается неудавшейся целиком:
полупустой тайл выглядит браком, а брак дороже стандартного фона.

### 4. Серверная сборка тайла 260×260

Шаблон — константа сервера, единственный источник размеров и стилей. Из модели в него
приходят только `x`, `y`, `rotate`, `d`, `cx`, `cy`, `r`.

```
<svg xmlns="http://www.w3.org/2000/svg" width="260" height="260"
     viewBox="0 0 260 260" fill="none" stroke="#000" stroke-width="1.9"
     stroke-linecap="round" stroke-linejoin="round">
  <g transform="translate({x},{y}) rotate({rotate})">
    <path d="{d}"/>          <!-- 0..4 -->
    <circle cx="{cx}" cy="{cy}" r="{r}"/>   <!-- 0..4 -->
  </g>
  ... 8..14 групп
</svg>
```

Шаги сборки:

1. Разобрать JSON (§2), отбросить негодные фигуры (§3), проверить порог в 8 фигур.
2. Собрать документ **через `XmlWriter`**, а не конкатенацией строк. Это второй пояс:
   даже при баге валидатора значение уедет в атрибут экранированным и не породит тег.
   Настройки — `OmitXmlDeclaration = true`, UTF-8 без BOM, без отступов (тайл читает
   браузер, а не человек).
3. Числа форматировать через `CultureInfo.InvariantCulture` (`ToString("0.###")`). Запятая
   вместо точки в русской локали ломает `d` молча — на Windows-хосте это не гипотеза.
4. Записать во временный файл и переименовать; ссылку в записи проекта ставить **после**
   успешного переименования (§6).

Слои `CanvasBackdrop` (нимб + паттерн) настоящий ADR **не меняет**: тайл по-прежнему только
альфа-маска, скругления линий заданы шаблоном, нимб — отдельный слой под ней. Меняются лишь
два входа компонента — источник маски (URL тайла проекта вместо константы) и цвет туши/нимба
(цвет проекта вместо `--canvas-ink`/accent). Плотность (`--canvas-alpha`) и её отдельная
калибровка под тёмную тему — зона дизайна, к контракту генерации отношения не имеет.

### 5. Цвет: одна точка истины — `Icon.Color`

Модель **предлагает** ключ палитры; хранится он там же, где жил всегда — в `Icon.Color`.
Отдельного «цвета фона» в записи проекта нет.

- `Icon.Color == null` (цвет автоматический, из хеша id) → генерация проставляет
  предложенный ключ молча: перезаписывать нечего.
- `Icon.Color != null` и отличается от предложенного → **сервер не трогает цвет**.
  Предложение возвращается в ответе эндпоинта (`suggestedColorKey`, `colorApplied: false`),
  диалог показывает фронт, и при согласии делает отдельный вызов существующей смены цвета.
- Фоновый сценарий (генерация при создании проекта, массовый прогон) вопросов не копит:
  предложение просто отбрасывается — модальное окно «про проект, созданный три дня назад»
  хуже, чем несовпадающий цвет.

Почему не хранить цвет фона отдельным полем: два поля с одним смыслом расходятся при первой
же правке цвета иконки, и фон начинает спорить с иконкой в доке и метками задач — ровно то,
что фича должна была починить. Цвет фона = эффективный цвет иконки, всегда.

### 6. Форма хранения: поля записи проекта + файл на проект

**Поля** (`data/projects.json`, аддитивно к `Project`):

```csharp
public enum ProjectBackgroundKind { Pending, Generated, Standard, Failed }

public sealed class ProjectBackground
{
    public ProjectBackgroundKind Kind { get; set; }
    public string? TileFile { get; set; }     // имя файла в data/project-backgrounds/{id}/
    public DateTime? StartedAt { get; set; }  // для Pending — протухание через 10 минут
    public DateTime? GeneratedAt { get; set; }
    public int Attempts { get; set; }
    public string? FailReason { get; set; }   // no-model | bad-json | rejected | io
}

// Project.Background: null = НИКОГДА не пробовали (единственный кандидат массового прогона)
```

**Файл**: `data/project-backgrounds/{projectId}/tile-{guid:N}.svg` — папка на проект, имя
с guid как cache-busting (в точности приём `icon-{guid:N}{ext}` из `ProjectsController`).
Файл иммутабелен: перегенерация пишет новый и удаляет прежний (`DeleteAsset`-паттерн).

Почему файл, а не строка в `projects.json`: стор читается и пишется **целиком** на каждое
изменение любого проекта и уезжает в каждый ответ `GET /api/projects`. Тайл — 2–6 КБ
текста; на 39 проектах это +150–250 КБ в сторе и в каждом списке проектов, ради данных,
которые нужны одному экрану и прекрасно кешируются браузером как отдельный ресурс.

**Сверка с правилом «новое хранилище → сверься с бэкапом» (CLAUDE.md), по всем пяти пунктам:**

1. *Кеш, лог или временный файл?* Нет. Тайл восстановим только повторным вызовом модели —
   это время и деньги. → в основной архив **едет**, исключение в `BackupPaths.ShouldInclude`
   **не нужно** (правило работает от обратного).
2. *Секрет или ключ?* Нет. → в `BackupPaths.SecretFileNames` **не добавляем**.
3. *Хранилище вне `data/`?* Нет, внутри. → `BackupCore.CopyDataTo` **не трогаем**.
4. *Не-JSON стор?* Файлы `.svg` иммутабельны (новое имя при каждой генерации), поэтому
   копирование файлом даёт корректный снимок — «протухшего снимка», как у живой SQLite,
   тут не бывает. Своего способа бэкапа **не требуется**.
5. *Критичный стор?* Нет: потеря тайла = стандартный фон, работа не встаёт. → в
   `BackupValidation.Validate` **не добавляем**.

Плюс шестое, про формат: поле `Background` аддитивно, старый бинарь читает `projects.json`
без него и при следующем `Save` потеряет — потеря невелика (фон вернётся к стандартному,
регенерируется кнопкой), молчаливого обнуления чужих данных нет. **`BackupSchema.Version`
не инкрементируем.** Объём архива растёт примерно на 4 КБ × число проектов — шум.

**Каскады.** Удаление проекта → удалить `data/project-backgrounds/{id}` там же, где сейчас
удаляется папка иконок (`ProjectManager`, строка каскада ассетов). Смена `RootPath`
и переезд между группами фон не задевают: он привязан к id, не к папке.

### 7. API и права

| Метод | Назначение | Гейт |
|---|---|---|
| `POST /api/projects/{id}/background/generate` | сгенерировать / перегенерировать | флаг + владелец |
| `POST /api/projects/{id}/background/reset` | «Вернуть стандартный»: `Kind = Standard`, файл удалить | флаг + владелец |
| `GET /api/projects/{id}/background/tile.svg?access_token=…&v={file}` | отдать тайл | владелец |

- Владение — по конвенции контроллера: `p is null || p.OwnerId != UserId → NotFound()`
  (404, не 403 — чужой проект не должен подтверждать своё существование).
- `access_token` в query у GET — потому что запрос идёт из CSS (`mask-image`), а браузер
  заголовок туда не поставит. Приём уже используется у `GET {id}/icon`.
- Ответ GET: `Content-Type: image/svg+xml`, `X-Content-Type-Options: nosniff`,
  `Content-Security-Policy: default-src 'none'`, `Cache-Control: private, max-age=604800,
  immutable` (имя файла меняется при регенерации, поэтому долгий кеш безопасен). CSP на
  собранном нами файле избыточен — и стоит одну строку на случай бага в сборке.
- Ответ POST: `{ kind, tileVersion, suggestedColorKey, colorApplied }`. Тексты состояний
  и ошибок для UI — в [docs/features/project-backgrounds.md](../features/project-backgrounds.md),
  здесь не дублируются.

### 8. Место в каталоге моделей

Новая строка `LocalActionCatalog`:

```csharp
public const string ProjectBackground = "project-background";
new(ProjectBackground, "Фон проекта", "Проекты", CheapProfile.Large,
    DefaultLocal: false, Tier: ModelTier.Strong)
```

- `Large` — ответ на 8–14 фигур это 2–4 КБ JSON; на профилях `Small`/`Text` потолок вывода
  обрежет его на полуслове, и получится неотличимый от таймаута «bad-json» (прецедент —
  планировщик «Командной реализации», 2026-08-05).
- `DefaultLocal: false` — решение владельца: рисование SVG не текстовая задача, локальная
  модель даёт кашу из линий. Это же выключает локаль и как страховку в цепочке
  `CheapTextRunner` (`LocalStepApplies`), что здесь и нужно: «сойдёт за успех» тут дороже отказа.
- Вызов — `RunAsync(ProjectBackground, prompt, ownerId: project.OwnerId)`: слот резолвится
  по владельцу проекта через `UserModelTierResolver`, а не по тому, кто нажал кнопку.

### 9. Процедура заведения флага — три шага

1. **Бэк:** строка в `FeatureFlagCatalog.All` + константа в `FeatureFlagKeys`:
   `Key: "project-backgrounds"`, `Title: "Свой фон у каждого проекта"`, `Default: false`,
   `Stage: "dev"`. Описание — из [features/project-backgrounds.md](../features/project-backgrounds.md).
2. **Фронт:** ключ в const `FLAGS` (`lib/featureFlags.ts`) — ровно та же строка.
3. **Обёртка:** `useFeature(FLAGS.projectBackgrounds)` гейтит раздел «Оформление» в настройках
   проекта и выбор источника маски в `CanvasBackdrop`; на бэке тот же флаг гейтит оба POST-эндпоинта
   и массовый прогон. Тумблер в модалке появится сам — он рендерится из каталога.

Снятие флага — по критериям приёмки из features-доки, здесь не дублируются.

### 10. Массовая генерация и её идемпотентность

Триггер — включение флага владельцем (и подстраховка на старте сервера: флаг включён,
кандидаты есть). Исполнитель — фоновый сервис.

- **Кандидаты отбора (`ProjectBackgroundBackfill.IsCandidate`):** `Background == null`,
  либо `Kind == Pending` со `StartedAt` старше 10 минут (сервер упал в середине). `Generated`
  и `Standard` не трогаются **никогда** — у них есть фон, перетирать который прогоном нельзя.
- **Транзиентный `Failed` возвращается в кандидаты — но только по явному включению флага**
  (`allowTransientRetry` в `RunAsync`, ставится только из `KickOff` эндпоинта
  `PUT /api/feature-flags/{key}`, не из стартового `RunAllAsync`). `FailReason ∈
  TransientReasons = ["no-model", "io"]` и `Attempts < MaxTotalAttempts (3)`. Сценарий,
  ради которого это нужно: типовое первое включение — строка каталога «Фон проекта» ещё
  не настроена или слот пуст → все проекты падают в `no-model` → админ настраивает модель,
  и повторное включение флага доводит фоны до конца. Со старта сервера возврата нет: иначе
  мёртвая модель долбилась бы при каждом рестарте. `bad-json`/`rejected` кандидатами не
  становятся никогда — причина в модели или проекте, повтор даст ту же кашу и счёт за токены.
- **Два порога попыток.** `MaxAttempts = 2` — внутрипрогонный: гасит случайный таймаут или
  rate limit здесь и сейчас, в рамках одного `GenerateOneAsync`. `MaxTotalAttempts = 3` —
  пожизненный потолок поля `Attempts` (счётчик растёт в `TryBeginBackground`): не даёт
  мёртвой модели долбиться при каждом включении флага. Перед каждой попыткой стор
  перечитывается, и при `Attempts >= MaxTotalAttempts` цикл останавливается — даже если
  внутрипрогонные `MaxAttempts` ещё не вышли.
- Отдельного стора «что уже прогнали» нет: состояние живёт в самой записи проекта, поэтому
  повторный запуск прогона — no-op (кандидатов не осталось). Это и есть идемпотентность;
  отдельный маркер был бы вторым источником истины и рассинхронизировался бы со стором.
- Взятие в работу — `Kind = Pending` + `StartedAt` под тем же локом, что и `Save()`
  в `ProjectManager`: два тика сервиса или тик и кнопка не заберут один проект дважды.
  `TryBeginBackground(candidatesOnly)` пропускает `null`/`Pending`/`Failed` и не пускает
  `Generated`/`Standard` — защита от перетирания чужой успешной работы; `Failed` проходит,
  потому что `IsCandidate` уже решил, что этот `Failed` — кандидат (у него нет тайла, портить нечего).
- Темп: не больше 2 генераций одновременно на инстанс и не больше 1 на владельца. 39
  залповых вызовов сильной модели упрутся в rate limit, и половина проектов получит
  `Failed` там, где виновата очередь, а не модель.

### 11. Инварианты

1. **Ни байта разметки от модели.** В странице только документ, собранный `XmlWriter`
   из шаблона §4; от модели в нём — числа и провалидированные строки `d`.
2. **Фолбэк на стандартный дудл.** Любой сбой (модели нет, JSON битый, фигур меньше восьми,
   файл не записался) оставляет `Kind != Generated`, и фронт рисует нынешний статический тайл.
   Пустого экрана без фона не бывает ни в одном состоянии.
3. **Атомарность записи.** Ссылка `TileFile` появляется в сторе только после успешного
   переименования временного файла. Обратная ситуация («ссылка есть, файла нет») деградирует
   штатно: GET отдаёт 404, фронт показывает стандартный фон.
4. **Идемпотентность массового прогона.** Кандидат — `Background == null` или протухший
   `Pending` всегда; транзиентный `Failed` (`no-model`/`io`) с `Attempts < MaxTotalAttempts` —
   только по явному включению флага, не со старта сервера. `Standard` (пользователь вернул
   стандартный), `Generated` и фатальный `Failed` (`bad-json`/`rejected`) автоматически не
   перегенерируются. Потолок `Attempts` не даёт мёртвой модели долбиться при каждом включении.
5. **Один цвет на проект.** Цвет фона = эффективный цвет иконки. Явно заданный
   `Icon.Color` сервер молча не перезаписывает — только предлагает замену через ответ API.
6. **Права владельца.** Генерация и сброс — только `OwnerId == UserId`; чужой проект — 404.
   Участник проекта, не являющийся владельцем, фон менять не может.
7. **Путь к файлу не строится из запроса.** Каталог — из `projectId` уже найденной в сторе
   записи, имя файла — из `TileFile` того же стора. Имя из query в путь не попадает
   (иначе это обход `SafeJoin` на ровном месте).
8. **Каскад.** Удаление проекта уносит `data/project-backgrounds/{id}`; регенерация удаляет
   прежний файл. Осиротевших тайлов не остаётся, сборщика сирот не требуется.
9. **Бэкап.** Тайлы едут в основной архив по умолчанию; исключений, секретов, своего
   способа копирования и инкремента `BackupSchema.Version` не требуется (сверка — §6).
10. **Тайл — только альфа.** В собранном документе нет `fill` (кроме `none` шаблона),
    `opacity`, `style`, `text`, градиентов и ссылок наружу. Цвет и плотность задаёт CSS.

## Альтернативы, которые отклонены

| Вариант | Почему нет |
|---|---|
| Сырой SVG от модели + белый список тегов/атрибутов | Fail-open: пропускает всё неизвестное. `foreignObject`, `use`, `image href`, `@import`, сущности — и это только сегодняшний список. Поддерживать его вечно дороже, чем не принимать разметку вовсе |
| Тайл строкой в `projects.json` | Стор пишется целиком и уезжает в каждый `GET /api/projects`: +150–250 КБ на ровном месте, без браузерного кеша |
| `data:`-URL тайла в DTO проекта | То же раздувание ответа плюс точный percent-encode на фронте как условие безопасности — лишний способ ошибиться |
| Библиотека готовых пресетов вместо генерации | Отклонено владельцем 2026-08-11 по тесту на 10 реальных проектах прода |
| Растровая картинка (fal.ai/glif) вместо SVG | Теряется бесплатная темизация: маска по альфе перекрашивается одним CSS-свойством, растр — нет. Плюс вес и невозможность перекраски под тему |
| Отдельное поле «цвет фона» в записи проекта | Второй источник истины о цвете; расходится с иконкой при первой правке |
| Автоматический ретрай неудачных генераций | Безусловный ретрай по кругу — счёт за токены без нового результата: причина отказа обычно не в попытке, а в модели или проекте. Поэтому отклонён **безусловный** ретрай; принят узкий — только транзиентный `Failed` (`no-model`/`io`), только по явному включению флага (не со старта сервера), с пожизненным потолком `Attempts` (§10) |

## Последствия

- В диалоге «Поставщики моделей» (уровень 3) появляется строка **«Фон проекта»** —
  админ может увести её на другую модель; дефолт — сильный слот.
- В `data/` появляется папка `project-backgrounds/`; архив растёт примерно на 4 КБ × проект.
- `CanvasBackdrop` получает два входа (источник маски, цвет) и обязан уметь работать без них —
  состояние «стандартный фон» остаётся штатным, а не переходным.
- Единоразовая стоимость при включении флага: 39 вызовов сильной модели, профиль `Large`.
- Риск, который ADR **не закрывает**: визуальный брак. Порог в 8 фигур отсекает пустые
  тайлы, но не гарантирует, что рисунок красив и в тему. Страховка — продуктовая: кнопки
  «Сгенерировать заново» и «Вернуть стандартный» плюс критерий снятия флага «ни один не
  выглядит браком».

## Что проверять при реализации

- Тест инварианта §11.1: подсунуть в ответ модели `d` со `<`, `"`, `script`, экспонентой,
  координатой 10⁶ — все отбиты валидатором, а собранный документ (при обходе валидатора
  в тесте) не содержит нового тега благодаря `XmlWriter`.
- Тест локали: сборка под `ru-RU` даёт `d` с точками, а не запятыми.
- Тест идемпотентности: два прогона подряд не создают второго файла и не дёргают модель
  для `Standard`/`Failed`/`Generated`.
- Тест прав: не-владелец получает 404 на всех трёх эндпоинтах.
- Тест каскада: удаление проекта уносит папку тайлов.
- `BackupPaths.ShouldInclude("project-backgrounds/{id}/tile-x.svg") == true`.
