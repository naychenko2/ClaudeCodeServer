## Контекст

Продуктовое решение принято и согласовано владельцем (интервью 2026-08-01, 7 развилок):
у каждого изменения кода появляется «паспорт» — AI-выжимка «зачем, что решили, что отвергли,
какие грабли», рождающаяся автоматически при коммите из чата/задачи, якорящаяся к файлам и
символам, живущая в общем слое знаний проекта и подмешивающаяся персонам в промпт при работе
с кодом. Этот ADR закрывает техническую часть: где хранить, как связать коммит с чатом, как
снимать выжимку, как доставлять в промпт, как экспортировать в git и что делать при
удалениях и переписи истории.

### Что уже есть в коде (и на что опираемся)

### Силы и ограничения

- **Per-owner изоляция.** Стор ключуется `owner:project`, как память команды. У разных
  владельцев допустима общая папка проекта (`ProjectManager.GetByRootPath`) — значит
  git-экспорт паспортов в общий репозиторий делает их видимыми соседу по папке.
- **Не трогать репозиторий пользователя.** Прецедент — вложения чата: правило пишется в
  `$GIT_COMMON_DIR/info/exclude`, а не в `.gitignore` проекта.
- **Коммиты из чата делает агент через Bash** (`git commit`), а не сервер. Серверный
  `git_commit` (MCP `workspace-server`, секция `git_write`) — редкий путь, по умолчанию
  выключенный. Значит «сервер знает про коммит» — не данность, её надо построить.
- **Состав `tools/list` не зависит от хода** (CLAUDE.md) — любой новый MCP-инструмент
  паспортов включается по владельцу/флагу, но не по свойствам конкретного хода.
- **Качество выжимки — главный продуктовый риск**, отсюда двухшаговая выкатка.

## Решение

Пять подсистем; каждая — минимальное расширение существующего механизма.

```
   чат/задача  --(коммит с трейлером CCS-Session)-->   git
        |                                               |
        |                                    DossierCaptureService
        |                                     (детект + сбор сырья)
        v                                               v
   лента хода  ------------------------------>  CheapTextRunner
                                                 (выжимка JSON)
                                                        |
                                                 SecretRedactor
                                                        v
                                    +-------------------+------------------+
                                    |                                      |
                          data/dossiers/{owner}/                  Dify: {ns}:{user}:
                            {project}.json                        dossiers:{project}
                          (source of truth)                       (семантика + фильтры)
                                    |                                      |
                                    +-------------------+------------------+
                                                        v
                                          recall в промпт персоны
                                       (секция в PersonaMemoryService)
                                       + MCP dossier_lookup / dossier_get
                                                        |
                                                        v
                                       git-экспорт в ветку ccs/dossiers/v1
                                            (вручную, plumbing, без checkout)
```

### 1. Связь «коммит ↔ чат-источник» — трейлер в сообщении коммита

**Сессия помечает себя сама, в сообщении коммита:**

```
feat(dossiers): добавить захват паспортов

CCS-Session: 8f2a1c34-…             <- обязательный трейлер
CCS-Task: a035ce8b-…                <- если коммит в рамках задачи
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

Инструкция уходит одной строкой в системный промпт хода — там, где уже живёт конвенция
`Co-Authored-By`. Сессия знает свой id (он уже прокидывается в MCP как `TASKS_SESSION_ID`,
ADR-001), поэтому дополнительных вызовов и состояния не требуется.

**Имена трейлеров неймспейснуты префиксом `CCS-`.** Голый `Task:` — распространённая
конвенция ссылки на внешний трекер (`Task: JIRA-123`), и чужое значение по ней не должно
даже доходить до разбора; `CCS-Session` заодно держит симметрию имён. Нераспознанные
трейлеры игнорируются молча — паспорт не создаётся, ошибка никуда не пишется.

**Трейлер — не доверенный ввод.** Это обычный текст в сообщении коммита: его пишет кто
угодно — человек руками, модель по инъекции из чужого README, соседний инстанс. Значение
трейлера — не ключ, а заявка, и она проверяется до любого использования:

1. **Формат** — `^[A-Za-z0-9_-]{1,128}$`, по образцу
   [`TranscriptMigrator.IsSafeSessionId`](../../backend/ClaudeHomeServer/Services/Llm/TranscriptMigrator.cs):
   тот же класс значений (id уходит в ключи стора и в метаданные документа Dify), тот же
   белый список вместо запрета разделителей. Не прошёл — трейлера как будто нет.
2. **Принадлежность** — сессия ищется в реестре и принимается, только если
   `session.OwnerId == project.OwnerId && session.ProjectId == project.Id`. Сессия не
   найдена; `OwnerId`/`ProjectId` пусты (глобальный или личный чат); не совпали — паспорт
   не создаётся. Проверка fail-closed: сомнение трактуется как «не наш чат».
3. То же для `CCS-Task:` — задача принимается, только если принадлежит тому же владельцу
   и тому же проекту; иначе `taskId` просто не заполняется, паспорт остаётся.

Без пункта 2 фича дырявит per-owner изоляцию в первом же штатном сценарии: одна папка,
подключённая как проект и владельцем A, и владельцем B, — это поддерживаемый случай
(`ProjectManager.GetByRootPath`, на нём держатся каскады «соседей по папке»). Оба
`DossierCaptureService` видят один и тот же коммит с трейлером чата A, и сервис владельца B
без проверки затянет реплики чужого чата к себе в стор и в свой датасет Dify. Подделка
чужого id руками или инъекцией — тот же вектор, менее вероятный, но закрывается той же
проверкой.

**Id чата уезжает в публичный remote** — вместе с обычным `git push` кода, в сообщении
коммита, навсегда и без нашего участия. Решение осознанное: id — непрозрачный uuid, сам по
себе он ничего не раскрывает и вне инстанса ни к чему не резолвится (реестр сессий
per-owner и живёт только у нас). Цена — в публичной истории видно, что коммит сделан
агентом из чата, и видно число различающихся чатов. Убрать трейлер из публичной истории
без потери атрибуции нельзя: на нём всё и держится.

Почему трейлер, а не «сервер угадает»:

- **Явность** (требование, заимствованное у Git AI): чат называет себя сам, сервер не гадает
  по времени и автору. Параллельные ходы двух чатов в одном проекте, ручной коммит человека
  поверх агентских правок, `git commit --amend` через час — всё это ломает любую эвристику.
  `FileChangeAttributor` для этого не годится принципиально: его окно 15 с и его вопрос —
  «в чью ленту показать карточку», а не «кто автор коммита».
- **Переживает перепись истории.** Squash фича-ветки конкатенирует сообщения — трейлеры
  всех сжатых коммитов попадают в новый; rebase/cherry-pick/amend сообщение переносят. Это
  закрывает требование «перенос якорей при squash/merge» без CI-инфраструктуры, которая
  понадобилась Git AI (у них якорь — строки, у нас — текст сообщения и символы). Даром это
  не даётся: трейлер не уникален per-коммит, поэтому «тот же трейлер» ≠ «тот же коммит» —
  правило различения squash и очередного обычного коммита в §7.
- **Восстановимость.** Даже если сервер лежал в момент коммита, факт «этот коммит родом из
  чата X» остаётся в git навсегда и паспорт можно снять позже — пока жив сам чат: сырьё
  выжимки берётся из его ленты. Удалён чат — паспорт задним числом уже не снять (и проверка
  принадлежности выше его всё равно бы не пропустила).

Второй канал (без трейлера): MCP `git_commit` — там сервер знает `X-Caller-Session-Id` и
**сам** дописывает трейлер перед коммитом.

Если трейлера нет — коммит считается «не из чата», паспорт не создаётся. Это осознанный
недосбор вместо ложной атрибуции.

### 2. Детекция коммита — серверный поллинг, без git-хуков

`DossierCaptureService` (hosted service): для проектов, где за последние N минут был активный
ход, сравнивает HEAD с последним виденным (`data/dossiers/state.json`), берёт дельту через
`FileService.GetCommitsRaw` + `git show --stat`, парсит трейлеры и **проверяет каждый по
правилам §1** (формат + принадлежность сессии владельцу и проекту) — только после этого
коммит идёт в конвейер выжимки. Тик 60 с, плюс внеочередная проверка по завершении хода
сессии — тогда паспорт появляется через секунды, а не через минуту.

**Единица наблюдения — рабочее дерево, а не проект.** Чат с `Session.WorktreePath` коммитит
в своё дерево, на свою ветку; HEAD корня проекта такого коммита не увидит вовсе — а именно
так работает командная реализация (`team-implement`, ADR-003). Поэтому:

- `state.json` ключуется `{ownerId}:{projectId}:{хеш EffectiveRoot}` — своё «последнее
  виденное HEAD» на каждое дерево (тот же ключ, что у снимка CodeGraph в ADR-003);
- внеочередная проверка по завершении хода идёт по `EffectiveRoot` **этой** сессии, а не по
  корню проекта;
- фоновый тик обходит корень проекта плюс деревья активных worktree-чатов (из
  `Session.WorktreePath` живых сессий) — списка `git worktree list` не спрашиваем, чужие
  деревья пользователя нас не касаются.

Коммит, увиденный в дереве, туда и относится: достижимость (§7) считается от HEAD того же
дерева, объектная база у них общая.

**Фильтр захвата (объём/стоимость).** Каждый паспорт — вызов модели, а ~43% коммитов
выжимать нечего (замер прода: 8% merge, 30% однофайловых, 5% — `style`/`chore`/`build`/`ci`).
Поэтому после проверки трейлера, но до конвейера выжимки, захват молчаливо (opt-out) пропускает:

- **merge-коммиты (2+ родителя)** — признак из git (`git show -s --format=%P`), а не из текста:
  стандартные автомержи «Merge branch …» conventional-типом не разбираются и фильтром по типу
  не ловятся; выжимка по мержу лишь пересказывает паспорта коммитов самой ветки. В
  `SkipCommitTypes` `merge` НЕ добавляем — иначе обычный коммит с таким префиксом молча потеряется;
- коммиты conventional-типов из `Dossiers:SkipCommitTypes` (дефолт `style`, `chore`, `build`,
  `ci` — меняется без пересборки);
- однофайловые правки, чьё сообщение (subject + body без служебных трейлеров) короче ~100
  символов — содержание для выжимки отсутствует.

Фильтр применяется **только на новом захвате**: переякорение при squash ему не подчиняется —
перепись истории объединяет в теле и `feat`, и `chore`, и потерять якорь существующего
паспорта из-за типа/merge нового коммита нельзя. Пропуск не теряет факт коммита: при
необходимости снимается переякорением, а «зачем» служебного коммита и так в его сообщении.

Отвергнуто — **git-хук `post-commit`** (путь Entire/Git AI): хук получил бы `sessionId` из
унаследованного env бесплатно, но (а) это запись в репозиторий пользователя, против нашего
прецедента с `info/exclude`; (б) чужой существующий `post-commit` пришлось бы либо
перезаписать, либо чейнить — оба варианта плохи; (в) в среде `container` хуку нужен доступ к
бэкенду и хостовые/контейнерные пути расходятся; (г) Entire ставит **свои** хуки через
`.claude/settings.json`, которым управляет наш сервер, — конфликт ровно в этой точке уже
зафиксирован как риск пилота.

Отвергнуто — **git notes** (путь Git AI): notes не переживают ремоут-операции без явного
`refs/notes` push/fetch, а UI git-хостингов их не показывает. Ветка (путь Entire) лучше,
см. §5.

### 3. Конвейер выжимки

Триггер — обнаруженный коммит с трейлером. Сырьё: `git show --stat` + сообщение коммита,
**окно реплик хода по времени коммита** (не весь чат и не «последние N»: сессия живёт сутками
и ведёт несколько дел — берётся кластер реплик вокруг `CommittedAt`: окно ±до/после плюс
отсечка по паузе между делами; только пользовательские реплики и финальные ответы ассистента,
с потолком по символам), карточка задачи (`title`, `description`, `resultMarkdown`). Коммит и
diff — главный якорь выжимки: «зачем» обязано объяснять именно эти файлы, а если реплики
окна говорят про другое дело — модель опирается на сообщение коммита и diff.

Шаги:

1. **Редакция секретов ДО модели.** Новый `SecretRedactor` (чистая статическая логика, под
   тестами):

   - **(а) точные значения известных секретов инстанса** — `LlmProviders:*:ApiKey`,
     `Dify:ApiKey`, содержимое `jwt-secret.txt`, VAPID-ключи, **токены подписки Claude**
     (`ClaudeSubscriptions:*:OAuthToken|ApiKey`, `CLAUDE_CODE_OAUTH_TOKEN` из окружения,
     значения из `.credentials.json` профилей CLI) и **ключи модулей** (`module-keys.json`).
     Полный список — ровно то, что бэкап уводит в отдельный локальный архив
     (`BackupPaths.SecretFileNames` + правило `.credentials.json`): один перечень секретов
     инстанса на две подсистемы, расходиться им нельзя. Набор собирается один раз и живёт
     в памяти сервиса (перечитывается по смене конфига и по времени записи файлов
     профилей) — читать `.credentials.json` на каждую редакцию слишком дорого.
   - **(б) regex-формы** — `sk-…`, `sk-ant-…`, `ghp_…`, `AKIA…`, JWT-триплет, `Bearer …`,
     строки подключения, **PEM/SSH-блоки** целиком: от `-----BEGIN … PRIVATE KEY-----` до
     `-----END … KEY-----` (агент вставляет такой блок в ленту при отладке доступов, а
     построчного совпадения в нём нет — резать надо блоком).
   - **(в) строки из diff'а, похожие на присваивание секрета** —
     `(?i)(api[_-]?key|token|secret|password)\s*[=:]\s*\S+`.

   Замена на `[REDACTED:kind]`. Порядок «сначала точные значения, потом regex» важен:
   точные значения ловят то, что regex не знает.

   **Порог длины для (а).** Точное значение участвует в замене-по-подстроке, только если
   оно непустое и длиннее 12 символов. Пустой `ApiKey` — штатное состояние (пустой ключ =
   провайдер выключен, CLAUDE.md), а короткое значение из тестового конфига превратило бы
   редактор в решето: подстрока `test` есть в половине текстов, и на выходе получился бы
   нечитаемый паспорт вместо безопасного. Отсечённые значения не молчат — сервис пишет
   предупреждение в лог при старте.
2. **Выжимка** — `CheapTextRunner.RunAsync` с новым ключом `LocalActionCatalog`
   `dossier-summary` (группа **«Паспорта изменений»**, профиль **Large**,
   `DefaultLocal: true`) и `jsonFormat: "json"`. Профиль Large (`NumCtx 16384`, `NumPredict 1024`) — тот же, что у
   `ChatExtractTasks`, у которого точно такое же сырьё: реплики хода целиком. В Text
   (`8192`/`768`) сырьё «diff --stat + реплики хода + карточка задачи» упирается в окно на
   любом нетривиальном коммите, а обрезка контекста снизу даёт ровно ту выдуманную выжимку,
   ради борьбы с которой заведён второй флаг. Цена смены профиля названа прямо: слот по
   умолчанию считается из профиля (`LocalActionCatalog.EffectiveDefaultTier`: Small/Text →
   слабая, Large → **средняя**), то есть облачный фолбэк места дорожает на шаг. Это
   приемлемо — место фоновое и редкое (≈ по вызову на коммит из чата), локаль всё равно
   первая в маршруте, а админ волен вернуть слабый слот в таблице назначений. Потолки сырья
   при этом всё равно явные:
   реплики хода ≤ 12 000 символов (обрезаем с начала, финальные ответы важнее), `git show
   --stat` ≤ 4 000, карточка задачи ≤ 2 000. Контракт ответа:
   `{ why, decisions[], rejected[], pitfalls[], invariants[] }`, каждый пункт ≤ 200
   символов. Пустые секции допустимы — «отказов не было» это валидный ответ, выдумывать их
   модель не должна (явный запрет в промпте).
3. **Редакция после модели** — тот же `SecretRedactor` по сгенерированному тексту (модель
   может процитировать то, что просочилось мимо шага 1).
4. **Якорение.** Файлы — из `git show --name-only` (относительные пути). Символы — по
   снимку CodeGraph того же `rootPath` (`EffectiveRoot` сессии, т.е. корректно для
   worktree-чатов, ADR-003): типы, чей `SourceFile` попал в список изменённых файлов
   (форматы совместимы — и git, и граф хранят относительный путь от rootPath через `/`).
   Не-C# файлы (`.tsx`, `.md`, конфиги) — **файловый уровень без символов**, честное
   ограничение v1. Граф строится лениво по запросу к CodeGraph API, а захват берёт готовый
   снимок (пересборка на тике коммита не триггерится — дорогой Roslyn-анализ). Поэтому если
   снимка для дерева ещё нет — символов не будет; в этом случае захват фоново запрашивает
   построение (`StartRebuildIfIdle`), и следующие коммиты этого дерева символы получат.
   Подробнее и цифры — §7 «Символы-якоря в v1».
5. **Сохранение** в стор → постановка в очередь Dify-синка (дебаунс, как у памяти).

Если выжимка не удалась (модель недоступна, JSON не распарсился) — паспорт сохраняется
«скелетом» (сообщение коммита + якоря + ссылки) с флагом `summaryFailed`, и в recall не
участвует. Терять факт коммита из-за упавшей модели нельзя: сырьё (ход) со временем уедет.

### 4. Хранение

**Стор (source of truth):** `data/dossiers/{ownerId}/{projectId}.json` — по образцу
`team-memory.json`, но с разбивкой по владельцу и проекту, потому что растёт линейно с
коммитами (**~5.2 КБ на паспорт** по замеру прода 2026-08-08 — ранние ~1.5 КБ были занижены
в 3.5×). Потолок `Dossiers:MaxEntries` (дефолт **5000** ≈ 26 МБ). Это верхняя граница терпимого
для whole-file JSON: `Save()` переписывает файл **целиком на каждое добавление** (~30 коммитов
с паспортом в день), список держится в памяти, а `data/` целиком едет в бэкап — 100 МБ на
проект при потолке 20000 означали бы впустую ~3 ГБ записи в день и +100 МБ в каждый архив.
Индекс «файл/символ → паспорта» строится в памяти при загрузке — отдельного файла-индекса нет,
второй источник истины не заводим.

**Архивный JSONL — не бесплатный.** Вытесненные в `{projectId}.archive.jsonl` записи append-only
и **не участвуют в поиске и recall** — старые паспорта фактически выпадают из ценности фичи.
Поэтому «просто крутить потолок вверх» проблему объёма не решает: это лишь откладывает
вытеснение, а ценность вытесненного всё равно теряется. Решение объёма — фильтр захвата (§2,
отсекает ~35% коммитов) либо смена модели хранения.

**Триггер перехода на SQLite — измеримый, не «когда-нибудь».** Переходим, когда файл проекта
превышает **~15 МБ** ИЛИ записей больше **3000** (при текущем темпе с фильтром — достижимо за
~5–8 мес). При подходе к порогу стор пишет warning в лог (счётчик записей и размер файла),
чтобы узнать о необходимости переезда до того, как whole-file `Save()` и бэкап станут ощутимо
тяжёлыми. Переезд обратим и локален — интерфейс сервиса не меняется (миграция данных в SQLite,
индексы по якорям вместо in-memory скана).

Запись паспорта:

```
id, ownerId, projectId, commitSha, commitSubject, committedAt,
supersededSha[],                         // прежние SHA после squash/rebase (§7)
sessionId, taskId, personaId,            // ссылки, могут протухнуть
files[], symbols[],                      // якоря
why, decisions[], rejected[], pitfalls[], invariants[],
sourceHash, difyDocId,                   // дифф-по-хешам, как в памяти
status: active | degraded | archived
```

**Ключ уникальности — `ownerId + projectId + commitSha`** (плюс совпадение с любым из
`supersededSha`). Захват идемпотентен по нему: повторно увиденный коммит обновляет
существующую запись, а не плодит вторую. Это не косметика — стор восстанавливается из
бэкапа вместе с `state.json`, и откат к снимку недельной давности иначе означал бы
повторный захват всей недели с дублями паспортов и дублями документов в Dify.

**Семантический слой:** датасет Dify `{username}:dossiers:{projectName}` (префикс
`Dify:Namespace` добавляется `KnowledgeService` сам, как везде). Метаданные документа:
`files`, `symbols`, `commit`, `task_id`, `persona`, `session`, `date` — по ним работают
фильтры `knowledge_search`. Без настроенного Dify — graceful degradation к полнотекстовому
поиску по стору, как у памяти команды.

**Бэкап** (правило «Новое хранилище → сверься с бэкапом»):

- `data/dossiers/**` попадает в архив автоматически (`ShouldInclude` работает от обратного) —
  и это верно: паспорта невосстановимы, сырьё для них исчезает вместе с историей чатов.
- Исключения не нужны: кешей и временных файлов в сторе нет.
- В `BackupPaths.SecretFileNames` добавлять нечего — секретов стор не содержит (§3 их
  вычищает). Обратная связь есть: `SecretRedactor` **читает** этот же список как перечень
  секретов инстанса, поэтому новый секрет добавляется в него один раз и закрывает обе
  подсистемы сразу.
- Хранилищ вне `data/` фича не заводит (ветка `ccs/dossiers/v1` живёт в репозитории
  пользователя и бэкапится его собственным remote).
- В `BackupValidation.Validate` **не добавляем**: паспорта не критичны для старта сервера,
  их порча не должна блокировать восстановление всего остального. `.archive.jsonl` — не JSON,
  но append-only, копирование файлом даёт консистентный снимок.
- `BackupSchema.Version` **не инкрементируем**: новый стор — не ломающее изменение формата
  существующих.

### 5. Recall в промпт персон

Два канала, как у графа кода (ADR-002/003): пассивный бюджет в промпте + активные
MCP-инструменты.

**Пассивный.** Новая секция в блоке, который уже собирает `PersonaMemoryService.BuildRecallAsync`
(после личной памяти и памяти команды). Бюджет — **до 3 паспортов, каждый ≤ 300 символов,
суммарно ≤ 1 КБ**; формат: «зачем + до двух пунктов из decisions/rejected + ссылка
`dossier_get(id)` за подробностями». Обоснование бюджета: личная память усекает записи до
240 символов и берёт единицы записей; блок паспортов не должен весить больше остальной памяти
вместе взятой.

**Запрос recall.** Проблема: релевантность паспорта определяется кодом, который персона
будет трогать, а состав промпта фиксируется в начале хода. Поэтому пассивный канал
ранжирует по якорям, известным **на старте хода**: `linkedFiles` задачи, файлы из текста
хода, файлы, затронутые предыдущим ходом этой сессии; плюс семантика по тексту хода. Всё,
что выясняется по ходу дела, добирается активно.

**Активный.** MCP `dossier_lookup(path|symbol|query)` и `dossier_get(id)` — новая секция
инструментов memory-сервера (состав `tools/list` фиксирован на запуск: секция включается по
флагу владельца, не по свойствам хода).

**Ранжирование:** `score = семантика × свежесть × статус`, где статус — множитель
градуированного устаревания:

| Состояние символа/файла | Как определяем | Статус | Множитель |
|---|---|---|---|
| Символ на месте, файл после паспорта менялся мало (≤ 3 коммитов ИЛИ ≤ 30 % строк) | `git log --oneline {sha}..HEAD -- {file}` + `--numstat` | `active` | 1.0 |
| Символ на месте, файл существенно переписан | там же | `degraded` | 0.5, в промпте пометка «код с тех пор менялся» |
| Узла с таким FQN в актуальном снимке CodeGraph нет | снимок графа `rootPath` | `archived` | 0 в пассивном канале; доступен через `dossier_lookup` |

Пересчёт — **лениво при recall**, с кешем на версию снимка графа/HEAD. Фонового сканера
устаревания нет: он платил бы git-вызовами за паспорта, которые никто не спрашивает.
Удаления при этом не происходит никогда (решение владельца).

### 6. Git-экспорт — ветка `ccs/dossiers/v1`

Архитектура ветки — как у Entire (обычный push/pull, чистое рабочее дерево, видно в UI
хостинга), в отличие от git notes.

```
ccs/dossiers/v1
├── dossiers/{yyyy}/{mm}/{sha7}-{slug}.md    паспорт: якоря + выжимка + ссылки
├── discussions/{yyyy}/{sess7}-{slug}.md     КОНСПЕКТ обсуждения, не транскрипт
└── index.json                               SHA ↔ паспорт ↔ обсуждение ↔ задача
```

**Техническое требование: пишем через plumbing, без `checkout`.** `git hash-object -w` →
временный индекс (`GIT_INDEX_FILE` во временном файле) → `git write-tree` →
`git commit-tree -p <прошлый>` → `git update-ref refs/heads/ccs/dossiers/v1`. Переключать
рабочее дерево пользователя нельзя ни при каких условиях; временный worktree — тоже нет
(лишние диск и гонки с `Session.WorktreePath`). Расширение — в `GitService`, который уже
гоняет git CLI.

**Предохранители:**

- **Push — только вручную** (кнопка/команда). Автопуш не делаем никогда — соответствует
  git-политике проекта.
- Экспортируются только чаты **этого проекта**; личные и глобальные — никогда.
- Тумблер у чата «не включать в летопись» (opt-out) — уважается и паспортом, и конспектом.
- `SecretRedactor` прогоняется повторно перед записью в ветку (данные могли прийти из
  архива, снятого более старой версией редактора).
- **Предупреждение при общей папке:** если у `RootPath` проекта есть проект другого
  владельца (`ProjectManager.GetByRootPath`), UI экспорта показывает, что паспорта станут
  видны соседу. Сам экспорт не блокируем — папка общая по решению пользователя.

**Конспекты, а не сырые ленты** (решение владельца): в `discussions/` едет структурированный
протокол обсуждения — решения, аргументы, отвергнутые варианты, — снятый тем же
`CheapTextRunner`. Дословный транскрипт продуктового чата в репозитории убивает откровенность
обсуждений и весит несоразмерно своей пользе.

**Конспект — отдельное место каталога, а не настройка паспорта.** Ключ
`LocalActionCatalog` — `discussion-digest` (группа **«Паспорта изменений»**, профиль
**Large**, **`DefaultLocal: false`**). Делить строку с `dossier-summary` нельзя: у мест
разное сырьё (весь чат целиком против дельты одного коммита) и разная частота (раз на
обсуждение против вызова на каждый коммит) — значит и профиль, и назначенный исполнитель
обязаны настраиваться порознь. Общая строка означала бы, что админ, удешевив выжимку
паспортов, молча удешевил и то, что уезжает в git.

- **Large** — по той же причине, что у `dossier-summary`, только острее: сырьё здесь
  максимальное из всех фоновых мест (лента продуктового обсуждения целиком). Меньший
  профиль означает молчаливую потерю хвоста промпта (`num_ctx` Ollama режет вход без
  предупреждения) — то есть конспект без второй половины обсуждения, и заметить это по
  результату нельзя. Даже Large сырьё не вмещает, поэтому потолок обязателен: реплики
  обсуждения ≤ 40 000 символов, обрезка с начала, `NumPredict`/таймаут потребитель передаёт
  поверх профиля (прецедент — `Changelog`, у которого свой `Changelog:TimeoutMs`).
- **`DefaultLocal: false`** — в отличие от паспорта. Паспорт живёт у нас и правится
  перезахватом; конспект уезжает в ветку `ccs/dossiers/v1`, а оттуда ручным push в remote и
  к соседям по общей папке — переписать уже опубликованное нельзя. Это «лицо продукта /
  генерация артефактов», где каталог уже держит дефолт claude (`Changelog`,
  `DailyBriefing`). Цена ничтожна: вызов раз на обсуждение, не на коммит. Админ волен
  включить локаль — строка в таблице назначений для того и заводится.
- Явный `Tier` не нужен: `EffectiveDefaultTier` от профиля Large даёт **средний** слот —
  ровно то, что требуется (место не агентное, сильный слот избыточен).

Группа общая с паспортами намеренно: `dossier-summary` и `discussion-digest` — единственные
LLM-места фичи, и админ должен видеть её полную стоимость одним блоком, а не выискивать
строки в «Git» и «Продукт». Группа — просто поле записи каталога, реестра групп нет: она
появляется в диалоге сама, порядком следования записей (`ModelProvidersModal` собирает
список групп из `actions`). Поэтому группа заводится сразу на этапе 1 вместе с
`dossier-summary`, а не на этапе 3 — иначе первую строку пришлось бы переносить из чужой
группы у админа на глазах.

Больше LLM-мест фича не содержит: `SecretRedactor` — чистая логика, статусы устаревания —
git-вызовы, семантический поиск — эмбеддинги Dify, а `{slug}` в именах файлов ветки —
детерминированная транслитерация subject'а коммита (для имени файла модель не зовём).

### 7. Каскады и краевые случаи

| Событие | Поведение |
|---|---|
| Удалён чат-источник | Паспорт живёт (он и есть выжимка); `sessionId` помечается протухшим, UI показывает «чат удалён», кнопка перехода гаснет |
| Удалена задача | То же для `taskId` |
| Удалён проект / пользователь | Каскад по образцу `UserKnowledgeCascade`: стор + датасет Dify. Ветка `ccs/dossiers/v1` в чужом репозитории не трогается — она уже не наша |
| Коммит из чата с worktree | Работает: SHA живёт в общей объектной базе, граф берётся по `EffectiveRoot` (ADR-003) |
| Squash/rebase фича-ветки | Трейлеры переезжают в новое сообщение; переякорение — по правилу ниже, а не по одному факту совпадения трейлера |
| Коммит человека руками | Трейлера нет — паспорта нет. Осознанно |
| `.tsx`/`.md`/конфиги | Файловый уровень без символов |
| Dify не настроен | Полнотекстовый recall по стору |

**Символы-якоря в v1 — известное ограничение.** Замер прода 2026-08-08: символы-якоря
заполнены лишь у ~11% паспортов (при файлах-якорях ~91%). Причина не в форматах путей (и git,
и граф хранят относительный путь от rootPath через `/` — матчится напрямую), а в том, что
**снимок CodeGraph на момент захвата часто отсутствует**. Граф строится лениво — по первому
запросу к CodeGraph API для конкретного дерева (`build-on-first-GET`), а захват берёт готовый
снимок и сознательно не триггерит дорогой Roslyn-пересбор на тике коммита. Для деревьев, по
которым никто не делал запросов (типичный worktree-чат новой фичи), снимка нет → символов нет.
Усугубляет устаревание: файлы, созданные после `BuiltAt` снимка, в нём отсутствуют.

Дёшево это в v1 не лечится: триггерить перестроение на каждый коммит — дорого и ломает
инвариант «тик не перестраивает граф». Сделан компромисс — при отсутствии снимка захват
фоново запрашивает построение (`CodeGraphService.StartRebuildIfIdle`, дедуп по idle,
неблокирующе): текущий паспорт символы ещё не получит, но следующие коммиты того же дерева —
да. Поиск по символам в REST при этом остаётся рабочим там, где снимок есть; основной канал
поиска — файлы (91%). Точки пересмотра: (1) автоматическая фоновая перестройка графа по
завершении хода для активных деревьев; (2) второй источник символов для не-C# (LSP) —
«К чему придётся вернуться» ниже.

**Правило переякорения (squash/rebase).** Совпадения трейлера мало: он не уникален
per-коммит — второй обычный коммит той же сессии несёт ровно тот же `CCS-Session:`, и
наивное «увидел знакомый трейлер → переякорил» либо угонит паспорт на несвязанный коммит,
либо заведёт дубль. Новый коммит с известным трейлером считается переписью старого, только
когда выполнены **оба** условия:

1. **Старый SHA больше не достижим** от HEAD того же рабочего дерева
   (`git merge-base --is-ancestor {старый} HEAD` → ненулевой код; после `gc` объекта может
   не быть вовсе — `git cat-file -e` даёт тот же вывод «его нет в этой истории»).
2. **Subject старого коммита присутствует в новом сообщении** — squash конкатенирует тела,
   и исходные заголовки в нём остаются. Матч по subject'у, а не по трейлеру: он различает
   исходные коммиты между собой.

Не выполнено любое — коммит обычный, заводится новый паспорт. Оба условия нужны именно
вместе: одна недостижимость ложно срабатывает на коммите, ушедшем в ещё не влитую ветку
(от HEAD текущего дерева он не достижим, хотя жив и ничем не переписан), а один subject-матч
— на `git commit --amend` без переписи предков и на ручном повторе сообщения.

При срабатывании старый SHA уезжает в `supersededSha[]`, запись остаётся одна (ключ
уникальности из §4), якоря пересчитываются по новому коммиту.

### 8. Фич-флаги и выкатка

Два флага вместо одного — иначе включение фичи одним движением сразу начинает подмешивать
непроверенную выжимку в промпты всем персонам проекта:

1. `change-dossiers` — захват + стор + REST/UI просмотра. Смотрим глазами, оцениваем
   качество выжимки на своей истории.
2. `change-dossiers-recall` — пассивная секция промпта + MCP-инструменты. Включается,
   когда паспорта перестали быть мусорными.

Оба заводятся по инструкции CLAUDE.md (`FeatureFlagCatalog.All` + `FLAGS` в
`featureFlags.ts`), дефолт `false`.

## Рассмотренные варианты

### Атрибуция коммита

| Вариант | Вердикт |
|---|---|
| Трейлер в сообщении коммита | **Выбран.** Явно, переживает перепись истории, ноль инфраструктуры |
| `post-commit` hook + env | Отклонён: запись в репозиторий пользователя, конфликт с чужими хуками и с хуками Entire, ломается в `container` |
| Хуки Claude Code (`.claude/settings.json`) | Отклонён: тем же файлом управляет наш сервер (профили/env/песочница) — ровно точка конфликта, зафиксированная как риск пилота Entire |
| Серверная эвристика (время + автор + `FileChangeAttributor`) | Отклонён постановкой и по существу: параллельные ходы и ручные коммиты дают ложную атрибуцию, а ложный паспорт хуже отсутствующего |
| Только MCP `git_commit` | Отклонён как единственный: секция `git_write` по умолчанию выключена, агент коммитит через Bash. Оставлен вторым каналом |

### Хранение

| Вариант | Вердикт |
|---|---|
| `data/dossiers/{owner}/{project}.json` + архивный JSONL | **Выбран.** Повторяет эталон памяти, бэкапится по умолчанию, переживает рестарт |
| Один файл `data/dossiers.json` на весь инстанс | Отклонён: перезапись файла целиком на каждый коммит, рост без границ |
| SQLite (как `ProjectEventLogService`) | Отклонён **на v1**: даёт индексы и запросы, но требует своей ветки в бэкапе (`BackupDatabase`) и миграций. Точка пересмотра — измеримый триггер в §4 (файл >15 МБ или >3000 записей) |
| Только Dify, без своего стора | Отклонён: Dify — производный слой, он может быть не настроен, а source of truth обязан жить у нас |
| git notes | Отклонён: не переживают ремоут без явного push/fetch notes, не видны в UI хостингов |

### Доставка в промпт

| Вариант | Вердикт |
|---|---|
| Секция в существующем блоке recall + MCP-инструменты | **Выбран.** Ноль новых каналов, бюджет под контролем, симметрия с графом кода (ADR-002/003) |
| Отдельный системный блок «паспорта» | Отклонён: третий конкурент за место в промпте, свой бюджет, своя отладка |
| Только MCP (без пассивного канала) | Отклонён: персона не знает, что спрашивать, пока не наткнётся на код; главный сценарий («правлю файл — вижу, зачем его меняли») не работает |

## Анализ компромиссов

- **Трейлер vs хук.** Трейлер зависит от дисциплины модели: забыла строку — паспорта нет.
  Хук был бы надёжнее, но ценой записи в чужой репозиторий и конфликта с Entire. Выбрана
  надёжность инварианта «не трогаем репозиторий пользователя» против полноты сбора; недосбор
  чинится дописыванием трейлера в промпт и вторым каналом `git_commit`.
- **Ленивое устаревание vs фоновый скан.** Лениво — дешевле и не тратит git-вызовы на
  паспорта, которые никто не спрашивает; цена — первый recall по давно не трогавшемуся файлу
  чуть дороже (несколько `git log` с кешем на HEAD).
- **JSON-стор vs SQLite.** JSON проще, бэкапится сам, повторяет эталон; цена — `Save()`
  переписывает файл целиком на каждое добавление, линейный индекс в памяти и потолок записей
  (вытесненные в архив выпадают из поиска/recall — рост потолка ценности не возвращает).
  Переезд на SQLite обратим и локален (интерфейс сервиса не меняется); триггер — §4: файл
  >15 МБ или >3000 записей.
- **Символы только для C#.** Roslyn-граф знает лишь типы, поэтому «символьный якорь» для
  фронтенда и скриптов деградирует до файла. Это честное ограничение v1, а не временный
  костыль: методов в графе нет вовсе, и добавлять их ради паспортов — отдельное решение.
- **Два флага vs один.** Лишняя сущность в каталоге против риска «включил и залил промпты
  мусором». Выбрана осторожность — она же прописана в продуктовом решении о двух шагах.

## Последствия

**Становится проще:**
- Персона, правящая файл, видит, зачем его меняли и что при этом отвергли, — без ручной
  документации и без раскопок в истории чатов.
- Обратный поиск «решение → коммит» появляется бесплатно: паспорт лежит в общем слое знаний
  с метаданными.
- История «зачем» переживает удаление чатов и задач.

**Становится сложнее:**
- Новый стор, новый датасет Dify, новый hosted service и новая секция MCP — четыре точки,
  которые надо помнить при каскадах удаления и бэкапе.
- Сообщения коммитов обрастают служебным трейлером — и он **уезжает в публичный remote**
  при обычном `git push` кода, вместе с id чата и id задачи, навсегда (§1: решение
  осознанное, id непрозрачен и вне инстанса не резолвится, но история публичная).
- Промпт персоны прирастает третьей секцией recall — бюджет контекста надо держать под
  наблюдением.

**К чему придётся вернуться:**
- Качество выжимки — решается только на реальных данных, отсюда флаг №2 отдельным шагом.
- Объём стора: файл проекта >15 МБ ИЛИ >3000 записей — переход на SQLite (измеримый триггер, §4;
  стор пишет warning при приближении). Не «когда-нибудь»: при текущем темпе достижимо за год.
- Символы для не-C#: если фронтенд-паспорта окажутся бесполезными на файловом уровне —
  вопрос о втором источнике символов (LSP из omc-плагина, см. решение по навигации кода).
- Пилот Entire CLI на небоевом репо (согласован отдельно) может изменить решение по экспорту:
  если опубликуют спеку формата — добавляем адаптер, свою ветку оставляем.

## Проверка

Общее для всех этапов: `dotnet build` и

```powershell
dotnet test --filter "FullyQualifiedName~Dossier|FullyQualifiedName~Backup|FullyQualifiedName~Mcp"
```

(каждая альтернатива `|` — полное выражение целиком, сокращённая форма `|~Backup` фильтром
не понимается и тихо сужает прогон).

### Этап 1 — захват

- Тест `SecretRedactor`: подставленный ключ провайдера, OAuth-токен подписки и JWT из
  фикстуры не попадают ни в промпт выжимки, ни в сохранённый паспорт; PEM-блок вырезается
  целиком; пустой и 4-символьный `ApiKey` в конфиге не режут посторонний текст.
- **Тест изоляции (guard §1):** одна папка подключена как проект владельцами A и B, коммит
  несёт трейлер чата владельца A → у A паспорт создан, у B стор пуст и в Dify ничего не
  ушло. Плюс тест на подделку: трейлер с чужим/несуществующим/невалидным по формату id →
  паспорта нет.
- Тест worktree: коммит сделан в дереве worktree-чата, HEAD корня не двигался → паспорт
  создан по внеочередной проверке, `state.json` содержит запись на это дерево.
- Тест переякорения: два коммита с трейлерами → squash → один коммит с обоими subject'ами в
  теле → оба паспорта указывают на новый SHA, `supersededSha` заполнены. Негативный:
  второй обычный коммит той же сессии (старый SHA достижим) → новый паспорт, старый не
  тронут.
- Тест идемпотентности: повторный проход по тому же коммиту (откат `state.json` из бэкапа)
  → записей в сторе столько же, документ в Dify один.
- Тест бэкапа: `BackupPaths.ShouldInclude("dossiers/{owner}/{project}.json")` → `true`;
  архив после restore содержит паспорта.
- Ручной сценарий: коммит из чата → через ≤ 60 с паспорт виден в панели.

### Этап 2 — recall

- Тест статусов: символ удалён из графа → `archived`, в пассивный канал не попадает.
- `McpToolsetStabilityTests`: состав `tools/list` не зависит от свойств хода.
- Ручной сценарий: правка файла в другом чате → паспорт подмешался в промпт (проверяется по
  манифесту атрибуции).
