# Панель Code Graph — предложение по макету

Спека: задача трекера `cbf7a55c` (Майя). Backend-контракт параллельно делает Денис:
`GET /api/projects/{projectId}/code-graph` → `{ nodes, edges, godNodes, metadata }`.
Артефакт согласования — кликабельный прототип `code-graph-panel.html` (все 4 сценария +
сценарий закрытия, обе темы, мобила). После одобрения Андрея уходит Кире на реализацию.

## Проблема

В крупном .NET-коде зависимости расползаются тихо: класс начинает вызывать десяток
других, интерфейс реализуется в пяти местах, god-объект копит связи незаметно. По файлам
это не видно — физическое дерево каталогов молчит про то, кто кого вызывает. Ответа на
«что с чем связано и где узкое место» в продукте нет. Code Graph даёт его: логическая
карта типов и рёбер между ними, с подсветкой god-nodes — точек перегруза.

## Решение — документ в центре + панель «Граф» в правой рельсе

По замечанию Андрея (итерация 2): граф живёт **в раскладке рабочих инструментов
workspace** (`RightPanelStack`), а не отдельной вкладкой уровня «Чат/Файлы». Две части:

- **Документ «Граф зависимостей» в центральной контентной зоне.** Ведёт себя как
  открытый файл (`openFile` → FileViewer): центр показывает либо чат, либо граф.
  Шапка документа — иконка, заголовок, metadata-чипы (типы/рёбра/файлы/время сборки),
  действие «Перестроить» и **крестик закрытия** — центр возвращается к чату.
- **Панель «Граф» в проектной рельсе справа** (новый ключ рядом с
  files/changes/tasks/team/terminal/preview). Это инспектор отображения: поиск типа,
  связи (Calls/Implements/References), легенда, god-узлы и паспорт выбранного типа.
  Панель — обычная карточка рельсы: открывается иконкой, сворачивается своим ×,
  живёт независимо от того, открыт ли документ.

### Фильтр компактный, паспорт — главный (итерация 3)

По замечанию Андрея: основная задача панели — контент по выбранному узлу, а фильтрация
опциональна, но доступна. Поэтому иерархия панели перевёрнута:

- **Связи** — одна строка компактных чипов-тогглов (цветная точка + имя + счётчик)
  вместо трёх полных строк чекбоксов: рабочий фильтр под рукой, но не давит по
  вертикали.
- **«Легенда и god-узлы»** — сворачиваемая секция, по умолчанию свёрнута. Справочная
  информация не занимает место, пока не понадобилась.
- **При выборе узла легенда сворачивается сама** — паспорт получает всю высоту панели.
  Развернуть обратно — один клик по заголовку секции.
- Паспорт — нижняя (и главная) секция панели: kind-бейдж, FQN, `sourceFile:location`,
  исходящие/входящие связи с переходом по клику.

Связка двух частей — по правилам, озвученным Андреем:

1. **Меняю режим в панели → меняется граф в центре.** Чекбоксы связей и поиск
   мгновенно применяются к открытому документу.
2. **Документ закрыт, а я меняю режим → документ открывается снова.** Снял чекбокс,
   кликнул god-узел или ввёл поиск при закрытом графе — центр сам переключается с чата
   на граф с уже применённым режимом. Плюс явная кнопка «Показать граф в центре» в
   панели.
3. **Могу закрыть в любой момент.** Крестик в шапке документа — и центр снова чат,
   режимы в панели при этом сохраняются (при следующем открытии граф придёт с ними).

Почему это лучше первой версии (вкладка уровня «Чат/Файлы»):

- **Не плодит верхнеуровневые вкладки.** Граф — рабочий инструмент проекта, как
  «Изменения» или «Задачи»: они тоже живут в рельсе, а их документы — в центре.
  Единообразие паттерна вместо особого случая.
- **Контролы не жрут холст.** Режимы и паспорт вынесены в панель справа — холсту
  достаётся вся ширина центра, а на узком экране панель просто сворачивается.
- **Паспорт и граф видны одновременно.** Клик по узлу подсвечивает его на холсте и
  заполняет паспорт в панели — два фокуса на одном экране без перекрытий.

## Раскладка

```
┌ WorkspacePage ─────────────────────────────────────────────────┐
│ ┌─────────┐ ┌──────────────────────────────┐ ┌────────┐ ┌───┐ │
│ │ чаты    │ │ Граф зависимостей        [×] │ │ Граф   │ │⚙ │ │
│ │         │ │ ┌──────────────────────────┐ │ │ поиск  │ │📁 │ │
│ │ · чат 1 │ │ │      SVG-холст графа     │ │ │ связи  │ │🌿 │ │
│ │ · чат 2 │ │ │   (клик → паспорт)       │ │ │ типы   │ │✔ │ │
│ │         │ │ └──────────────────────────┘ │ │ god    │ │🕸 │ │
│ │         │ │                              │ │ паспорт│ │   │ │
│ └─────────┘ └──────────────────────────────┘ └────────┘ └───┘ │
│   сайдбар      центр: чат XOR документ «Граф»   панель   рельса│
└────────────────────────────────────────────────────────────────┘
```

- **Центр**: `openGraph` рядом с `openFile`/`selectedTask` в WorkspacePage — тот же
  механизм «документ поверх чата», тот же крестик закрытия и возврат к чату.
- **Панель «Граф»**: ключ `graph` в `PANEL_META`/`PROJECT_RAIL_KEYS`
  (`RightPanelStack`), контент собирается в WorkspacePage, как у остальных панелей.
  DnD-раскладка панелей, сворачивание и колонки достаются бесплатно.

## Цвет и форму — только из токенов

| Что | Токен | Почему |
|---|---|---|
| Ребро **Calls** | `C.info` (синий) | вызов — «поток управления», синий не спорит |
| Ребро **Implements** | `C.success` (зелёный) | реализация контракта — «позитивная» связь |
| Ребро **References** | `C.plan` (индиго) | упоминание типа — отдельный оттенок от calls |
| **god-node** (контур + размер) | `C.accent` (оранжевый) | точка перегруза — главное, на что смотреть |
| Узел **Class** | нейтральный `C.textSecondary` | базовый вид, большинство узлов |
| Узел **Interface** | `C.info` | контракт |
| Узел **Struct** | `C.success` | тип-значение |
| Узел **Enum** | `C.plan` | перечисление |
| Бейдж **stale** | `C.warning*` | мягкое «может быть устаревшим», не тревога |
| Confidence **Extracted** | сплошная линия | извлечено из анализа кода — достоверно |
| Confidence **Inferred** | пунктирная линия | выведено эвристикой — «не уверен» |

Accent-дисциплина соблюдена: оранжевый — только god-nodes, кнопка «Перестроить»
(главное действие) и активная иконка «Граф» в рельсе. Три оси (relation, kind,
выделение) не сливаются в одно цветовое пятно.

## Четыре состояния + закрытие

1. **Построен и открыт** — документ в центре, панель справа. Демо-данные симулируют
   срез `Services/Llm`: `LlmProviderRegistry` и `ClaudeSession` — god-nodes. Клик по
   узлу подсвечивает инцидентные рёбра и заполняет паспорт в панели.
2. **Закрыт** — центр показывает чат; панель «Граф» открыта, режимы на месте. Смена
   любого режима (или клик по god-узлу, или кнопка «Показать граф в центре») открывает
   документ снова.
3. **Empty** — граф не построен: empty-state в документе с кнопкой «Построить граф»;
   панель деградирует до той же кнопки (фильтры бессмысленны без данных).
4. **Loading** — спиннер + прогресс по файлам в документе; контролы панели disabled.
5. **Stale** (`metadata.isStale=true`) — warning-бейдж в шапке документа + «Перестроить»
   как primary (и дубль в панели с пояснением, сколько файлов изменилось). Граф
   остаётся рабочим — осмотр не блокируем.

## Мобила (390px)

- Документ «Граф» — на весь экран, крестик закрытия ведёт назад к чату (мобильный
  паттерн «список → документ»).
- Панель «Граф» — **нижняя шторка** по FAB-кнопке с бейджем числа активных фильтров
  (как drawer панелей на планшете/телефоне в `RightPanelStack`).
- Холст: tap выделяет узел и его рёбра, второй tap по выделенному — раскрывает шторку
  на паспорте. Hover-состояний нет, тач-цели ≥ 40px.

## Как смотреть

Файл самодостаточен: открыть в браузере. Кнопка справа вверху переключает светлую и
тёмную тему. Сценарии — секциями один под другим: «построен», «закрыт → переоткрытие»,
empty, loading, stale, мобила (два фрейма). Интерактив: выбор узла и паспорт, фильтры
связей, поиск, закрытие документа, переоткрытие по смене режима. Шрифты — с Google
Fonts, фолбэки Georgia/system/monospace.
