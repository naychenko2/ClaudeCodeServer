# Хост-эмулятор панелей плагинов

Инструмент разработки (шаг A2 плана «Погода», доработка R1): собирает и гоняет панель
плагина в браузере **без установки**. Панель живёт ровно в той же среде, что вживую:
двухуровневый фрейм, `PANEL_CSP`, шим `window.ccsPlugin` из `plugin-kit.js`,
структурный CSS кита и токены `--cc-*` текущей темы. Эмулятор — **общий инструмент**:
панель, права и фикстуры задаются параметрами URL, ничего «погодного» в его код не
вшито. В пакет плагина он не попадает (allow-list пакета — только `panel/**` и
манифесты), и в прод не уходит: каталог живёт в `tools/plugins/dev-host/`, вне
`frontend/public/` (статика `public/` попадает в `dist` → `wwwroot`).

Сборка документа панели — копия логики хоста (`panelSrcdoc.ts`, `panelTokens.ts`,
`bridge.ts`); платформенный код эмулятор не трогает.

## Запуск

Из корня репозитория, без сборки:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Сервер слушает только локальный адрес, а корень репозитория раздаётся целиком (включая `.git/`
и `backend/`, где в рабочей копии лежат ключи в `appsettings.Local.json`): не запускай это
на общей сети и не оставляй надолго.

Единственный адрес эмулятора:

```
http://localhost:8000/tools/plugins/dev-host/index.html?panel=tools/plugins/weather/panel/index.html
```

Все пути в параметрах — относительные от корня репозитория. Эмулятор **не грузит
чужие страницы**: `panel=` и `fixtures=` принимаются только как пути внутри
репозитория (без схемы, без protocol-relative, без `..` за пределы корня).

## Что эмулятор воспроизводит из хоста

- двухуровневый фрейм, `PANEL_CSP`, шим кита, токены текущей темы;
- проверка сообщения моста: `source === 'ccs-plugin'`, `v === 1`, origin `'null'`
  (sandbox без `allow-same-origin`), сообщения только из окна панели;
- права `net:{host}` по точному хосту; тексты отказов — дословно из сервера
  (`PluginBridge.DeniedError` / `PluginNetProxy`): «Нет права: net:{host}» (хост из
  url вызова), «Нет права на сетевые запросы» (когда хост из аргументов не вытащить),
  «Таймаут запроса», «Превышено число запросов на плагин в минуту»,
  «Обработчик не зарегистрирован: {domain}»;
- вызовы `storage.*` — через **общую реализацию хоста** `frontend/src/features/plugins/hostOps/storage.js`
  (тот же модуль, что подключает `PluginFrame.tsx`): право, пределы, тексты отказов
  и тихость отказа по storage — те же, что на боевом хосте; `grant=` принимает и
  `storage`;
- гейты вызовов: не более 8 одновременных («Слишком много одновременных вызовов»),
  args не более 64 КиБ («Аргументы слишком большие»), таймаут `ready` 3 с
  («Мост не получил ответа за 3 с.») — как в `PluginFrame.tsx` / `bridge.ts`;
- сеть: только `http(s)`, `credentials: 'omit'` (куки и токен origin не уходят);
  основной режим — фикстуры, сеть — только если фикстур нет;
- высота по `resize` (кламп 48–20000 px).

## Что эмулятор НЕ воспроизводит

**CORS.** Боевой `PluginNetProxy` ходит с сервера, и CORS к нему не применяется; эмулятор
делает `fetch` из браузера (origin `localhost:8000`), поэтому внешний хост без
`Access-Control-Allow-Origin` вернёт панели сетевую ошибку вместо ответа. У Open-Meteo CORS
есть, у произвольного API может не быть: «зелёное в эмуляторе» не равно «зелёное в бою» и
наоборот.

Это инструмент разработки, он ходит **мимо серверной защиты**: статический сервер
не знает авторизации, прав и квот. Не моделируются: настоящий rate-limit «запросов
в минуту» (сбой `limit` только симулируется через `fail=`), SSRF и приватные
адреса, редиректы, секреты и белый список заголовков, маппинг HTTP-статуса в код
(любой статус приходит как успех `net.fetch`). Для боевого поведения — установка
плагина в продукт.

`grant=` — **имитация согласия**: реальные права выдаёт сервер при установке
плагина; здесь список хостов задаёт человек напрямую, и по нему эмулятор
отказывает или пропускает вызовы.

## Переключатели (в URL или в панели управления)

| Парамет | Значения | Что делает |
|---|---|---|
| `panel=` | путь к HTML панели внутри репозитория | какую панель монтировать (по умолчанию — исходник «Погоды» `tools/plugins/weather/panel/index.html`; копии нет — она бы расходилась с оригиналом) |
| `grant=` | net:хосты или `storage`, через запятую | выданные права; префикс `net:` необязателен. `ccsPlugin.state.granted` — ровно этот список в боевом формате (`net:{host}`, `storage`) |
| `fail=` | `upstream` / `timeout` / `limit` / `status400` | смоделировать сбой: коды и тексты — как у сервера (upstream — типичная сетевая ошибка «Connection refused»); `status400` приходит как **успех** `net.fetch` с `status: 400` (графль §1 плана) |
| `delay=` | мс | задержка ответа `net.fetch` — чтобы увидеть скелетон панели |
| `fixtures=` | пути к файлам через запятую | не выходить в сеть: ответ берётся из файла-фикстуры. Одна — для всех вызовов; несколько — по порядку вызовов. Необязательные `|match` (подстрока URL запроса) и `|delay` (мс задержки этого ответа) привязывают фикстуру к запросу, а не к порядку вызовов — для сценариев гонки (check.mjs, сценарий 7) |
| `theme=` | `light` / `dark` | тема хоста; переключается кнопкой без перезагрузки — панель перекрашивается сообщением `theme`, как вживую |
| `width=` | `rail` / `320` / `390` | ширина панели (кадра): `rail` — на всю карточку, как в рельсе; `320`/`390` — фиксированная ширина кадра, карточка расширяется под него |
| `selftest=` | `1` | панель сама прогоняет тестовые вызовы (прогноз, геокодер, прямой `fetch`) и пишет результат в лог эмулятора и в `window.__emulator.selftest` |

Фикстуры «Погоды» — в `tools/plugins/dev-host/fixtures/` (вне пакета: `fixtures/`
не в allow-list пакета, и валидатор отбивает такой пакет). Пример полного прогона
«Погоды» на фикстурах:

```
http://localhost:8000/tools/plugins/dev-host/index.html?panel=tools/plugins/weather/panel/index.html&selftest=1&grant=api.open-meteo.com,geocoding-api.open-meteo.com&fixtures=tools/plugins/dev-host/fixtures/forecast-yaroslavl.json,tools/plugins/dev-host/fixtures/geocode-yaroslavl.json
```

## Что и как проверять

1. **Права.** Открыть с `grant=api.open-meteo.com,geocoding-api.open-meteo.com`,
   `grant=api.open-meteo.com`, `grant=` (пусто). В консоли фрейма:
   `ccsPlugin.state.granted` — ровно то, что в `grant=`. Вызов
   `ccsPlugin.call('net.fetch', {url:'https://geocoding-api.open-meteo.com/v1/search?name=%D0%AF%D1%80%D1%86&count=10&language=ru&format=json'})`
   при `grant=api.open-meteo.com` (право на геокодер не выдано) даёт `denied` с текстом
   `Нет права: net:geocoding-api.open-meteo.com` и плашку «Нет права …» над панелью;
   при пустом `grant=` — `Нет права: net:{host}` (мост называет хост из url вызова),
   а если url нечитаем — `Нет права на сетевые запросы`.
2. **Данные.** С `fixtures=` вызовы возвращают фикстуры без сети; без него —
   реальный `fetch` хоста без куков и токена origin.
3. **Сеть закрыта.** Прямой `fetch(...)` из консоли фрейма падает: CSP панели —
   `connect-src 'none'`, весь выход наружу — только мостом.
4. **Чужая панель.** `panel=https://example.com/` не грузится: параметр принимает
   только пути внутри репозитория.
5. **Тема.** Кнопка «тема» перекрашивает панель без перезагрузки: шим переписывает
   `style#cc-tokens` (first-paint уже в цвете текущей темы).
6. **Высота.** Фрейм растягивается по `resize` панели (кламп 48–20000 px), как хост.
7. **Лог.** Каждый `call` и ответ видны в логе под карточкой — по нему видно,
   сколько вызовов сделала панель (например, ровно 2 на поиск города).
